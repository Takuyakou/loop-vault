## 1. 原因

**1(押している鍵の持ち方)が主因**でした。2(接続の切れ間)も、記録がずれ得る作りだったため同じ修正で揃えました。

- 画面は判定用に `heldRef`(音番号だけの Set)を持ち、別に liveMidi の押鍵記録(チャンネル+音、同じキーの note-on 回数)を持っていました。画面の鍵盤表示は liveMidi、判定は `heldRef` という別々の記録でした。
- 同じチャンネル+音の note-on が二重に届くと、liveMidi は回数を 2 にしますが、`heldRef` は 1 回しか追加しません。そのあと note-off が 1 回届くと `heldRef` は音を消します。liveMidi ではまだ押しているので、**画面の鍵盤には残っているのに判定の held から消える**状態になり、「音の数がちょうど同じ」を満たせませんでした。
- `heldRef` はチャンネルを見ていないため、別チャンネルの同じ音を片方離しただけでも判定から消えました。
- 接続が切れたときは `heldRef` を clear していましたが、liveMidi の記録と判定の記録が別なので、再接続後に押し直したときの held がずれる余地がありました。

利用者の「いったん全部の指を離して押し直すと通った」は、このずれた held がリセットされて一致したためです。

## 2. 直したこと

- 判定は **liveMidi の押鍵記録(チャンネル+音、note-on 回数)を reduce した一つの記録**から、押している音の集合(重複なし)を作って渡すようにした。画面の鍵盤と同じ記録系です。
- `voicingDrillSession.drillEvent` に「今押している音の snapshot」を渡せるようにし、`round.held` は snapshot を正とする。同じ音の二重 note-on、別チャンネルの同じ音、離すのが先に来る順でも、押している間は held に残る。
- 接続が変わったら liveMidi の記録を作り直し、周を捨てる。押したままの鍵は次の操作で作り直す。
- 約 1 秒通らないときに、カードの下へ理由を出す。
  - ① は音名付き: 余分な音 / 足りない音 / 右手の並びが違います / 左手が一番下にない / ペダルの音は数えない
  - ② は「形が違います」だけ
  - 通ったら消す。
- 「判定の様子」を開くと、直近 50 件の MIDI(時刻・チャンネル・音・押/離)と、そのときの判定(カード・通過/状態)を見られる。画面の中だけの memory で、保存も記録ファイルへの書き込みもしない。
