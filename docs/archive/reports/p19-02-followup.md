## 2. lap-result の「迷った」(FΔ7・G7)

**e2e がわざと違う音を押したのではありません。** 原因は写真用の演奏ドライバが、**前のカードから押さえたままの鍵も「新しく押す音」として送り直していた**ことです。

- C と Am7 は右手が同じ G4 C5 E5 です。C3 を離して A2 を押すと、**A2 を押した瞬間に Am7 が完成**します。そのあとドライバが持ち越しの G4 を押し直すと、これは「Am7 の後の新しい押鍵」= 次の FΔ7 の音として扱われ、FΔ7 に無い G4 が **迷った** になります。
- 同じく FΔ7 は A4 を押した瞬間に完成し、そのあと持ち越しの C5/E5 を押し直すと、次の G7 の音として扱われ、G7 に無い C5/E5 が **迷った** になります。

アプリの判定は仕様どおりです(カードが通った後の押鍵は次のカードの出来事。1 つの出来事で進むのは 1 枚)。直すのはドライバ側で、

- 次に必要な音だけを押す(押さえたままの鍵は押し直さない)
- 次のカードに無い鍵だけを離す

に変えました。`e2e/p19-voicing-drill.spec.ts` の ① は `last.marks` が空であることを断言し、写真用の `scripts/p89/p19-voicing-drill-screens.pw.ts` も同じ形にして、lap-result の写真を撮る前に **marks が空**であることを確認するようにしました。写真は撮り直し済みです。

単体テストを 2 件追加(`voicingDrillSession.test.ts`):

- 通ったカードの持ち越し鍵を押し直すと、次のカードの **迷った** になる(いまのイベントの意味を固定)
- 持ち越しを押し直さず、足りない鍵だけを押すと **迷った 0**
