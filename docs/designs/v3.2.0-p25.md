### K1. 置き場所と型

新しく `src/domain/voicingShapes/` を作る。React・音・ブラウザの物を使わない純粋な TypeScript。

```ts
export type VoicingShapeId = "shell" | "rootless" | "triad" | "quartal";
export type RootlessOrder = "auto" | "A" | "B";
export interface VoicingShapeOptions {
  readonly shape: VoicingShapeId;
  readonly tension: boolean;      // P26 の Color
  readonly spread: boolean;       // P26 の 広げる
  readonly rootlessOrder: RootlessOrder;
}
export const DEFAULT_VOICING_SHAPE_OPTIONS: VoicingShapeOptions =
  { shape: "shell", tension: false, spread: false, rootlessOrder: "auto" };

/** 実際に作った形。代わりになった時は選んだ形と違う。 */
export type UsedVoicingShape =
  | "shell" | "shell+tension" | "shell+spread" | "shell+tension+spread"
  | "rootless" | "rootless+spread" | "triad" | "quartal" | "close"
  | "basic" | "basic+tension" | "basic+spread" | "basic+tension+spread"   // K11(Voicing Loop の基本に部品を付けた時)
  | "legacy";   // K4:詰めた形まで作れず、今の作り方の音で鳴らす時

export interface ShapeVoicingPlacement { readonly left: readonly number[]; readonly right: readonly number[] }
export interface ShapeVoicingForm {
  readonly form: "A" | "B" | null;                 // ② だけ A/B。ほかは null
  readonly candidates: readonly ShapeVoicingPlacement[]; // P26 5.1 に合格した置き方の全部
  readonly staticChoice: ShapeVoicingPlacement;    // K3 の静的な選び
}
export interface ShapeVoicingResult {
  readonly requested: VoicingShapeOptions;
  readonly used: UsedVoicingShape;
  readonly fellBack: boolean;                      // 選んだ形と部品のまま作れなかった
  readonly forms: readonly ShapeVoicingForm[];     // 1 つ以上。② で片方しか置けないキーは 1 つ
  readonly addedTension?: string;                  // テンションを足した時の度数("9" "11" "13" …)。K5 のボタンの字に使う
}
export function buildShapeVoicing(chord: ChordSymbol, options: VoicingShapeOptions): ShapeVoicingResult;
```

- `used` の名前は、P26 の文書の「①+Color+広げる」を `"shell+tension+spread"` と書く(Color → tension)。
- 決まりの数(P26 3.2・3.3):左手 36〜64、右手 52〜88、片手 12 半音まで、左手 2 音まで(② だけ 4 音で、一番下が 48〜59・一番上が **70** 以下)、右手 4 音まで(詰めた形だけ 5 音まで)。間隔は**基準 B**(新しい関数 `textbookLowIntervalLimit`。今の `lowIntervalLimit.ts` は消さず、K の中では使わない)。
- 第 4 版で足した 2 つの決まり(`rec.py` の `lil_ok` と `check`):
  - **低い所の 6 度・7 度**:隣り合う 2 音が 9〜11 半音の時は下の音が MIDI 41 以上(`LOW_SEVENTH_MIN`)、8 半音の時は 43 以上(`LOW_SIXTH_MIN`)。
  - **両手の間**:左手が 2 音以上の時、右手の一番下 − 左手の一番上 ≦ 12(`HAND_GAP_MAX`)。左手が 1 音の時は ≦ 24(`HAND_GAP_MAX_ONE_NOTE`)。
- P26 の付録の `rec.py`(リポジトリの外)が、P26 の表を作ったプログラム(手本)。`recipe()`・`place()`・`check()`・`build()` を、そのまま TypeScript に移す。度数の表(`SEMI`・`QUAL`・`SAFE`)も同じ値。**自分で考えて変えない。**

### K4. 作れない時の代わり

P26 6 章のとおり(`rec.py` の `CHAIN` と `build()`)。④ / ③ → ②+広げる → ①+テンション+広げる → 詰めた形。② → ① → 詰めた形。① → 詰めた形。代わりになった時は `fellBack: true`。
- 分数コード(P26 3.6):①・② を選んでいる時は ①(`used` は `shell`。① で部品を選んでいれば、その部品が付く)、③・④ を選んでいる時は **`used` が `shell+tension+spread`**(分数コードでは広げるの左手が効かないので、鳴る音は ①+テンションと同じ)。`used` の字は正解の表に合わせる。

- 「詰めた形」は `rec.py` の `close`(ベース 1 音 + 残りを右手に)。今の `generated-close` の関数とは別物(K の中では `rec.py` のとおりに作る)。代わりで使うだけで、選ぶボタンは無い。
- **詰めた形まで全部作れない時**(正解の表の外のコード。例:`C7(b9,#9,#11,b13)`。今のアプリでは取り込めて試聴できるが、`rec.py` では `no shape` になる):**今の作り方の音で鳴らす**。テキスト取り込みは今の試聴の音(今の `generated-close` の経路)、Voicing Loop は今の `generated-close`。`used: "legacy"`(K1 の型に足す)・`fellBack: true`・候補はその 1 つ。カードに「A」、知らせは「このコードは形で作れないので、今までの作り方の音で鳴らしています」。今の作り方でも音が作れない時だけ、今と同じ「使えないコード」の扱いにする。`buildShapeVoicing` は投げない(例外を外に出さない)。
- 単体テスト:`C7(b9,#9,#11,b13)` を貼る → 試聴 → 形を選ぶ → 保存 → 開き直す → 鳴る音が v3.1.0 の試聴の音と同じ。

### K6. なめらかにつなぐ(今の最適化)

- 今の `optimizeProgression`(進行全体で、最後から先頭へのつながりも含めて選ぶ)を、そのまま使う。渡す候補を、K の `candidates`(② の並びが「自動」の時は A と B の候補を合わせた物、「A」「B」の時はその並びだけ)にする。**候補の外の音を選ばない。**
- Voicing Loop で ② の並びを「A」「B」に決めている時、そのコードでその並びが置けないカード(正解の表で片方しか無い物)は、**置ける方の並びを使う**(全体の設定は変えない。カードに「A」の印は出さない。カードの `title` に「このコードは B の並びだけ置けます」)。
- 最初のコードの費用にも、K3 の半音の費用を足す(並びが自由な形だけ)。
- 「そのまま使う」は、**今の循環の選び方(`optimizeCandidateGroups` の動的計画)を使い回す**という意味。今の関数は静的な費用・つながりの費用・同点の比べ方を中で決めているので、**費用の関数を外から渡せる形にする**(引数を足す。今の呼び出しは何も渡さず、今と同じ動き)。K からだけ K の費用を渡す。単体テストに、K の費用で選び方が変わる手書きの例を 1 件(② が混ざる進行で、今の費用だと低い方に寄り、K の費用だと K3 の高さになる物)。
- **費用は K の物を使う**(今の `candidateStaticCost`・`transitionCost` は、右手が空の候補を正しく扱えない:空の平均を 0 として数え、② に毎回 67 の罰が付く)。
  - 静的な費用:K3 の計算そのもの(両手なら中心 48・67 と開き × 0.25 と半音 +4、左手だけなら |平均 − 55|)。`candidateStaticCost` は呼ばない。
  - つながりの費用:今の `transitionCost` を使うが、渡す前に**費用を測るための見方**に直す:左手だけの候補(② で広げるが無い物)は、一番低い 1 音を「左」、残りの 3 音を「右」として渡す(画面と弾き合わせの左右は K のまま。費用の計算の中だけ)。
  - 単体テスト:② と、② から ① に代わったカードが混ざる進行(`| Cmaj7 | C | Dm7 | G7 |` を ② で)で、選ばれた置き方の高さが、K3 の静的な選びから 1 オクターブより離れないこと。
- 単体テスト:決まった進行(`| Dm7 G7 | Cmaj7 | Am7 | D7 G7 |` と `| Fmaj7 | Em7 A7 | Dm7 G7 | Cmaj7 |` を、4 つの形 × 部品で)で、選ばれた置き方が全部、そのコードの `candidates` の中にあること。

### K11. Voicing Loop の基本に部品を付けた時

**基本の音は、そのまま残す**(K の決まりで確かめ直さない・置き直さない。今の基本には P26 の決まりに合わない音を持つ物があるが、それも今の音として守る。例:`C11` の基本 `[48,58,65,67,74,76]`)。**K と同じにするのは、足す音と広げ方だけ。**

  - `title`:基本「今までどおりのおすすめの音」・シェル「左 R・7 / 右 3・5」・ルートレス「左手 4 音 · ルートなし」・シェル+三和音「左 2 音 / 右 三和音」・4 度積み「右手を 4 度で積む」。
  - **テンションを足す**(コードの中の名前は `tension`。P26 の文書の「Color」と同じ物):ボタンの字は「テンションを足す」と、その右に**足される音**(見本の `sub`)。① の時は、K で足される音を「+9(D)」「+11(F)」の形で出す(度数は ♭9・9・♯9・11・♯11・♭13・13、音名は今の表記)。足す音が無いコード(Cmaj9 など、コード名にもうテンションがある)では「なし」で押せない。ルートレス・シェル+三和音・4 度積みの時は「入り済み」で押せず、`title` は「ルートレス は、はじめからテンションが入っています」の形。基本の時は「—」で押せず、`title` は「基本は今までどおりの音なので、部品は付けられません」。ON の時の色は `#8bd7ff`(枠と字)・地 `#10314a`。
  - **広げる**:字は「広げる」と、その右に「左 R・5」。シェルとルートレスの時だけ押せる。ほか(基本を含む)の時は薄く、`title`「シェルとルートレスの時だけ使えます」。
  - **並び**(ルートレスの時だけ):「A」「B」。今の音が A なら A が選ばれている。押すと、そのカードの ② をその並びに固定する。何も押していない時は K3 の静的な選び(A と B のうち近い方)。そのコードで置けない並び(正解の表で片方しか無い 22 件。例:G7sus4 の ② は B だけ)のボタンは薄くして押せず、`title` は「このコードでは A の並びは範囲に入りません」。
  - 押した時:その形・部品・並びで作った音(K3 の静的な選び)を、そのカードの**形のスナップショット**にする(C11 の新しい書き方)。選ばれている印:そのカードの形のスナップショットが持つ形と部品。何も持たない時は**基本**。
  - 代わりの形になった時:鍵盤の上の行の右に、`#a5b2c6` で「Cm7♭5 は シェル+三和音 にできないので、ルートレス + 広げる で鳴らしています」(見本の `fellBack` の文。名前は K の `used` から作る。正解の表どおり、Cm7♭5 で ③ を選ぶと `rootless+spread`、Cdim で ③ を選ぶと `shell+tension+spread`)。
- **転回 ↑**:上の音のうち一番低い音を 1 オクターブ上へ。**転回 ↓**:一番高い音を 1 オクターブ下へ。
  - 「ベースあり」:音が 3 つ以上で、一番低い音の音名がコードのベース(分数コードは分母、無ければルート)の時。その時は一番低い音を動かさず、残りを「上の音」とする。それ以外は全部が「上の音」。
  - 動かした先が 36〜84 の外・ベース以下・もうある音と同じ高さになる時は、何も変えない。
- **高さ ↓ ↑**:全部の音を 1 オクターブ動かす。どれかが 36〜84 の外に出る時は、何も変えない。
- **前に近づける**:1 つ前のカードの音に、上の音が一番近くなる転回にする。
  - 候補:今の音と、そこから転回 ↑ を 6 回まで・転回 ↓ を 6 回まで重ねた物(動かせなくなったら止める)。
  - 近さ:|上の音の平均 − 前のカードの上の音の平均| + 0.5 × |一番上の音 − 前のカードの一番上の音|。「前のカードの上の音」は、前のカードが 3 音以上なら一番低い音を除いた物。
  - 一番小さい候補にする。今の音と同じ近さなら変えない。前のカードが無いカードは変えない(範囲が「このカード」「同じ」で先頭のカードの時は、ボタンを薄くする)。
- 転回・高さ・前に近づけるの結果は「手で直した音」になる(C11)。名前は変わらない(C7 をしない)。
- どれも、変えたら選んだカードをその音で 1 回鳴らす。
- **おすすめに戻す**:範囲の中に、形のスナップショット(基本以外)・手で直した音・弾いた音を持つカードがある時だけ出る。範囲のカードの音を、何も持たない状態(基本)に戻す。C7 で書き換えた名前は戻さない(戻すのは C8)。
- 転回・高さ・前に近づける・戻すの純粋な計算は、画面の部品から分けて `src/domain/` に置き、単体テストを書く。形の音は K の関数だけで作る(画面の部品の中で音を作らない)。

### C5. 直す範囲

- 「このカード」/「同じ Em7 · 2 枚」(同じ名前のカードが 2 枚以上ある時だけ出る)/「ぜんぶ · 14 枚」。枚数はコードのカードの数(休符は数えない)。
- **別のカードを選ぶと「このカード」に戻る**(← → でも)。
- 「同じ」:選んだカードに操作をした後、その結果(音、または形)を、同じ名前の全部のカードにそのまま写す。C3 のキーと C6 も同じに写す(C7 で名前が変わる時は、全部の入力を書き換える)。
- 「ぜんぶ」:形・転回・高さ・前に近づける・おすすめに戻すが、全部のカードに効く。**1 枚ずつ、そのカードの今の音から**動かす。前に近づけるは、先頭から順に、直した後の前のカードを使う。その形でそのまま作れないカードは K4 の代わりの形になる(そのカードに C4 の知らせが出る)。トーストで「3 枚は、この形にできないので近い形で鳴らしています」と知らせる。C3 のキーと C6 は、選んだカードだけに効く。
- 範囲に入っているカード(選んだカードのほか)は、プレビューで枠 `#42d8c6`・地 `#11292c` にする。
- ボタンの `title`:見本の `scopeDefs` の 3 つの文。

### C6. MIDI 鍵盤で弾いて入れる

- ボタンで入・切(`aria-pressed`)。**つなぐ所は自分で開かない**(P14。`KeyboardEntryBand` と同じ)。つながっていない時は、右の面に「MIDI 鍵盤がつながっていません」と「つなぐ」(`KeyboardEntryBand` の「つなぐ」と同じ動き)。
- 入の間:帯の上の線と鍵盤の枠が `#ffd166`。右の面は見本の `rec` の所の文「和音を押さえて離すと、このカードに入り、次のカードへ進みます。続けて弾けば、進行を順に弾き直せます。」と「やめる `Esc`」。形・転回・高さ・前に近づける・キーを押す操作は出さない(‹ › と ← → は効く)。
  - 見本の「手を離す(見本では…)」のボタンは見本だけの物。作らない。
- 押さえている音は鍵盤に `#ffd166` で光る。弾いた音がピアノの音で鳴る(今の `createMidiInputPianoMonitor`)。
- 決まる時:今の「鍵盤で入れる」と同じ決まり(`keyboardLatch`。一番多く押さえた時の音が、全部離した時に決まる)。**2〜10 音**の時だけ入る。
- 入った音は「鍵盤で弾いた音」(`live-played`)。C7 の名前の読み直しをする。その後、**次のカードへ進む**(範囲は「このカード」に戻る)。最後のカードに入れたら、切る。
- 「鍵盤で入れる」を on にした時は、これを切る(帯ごと消える)。両方が同時に鍵盤を聞くことは無い。

### C7. 音が変わった時のコード名

C3 のキーと C6 で音が変わった時だけ、次の順で名前を決める(形・転回・高さ・前に近づけるでは、しない)。

1. **今の名前のままでよい時**:次の 2 つを両方満たす時。名前は変えない。
   - 鳴らす音の音名が全部、「**書いてある音**(K の表の `tones()`)とベース」か、「**直す前から鳴っていた色**(直す前の音のうち、書いてある音でない音名。形が持っていた 9 や 13 など)」に入っている。**弾き合わせの `allowed`(安全な色を全部許す)とは別の物**:手で新しく足した 9 や 13 は、名前を読み直すきっかけになる。
   - `chordMatchSets(chord).required`(K9。`altered` の緩め方も同じ)が全部鳴っている。
2. そうでない時:**「鍵盤で入れる」と同じ読み方**(`detectLiveChord(liveNoteStateOf(notes))`)で読む。`kind === "chord"` で、その名前が今の名前と違い、テキストのコードとして読める(`parseExtendedTextChordLabel`)時、**入力のそのコードの字を、新しい名前に書き換える。**
   - 入力が `%` の所・度数で書いた所(`IIm7`)でも、新しいコード名の字に書き換える。
   - `[C]歌詞` の形(E)の行では、かっこの中だけを書き換える。
   - 1 つの字が何回も鳴る所(`x2` の繰り返し)は、その全部が変わる。
   - 書き換えた後も、そのカードが選ばれたままで、直した音がそのカードに残る(カードの鍵は `textProgressionEventKey` で名前を含むので、付け替える)。**ほかのカードの音(形・弾いた音・手で直した音)は外れない。**
   - 鍵盤の上の行の右に、`#8bd7ff` で「入力の Em7 を Em9 に書き換えました」(そのカードを選んでいる間)。
3. 読めなかった時(`kind` が `chord` でない・テキストとして読めない):名前は変えない。音はそのまま残す。右に `#ffd166` で「音から名前を決められません(Em7 のまま)」。保存はできる。

例(テストにする。**期待する名前は下の字で固定**。検出の関数から期待値を作らない):

| 直す前(① シェル) | 操作 | 結果 |
|---|---|---|
| Em7(E G B D) | B を外す | 1。`Em7` のまま |
| Em7 | E を外す | 1。`Em7` のまま |
| Em7 | D を外す | 2。`Em` に書き換わる |
| Em7 | F♯ を足す | 2。`Em9` に書き換わる |
| Em7 の ② ルートレス(G B D F♯) | B を外す | 1。`Em7` のまま(F♯ は直す前から鳴っていた色) |
| Em7 | 2 音だけにする | 3。`Em7` のまま・知らせ |

検出の関数が、表の `Em`・`Em9` と違う名前を返したら、止まる。

## E. `[C]歌詞` の形(歌詞の中のコード)

今は、`[C]きょうも[G]あるく` のような行は歌詞として読み飛ばされ、コードが落ちる。これを読めるようにする(`textNormalize.ts`)。

- **歌詞の中のコードの行**:表記をそろえた後の 1 行で、`|` が無く、`[…]` が 1 つ以上あり、**全部の `[…]` の中がコード名**(今の `isChordName`。`N.C.` も可)で、かつ(かっこの外に字がある、または `[…]` が 2 つ以上ある)行。
- 1 行に `[…]` が 1 つだけで、ほかに字が無い行は、今までどおり**見出し**(`[Aメロ]`・`[A]`)。変えない。
- `[…]` の中に 1 つでもコード名でない物がある行は、今までどおり歌詞として読み飛ばす。
- 読み方:出てくる順に、**1 コード 1 小節**。パーサーに渡す字は `| C | G | Am | F |`。
- 位置の対応:それぞれのコードは、入力のかっこの中の字に対応させる(カードを押すと入力のそのコードが選ばれる・波線・C7 の書き換えが、かっこの中に当たる)。
- 上の知らせの帯に足す:「歌詞の中のコード(`[C]` の形)を N 行読みました。長さは 1 コード 1 小節にしています。」(その行が 1 つでもある時)。「整えたテキストに置き換える」を押すと、その行は `| C | G | Am | F |` になる。
- 入力の面では、コードの行として印を付ける(左の線の色はコードの行と同じ)。
- `{title: …}` などの `{ }` の行は、今までどおり読み飛ばす。

- **休符だけの進行**(段 11 で分かった。決めた):下書きの画面を消したので、休符だけの進行は保存しない。コードのカードが 1 枚も無い時は、保存のボタンを**押せなくする**(今の空の時と同じ扱い)。ボタンの横に、今あった「コードのない進行です(休符だけ)」の一言を出す。押せるのに「保存できませんでした」になる形にはしない。外した e2e(phase5.31 の all-rest)は、この形を確かめる物に書き換える。

### E2. カンマ・ダッシュの区切りと `.`(DAW のコード進行の書き方)

利用者が決めた:FL Studio のコード進行ツールに打つような `C, G, Am, F`・`C-G-Am-F`・`C, ., G` も読めるようにする。今は、この行は歌詞として読み飛ばされ、知らせも出ない(今のコードで確かめた)。`textNormalize.ts` の「表記をそろえる」(A)の 1 つとして足す(E と同じ所)。

1. **区切りとして読む字**(かっこ `( )` の外だけ。`C7(b9,#11)` の中のカンマは今のまま):
   - カンマ `,`(全角の `,`・`、` も)。いつでも区切り。
   - ダッシュ `-`:**前後にスペースがある**(`C - G`)か、**すぐ後ろが A〜G かローマ数字の始まり(`I`・`V`・`i`・`v`)**(`C-G`・`vi-IV`)の時だけ区切り。それ以外(`C-7`・`F-7`・行の最後の `C-`・`Cm7-5`)は今のまま(マイナーなど、今の読み方)。前後にスペースがある `-` でも、同じ行の前か後ろにコードが無い時(行の頭・行の最後・`| - |`)は今のまま。
2. **`.`**:区切りで切った 1 つが `.` だけの時、**そのすぐ前のコードを、もう一度書いたのと同じ**(入力の読む順で、前の行も見る)。前にコードが無い時は、その `.` に今の「読めない字」の波線と、知らせ「`.` の前にコードがありません」。`N.C.` の中の `.` は今のまま。
3. **当てる行**:区切りを空白にし、`.` を前のコード名にした結果、**その行の全部が今の読み方でコード(と `|`・`%` など、今読める物)になる時だけ**、そう読む。1 つでも読めない物が残る行は、何も変えない(今までどおり歌詞として読み飛ばす。`Hello, world` など)。**ただし、前にコードが無い `.`(2 の知らせを出す物)は「読めない物」に数えない**:それ以外の全部がコード等で、その行にコードが 1 つ以上ある時は当てる(`., C` は当てて、`.` に 2 の知らせ)。`.` だけの行・`...` は当てない。見出し・`{ }` の行・コメント・E の歌詞の中のコードの行には当てない(歌詞の中のカンマは区切りにしない)。
4. 長さ:今の読み方のまま(`|` が無い行は 1 コード 1 小節。`| C, G | Am, F |` は 1 小節に 2 コード)。
5. 位置の対応:変えた所は、A のほかの変更と同じく `changes` に入れ、`codeOrigins` で入力の字に対応させる(カードを押すと入力のそのコードが選ばれる・波線が当たる)。`.` のカードは入力の `.` に対応する。C7 の書き換えを `.` のカードにした時は、その `.` を新しいコード名に置き換える。
6. 上の知らせの帯に足す:「カンマ・ダッシュの区切りを N 行読みました。」(その行が 1 つでもある時)。「整えたテキストに置き換える」を押すと、区切りはスペースになり、`.` は前のコード名になる。
7. `=` は、今の読み方の「前の音を伸ばす(保持)」のまま(`C = G` は今も読める)。区切りで切った後に `=` が残っても、今の保持として読む。FL のツールの意味(「今のコードを残す」)は足さない。`?`(FL のツールの中だけの操作)は読まない:`?` 以外の全部がコード等で、その行にコードが 1 つ以上ある時は、3 と同じく当てて、`?` に今の「読めない字」の波線と、知らせ「`?` は読めません」。`?` だけの行は当てない(今までどおり)。
8. 単体テスト(`textNormalize.test.ts`・`textUnified.test.ts`)。左を入れて、パーサーに渡る字が右と同じこと:

### I3. 判定(純粋な関数:`src/domain/progressionVoicingPractice/playAlong.ts`)

時計・画面から分けた純粋な関数にし、全部を単体テストする。元の設計書 3 の決まりに、次を足す・直す。

   - カードの終わり(未達の確定・次のカードへ):描画の `requestAnimationFrame` の中では、ref の比較(今のカードが変わったか)だけをする。変わった時だけ `setTimeout(…, 0)` で 1 回 state を更新する(カード 1 枚につき 1 回まで)。

### V37. テキスト取り込みで、コードの音を `{ }` で書けるようにする(利用者が決めた)

コード名のすぐ後ろに `{ }` で音を並べると、そのカードはその音で鳴り、その音で保存される。

```
| Cmaj7{C3 G3 E4 B4 D5} | Dm7 | G7{F3 B3 E4 A4} | Cmaj7 |
```

- 音は「音名 + 臨時記号 + オクターブ」(`C3`・`F#3`・`Bb4`・`E♭4`)。オクターブの数え方は帯の音名と同じ(真ん中のド = `C4` = MIDI 60)。空白かカンマで区切る。
- 2〜10 音。同じ音は 1 つにまとめ、低い順に並べる。左右の手は、今までどおりアプリの決まりで分ける(`;` で分ける書き方は入れない。ただし `;` が書いてあっても弾かず、区切りとして読み流す。例:`G#m9{G#2; F#3 A#3 B3 D#4}` は 5 音として読む)。
- **書き戻さない**:帯で音を直しても、文字の `{ }` は書き換えない。帯で直した音と `{ }` では、後から変えた方が勝つ(`{ }` の中身を書き換えると、その音にもう一度そろう)。
- 行まるごとの `{title: …}` などは今までどおり(コード名に続けて書いた `{ }` だけを音として読む)。

2. 平行調:長調の主音 t の平行調は短調の (t + 9) mod 12、短調の主音 t の平行調は長調の (t + 3) mod 12。次の関数を足す:
   ```ts
   /** P25 V39: between a key and its relative (the same notes), the first chord decides when the two are within one chord of support. */
   function relativeOf(candidate: ImportKeyCandidate, candidates: readonly ImportKeyCandidate[]): ImportKeyCandidate | undefined {
     const tonic = candidate.mode === "major" ? (candidate.tonicPitchClass + 9) % 12 : (candidate.tonicPitchClass + 3) % 12;
     const mode = candidate.mode === "major" ? "minor" : "major";
     return candidates.find((other) => other.tonicPitchClass === tonic && other.mode === mode);
   }
   function opensOnTonic(first: ChordSymbol, candidate: ImportKeyCandidate): boolean {
     const root = ((first.root % 12) + 12) % 12;
     return root === candidate.tonicPitchClass
       && (candidate.mode === "major" ? MAJOR_ARRIVALS : MINOR_ARRIVALS).has(first.quality);
   }
   ```

### V47. 入力の長い行で、字が二重に見える(横のスクロールのずれ)

写真 64(`| Cmaj7{C3 G3 E4 B4 D5} | Dm7 | G7{F3 B3 E4 A4} | Cmaj7 |` で 1 枚目のカードを選んだ所)で、入力の 1 行目が「Cmaj7Cmaj7{C3 …」と二重に見え、行の番号と「| 」が見えない。写真とコード(`src/components/capture/TextUnifiedEditor.tsx`)を見て決めた原因:
- 入力は、透明な字の `textarea` の上に、字と印を描く層を 2 枚重ねた作り。`syncScroll` は層を**縦にだけ**動かす(`translateY(-scrollTop)`)。
- 行が欄より長い時、カードを選ぶとその字が選ばれ(`setSelectionRange`)、`textarea` が**横に**スクロールする。層は横に動かないので、`textarea` の選ばれた字(選んだ所は白い字で描かれる)と、層の字がずれて二重に見える。V37 で行が長くなりやすくなって見つかったが、前からある不具合。

1. `TextUnifiedEditor.tsx` の `syncScroll`:`` layer.style.transform = `translateY(${-top}px)` `` を `` layer.style.transform = `translate(${-element.scrollLeft}px, ${-top}px)` `` にする(`const top = element.scrollTop;` はそのまま)。`textarea` の `scroll` は横に動いた時も出るので、ほかは変えない。行の番号の帯も層の中にあるので一緒に横へ動く(`textarea` の左の余白が動くのと同じ)。
2. テスト(新しい `e2e/p25-v47-hscroll.spec.ts`):1280×800 で、1 行に 24 小節の進行(`| Cmaj7{C3 G3 E4 B4 D5} | Dm7 | G7 | Cmaj7 |` を 6 回つなげた物)を入れ、最後のカードを押す。`textarea` の `scrollLeft` が 0 より大きいこと、`[data-testid="text-intake-marks"] > div` と `[data-testid="text-intake-decorations"] > div` の `transform` の横の数が `-scrollLeft`(±1)であること、選んだカードの字の印(`[data-mark="token"]` で `data-span-start` がそのカードの物)の左の端が、`textarea` の中のその字の位置(`textarea` の左 + 左の余白 + 字の幅 × 字の位置 − `scrollLeft`。字の幅は 1 字の `canvas` の `measureText` か、同じ等幅の字で測る)と ±2px で合うこと。最初のカードに戻して `scrollLeft` が 0 に戻ると、横の数も 0。
3. 写真 64 を撮り直す(字が二重に見えないこと)。

**テスト**:`npx vitest run src/components/capture`、`npx playwright test e2e/p25-v47-hscroll.spec.ts e2e/p25-v37-voicing-braces.spec.ts e2e/p24-05-text-unified.spec.ts e2e/phase8.8.5-text-workspace.spec.ts`。
