# v3.2.0 設計書:リポジトリと docs の整理

2026-11-24 確定。v3.2.0 で入れた。

## 目的

GitHub でリポジトリを初めて開いた人が、何がどこにあるかを迷わず分かること。

v3.1.0 の時点では、`docs/` の直下に 83 個のファイルと 99 個のフォルダが並び、報告(`docs/reports/`)は 599 件が 1 つのフォルダにたまっていた。リリースの記録の置き場も 2 つ(`release/` と `releases/`)あった。v3.1.0 の確定した設計書はリポジトリに無かった。リポジトリの直下にも、古い作業の資料(`artifacts/`・`CHECKLIST.md`・`TEST-PERFORMANCE-OPTIMIZATION.md`)が残っていた。

## 決めたこと

1. **消さずに移す。** 古い記録は `docs/archive/` に `git mv` で移した。履歴も中身も残る。消すと、公開するツリーとテストを通したツリーを同じにする約束(v3.1.0 のリリースの手順)が崩れ、古い資料をすぐ開けなくなるため。
2. **役割で分ける。** `current/`(今の正本 5 本)・`designs/`(版ごとの確定した設計書)・`contracts/`(テストとアプリが読むファイル)・`release/`(リリースの記録)・`archive/`(過去)。案内は [`docs/README.md`](../README.md)。
3. **テストとアプリが読むファイルは `contracts/` に集める。** archive の下をアプリが読むことが無いように。中身は 1 字も変えていない。
4. **package.json を日常のコマンドだけにする。** 昔の評価のコマンド(`eval:*` の 67 個)は外し、スクリプトは `scripts/archive/` に移した。昔のコマンドの一覧は [`scripts/archive/README.md`](../../scripts/archive/README.md)。
5. **使っていないコードを消す。** 前に画面を外した(Phase 8.9)AI のアドバイザーの実行のコード(画面側と Rust 側)を消した。設定の画面から、前に保存した API キーを確かめて消す所だけを残した。外部と通信する部品も外した(アプリは外部にデータを送らない)。
6. **README に技術の節とデモを足す。** Windows でなくても動きが見えるように、作り物のデータで撮った短い GIF を置いた。

## これからの決まり

1. 下書き・作業の指示・途中の記録はリポジトリの外に置く。リポジトリに入れるのは、リリースの時に確定した設計書だけ(`docs/designs/v3.x.0-<中身>.md`)。
2. `docs/current/` は 5 本のまま増やさない。リリースの時に、変わった所だけ書き直す。
3. docs の直下と `docs/archive/` に新しいファイルを足さない。リリースの記録は `docs/release/v3.x.0/` にまとめる。

## 機械の検査(`npm run validate:docs-layout`。FULL に入っている)

1. docs の直下とリポジトリの直下に、決めた物以外が無い。
2. コードと設定の中の `docs/…` の字が、実在の場所(か、git に入れない手元の場所)を指している。
3. `scripts/` の中の相対の import が、実在のファイルを指している。
4. 公開する文書(designs・current・README・CHANGELOG・今の版のリリースの記録)に、個人の情報と、公開に向かない言葉が無い(言葉の一覧はリポジトリの外のファイルから読む)。
