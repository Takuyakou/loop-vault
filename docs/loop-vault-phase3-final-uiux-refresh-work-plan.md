# Loop Vault Phase 3.0 最終作業計画書

## テーマ

**スタイリッシュでモダンで本当に使いやすいUIと分かりやすいUXへ。音を溜める、鳴らす、進める。**

Phase 3.0は、単なる画面の見た目調整ではなく、Loop Vaultの体験を作り直すフェーズとする。

Loop Vaultの核は以下の流れにある。

```text
音を溜める
  MIDIからコード進行を採集し、良い進行をVaultに保存する。

音を鳴らす
  保存した進行をすぐ試聴し、耳で選び直せるようにする。

音を進める
  今日触るLoopと次の一手を明確にし、曲として完成へ進める。
```

Phase 2でMIDI解析、候補ブロック、コード試聴、保存済みProgression Block、Chord Drip風グリッド、日本語/英語切替などの主要機能は実装済み。Phase 3.0では、新しい解析機能を増やすより、**既に入っている機能を日常的に使いたくなる画面へ再設計する**。

---

## Phase 3.0のゴール

### 目標

- アプリ全体の画面構造を分かりやすくする。
- Homeを「今日再開するLoopを選ぶ画面」にする。
- コード採集画面を「候補を聴いて保存する作業台」にする。
- Vaultを「採集したコード進行を掘り返す棚」にする。
- Settingsを「怖くない設定・データ管理画面」にする。
- 用語、ボタン、状態表示をユーザー目線に統一する。
- アプリアイコンの方向性をLoop Vaultの世界観に合わせる。
- App.tsx肥大化を抑え、今後の拡張に耐えられるUI構造へ整理する。

### やらないこと

- MIDI解析アルゴリズムの大幅刷新
- 音声解析
- FLP解析
- AIによるコード評価
- Chord Dripとの完全双方向連携
- 大規模なDB/永続化設計変更
- `fileVersion` を上げる破壊的変更
- 解析結果全体の恒久保存

# 1. アプリ全体の情報設計刷新

## 1.1 ナビゲーション再設計

### 現状の問題

現在のナビは以下のように機能名がそのまま横並びになっている。

```text
ホーム / MIDI解析 / ライブラリ / 設定 / 新規 / 保存済み
```

問題点。

- `保存済み` がボタンのように見える。
- `設定` が主要画面と同格に見える。
- `MIDI解析` が硬く、体験名ではなく機能名に見える。
- `ライブラリ` が普通の一覧画面に見える。
- `新規` が何を新規作成するのか分かりにくい。

### 採用する方針

ナビは以下に変更する。

```text
[ホーム] [コード採集] [Vault]
                         [+ Idea]  ✓ 保存済み  ⚙
```

### 画面名と役割

| 現在 | Phase 3.0 | 役割 |
|---|---|---|
| ホーム | ホーム | 今日再開するLoopを選ぶ |
| MIDI解析 | コード採集 | MIDIからコード進行を採集する |
| ライブラリ | Vault | 採集した進行・曲ネタを探す |
| 設定 | ⚙ | 一般設定/制作設定/データ管理 |
| 新規 | + Idea | 新しいネタを作る |
| 保存済み | ✓ 保存済み | ボタンではなく保存状態 |

### 画面タイトル

各画面の大見出しは以下にする。

```text
Home:
次に鳴らすLoopを選ぶ。

コード採集:
MIDIからコード進行を採集

Vault:
採集した進行を探す
```

Settingsでは大見出しを共通タイトルにせず、モーダル/ページ内で `設定` を表示する。

### 実装タスク

- `AppShell` または該当箇所のナビ文言を変更する。
- `MIDI解析` を `コード採集` に変更する。
- `ライブラリ` を `Vault` に変更する。
- `設定` は歯車アイコン `⚙` またはコンパクトなアイコンボタンにする。
- `新規` は `+ Idea` にする。
- `保存済み` はボタンではなくステータス表示にする。
- 保存状態は `保存中...` / `未保存` / `✓ 保存済み` のように小さく表示する。
- active navは背景だけでなく、下線/アクセントバー/文字色で自然に示す。

# 2. デザインシステム刷新

## 2.1 方向性

Loop Vaultの見た目は、以下の方向に寄せる。

```text
暗い制作部屋

コードカード
音楽の秘密基地
Vault/保管庫
```

現在の黒基調とシアンアクセントは良いので維持する。ただし、カード、余白、境界線、ボタン階層、警告色、ラベル表示を整理する。

### 推奨カラーイメージ

```text

パネル: #141715 / #181B19

境界線: #2A2F2C
```

- シアンは主要アクション、再生、保存、選択状態に使う。
- 黄色は本当に確認が必要な時だけ使う。
- `Next Action未設定` のような状態表示は、Library/Vaultでは強く出しすぎない。
- 警告やconfidenceを常時出さず、低信頼や注意が必要な時だけ表示する。

### Primary

- MIDIを選択
- + Idea
- コード採集を始める

- 再生 `▶`
- 停止 `■`
- 設定 `⚙`
- コピー
- その他 `…`

### 実装ルール

- 主要導線は `▶ 再生` と `保存` を最も目立たせる。
- 編集とコピーは補助操作として控えめにする。
- アイコンだけの場合は `aria-label` と `title` を付ける。
- コピー後はtoastを表示し、一定時間でフェードアウトする。

# 3. Home刷新

## 3.1 Homeの役割

HomeはKPI画面ではなく、**今日再開するLoopを選ぶ画面**にする。

現在の「今月の完成数」「進行状況」「Next Actionが必要」「放置中」は機能として良いが、情報の主役が管理寄りになっている。Phase 3.0では、今日のLoopとコード進行プレビューを中心に置く。

## 3.2 現状の問題

- `今月の完成数 0/1` が何を数えているのか分かりにくい。
- `Next Action`、`Build a loop from the captured progression`、`Detailを開く`、`Next完了`、`Idea` など英語と日本語が混ざっている。
- 今日のLoopカードにコード進行プレビューや再生ボタンがない。
- 月間ゴールと進行状況が強く、今日触るネタが主役になっていない。
- `放置中` は少し責める印象がある。

## 3.3 新レイアウト案

```text
次に鳴らすLoopを選ぶ。

┌─────────────────────────────────────────────┐

│ コード進行 main - turnaround                 │

┌──────────────┐ ┌──────────────┐ ┌──────────────┐
```

## 3.4 実装タスク

### 今日のLoopカード

- `pickFocus()` の結果を大きいカードとして表示する。
- Progression Blockがある場合、代表ブロックのコード進行をプレビュー表示する。
- 代表ブロックは以下の優先順位で選ぶ。
  1. favoriteがあればそれ
  2. 先頭のSavedProgressionBlock
  3. chordMemoの先頭行
  4. なし
- コード進行がある場合は再生ボタンを出す。
- 次の一手は `次の一手：...` と表示する。
- `Detailを開く` は `詳細を開く` に変更する。
- `Next完了` は `次の一手を完了` に変更する。

### 今月の完成カード

現在の `今月の完成数 0/1` を意味が分かる表示にする。

表示案。

```text
今月の完成
0 / 1
完成にしたネタ：0件
月間ゴール：1件
残り21日
```

補足文。

```text

```

### 状態カード

- `Next Actionが必要` → `次の一手が必要`
- `放置中` → `停滞中`
- `進行状況` → `制作状況`
- ステータス表示は日本語化する。

```text

hold      → 保留
abandoned → 没
```

### 最近採集した進行

- Home下部に `最近採集した進行` セクションを追加する。
- 保存済みProgression Blockから、capturedAt/updatedAtが新しいものを最大3件表示する。
- 表示項目。
  - summary
  - chord preview
  - parent idea title
  - `▶ 再生`
  - `Vaultで開く`

### 空状態

Focus候補がない場合、説明だけでなく行動ボタンを出す。


# 4. コード採集画面刷新

## 4.1 役割

コード採集画面は、MIDI解析の内部結果を見る画面ではなく、**使えそうなコード進行を聴いて保存する作業台**にする。

## 4.2 採用する画面タイトル

```text
MIDIからコード進行を採集
```

サブコピー。

```text
MIDIから使えそうなコード進行を見つけて、Vaultに保存します。
```

## 4.3 MIDI未選択時

MIDI解析前の画面は良くなっているので、その方向を維持する。

表示内容。

- 大きいドロップ/選択エリア
- `MIDIを選択`
- `ここにMIDIをドロップ`
- 使い方3ステップ

```text
1. MIDI全体をコードタイムライン化
2. 使えそうな4/8/16小節を候補化
3. 気に入った進行をVaultに保存
```

## 4.4 MIDI解析後の基本方針

主役はFull Timelineではなく、候補ブロック。

優先順位。

```text
1. 使えそうな候補ブロック
2. 再生
3. 保存
4. 編集
5. コピー
6. Full Timeline
7. 解析メタ情報
```

## 4.5 候補カードは1つだけ展開

### 現状の問題

- 候補カードがすべて大きく展開され、縦に長い。
- どの候補を見ているのか分かりにくい。
- 保存フォームがカード内に出ると、画面がさらに重くなる。

### 採用する方針

- 候補カードは通常時コンパクトに表示する。
- 選択中の候補だけ展開する。
- 編集フォームは選択中候補に対してだけ表示する。
- 保存フォームはカード内ではなく右サイドパネルに出す。

### 通常カード例

```text
候補 1    1-4小節    メイン / ターンアラウンド
| Dmaj9 | A6/C# | D | Em9 A7sus4 |
[▶] [保存] [編集] [コピー]
```

### 展開カード例

```text
候補 1    1-4小節    メイン / ターンアラウンド

┌───────┬───────┐
│ Dmaj9 │ A6/C# │
│ ♭VI   │ III/5 │
└───────┴───────┘
┌───────┬────────────┐
│ D     │ Em9 A7sus4 │
│ ♭VI   │ ♭VII / V   │
└───────┴────────────┘

[▶] [■] [保存] [編集] […]
```

## 4.6 保存フォームは右サイドパネル

### 現状の問題

保存フォームがカード内に出ると、画面内の主従が崩れる。

### 採用する方針

右側に保存パネルを出す。

```text
左：候補一覧 / 選択中候補
右：この進行を保存
```

保存パネルの内容。

```text
この進行を保存
| Dmaj9 | A6/C# | D | Em9 A7sus4 |

保存方法
○ 新しいIdeaとして保存
○ 既存Ideaへ追加
○ コードだけメモに追記

タイトル
[コード進行 main - turnaround]

次の一手
[採集したコード進行からループを作る]

[キャンセル] [保存]
```

### 文言変更

- `Chord Memoへコピー` → `コードだけメモに追記`
- `新規Idea` → `新しいIdeaとして保存` または `新しいネタとして保存`
- `既存Ideaへ追加` → `既存Ideaへ追加`

補足文を入れる。

```text
コードだけメモに追記:
進行ブロックは作らず、選択したIdeaのメモ欄へコード文字列だけ追加します。
```

## 4.7 再生/停止ボタン

### 採用する方針

文字ボタンではなくアイコン中心にする。

```text
[▶] [■] [編集] [保存] […]
```

ただし主導線は以下。

```text
[▶] [保存]
[編集] [コピー]
```

### 実装ルール

- 再生ボタンは `▶`。
- 停止ボタンは `■`。
- 再生中の候補だけ停止ボタンを表示する。
- `aria-label="再生"` / `aria-label="停止"` を付ける。
- tooltipも可能なら追加する。

## 4.8 コピー文言

### 現状の問題

`Chord Drip形式でコピー` は初見で意味が分かりにくい。

### 採用する方針

ボタン表示は以下にする。

```text
コード進行をコピー
```

コピー後toast。

```text
Chord Dripで使えるコード進行をコピーしました
```

一定時間でフェードアウトする。

### 将来拡張

コピーdropdown化しても良い。

```text

- コード進行をコピー
- Chord Drip用にコピー
- Markdownでコピー
```

Phase 3.0では、最低限 `コード進行をコピー` でよい。

## 4.9 拍位置表示を消し、度数/役割を出す

### 現状の問題

`1.1` / `2.1` のような表示は意味が分かりにくい。

### 採用する方針

拍位置表示はコードカード上では消す。代わりに、キーに対するルートの相対度数を表示する。

### 初期実装

高度な機能分析ではなく、まずは相対度数でよい。

例。

```text
Dmaj9
♭VImaj9
```

```text
A6/C#
III6 / bass C#
```

```text
B7
V7系
```

### 方針

- detectedKeyまたはidea.keyを基準にする。
- キーが不明な場合は度数を表示しない。
- キー推定が怪しい場合は `参考` として出す。
- Phase 3.0では完全な和声機能分析まではしない。

### 実装候補

```ts
export type RomanNumeralHint = {
  label: string;          // I, ii, bVI, V7 など
  detail?: string;        // bass C#, 分数コード など
  confidence: "high" | "medium" | "low";
};
```

配置候補。

- `src/domain/harmony/romanNumerals.ts`
- または `src/domain/romanNumerals.ts`

domain層に置き、Reactに依存させない。

## 4.10 warning/confidence表示

### 現状の問題

- `要確認: 低音の解釈に注意` が多く出るとノイズになる。
- `100%` が毎カードに出ると、情報としての意味が薄い。

### 採用する方針

- confidenceは通常非表示。
- 低信頼の時だけ `要確認` を小さく出す。
- 同じwarningが全候補に出る場合は、カードごとではなく画面上部にまとめる。
- `ambiguous-bass` のような内部キーは表示しない。
- 表示は日本語ラベル化する。

例。

```text
ambiguous-bass → 低音解釈あり
low-confidence → 要確認
melody-heavy → メロディ混在の可能性
```

## 4.11 ラベル日本語化

内部値は英語のままでよい。表示だけ日本語化する。

```text
main → メイン
intro-like → イントロ向き
turnaround → ターンアラウンド
variation → 変化形
chorus-like → サビ向き
bridge-like → ブリッジ向き
```

# 5. Vault刷新

## 5.1 Vaultの役割

Vaultは単なるIdea一覧ではなく、**採集したコード進行を探して、聴いて、再利用する棚**にする。

## 5.2 現状の問題

- Progression Blockがカード内の小さいプレビューに留まっている。
- `1 block` の意味が弱い。
- Next Action未設定バッジが強すぎて、コード進行より目立つ。
- Progression BlockがあるIdeaとないIdeaの違いが分かりにくい。
- Libraryから直接、試聴/コピー/再利用がしにくい。

## 5.3 2モード化

Vaultには2つの表示モードを追加する。

```text
[Idea] [Progression]
```

### Idea View

曲ネタ単位で見る。

### Progression View

保存済みProgression Block単位で見る。

## 5.4 Ideaカード改善

### 進行ありIdea

表示内容。

- title
- status
- BPM / key
- `進行 1件`
- 代表Progression Blockのコードプレビュー
- 次の一手
- actions
  - `▶`
  - `開く`
  - `コード進行をコピー`
  - `次の一手を追加`

例。

```text
IDEA · 進行 1件
コード進行 main - turnaround
76 BPM · F#メジャー

| A6 | Gmaj7 | F#m11 | B7 |

次の一手：採集したコード進行からループを作る
[▶] [開く] [コピー]
```

### 進行なしIdea

表示内容。

```text
test
BPM未設定 · アイデア

コード進行はまだありません
[MIDIから追加] [手入力で追加] [開く]
```

## 5.5 Progression View

保存済みProgression Blockをフラットに一覧表示する。

表示内容。

- block summary
- 親Idea title
- BPM / key
- source bar rangeがあれば表示
- tags/useCaseがあれば表示
- コード進行プレビュー
- actions
  - `▶`
  - `親Ideaを開く`
  - `コード進行をコピー`

## 5.6 検索対象拡張

検索対象に以下を含める。

- idea.title
- idea.chordMemo

# 6. Settings刷新

## 6.1 Settingsの役割

Settingsは、技術者向けのJSON管理画面ではなく、**一般設定・制作設定・データ管理を安全に扱える画面**にする。

## 6.2 現状の問題

- 言語、月間ゴール、Import、Export、バックアップ、データパスが同じ重さで並んでいる。
- `Export` / `Import` / `JSON` が技術者向けに見える。
- バックアップ一覧が長く、画面を支配している。
- データパスが目立ちすぎて怖い。
- `復元` が危険操作なのに説明が弱い。
- 月間ゴールが何をカウントするのか分かりにくい。

## 6.3 セクション化

Settingsは以下に分ける。

```text
設定

[一般]
[制作]
[データ]
[バックアップ]
[情報]
```

タブUIでも、左メニュー式でもよい。実装負荷を抑えるなら、縦セクション＋折りたたみでよい。

## 6.4 一般

項目。

- 表示言語
- 将来的にテーマ
- 将来的にアクセントカラー

文言。

```text
表示言語
画面に表示する言語を切り替えます。
```

## 6.5 制作

項目。

- 月間ゴール
- 完成カウントの説明
- 将来的にコード採集の既定設定
- 度数表示ON/OFF

月間ゴール説明。

```text
月間ゴール
ステータスを「完成」にしたネタを月ごとにカウントします。
```

度数表示設定。

```text
コードカードに度数を表示
キーが分かる場合、コード名の下に I / ii / V などの相対度数を表示します。
```

## 6.6 データ

項目。

- データ保存先
- フォルダを開く
- パスをコピー
- バックアップを書き出す
- バックアップを読み込む

文言変更。

```text
Export → バックアップを書き出す
Import → バックアップを読み込む
JSONを書き出す → バックアップファイルを書き出す
JSONを読み込む → バックアップファイルを読み込む
```

ただし内部的にはJSONでよい。

## 6.7 バックアップ

表示は最新5件だけにする。

```text
最新バックアップ
- data-20260710-0057.json   2026-07-10 00:57   [復元]
- data-20260710-0046.json   2026-07-10 00:46   [復元]

[すべて表示]
```

復元ボタンを押したら確認を出す。

```text
このバックアップに復元しますか？
現在のデータは上書きされます。復元前に現在のデータも自動バックアップされます。
```

実際に自動バックアップしない場合は、その文言は出さない。現実の実装と文言を一致させること。

## 6.8 情報

項目。

- App name
- Version
- Data format version
- Storage path
- 依存やライセンスは必要なら後回し

# 10. アプリアイコン方向性

## 10.1 現状の問題

現在のアイコンは暫定感があり、Loop Vaultのコンセプトである「コード進行や8小節ループを保管する音楽の金庫」が伝わりにくい。

## 10.2 方向性

### 推奨案A: Vault Door + Loop

最有力。

```text
黒い角丸正方形の中に、金庫の丸い扉のような円形ループ。
円の周りに小さなMIDIノートブロックやコードカードを抽象的に配置。
中央に小さな鍵穴、または控えめなLVモノグラム。
色はダークグレー/黒をベースに、ネオンシアンの細いライン。
少量のオフホワイト、または淡いゴールドで宝物感を足す。
```

この案が、LoopとVaultの意味を一番直感的に表現できる。

### 案B: Chord Cards in a Vault

```text
4枚の小さなコードカードが円環状に並び、金庫の中に保管されている。
カードには文字を入れず、短いラインでコード感を表現。
黒い背景にシアンアクセント。
```

Progression Block機能に合う。

### 案C: Minimal LV Monogram

```text
黒い角丸正方形にシアンのLVモノグラム。
Vの一部がループ矢印になっている。
背景に薄く金庫の円形ライン。
```

小さいサイズでも潰れにくい。

## 10.3 避ける方向

- ただの音符
- ただの鍵盤
- ただのLV文字
- 派手すぎるDJ風
- かわいすぎるポップアイコン
- 細かすぎて小さいサイズで潰れるもの

## 10.4 デザイナー/生成AIへ渡す説明文

```text
Loop Vaultという音楽制作アプリのアイコンを作りたいです。
コンセプトは「コード進行や8小節ループを保管する音楽の金庫」です。

黒〜チャコールの角丸正方形をベースに、中央に金庫の丸い扉のような円形ループを置いてください。
円形ループの周囲には、小さなMIDIノートブロックやコードカードを抽象的に配置します。
中央には小さな鍵穴、または控えめなLVモノグラムを入れます。

雰囲気は、暗い制作部屋、ネオンシアン、ミニマル、少し未来的、でも派手すぎない。
音符や鍵盤をそのまま使うのではなく、コード進行・MIDI・保管庫を抽象的に表現してください。

小さいデスクトップアイコンでも潰れないように、線は太め、要素は少なめ。
色は黒、ダークグレー、ネオンシアン、少量のオフホワイト。
可能ならごく少量の淡いゴールドを入れて、保存された音楽ネタの宝物感を出してください。
```
