## 2. データの流れ

```text
MIDI のバイト列
  └ vaultStore.analyzeMidiBytes(bytes, { fileName, mode, accuracyFirst, analysisInput })
      ├ analyzeMidi()                    … 解析（Core C。変えない）
      ├ parseMidi() → normalizeNotes() → buildVoices() → annotateVoiceRolesV2()   … 元の音と Voice の役割
      └ attachSourceVoicings()           … fullTimeline・自動候補の各カードに sourceVoicing を付ける
  → store.analysis = { status: "done", result, sourceData, sourceVoices }
CaptureView
  ├ result.fullTimeline      … 曲全体のカード（TimelineDetails・SongMiniMap）
  ├ result.blockCandidates   … 自動候補（ProgressionCandidateCard ごとに EditableProgression）
  ├ activeDraft: ManualCandidateDraft | null      … 範囲から作った手動候補、または自動候補から作った Draft
  └ 保存
      ├ saveNew(candidate, title, …)      → createIdeaFromDraft({ progressionBlock, progressionAnalysis, … })
      └ appendExisting(candidate, …)      → appendBlockToIdea(ideaId, candidate, analysis, …)
          └ vaultStore が保存の時に attachExtractedVoicing()（sourceVoicing が無ければ解析と同じ抽出。あれば playbackChoice を SOURCE に）
          └ 直した記録：appendAnalysisFeedback・appendLabelCorrectionLogs（手元の記録。Vault とは別）
```

- **解析結果の置き場所**：`vaultStore` の `analysis`（Vault には保存しない。`sourceData` と `sourceVoices` もここにある）。
- **下書き（`ManualCandidateDraft`、`src/domain/midi/manualDraft.ts`）**：`events`・`originalEvents`・`selectedRange`・`repairOperations`・`history`／`historyIndex`（`DraftSnapshot` の前後を持つ履歴）。元に戻すは `captureEditHistory.ts` の `undoCaptureDraft`・`redoCaptureDraft`・`jumpCaptureDraftHistory`。
- **自動候補の編集**：`ProgressionCandidateCard` の中で `EditableProgression`（`src/domain/progressionEditing/`）を別に持つ。元に戻すは `EditableProgression` 側の履歴で、Draft の履歴とは別。
- **保存の経路**：`saveNew`・`appendExisting` は `ProgressionBlockCandidate` を受け取る。`draftToCandidate(draft)` で Draft から作る。

### Phase 10 で使い回せる所

- 解析と `sourceVoicing` を付ける流れ（`analyzeMidiBytes`）はそのまま使える。CorrectionModel の材料（`fullTimeline`・`sourceData.notes`・`sourceVoices`・`sections`）は全部 `analysis` にある。
- 保存の経路（`saveNew`・`appendExisting`→ store）と、直した記録（feedback・label correction log）。
- 元に戻すの形（前後のスナップショットを持つ履歴）。`ManualCandidateDraft` の `repairOperations` は「直した回数」の数え方として使える。
- `QuickChordEditor`、確認のダイアログ、`SourceBasslineCapturePanel`、`PreAnalysisWorkspace`。

### そのままでは使えない所

- **音の単位の編集が無い。** 今の編集はカード（コード）の単位だけ。外す・戻す・足す・高さを直すは、どの型にも無い（`ManualRepairOperation` にも無い）。CorrectionModel と、その操作の型を新しく作る必要がある。
- **履歴が2つある**（Draft と `EditableProgression`）。仕様書 7.4 の1本の履歴には、どちらかに寄せるか新しく作る。
- **保存が「範囲」を前提にしている。** 保存する中身は候補（`ProgressionBlockCandidate`）で、`voicingMemory` は解析時の `sourceVoicing` をそのまま持つ。直した音を保存するには、保存の前に `voicingMemory` を作り直す段が要る（監査B）。
- **コード名を変えると `sourceVoicing` が消える**（`compatibleVoicingMemory`）。保存の時に新しい名前で抽出し直すので、名前を変えた後の音は「人が選んだ音」ではなく「抽出し直した音」になる（監査B）。
- 自動候補の「同じ直しを他にも反映」は `ProgressionCandidateCard` の中にあり、曲全体の作業場からそのまま呼べる形ではない。

## 4. `CaptureView.tsx` からロジックを切り出す計画（P10.0-02 の最初の作業。ここでは実装しない）

見た目は変えずに、独立した commit で次の順に分ける。

1. **`useCaptureIntake`**（ファイル・ドロップ・読み込み・解析の開始・進み具合・エラー）：`sourcePath`・`intakeError`・`analysisProgress`・`analysisRunGeneration`・`isDraggingMidi` と、読み込みの関数。
2. **`useCaptureSave`**（保存と記録）：`saveNew`・`appendExisting`・`correctionEvents`・`persistCorrectionEvents`・`progressionSaveFeedback`・`persistLabelCorrectionLogs`・`announcePersistenceError`・`persistenceError`。Phase 10 の保存は最終的にここを呼ぶ。
3. **`useCaptureDraft`**（Draft と履歴）：`activeDraft`・元ベースラインの3つの状態・`saveActiveDraftForSwitch`・履歴の操作。
4. **`useCapturePlayback`**（試聴と曲全体の再生）：`createTimelineVoicingPlaybackPlan` を使う所、`stopCapturePlayback`、テキストの試聴。
5. テキストの取り込み（`saveExtendedTextProgression` など）は今の場所のままにする（Phase 10 の対象外）。

各 hook は今の関数をそのまま移し、`CaptureView.test.tsx` がそのまま通ることで確かめる。そのあとで CorrectionModel（`src/domain/correction/` などの新しい置き場所）を作り、新しい作業場の部品は `src/components/correction-workspace/` に置く案。
