# P10 — 全自動で進める時の決まり

root `AGENTS.md` が安全の規則の正本。この文書は Phase 10 での上乗せだけを書く。食い違う時は `AGENTS.md` を優先する。Phase 8.9 の決まり（`docs/phase8.9/contracts/P8.9-autonomous-run.md`）と同じ形で、Phase 10 に合わせて直したもの。

## 1. 進め方

- 1段階＝1つの zip＝1セッション。zip の `START-HERE.md` に従い、段階を最後まで進める。
- **途中で人間の承認を求めない。** 計画モードは使わず、計画は報告の冒頭に書いてそのまま実装に入る。
- 人間は段階の成果物（報告・スクリーンショット・EXE・差分レビューの結果）で判断する。次の段階の zip が渡されることが、前の段階の承認になる。
- 段階が終わったら merge 候補で止める。次の段階・次のフェーズへ自動で進まない。

## 2. 迷った時の扱い（止まって聞かない）

| 状況 | やること |
| --- | --- |
| 仕様書に書いていない操作や表示を足したくなった | 足さずに進め、報告の「判断ポイント」に案として書く |
| 仕様書どおりだと使いにくい・幅に収まらない | 仕様書とモックに近い形で調整して進め、違いと理由を報告に書く |
| 新しい依存パッケージが欲しくなった | 追加せずに今あるもので作り、報告に書く |
| テストの期待値が古い取り込み画面の配置を固定している | その段階で作り直した部分の分だけ更新してよい。更新理由を報告に書く |
| 指示書の記述が Git の実態と合わない | Git を正として進め、差異を報告に書く |
| 監査の結果、仕様書の前提が崩れていると分かった | その段階の作業は続け、崩れた前提と影響を報告の「人間に決めてほしいこと」に書く |

## 3. 段階をそこで終える条件

次のどれかに当たったら、その段階をそこで終える。変更は捨てずに commit し、報告と `execution-state.json`（`blocked: true`、`blockerReason`）に理由を書いて終了する。

- Vault の保存形式（`fileVersion: 2`）の変更や、既存の記録の書き換えをしないと進めない。
- 解析ロジック（`src/domain/midi/` の Analyzer／Extractor・キー検出、Identity／Decoder）や transport scheduler に手を入れないと進めない。
- P10.0-01 以外の段階で、再生の選び方（`resolveVoicing` など）を変えないと進めない。
- データ保持の往復テストが、製品コードを変えないと通らない。
- `AGENTS.md` の停止条件に当たった。

## 4. 触らない範囲と読まない場所

- 上の解析ロジックと transport。`AGENTS.md`。
- `.local-evaluation/` は `test-logs/` と `gate-cache/` だけ読んでよい。それ以外は、読み取りの道具でもシェルのコマンドでも開かない。
- `test/private-midi/`、`docs/loop-vault-evaluation-corpus/`、私的な MIDI や音声を読むスクリプト（`npm run eval:*`・`tune:*`・`benchmark:*`・`diagnose:*`・`ablate:*`）は使わない。
- Phase 9 の研究ブランチ（`research/phase9-core-v2`）は取り込まない（取り込むかは人間の別の判断）。そこにある公開・合成のコーパスや報告を参考にする時は、`git show` や一時的な worktree で読み取りだけにする。
- リポジトリ直下の `Claude outputs/` は人間の資料置き場。読んでもよいが、コミットしない。
- サイト名は UI・コード・テスト・公開文書に出さない（「拡張記法」と呼ぶ）。

## 5. 許可の設定

- Phase 8.9 で置いた `.claude/settings.json` と `.claude/settings.local.json` をそのまま使う。すべて許可のモード（`bypassPermissions`）は使わない。
- 設定で確認が出た操作は、報告の「判断ポイント」に書き、次の段階の zip で許可か禁止に振り分ける。

## 6. git

- 段階ごとにブランチを切る（`feat/p10.0-NN-<短い名前>`）。基点は local `master`。
- 前の段階の merge 候補は、次の段階の zip の最初の手順で local `master` に取り込む（`AGENTS.md` の常設の許可。`--no-ff`）。衝突したら取り込みをやめて止まる。
- `git add` はパスを明示する。`-A`・`.`・`--all` は使わない。commit の前に `git status --short`・staged の差分・name-status を確認する。
- 小さい単位で commit する。ロジックの切り出しは、UI の差し替えとは別の commit にする。
- push・tag・release はしない。

## 7. 報告とレビュー

- 報告は日本語で `reports/` に書く（書く項目は [reports/README.md](../reports/README.md)）。
- 差分レビューは必須：Claude の実装 → Codex か別の Claude セッションによる差分レビュー → 人間の成果物確認。報告の最後に「レビューで見てほしい所」を3〜5点書く。
- 判断ポイントは「選んだこと／理由／別案」を1〜2行ずつ、結論だけ短く書く。
