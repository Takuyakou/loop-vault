## 0. 位置づけと前提

P9.MID の結論（`CORE_C_PLUS_CORRECTION_UX`）を受けて、解析ロジックではなく「解析の誤りを人が速く直せる画面」に投資するフェーズ。

守ること：

1. **解析ロジックは変えない。** Core C、Product extractor、Identity／Decoder は今のまま。P9.1〜P9.5 の研究部品は入れない。
2. **元の MIDI を書き換えない（Architecture A）。**
   - 「外す」は、和音として使うかどうかの切り替えで、元の音は残す（FL Studio の「ミュート」と同じ扱い）。
   - 「高さを直す」は、元の高さを残したまま、直した高さを別に持つ。
   - 「足す」は、元の MIDI に無い音として、出どころを分けて持つ。
3. **音は落とさない側に倒す。** 自動で外すことはしない。
4. **一括の操作は「選ぶ」まで。** 曲全体にかかる操作（メロディの線、同じ高さの短い音など）は、該当する音を選ぶところで止め、外すかどうかは人が確定する。
5. **判定は断定しない。** 要確認は「〜の可能性があります」と示し、信頼度の数字は出さない。
6. **Vault の保存形式は変えない（`fileVersion: 2`）。**
7. **修正の手間を指標にする。** 正解率ではなく「取り込んでから保存するまでに何回直したか」「どれくらい時間がかかったか」で良し悪しを見る。

## 1. 目的と成功の基準

### 目的

取り込んだ MIDI のコード進行を、**怪しい所だけ順に確かめて、数クリックで直し、保存できる**ようにする。

### 成功の基準（v2.3：アプリが自動で数える記録（13章）で見る。今の画面との比べは分かる範囲だけ）

| 指標 | 測り方 | 目標 |
| --- | --- | --- |
| 直した回数（Correction Vector） | 分割・結合・外す・戻す・足す・高さを直す・名前を変える・境目を動かす、を種類別に数える | 今の画面より少ない |
| 取り込みから保存までの時間 | 画面を開いてから保存するまで | 今の画面より短い |
| 要確認の当たり具合 | 印を付けた所のうち、実際に直した割合（`Y` で「このままでよい」にした割合の逆） | 印が多すぎない（例：誤った印が 100 カードあたり X 件以下） |
| 要確認の見逃し | 印が無いのに直した所の数 | 減っていく |
| 音の欠落 | 保存したカードの音から、和音の音が落ちていないか | 今より増やさない |

計測は手元だけで行い、Vault には入れない（13章）。

## 2. 範囲

### 対象

- MIDI 取り込み後の結果画面の全体（見出し・曲全体の帯・タイムライン・ピアノロール・右の欄・保存）
- 既存の編集機能の統合（手動候補の編集、自動候補の編集、曲全体のコード、Draft バー）
- **取り込みの下書き（import draft）の上での、可逆な編集。** 保存するまでは、外す・足す・高さを直す・つなぐ・分ける・名前、のすべてを元に戻せる

### 対象外

- **Vault に保存した後に、直した内容を完全に元に戻すこと。** 保存すると、外した音や直す前の状態の一部は Vault に残らない（10.2）。これは別の保存（Persistence）のフェーズで解決する
- 解析前のパート選択（`PreAnalysisWorkspace`）の中身。入口の「パートの設定」ボタンから今のまま開く
- テキストからの取り込み（通常・拡張）
- Live MIDI
- 解析ロジック、Vault の保存形式、transport
- 保存後の進行ページ（別のフェーズ）

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| カード | 1つのコード。Core C の `ChordTimelineItem` 1つに当たる |
| 区間 | カードの開始から終了までの時間 |
| 元の音 | 取り込んだ MIDI にある音（出どころ `SOURCE`） |
| 足した音 | 人が足した、元の MIDI に無い音（出どころ `MANUAL_ADDED`） |
| 使っている音 | カードの和音として鳴らす音 |
| 外した音 | 元の MIDI にはあるが、和音として使わない音。破線で表示し、戻せる |
| 高さを直した音 | 採譜の誤りなどで、人が上下に動かした元の音。元の高さも残す |
| 要確認 | 画面が「直した方がよいかもしれない」と印を付けたカード |

| 区切り | 曲をいくつかに分けた帯。解析は返さないので画面の側で計算する（8.1）。1つにしかならない時は8小節ごと |
| 打ち直し（×n） | 同じ和音を続けて弾き直した回数。つないだカードに表示する |

## 4. 画面構成

基準の大きさは 1440×900。横 1220px 以上で「タイムライン＋右の欄」の2列、それより狭い時は 11章の配置にする。

```text
┌ 取り込む [MIDI][テキスト]                        MIDI 未接続  試聴音色 ┐
├ ファイル名  64小節・92BPM・4/4・解析対象   要確認 10 外した音 283 直した回数 2 [パートの設定][別のMIDI] ┤
├──────────────── タイムライン ────────────────┬──── 右の欄 ────┤
│ 曲全体   [区切り・コード・要確認の点・今見ている枠]   │ 選んだカード      │
│ 表示 [全体][16小節][4小節]   ◀前の要確認 3/10 次の要確認▶ │  名前（大）        │
│ 小節     1   2   3 …（横スクロール）                 │  要確認の理由と操作 │
│ 区切り   [1〜8小節 · 2回出てくる][9〜16小節] …         │  鳴らす音          │
│ コード   [Fmaj7][Em7][A7] …                           │  聴き比べ A / B     │
│ 鍵盤｜ピアノロール                                     │  名前の候補 1〜4    │
│ 凡例                                                 │  分ける・つなぐ・音を直す │
│ [▶再生][追従]  1.1/64小節        [↶][↷] 操作 2・最後：… │                  │
├──────────────────────────────────────────────┴──────────────┤
│ ショートカットの帯（状態ごとに変わる）                                  │
└──────────────────────────────────────────────────────────────┘
```

### 4.1 ファイル帯

- ファイル名、小節数・BPM・拍子・解析対象を1行で。今の4つの大きな枠と「標準モードで解析済み」の枠は廃止する。
- 右に2つの数：**要確認**（押すと次の要確認へ）と**直した回数**。
- 「外した音」の数は上に出さない。長い曲では、和音に使っていないメロディや打楽器の音が数百になり、「そんなに間違っているのか」と見えてしまうため。必要なら右の欄や `?` の中で「和音に使っていない音」として出す。
- 「パートの設定」（今の「パート選択を変更」）と「別の MIDI」。「クリア」は「別の MIDI」のメニューへ。

### 4.2 曲全体の帯（今の SongMiniMap を細くしたもの）

- 高さ 34px。区切りと名前、カードの細い線、要確認の黄色い点、再生位置、**今見ている範囲の枠**。
- 押す・ドラッグで、その場所へタイムラインを動かす。

### 4.3 タイムライン

縦に4段。左の列（84px）はラベルと鍵盤で、横スクロールしても動かない。

| 段 | 高さ | 中身 |
| --- | --- | --- |
| 小節 | 26px | 小節番号。詰まったら4小節・8小節ごとに間引く |
| 区切り | 30px | 曲の区切りごとの帯（8.1 の計算）。押すと保存する範囲になる。同じ区切りが2回以上あれば、**そのすべての帯に**「2回出てくる」（N回なら「N回出てくる」。狭い帯は「×2」）。1小節だけの区切りは「9小節」 |
| コード | 98px | カード。下 20px は「つなぐ」の提案を出す場所 |
| ピアノロール | 音域 × 6px | 音と鍵盤。音域は曲で使っている音に合わせて自動で決める |

### 4.4 右の欄（340px）

状態（5章）ごとに中身が変わる。

- 聴き比べ：**A＝区間に鳴っている元の音すべて**（メロディも含む。外した音も鳴る）、**B＝カードの音**（保存すると鳴る音）。
- 名前の候補は**横1列のボタン**（最大4つ、`1`〜`4`）。

## 6. 表示のルール

### 6.1 音

| 状態 | 表示 |
| --- | --- |
| 使っている和音の音（元の音） | 青緑の塗り |
| 使っているベース（元の音） | 水色の塗り |
| メロディ・打楽器の可能性があるのに使っている音 | 黄色の塗り（要確認の原因） |
| メロディとして外した音 | 紫の枠だけ |
| その他の外した音 | 灰色の破線の枠 |
| 高さを直した音 | 塗りに縞模様。元の高さに紫の破線の枠 |
| **足した音** | 薄い青緑の塗り＋太い青緑の枠（元の音と見分けられる形） |
| 選んでいる音 | 白い外枠。カーソルは上下の矢印 |

- とても短い音も最小 4px の幅で描く（押せるように）。
- マウスを重ねると「D5 · 4拍 · 使っている」「G4 · 手動で足した音」をツールチップで出す。
- 色だけで区別しない（外した音は破線、足した音は太い枠）。

### 6.2 カード

- 幅は長さに比例。幅が足りない時は段階的に小さくする：72px 未満で名前を小さく、40px 未満で拍の表示を消し、名前が入らなければ**根音だけ**（「Fmaj7」→「F」。「F···」のように切らない）、18px 未満で名前も消して色だけ。全部の名前はツールチップと右の欄で見る。
- 表示：名前、長さ（拍）、打ち直しがあれば「×2」、要確認なら黄色の点と黄色の枠。
- 選択中は青緑の太枠。左右の端に境目の取っ手。
- 信頼度（%）は出さない。

### 6.3 要確認の理由（初期のルール）

言葉は断定せず「〜の可能性があります」「〜です（事実）」の形にする。

| 理由 | 判定（UI 側で計算） | 右の欄の文 | 操作 |
| --- | --- | --- | --- |
| メロディの混ざり | 区間の前から続く一番上の音、または解析前の役割が「メロディ」の音が、使っている音に入っている | 「上の D5 は前の区間から続く高い音です。メロディの可能性があります。外すと Cmaj7 になります。」 | 「D5 を外す」「音を直す」「このままでよい」 |
| 打楽器の混ざり | 同じ高さ・0.3拍以下・拍に沿って繰り返す音（曲全体で N 回以上）が、使っている音に入っている | 「C#2 の短い音が拍ごとに繰り返しています。ドラムの可能性があります。」 | 「同じ高さの短い音を選ぶ（40個）」「このままでよい」 |
| 同じ和音の分かれ | 隣のカードと使っている音（音の種類＋一番下の音）が同じ | 「次のカードと同じ和音です。打ち直しで分かれた可能性があります。」 | 「次とつなぐ」「このままでよい」 |

- 判定は「候補を示す」ためだけに使う。判定で音を自動で外すことはしない。
- 理由は増やせる形にする（例：名前と音が合わない、区間の中に使っていない長い音がある）。
- 判定の数字（N など）は P10.0-00 で決め、設定ファイルにまとめる。
- 「このままでよい」にしたカードは、その取り込みの間は印を出さない。

### 6.4 足りない音を見つける手がかり

元の MIDI にも無い音は、聴き比べ（A 元の音・B カードの音）のどちらにも入っていないので、画面を見ても足りないことに気付けない。そこで右の欄に、次を常に出す。

- **「＋ 音を足す」ボタン**（①でも②でも目立つ位置）。押すと 12 の音名が並び、選んだ音を和音の音域に足す。足した後は `↑`／`↓`／`Ctrl+↑↓` で高さを直せる。
- **名前の構成音との違い（参考）**

```text
G7sus4 の構成音   G C D F
今の音            C D F G      ← 足した後の例
追加候補（参考）  ＋D          ← 押すとその音を足す
```

- 言葉は「足りません」「欠落しています」と断定せず、「名前の構成音にあって、今の音に無い音（追加候補・参考）」とする。
- 基準にするのは今のカードの名前（名前が間違っていれば候補も外れる）。名前の候補を選び直すと、候補もそれに合わせて変わる。
- 省略が普通の音（5度など）も候補に出るので、足すかどうかは人が耳で決める。

### 6.5 曲全体の提案（最初にやるとよいこと）

解析前の役割でメロディが付いた Voice がある時は、メロディの音がほぼ全部のカードに入る。カードごとに印を付けると印だらけになるので、代わりに画面の上に**曲全体の提案**を順に出す。

1. 「メロディの Voice（トラック名）の音が 96 枚のカードに入っています」→［まとめて選ぶ］。選んだ後に外すかどうかは人が決める（`Delete`）。
2. 外した結果、隣どうしのカードの音が同じになった所が出たら「同じ音が続く所が N か所あります」→［確認してつなぐ］（7.1 の `Shift+M` と同じ確認）。

- この提案が出ている間は、そのメロディの音を理由とするカードごとの印は出さない（前から続く一番上の音の印は出す）。
- 提案は閉じられる（「このままでよい」）。閉じたら、その取り込みの間は出さない。

## 7. 操作

### 7.1 カードと境目

| 操作 | 結果 |
| --- | --- |
| カードを押す | そのカードを選ぶ（③では、その区切りを保存範囲にする） |
| 取っ手をドラッグ | 境目を1拍単位で動かす。隣のカードの長さも変わる。`Alt` を押している間は ¼拍単位。動かしている間は「5.3」のように位置を出す |
| 「つなぐ」の提案を押す／`M` | 次のカードとつなぐ。打ち直しの回数は「×n」で残す |
| `Shift+M` | 使っている音（高さの集まりと一番下の音）が**完全に同じ**隣どうしを曲全体から探し、「同じ音が続く所を 7 か所つなぎます」と一覧で確認してから、一括でつなぐ（`Enter` でつなぐ、`Esc` でやめる。履歴は1回分）。名前が同じでも音が違う所（ボイシングの変化）はつながない |
| `S` | 選んだカードを半分に分ける（1拍以下は分けない） |
| 名前の候補を押す／`1`〜`4` | 名前だけ変える。音は変わらない |
| `F2`／名前をダブルクリック | 名前を文字で入力（今の QuickChordEditor を使う。モックには無い） |

### 7.2 ピアノロール（FL Studio に近い操作）

| 操作 | 結果 |
| --- | --- |
| 左クリック（使っている音） | その音を選び、鳴らす。区間の持ち主のカードも選ぶ |
| 左クリック／左ドラッグ（外した音） | 戻す。なぞった音を続けて戻す |
| 右クリック／右ドラッグ（元の音） | 外す。なぞった音を続けて外す。右クリックのメニューは出さない |
| 右クリック／右ドラッグ（足した音） | 消す（元の MIDI に無い音なので、外すのではなく消える） |
| 空いた所を左クリック | ①：選択を外す。**②：その高さの音を足す（FL の鉛筆と同じ）** |
| 空いた所をダブルクリック | ①でも②でも、その高さの音を足す（①での近道） |
| 空いた所をドラッグ | ①：範囲で選ぶ。②：`Ctrl`＋ドラッグで範囲で選ぶ（FL と同じ）。どちらも `Shift` で選択に足す |
| `Shift`／`Ctrl` ＋クリック | 選択に足す・外す |
| 選んだ音を上下にドラッグ | 半音単位で高さを直す。複数選んでいれば一緒に動く。動かしている間は「D4 → E4」を出す（足した音は高さだけ） |
| 選んだ音をドラッグせずにクリック | その1つだけを選ぶ（FL と同じ） |
| `↑`／`↓` | 選んだ音を半音動かす |
| `Ctrl+↑`／`Ctrl+↓` | 1オクターブ動かす |
| `Delete`／`Backspace` | 選んだ元の音は外し、選んだ足した音は消す |
| `R` | 選んだ音を戻す |
| `Ctrl+A` | 選んだカードの区間の音を全部選ぶ |
| 鍵盤を押す | その高さを鳴らす |
| 鍵盤を `Ctrl`＋クリック | その高さの音を曲全体で選ぶ |
| `Enter` | 直し終わる（選択を閉じる。②なら①へ戻る） |
| `Esc` | 選択を外す |

- **音を足す操作を状態で分ける理由：** ②は「音を直す」とはっきり入る状態なので、FL の鉛筆に当たる1クリックで足す方が速く手に合う。①は確かめるのが中心なので、誤って足さない方を優先してダブルクリックにする。誤って足しても、足した音は見た目で分かり、`Ctrl+Z` か右クリックで消せる。
- 足した音の時間は、押した場所のカードの区間いっぱい。同じ高さをすでに使っている時は足さない。保存される音の写しは時間を持たないので、長さは見た目の意味だけになる。
- **1枚のカードで鳴らせる音は 2〜10 個。** 11個目を足そうとした時（足す・戻す・まとめて戻す）は足さずに「このカードで鳴らせるのは10音までです」と出す。1個以下になる外し方の時は外せるが、右の欄に「2音以上にしてください」と出し、保存の時に止める（10.2）。
- **時間方向（横）には動かさない。** 区間の直しはカードの境目で行う。
- **曲全体にかかる選び方（選ぶまでで止める）**
  - **同じ高さの短い音：** 音を1つ選んだ時、それが短い音なら「同じ高さの短い音が曲全体に N 個」と「まとめて選ぶ」を出す。長い音（0.3拍より長い）は含めない（ベースを巻き込まないため）。
  - **メロディの線：** ②で、区間の中に点線を出し、「線より上の音を選ぶ（N）」で、線より上で今使っている音を曲全体から選ぶ。外すかどうかは、選んだ後に `Delete` かボタンで人が決める。線の高さはドラッグで変えられる（モックでは固定）。

| 操作 | 結果 |

| `]`／`[` | 次／前の要確認のカードを選び、画面に入れる |

| `←`／`→` | 前後のカード（画面の外なら動かす） |

### 7.4 元に戻す

- `Ctrl+Z` で元に戻す、`Ctrl+Shift+Z`／`Ctrl+Y` でやり直す。
- 対象：外す・戻す・足す・消す・高さを直す、つなぐ・分ける、境目、名前、このままでよい。
- ドラッグ1回（なぞる、範囲の移動、境目）は履歴1回分にまとめる。
- 再生・スクロール・選択は履歴に入れない。
- 履歴は取り込みの間だけ持つ。「操作 3 · 最後：G4 を足した」を再生の横に出す。

### 7.5 キー操作の注意

- 入力欄にフォーカスがある時は、文字のショートカットを効かせない。
- `Ctrl` の組み合わせは、この画面の中だけで奪う（`Ctrl+A`・`Ctrl+Z`・`Ctrl+Y`）。
- 右クリックやダブルクリックが使えない人向けに、同じことを `Delete` と右の欄のボタンでもできるようにする（音を足すのは右の欄の「＋ 音を足す」でもできる）。

## 8. 編集の意味（データ）

Phase 10 は、今の解析結果の上に「修正のための作業データ（CorrectionModel）」を作り、そこで直してから保存する。解析ロジックと元の MIDI には手を入れない。

### 8.1 作業データの作り方

| 要素 | 作り方 |
| --- | --- |
| カード | 解析結果の `fullTimeline`（区間・名前・別候補） |
| 元の音 | 取り込んだ MIDI の、解析に使った Voice の音（`MidiSongData` と解析前の選択） |
| 使っている音 | カードの `sourceVoicing.midiNotes` に入っている高さの音を、その区間から探して「使っている」にする（P10.0-00 の合成の確認では、見つからない高さは 0） |
| 役割 | 解析前の Voice の役割（和声・ベース・メロディ・除外）と、音の長さ・高さから UI 側で付ける |
| 区切り | 今の解析はセクションを返さない。画面の側で `segmentSections()` を呼んで作る（解析ロジックは変えない）。区切りが1つにしかならない時は8小節ごとに区切り、名前は「1〜8小節」のように小節番号にする。曲の構成を当てているように見せないため、段の名前は「区切り」にする |

### 8.2 音のデータ

```ts
interface CorrectionNote {
  id: string;
  provenance: "SOURCE" | "MANUAL_ADDED";
  sourceNoteId: string | null;   // 元の音なら元の MIDI の音への参照。足した音は null
  pitch: number;                 // 今の高さ
  originalPitch?: number;        // 元の音の高さを直した時だけ、直す前の高さ
  start: number;                 // 拍。足した音はカードの開始
  duration: number;              // 拍。足した音はカードの長さ
  used: boolean;                 // 和音として使うか
  roleHint?: "harmony" | "bass" | "melody" | "percussion" | "ornament";
  reviewReason?: string;         // 「メロディの可能性」など、断定しない表現
}
```

### 8.3 操作とデータ

| 操作 | 作業データ | 元の MIDI |
| --- | --- | --- |
| 外す／戻す（元の音） | `used` を切り替える | 変えない |
| 足す | `provenance: "MANUAL_ADDED"`、`sourceNoteId: null`、`used: true` の音を作る | 変えない |
| 消す（足した音） | その音を作業データから消す | 変えない |
| 高さを直す（元の音） | `pitch` を変え、最初の高さを `originalPitch` に残す | 変えない |
| 高さを直す（足した音） | `pitch` を変える | 変えない |
| つなぐ | 2つのカードを1つに。長さは足し算、打ち直しの回数を持つ | 変えない |
| 分ける | 1つのカードを2つに。音は区間で分かれる | 変えない |
| 境目を動かす | 隣り合う2つのカードの開始・長さを変える | 変えない |
| 名前を選ぶ | カードの名前だけを変える | 変えない |
| このままでよい | カードに「確認済み」を付ける | 変えない |

- 打ち直しの回数は、画面の中だけで持つ（保存しない）。
- **音の状態（使う・外す・高さ）は、カードの区間で切った断片ごとに持つ。** つなぐ・分ける・境目を動かすで断片を切り直した時は、**元の断片の状態をそのまま引き継ぐ**（例：外した音の断片が隣のカードに移っても、外したまま）。同じ元の音の断片が1枚のカードの中で隣り合い、状態も同じなら1つにまとめる。
- 足した音は持ち主のカードの区間いっぱい。境目を動かしたら、持ち主のカードの新しい区間に合わせる。カードをつなぐと足した音も1枚にまとまり、同じ高さが重なれば1つにする。分けると両方のカードに同じ音を置く。

### 8.4 名前の候補の更新

- 音を外す・戻す・足す・高さを直すと、そのカードの**名前の候補（Top-K）を計算し直す**。候補は `detectLiveChord`（最大3つ）と解析の別候補を合わせ、重複を除いて最大4つ。4つに満たない時は無理に埋めない。
- 名前が変わった時（自動の更新・人が選ぶ・文字で入れる）は、直した音の札（`capturedForChordKey`・`capturedForChordLabel`）を今の名前に付け直す。これで、名前が変わっても直した音が生成の音に切り替わらない。
- 名前が「自動の名前」のままなら、表示する名前を新しい候補の先頭に更新する。「自動の名前（音を変えると候補から更新）」と小さく示す。
- **人が名前を選んだ・入力したカードは、絶対に上書きしない。**「あなたが決めた名前」と示し、新しい候補は候補の一覧にだけ出す。
- 自動の更新も、音の操作と同じ履歴の1回に入れる（`Ctrl+Z` で音と名前が一緒に戻る）。
- 候補の一覧（Top-K）はいつも残し、`1`〜`4` で選び直せる。

## 10. 保存（Vault v2 のまま）

### 10.1 流れ

1. 区切りの帯を押す、または右の欄の「おすすめの範囲」で範囲を決める（③）。
2. 名前を確かめて「Vault に保存」または「既存のアイデアに追加」。
3. 保存したら、同じ画面で次の範囲を選べる（取り込みは閉じない）。

### 10.2 保存する中身

**Phase 10 の修正作業場は、取り込みの下書きの上の可逆な編集を対象とする。Vault に保存した後に、直した内容を完全に元へ戻す仕組みは、別の保存（Persistence）のフェーズで解決する。**

| 画面の状態 | 保存先 |
| --- | --- |
| カードの区間と名前 | `ChordTimelineItem`（今のまま） |
| 使っている音が元の音だけ（高さも直していない） | `voicingMemory.sourceVoicing`（元の MIDI の音の一部なので Source のまま。`userVerified: true`、`playbackChoice: "SOURCE"`） |
| 足した音・高さを直した音を含む | `sourceVoicing` には使っている元の音（直す前の高さ）、直した後の音の集まりは `practiceVoicingOverride`（`source: "manual"`、`userVerified: true`、`playbackChoice: "CUSTOM"`、札 `capturedForChordKey`／`Label` は保存時のカードの名前、音は 2〜10。v2.2 で決定） |
| 打ち直しの回数 | 保存しない（Phase 9 で保留した `attacks` と同じ扱い） |
| 外した音 | 保存しない |
| 足した音の出どころ（`MANUAL_ADDED`） | 保存しない（直した後の音の集まりの中に入るだけ） |
| 直した記録 | 今の `propagationEvents` など既存の項目だけ |

- 保存後に失われるもの（外した音、直す前の高さの対応、足した音の出どころ、打ち直しの回数）は、保存の画面で「保存すると、外した音は戻せなくなります」と一度だけ知らせる。
- 元ベースラインは右の欄の「詳しい設定」の中へ。保存できるベースが無い時は欄ごと出さない。
- 保存していない直しがある時に画面を離れる・別の MIDI を開く時は、今の確認ダイアログを使う。

### 10.3 P10.0-00 で監査したこと（保存先と再生）

**結果（P10.0-00）：** `voicingCompatibility` は音の中身を名前と比べず、札（取った時の名前）と今の名前が同じかだけを見ていた。`practiceVoicingOverride` はどの場面でも「人が選んだボイシング」として `sourceVoicing` より先に鳴っていた。人間の判断で、P10.0-01 は行わず、作業場の中で札を付け直す。保存後に進行ページで名前を変えると直した音が捨てられるのは今のアプリの動きで、進行ページを作り直すフェーズの課題として残す。

以下は監査の前に書いた項目（記録として残す）。


1. **`practiceVoicingOverride` をどこが読んでいるか。** カードの試聴、取り込みの試聴、曲全体の再生、進行ページ、Voicing Loop、移調練習、MIDI の書き出しのそれぞれで、読むか・優先するかを表にする。
   - 途中の確認では、`resolveVoicing.ts` で、`playbackChoice` が無い時に `sourceVoicing` より優先されていた。`manualDraft.ts`、`textProgressionDraft.ts`、`transposeProgression.ts`、`progressionVoicingPractice/snapshot.ts` でも使われていて、「人が選んだボイシング」として一般的に使われている。
   - 練習専用の意味で使っている所があれば、直した音の保存先を考え直す（新しい任意の項目が要るなら、それは別の判断）。
2. **コード名と合わないと生成の音に切り替わる仕組み。** `resolveVoicing.ts` は、`SOURCE` でも `CUSTOM` でも、音がコード名と合わない（`voicingCompatibility` が compatible でない）と生成の音に切り替える。
   - 人が音を足したり高さを直したりして名前と合わなくなると、直した音ではなく生成の音が鳴ってしまう。
   - **基本方針：人が明示的に確定した音（`CUSTOM`、または `userVerified` の `SOURCE`）は、コード名と合うかの判定より人の指定を優先する。** 人が G を足して「これが正しい」と直したのに、名前と合わないから生成の別の音が鳴る、という最悪の体験を避ける。
   - 再生の共通部分の変更なので、Phase 10 の他の段階とは切り離し、独立した共有の直し（P10.0-01。P8.1 や Phase 9 の 9.1-P と同じ扱い）として、テストしてから入れる。

## 13. 計測（手元だけ）

- 取り込みごとに、直した回数を種類別（Correction Vector。足した音の数を含む）、要確認の数と「このままでよい」の数、取り込みから保存までの時間を記録する。
- 保存先は端末の中だけ（アプリのデータフォルダの計測用ファイル）。Vault には入れない。曲名・パス・音の並びは記録しない。
- 設定の「開発者向け」に、計測の ON／OFF と「計測を消す」を置く。

## 14. アクセシビリティ

- すべての操作をキーボードでもできる（右クリックは `Delete` で代わる）。
- カードは `button`、選択中は `aria-pressed`。右の欄は `aria-live="polite"`。
- ピアノロールの音は、キー操作で選ぶ時だけフォーカスを受ける（何百個の Tab 移動を避ける）。区間の音は右の欄の一覧でも操作できる。
- OS の「動きを減らす」設定では、スクロールのなめらかな移動を止める。
- 色だけで状態を分けない（外した音は破線、足した音は太い枠、要確認は点も付ける）。
