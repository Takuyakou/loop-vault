# P10 — テストの回し方と証跡

## 1. Test DX

- 普段の作業：編集 → `npm run test:fast` → `npm run test:feature` → 次の作業。
- 画面を変えた時は `npm run test:ui` も回す。
- `npm run test:full` は、段階の merge 候補・共有部分の変更・製品の再生や保存に関わる変更の時に、fresh で回す。小さな変更ごとには回さない。
- PASS の詳しいログは `.local-evaluation/test-logs/` に残し、報告には要約行だけを貼る。FAIL の時だけ該当のログを読む。
- 以前の HEAD のテスト結果を、今の HEAD の結果として使わない。

## 2. データ保持

- `src/domain/p89DataRetention.test.ts`（合成の Vault を保存・再読込して完全一致を確かめる往復テスト）を毎段階 PASS させる。
- 保存に関わる段階（P10.0-01・P10.0-06）では、直した音・足した音・高さを直した音を含むカードの往復テストを足す。

## 3. 合成データだけでテストする

- テストと計測は、Git に入っている合成の MIDI・fixture と、テストの中で作る合成データだけを使う。
- 手元の曲（私的な MIDI）は、人間が最後に確かめる時だけ。Claude Code は読まない。

## 4. スクリーンショット

- `npm run p89:screens -- <名前>` で、4つの大きさ（1920×1080・1440×900・960×1032・768×640）を撮る（Phase 8.9 の道具をそのまま使う）。
- 新しい作業場の状態（①②③、長い曲）を撮れるように、P10.0-02 以降で道具に画面を足してよい（テストの道具だけの変更）。
- 置き場所は道具の既定（Git 管理外）。報告にはパスを文字で書く。

## 5. 基準画像

- 取り込み画面の基準画像は、作り直した段階で、テストごとに `--grep` を付けて作り直し、差分を目で見てから更新する。
- 関係のない画面の基準画像は更新しない。

## 6. 計測（P10.0-00・P10.0-07）

- 自動の計測は合成データで行い、集計だけを `docs/phase10.0/evidence/` に JSON で残す。
- 人間の操作の計測（取り込みから保存までの時間、直した回数）は、人間が手元で行い、記入用の表に書く。Claude Code は表の形だけを用意する。
