## 8. 判断ポイント

- **hook の分け方**：選んだこと＝関数は中身を変えずに移し、Draft と候補を閉じる処理だけ `onAnalysisReset` の callback（ref で読む）にした。理由：`useCallback` の依存を変えずに、取り込みの hook が Draft の hook に依存しないで済む。別案：状態を1つの reducer にまとめる（差が大きく、テストの書き換えが要る）。
- **共通の小さな関数**：選んだこと＝`captureRuntime.ts` に移し、`CaptureView` から再輸出。理由：hook から `CaptureView` を import すると循環になる。今のテストの import も変えずに済む。別案：hook の中に複製する。
- **判定の数字の読み方**：選んだこと＝`docs/` の JSON をそのまま import して Zod で確かめる。理由：数字を書き写さず、契約のファイルが1つで済む。別案：`src/` に JSON を写す（2か所になる）。
- **聴き比べ A**：選んだこと＝区間に鳴っている元の音すべて（メロディも含む）。理由：「元の音」と「カードの音」の違いがそのまま聞こえる。別案：使っている音だけ（B とほぼ同じになる）。
- **合成の曲の置き場所**：選んだこと＝`src/testing/p10SyntheticSongs.ts` に移し、単体テスト・監査のスクリプト・E2E・`p89:screens` で共有。理由：同じ曲で数を突き合わせられる。別案：E2E の道具に別の曲を作る。
- **設定を読む時**：選んだこと＝取り込む画面を開いた時に1回読む。理由：設定は別の画面で変えるので、それで足りる。別案：変更を購読する。
- **基点**：選んだこと＝`692e794` へ fast-forward してから始めた。理由：その間に master に入った Voicing Loop の直しを含めて確かめるため。別案：`a5e111a` のまま進める（取り込み時に差が出る）。
