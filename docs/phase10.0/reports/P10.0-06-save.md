## 区切り1：保存の中身（`612436a`）

- `src/domain/correction/saveCandidate.ts`：
  - `cardTimelineItem`：1枚のカードを保存する `ChordTimelineItem` にする。
  - `buildSaveCandidate`：作業データと小節の範囲から、今の保存の経路が受け取る `ProgressionBlockCandidate` を作る。

### 保存の中身

| カードの状態 | 書くもの | `playbackChoice` | `extractorVersion` |
|---|---|---|---|
| 区間も音も変えていない | 解析の `ChordTimelineItem` と `voicingMemory` をそのまま（名前を変えた時は札だけ付け直す） | 解析のまま | 解析のまま |
| 音は元のまま、区間が変わった（つなぐ・分ける・境目） | `sourceVoicing`＝新しい区間の使っている音（`midi-extracted`・`simultaneous-voicing`・`userVerified: true`） | `SOURCE` | 解析の時の値（無ければ今の抽出の値 `voicing-extractor-v1`） |
| 外した音だけ（`edited`） | 同上。override は書かない | `SOURCE` | 同上 |
| 足した音・高さを直した音を含む（`edited`） | `sourceVoicing`＝使っている元の音（直す前の高さ、2音未満なら書かない）、`practiceVoicingOverride`＝直した後の音（`source: "manual"`・`userVerified: true`） | `CUSTOM` | source は上と同じ、**override は `p10-correction:v1`** |

- 札：音を書くすべての snapshot で、`capturedForChordKey = normalizedChordKey(保存する名前)`、`capturedForChordLabel = 保存する名前の label`。
- 名前：`parseChordLabel(カードの名前)`。読めなければ保存できない（「読めない名前があります：3小節の F??」）。
- 音の数：直したカードで使っている音が2音未満なら保存できない（「2音以上にしてください：3小節の C」）。10音を超えたら「10音までにしてください：…」（編集で10音までにしているので普通は出ない）。範囲の外のカードは見ない。
- 拍の位置：今の保存の経路と同じ。保存する進行は曲の中の小節番号のまま（例：5〜8小節）、`events` は範囲の始めからの拍。指示書の「範囲の最初のカードが1小節1拍」は今の経路と違ったので、今の経路に合わせた。
- 保存しないもの：打ち直しの回数、外した音、足した音の出どころ。
- 直した記録：解析の名前で同じ区間を並べた「元の候補」（`original`）と、1カード1スロットの `EditableProgression` を作る。人が決めた名前のカードだけを `edited: true` にし、`editSource` を付ける（解析の別候補にあれば `alternative`、無ければ `manual-label`）。これを `useCaptureSave` の `saveNew`／`appendExisting` に渡すと、今の `buildCorrectionEvents`・`buildProgressionSaveFeedbackEvent`・`buildLabelCorrectionLogs` がそのまま動く。音の操作で変わった自動の名前は、直した記録にしない。
