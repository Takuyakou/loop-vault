## 区切り1：EXE 確認の直し（`b0b788e`）

- **1.1 押して鳴らす**：
  - タイムラインの表示の切り替え（全体・16小節・4小節）の右にチェック「押して鳴らす」。既定 OFF。端末の中に覚える（`loop-vault:p10-card-click-audition:v1`、`src/storage/cardClickAuditionSettings.ts`、読み書きは try/catch）。
  - ON の時、カードを普通に押すと、そのカードの音（B＝`cardAuditionNotes`）を `controller.play` で鳴らす。前の試聴は止まる（`toggle` ではないので、同じカードを続けて押しても止まらずに鳴り直す）。
  - `Shift`＋クリック・境目の取っ手・キーでの移動・曲全体の再生中は鳴らさない。
- **1.2 再生の縦線**：
  - 原因：100ms の `setInterval` で作業場全体を描き直し、その時だけ再生位置を計算していた。
  - 直し方：位置の計算を純粋な関数 `playheadBeatAt`（`workspaceGeometry.ts`）に分けた。作業場の中の1つの `requestAnimationFrame` の繰り返しで、ピアノロールと曲全体の帯の縦線を `transform` で動かし、再生位置の文字と追従のスクロールも同じフレームで行う。作業場全体は描き直さない。100ms の描き直しはやめた（再生中にそれを使っていたのは縦線・位置の文字・追従だけ）。
  - 時計：再生の部品（`playbackController`）が `startedAt` に使う `performance.now()` に合わせた。音の時計（AudioContext）は transport の scheduler の中にあり、この段階では変えない決まりなので使っていない。
  - 動きを減らす設定でも縦線は動く。追従のスクロールは `scrollLeft` を直接動かす（なめらかにしない）。
- **1.3 元に戻す**：右の欄のカードの操作の並び（名前を入力の右）に「元に戻す `Ctrl+Z`」。履歴が無い時は押せない。押すと `Ctrl+Z` と同じ。
- **1.4 2音未満**：`saveCandidate.ts` の、音を直していないが区間が変わったカードで、使っている音が2音未満なら「区間を変えたので、このカードの音が2音未満です：3小節の F」を返す。保存の時に今の抽出が音を探すことはなくなり、B と保存した音は例外なく同じになる。
- **1.5**：警告（「2音以上にしてください」）のあるカードでは、緑の「このカードに要確認の印はありません。」を出さない。
- **1.6 閉じる時・離れる時の確認**：
  - 原因：ウィンドウを閉じる時、`closeGuard.ts` が Tauri の `ask`（OS の標準のダイアログ）で確認していた。
  - 直し方：`closeBlocker.ts` に `registerCloseDialogHost`／`showCloseDialogInApp`（`Promise<boolean>`）を足した。App に1つだけ置いた `CloseDialogHost`（`src/components/shell/CloseDialogHost.tsx`）が今の `ConfirmDialog` を出し、`closeGuard.ts` は `ask` の代わりにそれを待つ。受け手がいない窓（Live MIDI の窓など）は今の `ask` のまま。確認を出す前にウィンドウを前に出す（`unminimize`・`setFocus`、できない時は飛ばす）。確認の間にもう一度閉じるを押しても、今の `closeInProgress` で2つ目は出ない。保存の失敗の知らせも、受け手がいればアプリの中で出す。進行ページの確認も同じ仕組みで出る（文はその画面のまま）。
  - 文（仕様書 10.2 v2.5）：見出し「保存していない変更があります」、本文「この曲で直した内容のうち、N 件をまだ Vault に保存していません。このまま閉じる／移る／開くと、その変更は消えます。」、ボタン「保存せずに閉じる／移る／開く」（危険の色）と「戻る」（既定のフォーカス）。N は最後の保存の後に履歴に入った操作の数。作業場からは件数を App に渡し（`onWorkspaceDirtyChange`）、画面を移る時の文にも使う。

### 決めたこと

- **縦線の時計**
  - 選んだこと：`playbackController` の `startedAt` と同じ `performance.now()`。
  - 理由：音の時計は transport の scheduler の中で、この段階では変えない。開始の時刻は同じ時計なので、ずれは今と同じ。
  - 別案：AudioContext の時計を外に出す（transport の変更になる）。
- **閉じる時の確認の受け手**
  - 選んだこと：`closeBlocker.ts` に受け手を1つだけ登録する形。
  - 理由：今の確認の登録（`registerCloseBlocker`）と同じ場所で、窓ごとに受け手の有無が決まる。
  - 別案：`closeGuard` に App の関数を直接渡す（Live MIDI の窓と分けにくい）。
