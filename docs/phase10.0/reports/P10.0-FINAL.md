## Phase 10 で変わったこと

### 取り込み後の画面

- MIDI を解析した後の画面は「修正作業場」だけになった。古い取り込み画面（候補カード・全曲・タイムライン・下書き・手動範囲）と、その部品・設定は消した（P10.0-07）。
- 作業場：
  - ファイル帯（ファイル名・小節数・BPM・拍子・解析の種類・解析したパート、要確認と直した回数）
  - 曲全体の帯、区切りの帯、コードのカード、ピアノロール
  - 右の欄（選んだカード・鳴らす音・聴き比べ・名前の候補・構成音との違い・保存）

### 編集

- 音（P10.0-03）：
  - 外す・戻す・足す・消す・高さを直す。
  - 範囲で選ぶ、同じ高さの短い音を選ぶ、メロディの線より上を選ぶ。
  - 1本の履歴（`Ctrl+Z`／`Ctrl+Y`）。名前は音に合わせて自動で更新され、人が決めた名前は変わらない。
- カード（P10.0-04）：
  - つなぐ（`M`）・同じ音が続く所を一括でつなぐ（`Shift+M`、確認あり）・分ける（`S`）。
  - 境目の取っ手（1拍、`Alt` で ¼拍）、名前の候補（`1`〜`4`）・文字で入力（`F2`）、このままでよい（`Y`）。
  - 同じ直しを他にも反映。
- 長い曲と狭い画面（P10.0-05）：
  - 見えている範囲だけを描く（300小節・5,000音でも1フレームに入る）。
  - ホイール（横・`Shift` で縦・`Ctrl` でマウスの位置を中心に拡大縮小）。
  - 追従（再生中に手で動かすと止まる）。
  - 狭い画面では右の欄がタイムラインの下に1行で出て、開くと下からのパネルになる。
- EXE 確認の直し（P10.0-07）：
  - 「押して鳴らす」（既定 OFF）。
  - 再生の縦線を毎フレーム動かす。
  - 右の欄の「元に戻す」。
  - 閉じる時・離れる時の確認をアプリの中のダイアログにした（文も直した）。

### 保存（P10.0-06・07）

- 範囲は3つの方法で選ぶ：区切りの帯、おすすめの範囲、カードの `Shift`＋クリック。
- 右の欄の保存フォームから保存する：新しい Idea・既存の Idea へ追加・メモに追記。保存した後も作業場に残り、範囲に「保存済み」と出る。
- 保存できない時は、ボタンを押すと理由と場所を出し、「このカードへ」で移れる。
- 元ベースラインは、保存フォームの「詳しい設定」に置いた。
- 保存していない変更がある時は、画面を移る・別の MIDI を開く・ウィンドウを閉じる時に、アプリの中で確認する。
- 自動の計測（端末の中だけ）：取り込みごとに、直した回数・保存までの時間などを記録する。曲名・ファイル名・コード名は記録しない。

## 仕様書 v2.5 との違い

| 項目 | 仕様書 | 実際 | 理由 |
|---|---|---|---|
| 再生の縦線の時計 | 画面の書き換えごとに動かす（可能なら音の時計） | 毎フレーム動かす。時計は `playbackController` の開始時刻と同じ `performance.now()` | 音の時計は transport の scheduler の中にあり、Phase 10 では変えない決まり |
| 保存した音と聴いた音が同じこと | テストで確かめる | 単体テスト（今の store で保存 → 読み直し → 進行ページと同じ解決）で番号まで確かめた。E2E では音の番号を取り出していない | E2E から鳴らした音を取り出す仕組みが無く、作るとテストのためだけの製品コードになる |
| 元の音が無い解析結果 | 書いていない | 作業場の代わりに「この解析結果は修正作業場で開けません」と「MIDI を選び直す」 | 今の取り込みでは起きない。古い画面を残す理由にしない |
| 古い見出しの「標準モードで解析済み」 | 書いていない | 作業場のファイル帯に移した（説明の文は無くした） | 解析の種類が分からなくならないように |
| 計測の書き出し | 取り込みごとに1行 | 作業場が消える時とアプリを閉じる時に1行。1秒未満の作業場は書かない | React の StrictMode（開発の時だけ）がすぐに一度外すため |
| フォーカスのあるボタンでの `Enter`／`Space` | 7.5 に書いていない | 作業場のキーより、そのボタンを押す方を優先 | キーボードだけでボタンを押せるように |

## Phase 11 への申し送り

### 直した音の印

| 項目 | 値 | 付く所 |
|---|---|---|
| `practiceVoicingOverride.extractorVersion` | **`p10-correction:v1`** | 作業場で音を足した・高さを直したカードの、直した後の音（`source: "manual"`、`userVerified: true`、`representation: "simultaneous-voicing"`、`bassNote` は一番下の音） |
| `voicingMemory.playbackChoice` | `CUSTOM` | 上と同じカード |
| `sourceVoicing.extractorVersion` | 解析の時の値（無ければ `voicing-extractor-v1`） | 作業場で区間や音を変えたカードの、使っている元の音（`source: "midi-extracted"`、`userVerified: true`）。足した・高さを直したカードでは直す前の高さ |
| 札 `capturedForChordKey`／`capturedForChordLabel` | 保存する名前の `normalizedChordKey`／`label` | 音を書くすべての snapshot |

印の定数は `src/domain/correction/saveCandidate.ts` の `CORRECTION_EXTRACTOR_VERSION`。

### 保存の中身

| カードの状態 | 書くもの | `playbackChoice` |
|---|---|---|
| 区間も音も変えていない | 解析の `ChordTimelineItem` と `voicingMemory` をそのまま（名前を変えたら札だけ付け直す） | 解析のまま |
| 音は元のまま、区間が変わった（つなぐ・分ける・境目） | `sourceVoicing`＝新しい区間の使っている音。2音未満なら保存を止める | `SOURCE` |
| 外した音だけ | `sourceVoicing`（使っている音）。override は書かない | `SOURCE` |
| 足した音・高さを直した音を含む | `sourceVoicing`＝使っている元の音（直す前の高さ、2音未満なら書かない）、`practiceVoicingOverride`＝直した後の音 | `CUSTOM` |

- 保存形式は `fileVersion: 2` のまま。新しい項目は足していない。
- 保存しないもの：打ち直しの回数、外した音、足した音の出どころ。
- 保存する進行の小節番号は、曲の中の番号のまま（今の保存の経路と同じ）。

### 既知の問題

- 保存の後に進行ページで名前を変えると、直した音が捨てられる（札が合わなくなり生成の音になる。P10.0-00 の監査のとおり、今のアプリの動き）。進行ページを作り直すフェーズで扱う。
