## 3. 作業データ（CorrectionModel）

`src/domain/correction/` に、React を使わない純粋な関数として作る。入力は変えない（テストで凍結して確かめる）。

### 3.1 型

仕様書 8.2 の `CorrectionNote` を基に、次を持つ。

- `CorrectionCard`：`id`、`start`・`duration`（拍）、`bar`・`beat`、`name`（今の名前）、`nameSource`（`"auto"` のみ。人の名前は P10.0-04）、`alternatives`（解析の別候補）、`timelineIndex`（`fullTimeline` の何番目か）、`reviewReasons`、`reviewed: false`、`attacks: 1`。
- `CorrectionNote`：仕様書 8.2 の項目に `cardId` を足す。**元の音はカードの区間で切った断片として持つ**（1つの元の音が2枚のカードにまたがる時は2つの断片。`sourceNoteId` は同じ、`id` は `${sourceNoteId}@${cardId}`）。前から続いているかは元の音の開始で判定できるよう、`continuesFromBefore` を持つ。
- `sourceNoteId`：`トラック:チャンネル:開始tick:高さ`。同じ値が重なる時は `#2` のように番号を付ける。同じ MIDI からは毎回同じ ID になること。
- `CorrectionSegment`（区切り）：`id`、`startBar`・`endBar`、`label`、`repeatGroup`（同じ区切りの2回目以降なら何回目か）、`source`（`"segmentSections"` か `"fallback-8bar"`）。
- `SongSuggestion`（仕様書 6.5）：`kind: "melody-voice"`、`voiceLabel`、`cardCount`、`noteIds`。
- `CorrectionModel`：`cards`・`notes`・`segments`・`suggestions`・`pitchRange`（表示の音域）・`totalBeats`・`bpm`・`timeSignature`・`thresholdsVersion`。

### 3.2 作り方（仕様書 8.1）

`buildCorrectionModel(input, thresholds)`：入力は `analysis.result`（`fullTimeline`・`bpm`・`timeSignature`）・`analysis.sourceData`（音と分解能）・`analysis.sourceVoices`・解析前の `roleOverrides`。

| 項目 | 作り方 |
| --- | --- |
| カード | `fullTimeline` の各項目を1枚に。**数・順番・区間・名前は `fullTimeline` と完全に同じ** |
| 元の音 | 解析に使った Voice の音（除外した Voice の音は入れない）。拍に直してカードの区間で切る |
| 使っている音 | カードの `voicingMemory.sourceVoicing.midiNotes` の高さと同じ高さの断片を、そのカードの中で全部 `used: true` にする（打ち直しで同じ高さが複数ある時も全部）。`sourceVoicing` が無いカードは全部 `used: false` |
| 役割 | Voice の `inferredRole`（人が変えた役割があればそちら）を `roleHint` に。打楽器らしい高さ（`P10-review-thresholds.json` の percussion）は `percussion` |
| 区切り | `segmentSections(sourceData, fullTimeline)` を呼ぶ。2つ以上ならそれを使い、名前は「区切り1」「区切り2」…、同じ中身の2回目以降は「2回出てくる」。1つ以下なら8小節ごとで、名前は「1〜8小節」 |
| 要確認 | 3.3 |
| 曲全体の提案 | 役割がメロディの Voice があり、その音が `used` のカードが1枚以上ある時に1つ作る。`noteIds` はそのカードの中の、その Voice の `used` の音 |
| 音域 | 使っている音と外した音の最低〜最高に上下2半音の余白。最低でも2オクターブ |

### 3.3 要確認の理由（仕様書 6.3・6.5）

- 判定の数字は `contracts/P10-review-thresholds.json` を**そのまま読む**（数字をコードに書き写さない。読み込みの形は Zod で確かめる）。
- 3つの規則（メロディの混ざり・打楽器の混ざり・同じ和音の分かれ）を、監査C と同じ意味で実装する。監査のスクリプト（`scripts/p10/correction-model-audit.ts`）と数を突き合わせ、合成の場面で同じ枚数になることをテストで確かめる。
- **曲全体の提案が出ている時は、「役割がメロディ」を理由にしたカードの印は出さない**（前から続く一番上の音の印は出す）。
- 理由は `{ kind, noteIds, text }`。`text` は仕様書 6.3 の文の形（「〜の可能性があります」「〜です」）。音名は既存の音名の関数で作る。「欠落」「誤り」「間違い」は使わない。

### 3.4 名前の候補と構成音（仕様書 8.4・6.4）

- `nameCandidatesFor(card, notes)`：`used` の音を `detectLiveChord` に入れた結果（最大3つ）と、カードの `alternatives` を合わせ、同じ名前を除いて最大4つ。先頭は `detectLiveChord` の1つ目。4つに満たない時は埋めない。2音以下は解析の別候補だけ。
- `chordToneDiff(name, notes)`：`chordPitchClasses(name)` と `used` の音の音名を比べ、「構成音」「今の音」「名前の構成音にあって今の音に無い音」を返す。
- この段階では表示だけ。候補を選ぶ操作は P10.0-04。

### 3.5 単体テスト（合成データだけ）

`src/domain/correction/*.test.ts`。合成の MIDI はテストの中で作る（監査のスクリプトの作り方を、テスト用の小さな関数に移してよい）。少なくとも：

1. カードが `fullTimeline` と 1対1（数・順番・区間・名前）。8小節・64小節・300小節で。
2. `sourceVoicing` の高さが全部 `used` になり、区間の他の音は `used: false`。見つからない高さは 0。
3. 区間をまたぐ元の音が2つの断片になり、`sourceNoteId` が同じ。`sourceNoteId` が同じ入力で毎回同じ。
4. 入力（`fullTimeline`・元の音・Voice）を凍結しても動き、中身が変わらない。
5. 区切り：`segmentSections` が2つ以上返す場面と、1つになる場面（8小節ごと、「1〜8小節」「9〜16小節」、端の半端な小節）。
6. 要確認の3つの規則が、監査C の合成の場面と同じ枚数。数字を変えると枚数が変わる。
7. メロディのトラックがある場面で、曲全体の提案が1つ出て、役割がメロディを理由にしたカードの印が消える。
8. 名前の候補が最大4つ・重複なし。構成音との違いが正しい（例：G7sus4 に G C D だけ → 追加候補 F）。
9. 文の言葉に「欠落」「誤り」「間違い」が無い。
10. 300小節の合成で作る時間を測り、報告に書く（テストの判定は緩く、2秒未満）。

commit：`feat(correction): add CorrectionModel (display only)` とテストの commit。

2. カードの数と名前が、今の画面の「曲全体のコード」と同じか。
3. 要確認の印が多すぎないか・少なすぎないか（何枚中何枚か）。曲全体の提案の文が分かるか。
4. `]`・`[` で要確認を回れるか。聴き比べ A／B で違いが聞こえるか。
5. 区切りの帯が、曲の感じと大きく外れていないか（外れていても直せるのは P10.0-04 以降）。
6. 「今の画面で保存する」で戻って、今までどおり保存できるか。
7. 設定を OFF に戻すと、今の画面だけになるか。
