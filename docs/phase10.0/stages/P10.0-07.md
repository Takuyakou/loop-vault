## 区切り1：EXE 確認の直し

人間が EXE で見つけたもの（仕様書 v2.5 の変更点 1〜5・7）。

### 1.1 カードを押した時に鳴らす（既定 OFF）

- タイムラインの表示の切り替えの並び（全体・16小節・4小節の近く）に、チェック「押して鳴らす」を置く。既定 OFF。端末の中に覚える（キー `loop-vault:p10-card-click-audition:v1`、読み書きは try/catch）。
- ON の時、カードを**普通に押した時だけ**、選ぶのに加えてそのカードの音（B＝`cardAuditionNotes`、保存すると鳴る音）を鳴らす。前の試聴は止める。
- 鳴らさないもの：`Shift`＋クリック（範囲を決める）、境目の取っ手のドラッグ、`←`／`→` などのキーでの移動、曲全体の再生中。
- 単体または E2E：OFF の時は鳴らない、ON の時は押したカードの音の再生が始まる、`Shift`＋クリックでは鳴らない、設定が残る。

### 1.2 再生の縦線をなめらかに

- **原因（読んだ所）**：`CorrectionWorkspace.tsx` が `setInterval(…, 100)` で作業場全体を1秒に10回描き直し、再生位置をその時だけ計算している。縦線が10回／秒の段付きで動き、そのたびに作業場全体が描き直される。
- **直し方**：
  - 縦線（ピアノロールの `lv-cw-playhead`、曲全体の帯の `lv-cw-ov-ph`）は、小さな部品に分け、`requestAnimationFrame` で位置を計算して `transform` で動かす。作業場全体は描き直さない。
  - 位置の計算は今の式（`playback.startedAt` からの経過時間と BPM）を純粋な関数に分ける。可能なら、再生の部品が使う時計（音の時計）に合わせる。どちらにしたかを報告に書く。
  - 追従（`F`）のスクロールも同じフレームで行う。
  - 100ms の `setInterval` による全体の描き直しはやめる（再生中に要る他の表示が無いかを確かめてから）。
  - OS の「動きを減らす」設定でも、縦線は動かしてよい（位置の情報なので）。追従のスクロールはなめらかにしない。
- テスト：位置の関数の単体テスト。E2E で、再生中に縦線の位置を 500ms の間に何度か読み、20 回以上違う値になる（1秒に40回以上動く）こと。

### 1.3 右の欄に「元に戻す」

- 右の欄のカードの操作の並び（前とつなぐ・次とつなぐ・分ける・名前を入力）の、名前を入力の右に「元に戻す `Ctrl+Z`」。履歴が無い時は押せない。押すと `Ctrl+Z` と同じ。
- 「やり直す」は下の再生の横のまま（右の欄には置かない）。

### 1.4 区間が変わって2音未満のカードは保存を止める

- `saveCandidate.ts`：音を直していないが区間が変わったカードで、新しい区間の使っている音が2音未満なら、保存できない理由を返す：「区間を変えたので、このカードの音が2音未満です：3小節の F」。「このカードへ」で移れる（今の仕組み）。
- 単体テストを足す。作業場で聴いた音（B）と保存した音は、これで例外なく同じになる。

### 1.5 警告がある時の「要確認の印はありません」

- `CorrectionInspector.tsx`：そのカードに警告（「2音以上にしてください」など）がある時は、緑の「このカードに要確認の印はありません。」を出さない。

### 1.6 閉じる時・離れる時の確認をアプリの中のダイアログに

- **原因（読んだ所）**：ウィンドウを閉じる時、`src/store/closeGuard.ts` が Tauri の `ask`（OS の標準のダイアログ）で確認している。画面を移る時・別の MIDI の時は、アプリの `ConfirmDialog`。
- **直し方**：
  - 閉じる時の確認を、アプリの画面の中の `ConfirmDialog` で出す。例：`closeBlocker.ts` に「確認を頼む」関数（`Promise<boolean>` を返す）を足し、App に1つだけ置いた受け手が `ConfirmDialog` を出す。`closeGuard.ts` は `ask` の代わりにそれを待つ。
  - 受け手がいない窓（Live MIDI の窓など）では、今の `ask` のまま（その窓の動きは変えない）。
  - 確認の間はウィンドウを前に出す（できれば）。確認中にもう一度閉じるを押しても、ダイアログを2つ出さない。
  - 保存の失敗の知らせ（`showCloseSaveError`）も、受け手がいればアプリの中で出す。
  - 進行ページ（`ProgressionDetailView`）の閉じる時の確認も同じ仕組みで出る（文はその画面のまま）。
- **文**（仕様書 10.2 v2.5 の表）：見出し「保存していない変更があります」。本文「この曲で直した内容のうち、N 件をまだ Vault に保存していません。このまま閉じると、その変更は消えます。」（移る・開くの時は言葉を変える）。ボタン「保存せずに閉じる／移る／開く」（危険の色）と「戻る」（既定のフォーカス）。「破棄」「直し」の言葉は使わない。N は最後の保存の後に履歴に入った操作の数。
- テスト：閉じる時の仕組みの単体テスト（受け手がいる時は `ask` を呼ばずに受け手を待つ、戻るで閉じない、保存せずに閉じるで閉じる、受け手がいない時は今のまま）。E2E で、移る時・別の MIDI の時の文とボタン。

commit：区切りの中を小さく分けてよい（例：`fix(correction): smooth playhead` など）。

## 区切り2：自動の計測（仕様書 13章 v2.5）

- `src/domain/correction/`（純粋な部分）と保存の部分（Tauri の app data フォルダへの追記。今の app data への書き込みの仕組みを使う）。
- 取り込みごとに1行（1行1件の JSON）：日時、小節数、カード数、要確認の数（最初・保存の時）、「このままでよい」の数、直した回数の種類別（元に戻した操作は引く）、元に戻した回数、保存した範囲の数、最初の保存・最後の保存までの秒数、保存なしで離れたかの印。
- **記録しないもの：曲名・ファイル名・パス・音の並び・コード名。** テストで、記録の中にファイル名や名前が入らないことを確かめる。

- 書けない時（ファイルの失敗、Tauri でない時）は黙って飛ばし、取り込みと保存は止めない。

commit：`feat(correction): local edit metrics`。
