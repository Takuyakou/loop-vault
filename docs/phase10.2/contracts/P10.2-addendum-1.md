## 1. 決まった保存する範囲を見えるようにする

### 1.1 消える理由（読んだ所）

- 黄色の点線（`lv-cw-range-brace`、`correction-range-pending`）は、**決める前の見込み**だけを描いている（`pendingRange` がある間だけ）。
- 2回目の右クリックで範囲が決まると見込みが消え、決まった範囲は **範囲の外のカードを薄くする**（`data-out-of-range`、濃さ 40%）だけで描いている。
- そのため、決めた瞬間に一番はっきりした印が消え、範囲がどこからどこまでかが分かりにくくなる。区切りの帯は、範囲が区切りとちょうど同じ時しか光らない。

### 1.2 直し方

- **決まった範囲の枠**を、見込みの点線と同じ場所（カードの下）に出す。
  - 青緑（`--lv-accent`）の**実線**（1.5px、上の辺なし、下の角だけ丸く）。中は塗らない。
  - 左の端に「A」、右の端に「B」の小さな札（青緑の地に濃い文字）。
  - 文字：「保存する範囲 25〜28小節・4コード」（1小節だけなら「保存する範囲 25小節・1コード」）。
  - `data-testid="correction-range-confirmed"`。マウスの操作は受けない。
- 範囲がある間は、どの選び方（右クリック・区切りの帯・おすすめの範囲・`Shift`＋クリック・小節の行の `Shift`＋クリック）でも同じ枠を出す。`範囲を外す`・`Esc`・最初からやり直すで消える。
- 範囲の中のカード：背景を少し明るく（`--lv-surface-raised`）、名前を白に。範囲の外のカード：今の 40% のまま。
- **範囲がある時に新しく「ここから」を付けた時は、両方を出す**（決まった範囲の青緑の実線と、新しい見込みの黄色の点線）。見込みの点線は実線と重ならないよう、少し下にずらす（コードの行の高さはそのぶん伸ばしてよい）。
- 曲全体の帯にも、範囲を薄い青緑の塗りで出す（今の「見えている範囲」の枠とは別。枠は線、範囲は塗り）。
- 範囲が見えている範囲より広い時は、枠の文字を見えている範囲の左端に貼り付ける（区切りの名前と同じ）。
- 読み上げ（P10.2 9章）は今のまま。

### 1.3 テスト

- E2E：右クリック→右クリックで決めた後、`correction-range-confirmed` が出て文字が合う。区切りの帯を押した時・おすすめを押した時も出る。`範囲を外す` で消える。範囲がある時の「ここから」で、実線と点線の両方が出る。
- 単体：枠の文字（1小節・複数小節、1コード・複数コード）。

## 2. 右の欄の並び（P10.2 10.3 を上書き）

上から次の3つ。

| 場所 | 中身 | 動き |
| --- | --- | --- |
| 上（固定） | **おすすめの範囲（n）** | 見出しの**左**に `▸`／`▾`。見出しの行全体を押して開け閉め（`aria-expanded`）。開くと、見出しのすぐ下に一覧。一覧の高さは右の欄の 35% まで（それ以上は一覧の中でスクロール）。閉じた時は見出しの1行だけ |
| 中（この中だけスクロール） | **選んだカード** | P10.2 10.3 の 1〜7 のまま |
| 下（固定） | **保存する範囲** | P10.2 10.3 の 8 のまま。ただし **「▸ おすすめの範囲（n）」の切り替えは置かない**（上へ移す） |

- 一覧の中で、今の保存する範囲と同じものは青緑の枠で示す（`aria-current="true"`）。保存済みのものには「保存済み」。
- **最初は閉じている。** 開け閉めは端末の中に覚える。P10.1 から既定が変わる（P10.1 は最初に開く）ので、キーを `loop-vault:p10-recommended-ranges-open:v2` に変える（前のキーは読まない）。見出しの横に説明の文は付けない。
- おすすめが 0 件の時は、上の欄ごと出さない。
- 狭い画面（右の欄を開け閉めする幅）でも同じ並び。
- 「一覧が保存する範囲の上に浮いて開く」今の作り（`RecommendedToggle` を保存の欄に置き、一覧を保存の欄の上に出す形）はやめる。

### 2.1 テスト

- E2E：右の欄の並び（おすすめの見出し → 選んだカード → 保存する範囲）、見出しの左の `▸` を押して開く、開いた一覧で選ぶと範囲が入り、その行が青緑の枠になる、再読み込みしても開け閉めが残る、保存の欄におすすめの切り替えが無い。
- P10.2 で書いた「おすすめは保存の欄の上に開く」前提の E2E は、この並びに合わせて書き直す（理由を報告に）。

## 3. 構成音との違い（P10.2 10.3 の 6 を上書き）

- **違いが無い時は、欄ごと出さない**（名前の構成音と今の音が同じ時）。
- 違いがある時は、見出し「構成音との違い（参考）」の下に、**名前の構成音を根の音から1列のチップで並べる**。
  - 今の音にある構成音：普通のチップ（`B`）。
  - 今の音に無い構成音：青緑の点線のチップ「＋C#」。押すとその音を足す（今の「追加候補」のボタンと同じ動き）。
  - 名前に無い音が今の音にある時だけ、2行目に「名前に無い音　B」（薄い文字のチップ、押せない）。
- 今の「構成音」「今の音」「追加候補」の3行の表と、説明の文（「名前にあって今の音に無い音（足すかは耳で）」）はやめる。説明は見出しの `title` に入れる：「点線の音は、名前の構成音にあって今の音に無い音です。押すと足せます。省くのが普通の音もあるので、足すかどうかは耳で決めてください。」
- `data-testid="correction-addable"` は点線のチップの並びに付け替える。
- テスト：単体または E2E（違いが無い時は欄が無い、無い音が点線のチップになり押すと足される、名前に無い音の行、説明の文が画面に無い）。
