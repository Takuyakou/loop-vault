## 0. 人間からの要望

今は MIDI の一部を範囲で選んで保存する前提になっている。読み込んで、そのまますぐ保存したい時もある。

人間の決定：**A（範囲を選んでいない時は曲全体を保存）を基本にし、B（区切りごとにまとめて保存）を ▾ のメニューに入れる。**

---

## 1. A：範囲を選んでいない時は、曲全体を保存

- 保存する範囲を選んでいない時、右の欄の下の保存の欄を次のようにする。
  - 見出し：「保存する範囲　曲全体（1〜52小節）」。`範囲を外す` は押せない（今のまま）。
  - 保存のボタン：「**曲全体を保存**」（押せる）。押した後の流れ（題名・次にやること・新しいアイデア／今あるアイデアに追加・保存すると外した音は戻せない旨）は、今の `SaveProgressionPopover` と同じ。
  - P10.1・追加 1 の「まだ選んでいません。…」の文はやめる（見出しで曲全体と分かるため）。
- **曲全体の範囲** = 最初のカードが始まる小節 〜 最後のカードが終わる小節（曲の頭や終わりの休みは含めない）。カードが1枚も無い時は押せない。
- 中身は、範囲を選んだ時の保存と同じ（`buildSaveCandidate` に曲全体の範囲を渡す）。作業場で直した音・名前・境目・テンポ（P10.1 12.4）を含む。2音未満のカードなどの保存できない理由も、今と同じ形で出す（「このカードへ」）。
- 保存できたら、曲全体の範囲に「保存済み」の印を付ける（今の `savedRanges`）。区切りの帯・おすすめの範囲で同じ範囲のものにも「保存済み」が出る。
- 範囲を選ぶと、今までどおりその範囲の保存になる。`範囲を外す` で曲全体に戻る。
- **確かめること（報告に書く）：** 長い進行（52小節・コード数十個）を1つの進行として保存でき、読み直しても残り、Voicing Loop と進行ページで開けて再生できるか。開くのが遅い・表示が崩れる時は、直さずに報告に書く（人間が決める）。保存の形式に長さの上限があって入らない時は、保存を止めて理由を出し、報告に書く。

## 2. B：区切りごとにまとめて保存（▾ のメニュー）

### 2.1 入口

- 保存のボタンの右の `▾` をメニューにする。中身：
  1. 新しいアイデアに保存（今の動き）
  2. 今あるアイデアに追加（今の動き）
  3. （仕切り）
  4. **区切りごとに保存…**（小さな文字で「13個・同じものは1つに」）
- 範囲を選んでいる時も、メニューに 4 を出す（範囲には関係なく、曲全体の区切りが対象）。
- `SaveProgressionPopover` はほかの画面でも使っているので、作業場だけに項目を足せる形（項目を渡す引数など）にし、ほかの画面の動きは変えない。

### 2.2 区切りごとに保存のダイアログ（アプリの中の `ConfirmDialog` と同じ見た目）

- 見出し：「区切りごとに保存」
- 一覧：曲の区切り（今の `present.segments`。P10.2 11章で端を動かしていればその後の区切り）を上から並べる。各行はチェック・区切りの名前・小節（「9〜12小節」）・コード名の並び。
  - **同じコードの区切り**（今の `repeatCount` と同じ判定）は、最初の1つだけを行にし、「区切り2・区切り6 と同じ」と添える。後の同じものは保存しない。
  - 保存済みの範囲と同じ行は、最初からチェックを外し「保存済み」。
  - 保存できない理由がある区切り（2音未満のカードなど）は、チェックできない行にし、理由と「このカードへ」（押すとダイアログを閉じてそのカードへ）。
  - 既定は、保存できて保存済みでない行すべてにチェック。
- 保存先：「新しいアイデア（題名：ファイル名から）」と「今あるアイデアに追加（選ぶ）」の2つから選ぶ。既定は新しいアイデア。
- 各進行の題名：今の題名の決め方（`titleFor`）に区切りの名前を付ける（例：「Sugar Cube Maze 区切り3」）。題名の個別の編集はこのダイアログではしない（保存した後に進行ページで直せる）。
- ボタン：「n個を保存」（主）と「戻る」（既定のフォーカス）。n が 0 の時は押せない。
- 保存は、新しいアイデアなら最初の1つでアイデアを作り、残りはそのアイデアに追加する（今の `onCreate`・`onAppend` を順に呼ぶ）。途中で1つ失敗したら、そこで止め、保存できたもの・できなかったものを知らせに出す（保存できたものは残す。取り消さない）。
- 保存できた区切りに「保存済み」の印。知らせ：「12個の進行を保存しました」。
- 保存の中身・印（`p10-correction:v1` など）は、範囲を選んで1つずつ保存した時と同じ。

## 3. 保存していない変更・計測

- A・B のどちらでも、保存した後の「保存していない変更」の扱いは今と同じ（最後の保存の後に直したかで決める）。
- 計測（`correction-metrics`）：保存の回数に、A は1回、B は保存できた数を足す。種類（曲全体・区切りごと・範囲）を数だけ残す。名前や小節は書かない。

## 4. テスト

- 単体：曲全体の範囲（頭と終わりの休みを含めない、カードが無い時）、区切りごとの一覧（同じコードの区切りを1つに、保存済みのチェックを外す、保存できない区切り）。
- データ保持：曲全体の保存と、区切りごとの保存（同じアイデアに複数の進行）が、保存・読み直しで完全に一致する（`p89DataRetention` の形の往復テストを足す）。
- E2E：
  - 読み込んで範囲を選ばずに「曲全体を保存」→ 新しいアイデアに保存 → Vault に1つの進行が入り、コードが全部ある。
  - ▾ →「区切りごとに保存…」→ 一覧に同じコードの区切りがまとめられている → 保存 → 1つのアイデアに複数の進行が入る。もう一度開くと「保存済み」でチェックが外れている。
  - 範囲を選ぶとボタンが範囲の保存に戻り、`範囲を外す` で「曲全体を保存」に戻る。
