## 1. 知らせの扱い

- **原因（読んだ所）：** `CorrectionWorkspace.tsx` は、範囲を決めた時に `setNotice("保存する範囲を … にしました")` を出し、知らせは次の知らせが来るまで操作バーの右端（`correction-notice`）に残る。範囲を外す時に知らせを消す処理が無い。
- **直し方：**
  - 範囲を決めた・外した時の文は、**画面に出さず、読み上げ（画面に見えない `aria-live`）だけ**にする。範囲は、カードの下の枠と 3章の札で見える。
  - 外した時の読み上げ：「保存する範囲を外しました」。
  - ほかの知らせ（「名前を Am7 にしました（音から）」「最初からやり直しました」など）は画面に出すが、**5 秒で消す**。新しい知らせが来たら置き換える（今のまま）。マウスを乗せている間は消さない。
  - 保存の失敗など、人が読む必要のある知らせ（今 `role="alert"` のもの）は自動で消さない。
- テスト：範囲を決めても画面に文が出ない（読み上げの要素には入る）、外すと読み上げの文が変わる、ほかの知らせが 5 秒で消える。

## 2. 歯車のマーク

- 作業場の操作バーの右端のメニュー（押して鳴らす・凡例を出す・最初からやり直す）のアイコンを**歯車**にする。
- `src/components/icons/index.tsx` に `GearIcon` を足す（今のアイコンと同じ線の太さ・大きさ）。**今の `SettingsIcon`（横棒のつまみ）は変えない。サイドバーの「設定」はそのまま。**
- ボタンの名前（`aria-label`・`title`）：「この画面の設定」。
- `icons.test.tsx` の一覧に足す。

## 3. 範囲の札（操作バー）

- 保存する範囲がある時だけ、操作バーの右側（`⚙` の左、今の知らせの欄の手前）に札を出す：

  `保存する範囲 6〜7小節・2コード  ×`

  - 青緑の枠と薄い塗り（追加 1 の決まった範囲の枠と同じ色）。Voicing Loop の区間ループの札（見出しの右の「区間 10〜13小節 ×」）と同じ形にする。
  - `×` は `button`、名前は「範囲を外す（Esc）」。押すと範囲を外す（`Esc` と同じ）。
  - 札の文字を押すと、範囲の頭のカードが見える所まで表示を動かす（選ばない）。
  - 幅が足りない時は「6〜7小節 ×」まで縮める（「保存する範囲」と「・2コード」を外す。`title` に全文）。
  - `data-testid="correction-range-chip"`。
- **右の欄の下の保存の欄から「範囲を外す」のボタンを無くす。** 欄は「保存する範囲 6〜7小節・2枚」・コード名の1行・保存のボタンと `▾`。範囲が無い時は今のまま「曲全体（…）」と「曲全体を保存」。
- P10.1 8章の「範囲を外すは常に出し、範囲が無い時は押せない」は、この札で置き換える（範囲が無い時は札ごと出さない）。

## 4. 区切りごとに保存した進行に区切りの名前を残す

- **今：** 進行に題名の欄が無く、題名を持つのはアイデアだけ。そのため、区切りごとに保存した進行どうしの見分けが付かない。
- **直し方（保存の形式は変えない）：** 進行に今ある `memo` の欄に、区切りの名前と小節を入れる：「区切り3（9〜12小節）」。仮の区切りは「9〜16小節」（6章の名前）。
- **気を付けること（読んだ所）：** `memo` には解析の注意のコード（`;` 区切り）が入ることがあり、詳細ページの `describeBlockMemo`（`views/captureLabels.ts`）は「全部が注意のコードの時だけ」日本語に直し、それ以外は `memo` をそのまま出す。区切りの名前を足すと、注意のコードが生のまま見えてしまう。
  - 保存の時：今 `memo` に入るものを確かめ、注意のコードがあればそれを残し、区切りの名前を `;` でつないで足す。
  - 表示の時：`describeBlockMemo` を、注意のコードは日本語に直し、それ以外の部分はそのまま出す形にする（「区切り3（9〜12小節）、候補が僅差」など）。
- 範囲を選んで1つずつ保存した時・曲全体を保存した時は、今のまま（区切りの名前を足さない）。
- Vault・進行ページ・Voicing Loop で、進行の一覧や見出しに `memo` が見えるかを確かめる。見えない所は直さず、報告に書く（どこに出すかは人間が決める）。
- テスト：区切りごとに保存した進行の `memo` に区切りの名前が入る、注意のコードと混ざっても詳細ページで日本語と区切りの名前が両方読める、往復テスト（保存・読み直しで一致）。

## 5. 長い進行の進行ページの折り返し

- **今：** 65小節・97コードの進行を開くと、カードの「要確認・候補が僅差」などの文字が1〜2文字ずつ縦に折り返して読めない。
- **直し方：** その文字は1行で出し、入らない分は省略して `title` に全文。カードの幅が狭くて入らない時は、文字の代わりに小さな印（今の要確認の色の点）だけにする。
- 対象のコンポーネントを特定して報告に書く（`EditableChordCard.tsx`・`ChordInspector.tsx` など、`captureLabels.ts` を使う所）。
- 長い進行での表示の速さ（開くのに約 150ms）は今のままでよい。
- テスト：長い合成の進行（60小節以上）で、カードの注意の文字が縦に折り返さない（高さが1行分）。スクリーンショットを1つ足す。

## 6. 仮の区切りの名前の付け直し

- **今（読んだ所）：** 解析に区切りが無い時の8小節ごとの仮の区切り（`source: "fallback-8bar"`、名前は `barRangeLabel`）は、P10.2 11章で端を動かしても名前が「1〜8小節」のまま残る。
- **直し方：** 端を動かした後、仮の区切り（`fallback-8bar`）の名前は、**新しい小節で付け直す**（「1〜6小節」「7〜16小節」）。解析の区切り（`segmentSections`、「区切り3」など）の名前は今のまま変えない。
- 元に戻すと名前も戻る（履歴の中なので）。
- テスト：仮の区切りの端を動かすと名前が付け直される、解析の区切りの名前は変わらない、元に戻すで戻る。

## 7. 「保存した音」が 96/97 になる理由

- **調べる：** 65小節・97コードの曲全体を保存して Voicing Loop で開くと、「保存した音」が 96/97。どのカードが保存した音を持っていないか、理由は何かを特定する。
  - 見込み：使っている音が1音だけのカード（保存の決まりで、ボイシングは2音以上が要る）、休み、名前と音が合わないカード、のどれか。
- **直すかの決まり：**
  - 理由が「1音だけ」など**今の決まりどおり**なら、直さない。報告に「どのカード・なぜ」を書く。Voicing Loop は今のとおり、足りないカードを自動の音で補い A の印を付けているかを確かめる。
  - 理由が**保存の作りの誤り**（音があるのに保存されていない、など）なら、保存の形式・中身を変えずに直せる範囲で直し、往復テストを足す。直せない時は止めずに報告に書く。

## 9. 受け入れ条件

1. 範囲を決めても外しても、操作バーに文が残らない。ほかの知らせは 5 秒で消える。
2. 作業場のメニューのアイコンが歯車。サイドバーの「設定」は今のまま。
3. 範囲がある時だけ、操作バーに「保存する範囲 … ×」の札があり、× で外せる。右の欄の下に「範囲を外す」が無い。
4. 区切りごとに保存した進行の詳細ページで、区切りの名前と注意の文が読める。
5. 長い進行の進行ページで、カードの注意の文字が縦に折り返さない。
6. 仮の区切りの端を動かすと、名前が新しい小節になる。
7. 「保存した音 96/97」の理由が報告にある（直したなら、その往復テストがある）。
8. 解析・transport・再生の選び方・Vault の保存形式・保存の中身（4章の memo を除く）は変わらない。fresh FULL と EXE が通る。
