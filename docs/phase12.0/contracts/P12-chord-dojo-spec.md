## 0. 要約

1. **入口は「今日の練習」の「始める」1つ。** 何を・どの段で・どのキーで練習するかはアプリが記録から決める。今の5つの選択（進行・レベル・判定・モード・ボイシング）は無くす。
2. **練習は3種類。** 型を覚える／登録した音を覚える／進行で弾く。今日の練習は、答えなしの確認を先頭にして、この3つから少しずつ組む。新しいコードの種類は、型の前に「構成を知る」を1回挟む。
3. **1つの練習の中は3段。**
   - コード：（新しい種類なら構成を知る →）① 見て弾く → ② 名前だけで弾く（違う3つのキー）。テンポの中で使えるかは、進行で確かめる。
   - 進行：① 見て弾く → ② 覚えて弾く（見てから隠して頭から）→ ③ テンポで弾く（隠したまま）。③ があるのは進行だけ。
   - 答えは弾いた後に見せる。
4. **習得の段階は、練習するものごとに違う。**
   - 型：3段（仮の合格 → 合格 → 12キー習得）。
   - 登録した音・自分の進行：2段（仮の合格 → 合格）。キーは広げない。
   - 組み込みの進行：2段。合格の後、確認の時にキーを変える。
   - コードの種類：「構成を知る」の後、ときどき「構成を思い出す」で確かめる。
   - 詳しくは 4.2。
5. **組み込みの進行を持つ。** 何も保存していなくても練習できる。度数で持ち、キーは出す時に決める（Bass Practice と同じ形）。
6. **MIDI が無い時は自分で判定する。** 答えを見て「弾けた／まだ」を押す。秒数は測らず、記録は「自分で判定」として残す。自分で判定した結果で進めるのは仮の合格まで。
7. **記録は Vault の外の自分のファイル**に置く（Bass Practice と同じ形）。Vault の保存形式は変えない。今の `block.practice` は読むだけにする。

## 1. 目標と、今の Chord Dojo の問題

順番にすると：**コードを覚える → 進行を覚える → 使えるボイシングを学び、すぐ出せるようにする。**

## 3. 練習の単位（練習するもの）

### 3.1 型（レシピ × コードの種類 × ベース）

- **レシピ**は4つの軸で表す：構成（基本／骨組み／上に三和音）・配置（まとめる／広げる）・ベース（自分で弾く／別のパート）・トップ（指定なし／3・5・7・9…）。
- 画面では4つのプリセットで見せる：**基本・骨組み・上に三和音・広げる**。記録はプリセットの名前ではなく、軸の値で持つ。
- コードの種類の初めの範囲（Phase 12）：**メジャー・マイナー（三和音）**、maj7・maj9・6/9・m7・m9・m6・7・9・13・7sus4・m7♭5・dim7 の14種類。分数コードとオルタードは後回し。
- **どの音になるかの表は段階 12-00 で固める。** 今の生成スタイル（Default close・Shell 1-7・Open 1-7・Rootless A/B）と自動生成の出力を、全種類×全プリセットで作る。それをレシピの軸に機械的に分類し、人間が表を見て決める。
  - 対応の見込み（仮説）：基本≒Default close、骨組み≒Shell、広げる≒Open、上に三和音＝新しく足す。
- ベースの「自分で弾く ⇄ 別のパート」の切り替えは、基本の構成ではルートを抜くだけ。それ以外の構成での例外は 12-00 で洗い出す。

### 3.2 登録した音

- Vault の進行のコードのうち、**Phase 11 の出どころが「保存した音」「元MIDI」「カスタム」のもの**。「自動生成」は対象にしない（それは型で練習する）。
- 音域まで同じに弾く。
- **練習の単位は「鍵盤の音」で決める（重なりを1つにまとめる）。**
  - 同じ配置が、出どころを変えて（保存した音・元MIDI・カスタム）、あるいは別の進行・別の曲に何度も出てくることがある。
  - **鍵盤の音（MIDI の音の番号を低い順に並べたもの）が同じなら、同じ1つの練習の単位**として扱う。昨日覚えた Amaj9 が、別の出どころや別の進行から「新しいもの」として出ることはない。
  - どの進行のどのカードに出てきたか、出どころは何か（出どころの記録）は、単位の中に**一覧として持つ**だけで、単位の識別には使わない。画面に出す曲名と区切りは、一覧の中で一番新しいもの。
  - コード名は単位の識別に使わない（同じ音で名前が違う時は、一番新しい名前を出す）。
  - 進行ページで音を変えると、鍵盤の音が変わるので**別の単位**になる。元の単位の記録は残る。出てくる所が無くなった単位は、新しいものとしては出さないが、☆ が付いているか合格していれば確認には出す。
- 選ぶ順：お気に入りの進行 → 最近保存した進行 → まだ練習していないコード。同じ進行から続けて出しすぎない（1日に同じ進行から2つまで）。
- 登録した音は、まず元のキー・元の音域で覚える。12キーへは広げない。
- 「この形を自分の型として12キーで練習する」は Phase 12 では作らない。ロードマップ（15章）に置き、記録の形だけ先に備える（8.2）。

### 3.3 進行

- Vault の進行（自分の進行）と、組み込みの進行。
- **目的は「進行を覚える」こと。** 練習の段で、コード名を隠して頭から出す（4.1）。
- 自分の進行は、`progressionFingerprint` で「中身が変わったか」を見る。変わったら記録を「まだ」に戻す。
- 長い進行は、8小節までの区切りで出す（区切りの名前は P10.3 の `memo`）。
- **自分の進行は元のキーで覚える。** 別のキーでは出さない。
  - ⚙ の「度数も出す」で、カードに度数（Ⅳmaj7 など）を小さく出せる。初めは OFF。
  - 別のキーで練習する入口は Phase 12 では作らない。

### 3.4 組み込みの進行

**選ぶ基準：覚えると別の曲でも何度も使える・作曲でそのまま使える・ボイシングの練習にもなる。** ジャンルや曲らしさでは選ばない。曲名・サイト名は使わない。

- I–V–vi–IV は三和音（メジャー・マイナー）を含む。三和音は型の種類に入れ、カリキュラムの最初に置く（Q11）。
- コードの種類・度数・「今日のポイント」の文は**案**。12-00 で、基本のボイシングで実際に鳴らして、ポイントの文が音として正しいかを確かめ、人間が決める。
- **「今日のポイント」は自動のテストで確かめる。** 理論の上では正しくても、作られたボイシングがその音を省いていると、画面の言葉と鳴っている音が食い違うため。
  - 各進行に、機械で確かめられる形の主張（`pointCheck`）を持たせる。例：
    - `{ kind: "half-step", from: { chord: 0, tone: "7" }, to: { chord: 1, tone: "3" }, dir: "down" }`（7度が次の3度へ半音で下りる）
    - `{ kind: "common-tones", chords: [0, 1], tones: ["1", "3", "5"] }`（共通の音を同じ高さで残す）
    - `{ kind: "max-upper-motion", semitones: 4 }`（上の音の動きが4半音以内）
  - テスト：12キーすべてで、実際に練習に出すボイシング（型の「基本」、前のコードに近い高さでつなぐ）を作り、主張がその音の中で成り立つかを見る。
  - 成り立たない時は、次のどちらかにする（12-00 で人間が決める）：
    - (a) その進行のボイシングの作り方を直して成り立たせる。
    - (b) 画面の言い方を「理論の上では：…」に変える。
  - **テストが通らないまま出さない。**
- 次の候補（Phase 12 では入れない）：iii–VI7–ii–V、マイナーの ii–V の連鎖（Bm7♭5–E7–Am7 → Am7–D7–Gmaj7 のような発展）、ii7–V13sus のような2コードのボイシング練習、同じ進行を基本・骨組み・広げるで弾き分ける練習。

```ts
  pointText: string;                              // 画面に出す「今日のポイント」1行
  pointCheck: PointCheck[];                       // pointText を実際のボイシングで確かめる主張（上の例）
  pointIsTheory?: boolean;                        // (b) にした時だけ true。画面は「理論の上では：…」
}
type LearnTag = "guide-tone-resolution" | "minor-ii-v" | "secondary-dominant" | "turnaround"
  | "diatonic-descent" | "borrowed-minor" | "backdoor-resolution" | "common-tone-voice-leading" | "bass-vs-upper-motion";
```

- `learns` は決まった言葉の中から選ぶ（自由な文字にしない）。今は画面に出さず、「今日のポイント」の1行だけを出す。後で「この覚え方の進行をもう1つ」のような選び方に使える。
- Bass Practice の `progressionPresets.ts` と**形（度数・種類・長さ・版）をそろえる**。一覧そのものは Chord Dojo 用に別に持つ（目的が違うため）。

#### 出し方

- 保存した進行が無い時、または今日の「進行で弾く」に自分の進行が選ばれない日に出す。
- 層の順：基礎の4つ → 作曲の3つ → ボイシングの1つ。使う種類がまだ型で習っていない進行は後に回す（例：m7♭5 を習う前は iiø–V–i を出さない）。
- 初めは C か F で出す。合格した後は、確認の時にキーを変える（弱いキーを優先）。ボイシングは型の「基本」で作る。
- 練習の画面では、進行の名前の下に **「今日のポイント：7度が次のコードの3度へ半音で下りる」** を1行で出す（①と②の覚える時。弾いている間は出さない）。

## 4. 練習の進め方

### 4.1 1つの練習の中の段

#### コード（型・登録した音）

| 段 | やり方 | 答えの鍵盤 | 時間の基準 | 次の段へ |
| --- | --- | --- | --- | --- |
| **構成を知る**（新しい種類の初回だけ） | 「Cm9　構成：1 ♭3 5 ♭7 9」と音名（C E♭ G B♭ D）を見て、構成の音を押す。オクターブ・順番・最低音は問わない | 最初から見える | なし | 1回そろう |
| **① 見て弾く** | 1つのキーで見ながら。合うまで待つ | 最初から見える | なし | 1回合う（知っている型は飛ばす） |
| **② 名前だけで弾く** | **違う3つのキー**で、答えなし。合うまで待つ | 弾いた後、または時間を過ぎたら | 5秒 → 3秒 → 自分の基準 | 3つのキーで基準内に合う＝**仮の合格** |

- 「構成を知る」は、コードの種類ごとに最初の1回の**説明**（記録に「知っている種類」として残す）。2回目からは①の時に構成（1 ♭3 5 ♭7 9）を小さく出すだけ。人が「もう一度見る」を押せば何度でも出せる。
- **構成を思い出す**（答えなしの確認に混ぜる）：
  - 画面は「Cm9　構成の音を弾いてください」だけ。構成の表と答えは出さない。
  - 判定は音名だけで行う（オクターブ・順番・一番下は自由、余分な音は違い）。合えばすぐ次へ。秒数は記録するが、基準には使わない。
  - 外したら構成の表と答えを出して、もう一度押してもらう。その種類の次の型の①では、構成を大きめに出す。
  - 間隔：知った日から7日 → 合えば30日 → 合えば90日。外したら次の日に戻す。
- ②で外したら、一言で知らせ、答えを見せて、**同じものをすぐもう一度**出す（D5）。
- 「登録した音」は①②を元のキーで行う。「違う3つのキー」の代わりに、**日をまたいで**確かめる。「構成を知る」は挟まない（種類を知らない時だけ、①で構成を小さく出す）。

#### 進行

| 段 | やり方 | コード名 | 次の段へ |
| --- | --- | --- | --- |
| **① 見て弾く** | コード名を見ながら、頭から。合うまで待つ | 見える | 1周弾く |
| **② 覚えて弾く** | 進行を見て「覚えた」を押す（時間の制限なし。聴いてもよい）→ 名前を隠し、頭から弾く。合うまで待つ | 隠す。合ったカードから名前が出る。5秒止まったら「4番目：Eadd9/F#」とそのカードだけ出す | 1周を出してもらわずに弾けた＝**仮の合格** |
| **③ テンポで弾く** | 隠したまま、テンポで1周 | 隠す。外した所は1周の後に出す | 1周を止まらずに合う＝**合格**（次の日以降） |

- ②で名前を出してもらったカードは、その周の後にもう一度②（そのカードの前後2つ）を出す。
- 「次のコードは？」だけを答える練習（Progression Recall）は Phase 12 では作らない（15章）。

### 4.2 合格の段階とキーの広がり

まず、練習するものごとの習得の段階（実装者が混同しないための一覧）：

| 練習するもの | 段階 | キーを広げるか |
| --- | --- | --- |
| 型（レシピ×種類×ベース） | まだ → 仮の合格 → 合格 → **12キー習得** | 広げる（12マス） |
| 登録した音 | まだ → 仮の合格 → 合格 | 広げない（元のキー・元の音域） |
| 自分の進行 | まだ → 仮の合格（②）→ 合格（③） | 広げない（元のキー） |
| 組み込みの進行 | まだ → 仮の合格（②）→ 合格（③） | 合格の後、確認の時にキーを変える |
| コードの種類 | 構成を知る → 構成を思い出す（7日・30日・90日） | —（音名だけ） |

記録の単位：型は「レシピ × 種類 × ベース」、登録した音は「コード」、進行は「進行」。

| 状態 | 型の条件 | 登録した音の条件 | 次に出る時 |
| --- | --- | --- | --- |
| まだ | 最初 | 最初 | 新しいものとして |
| **仮の合格** | ②で違う3キーが基準内に合う（その日） | ②で基準内に合う（その日） | 次の日以降の確認 |
| **合格** | 仮の合格の次の日以降、答えなしで4キーが基準内に合う（弱いキー優先） | 仮の合格の次の日以降、答えなしで1回合う | 14日後に確認 |
| **12キー習得** | 12マス全部、答えなしで一度以上基準内に合う | —（無い） | 30日後に確認 |
| 確認が要る | 合格・12キー習得から日がたった | 同じ | 答えなしの確認。外したら仮の合格の前に戻る |

- 進行：②で出してもらわずに1周＝仮の合格、次の日以降に③で止まらずに1周＝合格、14日後に③で確認。外したコードは、登録した音・型の確認として翌日以降に出しやすくする。
- **弱いキーの選び方**：まだ合っていないキー → 遅かったキー → しばらく出ていないキーの順。ランダムだけにはしない。
- 14日・30日は設定で変えられる値にする（画面には出さない）。

### 4.3 速さの基準

- 時間は「名前が出てから、全部の音がそろうまで」。
- ②の基準：始めは5秒、仮の合格を3つ取ったら3秒、その後は**自分の基準**。自分の基準は、直近20回の合った秒数の中央値の1.2倍、ただし2秒より短くしない。
- 段階 12-00 で今の自分の秒数を測り、5秒・3秒が妥当かを確かめる。

### 4.4 今日の練習の組み立て

```text
1. 答えなしの確認    確認の日が来たもの。最大6つ。弱いキーで出す
                      （このうち「構成を思い出す」は1日1つまで。「☆ 使いたい」の枠が1つ）
2. 型を覚える        新しいもの 1〜2（確認が多い日は 1）
3. 登録した音        1〜2（Vault に対象が無ければ飛ばす）
4. 進行で弾く        1（自分の進行。無ければ組み込みの進行）
```

- 目安は10〜15分。1つの練習の見込み時間（型：①②で約1分、登録した音：約40秒、進行：1周＋α）から合計を出し、15分を超えそうなら 2→3 の順に減らす。
- 新しいものは1日に2つまで（確認が回らなくなるのを防ぐ）。
- **☆ 使いたい**：型・登録した音・進行に、人が ☆ を付けられる（練習の画面とおわりの画面で）。確認の枠のうち1つは、「☆ が付いていて、7日以上弾いていないもの」に使う（確認の日が来ていなくても出す）。☆ は記録ファイルに持つ。
- 型の新しいものの順（カリキュラム）：
  0. メジャー・マイナー（三和音、基本）
  1. m7・7・maj7（基本）
  2. 同じ種類の骨組み
  3. 9th の種類（m9・9・maj9）
  4. 6/9・m6・13・7sus4
  5. m7♭5・dim7
  6. 上に三和音・広げる

  順番は表として持ち、後で変えられるようにする。
- 今日の練習は、その日の最初に組んで記録ファイルに保存する。
  - **どこで止めても、同じ日に開けば続きから始まる。** 次の日は組み直す（やり残しは確認として翌日に入る）。
  - 全部終わった後の「もう少しやる」で、型を1つ足せる。
- **何も記録が無い最初の日**：**メジャー三和音・基本**（構成を知る → ① → ②）1つ ＋ 組み込みの進行 **I–V–vi–IV** 1つ。「コードの構成 → 型 → 進行」の流れが初日から分かるようにする。
- 保存した進行が無い：登録した音を飛ばし、進行は組み込みから。

## 5. 判定（MIDI）

### 5.1 言葉の決まり（v0.5 8.1 のまま）

- MIDI からは左右の手は分からない。判定の文では「右手」「左手」を使わない。
- **最低音**：押している一番低い音。**上声部**：最低音より上の音の並び（下からの順）。

### 5.2 何を見るか

| 項目 | 型（ふつう） | 登録した音（きびしい） | 進行（構成の芯） |
| --- | --- | --- | --- |
| 構成の音 | 音名がそろう | 同じ鍵盤 | 音名がそろう（5度の省略など、レシピが許すものは可） |
| 上声部の並び | 下からの順が合う | 同じ鍵盤 | 問わない（転回・内声は自由） |
| 最低音 | ベースが自分で：ルート。別のパート：ルートでない | 同じ鍵盤 | ベースの条件だけ |
| トップ | 指定がある時だけ | 同じ鍵盤 | 問わない |
| オクターブ | 全体の上下のずれは許す | 許さない | 許す |

- 今の判定（`matchPerformance`・`chordRequirements`）を土台に、上声部の並び・トップ・鍵盤の位置を見る判定を足す。**今の判定の関数の結果は変えない**（足すのは別の関数）。
- 判定のタイミング：押している音の数が答えの音の数に達したら、**最後の音が入ってから短い待ち時間（そろうのを待つ時間）**の後に判定する。足りないうちは待つ。全部離したらやり直し。
  - 人が和音を弾くと、音は同時には入らない（数十ミリ秒ずれる）。待たずに判定すると、正しく弾いたのに「違う」と出ることがある。**正しいのに外れと出るのが一番使う気を失わせる**ので、ここは精度を優先する。
  - 待ち時間の中に余分な音が入ったら、それも含めて判定する。待ち時間の中で音を離した時は、離す前の形で判定する。
  - 秒数は「名前が出てから、最後の音が入るまで」。待ち時間は秒数に含めない。
  - 待ち時間の値は 12-00 で決める：今の `inputState`・`cleanRound`（と Voicing Loop の判定）に同じ仕組みがあるかを調べ、あればそれを使う。無ければ、自分の鍵盤で和音を弾いた時の音のずれを測り、その最大より少し長くする。値は設定として持つ（画面には出さない）。
- 進行の③の判定：そのコードの長さの間に、一度でも合う形が押されていれば合い。

### 5.3 知らせ方

- 合ったら、短い音と緑で「✓ 合いました 1.6s」。答えの音を一度鳴らす。
- 違ったら、どこが違うかを一言で出す。言葉は責めない。例：
  - 一番下の音が F（D を指定）
  - 7 がありません
  - 余分な音 E があります
  - 一番上が E（D を指定）
  - 音は合っています。音域（鍵盤の位置）が違います
- 答えの鍵盤は、弾いた後に出す。押した音は青、答えは青緑の点、違う音は赤、押し忘れた答えは点線の点。
- 時間を過ぎても弾いていない時は「答えを見る」を出す（自動では出さない）。

### 5.4 MIDI が無い時（D4）

- はじめの画面に「MIDI キーボードがつながっていません。答えを見て、自分で『弾けた／まだ』を押す形で進みます」。
- 練習の流れ：名前を見る →（頭の中で形を決めて弾く）→「答えを見る」→「弾けた／まだ」。①は最初から答えが見える。
- 秒数は測らない。記録には「自分で判定」を付ける。
- **自分で判定した結果で進めるのは仮の合格まで。** 合格・12キー習得には、MIDI での判定が要る。
- 練習の途中で MIDI がつながったら、次の練習の単位から MIDI の判定に切り替える。

```ts
interface ChordDojoStoreV1 {

  knownQualities: Record<QualityId, { at: string; lastRecallAt?: string; nextRecallAt: string; recallStep: 0 | 1 | 2 }>;
                                                  // 「構成を知る」が済んだ種類と、「構成を思い出す」の予定（7日・30日・90日）
  shapes: Record<ShapeKey, ShapeRecord>;          // プリセット："preset:<構成>|<配置>|<ベース>|<トップ>:quality:<種類>"
                                                  // 自分の型（15章、Phase 12 では作らない）："personal:<id>""
  voicings: Record<VoicingKey, VoicingRecord>;    // 鍵：鍵盤の音の指紋 "notes:45,61,68,71"（出どころ・進行は鍵に入れない）
  progressions: Record<ProgressionKey, ProgRecord>; // Vault: 進行 ID ＋ fingerprint ／ 組み込み: presetId ＋ 版
  today?: TodayPlan;                              // 日付・組んだ中身・今どこまで
  settings: { reviewDays: [14, 30]; progBpm: number };
}
interface ShapeRecord extends ItemRecord {
  keys: Record<PitchClass, { lastSec?: number; bestSec?: number; lastAt: string; self?: boolean }>; // 12マス
}
interface VoicingRecord extends ItemRecord {
  notes: number[];                                 // MIDI の音の番号（低い順）
  occurrences: {
    progressionId: string; chordId: string;
    source: "saved" | "source-midi" | "custom";
    harmony: { root: PitchClass; quality: string; bass?: PitchClass; symbol: string };  // どのコードとして出てきたか（例：C6 ／ Am7/C）
    seenAt: string;
  }[];
  // 出てきた所の一覧。重なりの判定（鍵）には使わない。画面には一番新しいものを出す。
  // 同じ鍵盤の音が別のコードとして出てきたら（C E G A が C6 と Am7/C）、両方をここに残す。
  // 将来「自分の型へ昇格」する時に、どのコードとして型にするかを選ぶのに使う（15章）。
}
interface ItemRecord {
  state: "new" | "provisional" | "passed" | "twelve-keys";
  wanted?: boolean;                                // ☆ 使いたい
  provisionalAt?: string; passedAt?: string; nextCheckAt?: string;
  recent: { at: string; ok: boolean; sec?: number; self?: boolean }[]; // 直近20
}
```

- 曲名・ファイル名・個人のパスは記録に入れない（進行は ID で持つ）。
- **型の鍵は「プリセット」と「自分の型」を分けて持つ**（`preset:` と `personal:`）。15章の「自分の型へ昇格」を後で足す時に、記録の形を移し替えずに済むようにする。Phase 12 では `personal:` を作らない。
- Vault から進行が消えたら、その記録は使わない（消さずに残し、30日後に片付ける）。

## 12. 受け入れ条件

1. Chord Dojo を開くと「今日の練習」と「始める」が出て、押すだけで練習が始まる。始める前に選ぶものは無い。
2. 今日の練習が、確認 → 型 → 登録した音 → 進行の順に出る。どこで止めても、同じ日に開けば続きから始まる。
3. 型の練習で、（新しい種類なら構成を知る →）① 見て弾く → ② 違う3つのキーで名前だけ、が進み、仮の合格が記録される。次の日以降に答えなしの確認として出る。
4. 判定が練習の種類で変わる（型：音名と並び、登録した音：同じ鍵盤、進行：構成とベース）。違った時は一言で知らせ、答えを見せて同じものをもう一度出す。和音を少しずらして弾いても、正しければ合いになる（待ち時間）。
5. 登録した音が、Phase 11 の出どころ（保存した音・元MIDI・カスタム）から選ばれる。
6. 進行で弾くが ① 見て → ② 覚えて（隠して頭から）→ ③ テンポで進み、②③ ではコード名が隠れている。外した所が何番目かと一緒に出る。保存した進行が無い時は組み込みの進行で出る。組み込みの進行の「今日のポイント」が、12キーすべてで実際の音で成り立つ（テスト）。
7. 答えなしの確認に、ときどき「構成を思い出す」（名前だけ見て構成の音を押す）が出る。同じ配置の登録した音は、出どころ・進行が違っても1つの練習として出る。
8. ☆ 使いたい を付けたものが、7日以上弾いていなければ今日の練習の確認に入る。おわりの画面に「今日、自分の語彙に増えたもの」が出る。
9. MIDI が無い時、答えを見て「弾けた／まだ」で進める。自分で判定した結果では、合格・12キー習得にならない。
10. 記録は `chord-dojo-v1.json` にあり、Vault の保存形式は変わらない。`block.practice` は読むだけ。
11. Voicing Loop・Bass Practice・ホーム・Vault の札が壊れていない（それぞれのテストがそのまま通る）。
12. fresh FULL と EXE が通る。

## 15. ロードマップ（Phase 12 の後）

Chord Dojo の核は、**曲から見つけた音を、自分の手の語彙として12キーで出せるようにする**ことにある。

```text
曲から見つける（取り込む・進行ページで直す）
  ↓
登録した音として覚える（Phase 12）
  ↓
「これ使える」☆ 使いたい（Phase 12）
  ↓
自分の型へ昇格（次）── ルートからの音程の並びとして保存
  ↓
別のキーでも出せる（次）── 型と同じ①②・12マス
  ↓
作曲中にすぐ使える
```

| 項目 | 中身 | 時期 |
| --- | --- | --- |
| **登録した音 → 自分の型へ昇格** | 登録した音を「ルートからの音程の並び（と最低音の扱い）」として保存し、型と同じように12キーで練習する。記録は `personal:` の鍵。同じ音が複数のコードとして出てきた時は、`occurrences.harmony` から「C6 として／Am7/C として」を選ぶ | Phase 12 の次（最優先） |
| 進行の別のキー | 自分の進行を度数で別のキーへ。合格した進行だけ | 後 |
| 次のコードは？（Progression Recall） | 進行の中の1つを見せ、次のコードを弾く／答える | 後 |
| 運指 | 現行Voicing Loop productionを再利用。①・Hint・回答で表示、②・③では非表示。判定に使わない | Phase12（2026-10-05変更） |
| 分数コード・オルタード | 型の種類を広げる | 後 |
