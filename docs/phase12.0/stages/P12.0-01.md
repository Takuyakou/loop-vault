## 区切り0：調べる（仕様 9章・3.1・3.4・5.2）

1. **部品の読み直し**：仕様 9章の表の部品が今どこにあり、何を前提にしているか。Phase 11 で変わった所。壊してはいけない所（Voicing Loop・Bass Practice・ホームの「今日の練習」・Vault と進行ページの札・`App.tsx` の `practiceMode` とサイドバー）が使う関数・コンポーネント。今の Chord Dojo を通るテスト（単体・E2E）の一覧。`progressionBag` が今日の練習の組み立てに使えるか。Bass Practice の `progressionPresets.ts` と仕様 3.4 の形の差。出どころとコードの情報（`occurrences.harmony` に要るルート・種類・ベース・名前）が取れるか。**私的な Vault の中身は読まない。**
2. **型の音の一覧表**：14種類（メジャー・マイナーの三和音、maj7・maj9・6/9・m7・m9・m6・7・9・13・7sus4・m7♭5・dim7）× 4プリセット × ベース2 を、今の生成の作り方で作る。キーは C と F#。鍵盤の図・下からの度数・レシピの軸への分類・元にした生成スタイルを HTML の表に（`p12-generated/P12.0-01/recipe-table.html`）。上の「決め方」で採った音に印を付ける。
3. **組み込みの進行の確認表**：仕様 3.4 の8つを、型の「基本」で前のコードに近い高さでつないで12キーで作り、`pointCheck` が成り立つかを表に（`p12-generated/P12.0-01/point-check.html`、鍵盤の図つき）。成り立たない所は (a)(b) のどちらにしたか。
4. **和音の音のずれ**：今の MIDI 入力の経路と note-on の時刻が取れる所、今の判定に待ち時間の仕組みがあるかとその値。**人間が測るための開発用の道具**を `scripts/p12/` に用意する：

   - 三和音・7th・9th を混ぜて30個出す。
   - 記録すること：最初の音から最後の音までのずれ（ミリ秒）、名前が出てから最後の音までの秒数。
   - 結果を JSON で保存し、中央値・90%点・最大を出す。開き方を報告に書く。
5. 区切り0の結果を報告の下書きに書き、commit（スクリプトと docs だけ。`src/` はまだ変えない）。

## 区切り1：記録と組み立て（仕様 3〜5・8章。画面なし）

`src/domain/chordDojo/`（新しい場所。名前は今のリポジトリの決まりに合わせてよい）に、React を使わずに作る。

1. **型の音の表**（データ）と、型の音を作る関数（鍵＝キー×レシピ×種類×ベース → MIDI の音）。
2. **組み込みの進行**（`BuiltinProgression` の8つ、`pointCheck` を含む）と、`pointCheck` を確かめる関数。
3. **記録ファイル** `chord-dojo-v1.json`：Bass Practice の `practice-v1.json` と同じ作り（版つき・Zod で検証・バックアップ20個・壊れていたらバックアップから戻す）。中身は仕様 8.2（`knownQualities`・`shapes`（`preset:`／`personal:` の鍵）・`voicings`（鍵は鍵盤の音、`occurrences.harmony` つき）・`progressions`・`today`・`settings`・☆）。
4. **状態の進み方**（仕様 4.2 の表を練習するものごとに）、**弱いキーの選び方**、**構成を思い出す**の間隔（7・30・90日）、**今日の練習の組み立て**（仕様 4.4：確認最大6・構成を思い出す1日1つ・☆の枠1つ・新しいもの2つまで・15分で減らす・最初の日はメジャー三和音・基本 → I–V–vi–IV・続きから）。
5. **判定の追加**（仕様 5.2）：上声部の並び・トップ・鍵盤の位置・構成の音名だけ（構成を知る／思い出す）・進行の③の長さの中で合うか。**和音の音がそろうのを待つ時間**を含む。今の `matchPerformance` の結果は変えない。
6. **登録した音の選び方**：Vault の進行から、出どころが保存した音・元MIDI・カスタムのコードを集め、**鍵盤の音が同じものを1つにまとめ**、`occurrences` に全部の出てきた所と `harmony` を残す。
7. テスト（単体）：
   - 型の音の表：14種類×4×2 で音が作れる（作らない組み合わせは「なし」と明示）。12キーで同じ形になる。
   - `pointCheck`：8進行×12キーで、(a) は成り立つ、(b) は `pointIsTheory` が付いている。
   - 記録：検証・往復・壊れたファイルからの復元・`personal:` の鍵を持てる。
   - 状態の進み方：型（3段）・登録した音（2段）・進行（②で仮の合格、次の日以降に③で合格）・自分で判定は仮の合格まで。
   - 今日の練習の組み立て：最初の日、確認が多い日、☆が7日以上の日、保存した進行が無い日、15分を超える日、同じ日に開き直した時の続き。
   - 判定：和音を 0〜待ち時間の範囲でずらして入れても合いになる、待ち時間の中の余分な音、構成の音名だけの判定、上声部の並び・トップ・音域の違いの知らせの文。
   - 重なり：同じ鍵盤の音が別の出どころ・別の進行・別のコード名で出ても1つ、`occurrences` に全部残る。

commit 例：`feat(chord-dojo): recipes, builtin progressions and point checks`、`feat(chord-dojo): practice store and today's plan`、`feat(chord-dojo): chord-entry settle and shape judging`。

## 区切り3：登録した音と進行（仕様 3.2・3.3・4.1）

1. 登録した音の練習（① → ②、元の音域、きびしい判定）。
2. 進行で弾く：① 見て弾く → ② 覚えて弾く（覚えた → 隠す → 合ったカードから名前、5秒で1枚だけ出す、出してもらったら前後をもう一度）→ ③ テンポで弾く（隠したまま、外した所を何番目かと一緒に）。自分の進行は元のキー、⚙ の「度数も出す」。組み込みの進行は層の順と「今日のポイント」1行。
3. 進行ページからの入口：その進行の「進行で弾く」を今日の練習の外で1回だけ。
4. テスト：
   - E2E：登録した音（同じ配置が2つの進行にあっても1つとして出る）、進行の ① → ② → 仮の合格、②で止まった時の名前の出方、③の結果、保存した進行が無い時の組み込みの進行、進行ページからの入口。
   - 単体：進行の8小節の区切り、`progressionFingerprint` が変わった時に「まだ」に戻る。

commit 例：`feat(chord-dojo): registered voicings and progression recall`。

### 人間が後でやること（報告に載せる）

1. EXE で Chord Dojo を開き、「始める」から今日の練習を最後まで（MIDI キーボードをつないで）。
2. `p12-generated/P12.0-01/recipe-table.html` を見て、型の音で直したい所を挙げる。
3. `point-check.html` を見て、「理論の上では：…」になった進行を確かめる。
4. 測る道具で30個弾く（約5分）。結果で待ち時間と速さの基準を決める。
5. 報告の「人間が後で見ること」の表を見る。

### 人間が EXE で確かめること（報告に載せる）

1. 開くと「今日の練習」と「始める」だけが目立ち、押すだけで始まる。
2. 初めての種類で「構成を知る」が出て、構成の音をどの高さで押しても進む。
3. ② で答えが隠れ、弾いた後に出る。和音を少しずらして弾いても、正しければ合いになる。
4. 途中で「やめる」→ 開き直すと続きから。
5. 進行の②で名前が隠れ、合ったカードから名前が出る。止まると1枚だけ出る。
6. MIDI を外すと「答えを見る → 弾けた／まだ」で進む。
7. おわりの画面に「今日、自分の語彙に増えたもの」が出て、☆ を付けられる。
8. Voicing Loop・Bass Practice・ホームは前と同じに動く。
