# Reports

段階の報告を置く。報告は日本語で書く。名前：`P12.3-01-dojo-progressions.md`。

書くこと：

1. **計画**（段階の最初に書く。承認は待たない）：始めた時の HEAD。
2. **仕様の 2〜12章**：各章を1行ずつ。
   - 満たしたか
   - 確かめたテスト名
   - 2・3章：期待データとの一致の数（300 組）。3章の直しで変わった組の数（41 のはず）
   - 5章：確かめた記録の値（`hints`・`answerSeen`・`matched`）
   - 10章：ランダムキーの前後で、Dojo の記録の文字列が同じだったこと
3. **仕様と違うことをした所**（あれば）：違い／理由／別案。
4. **変えたファイルと commit の一覧。**
5. **直した今の E2E の行と理由。**
6. **書き換えた基準画像と理由**（Chord Dojo の練習画面の分だけのはず）。
7. **ゲートの結果**：Test DX の要約行をそのまま貼る。commit hash も書く。
8. **スクリーンショットの場所**：パスを文字で書く（`/` 区切り）。
9. **判断ポイント**：選んだこと／理由／別案を1〜2行ずつ。
10. **人間が EXE で確かめること**
    - 実際の MIDI キーボードで、カードを押した音と鍵盤の表示
    - 度数の表示
    - 定番の進行の一覧（25・まとまり・キーを変えた時）
    - ランダムキー：
      - 1巡（12キー）
      - コードの間で押したままの音がある時
      - ヒント・とばす・やめた時のまとめ
      - USB の抜き差し
    - キー A などで、答えのとおりに弾いて合うこと（3章）
11. **レビューで見てほしい所**（3〜5点）。

報告に書かないもの：

- 私的な MIDI・Vault の中身
- 端末の ID
- 個人の絶対パス
- `.local-evaluation` の中身
