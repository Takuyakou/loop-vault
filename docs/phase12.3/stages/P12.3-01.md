## 迷った時の決め方

1. 仕様とモックが食い違う時は、仕様を正とする。
2. 仕様に無い細かい見た目は、今の `chord-dojo.css` の近い部品（`.dojo-chord-cards`・`.dojo-card`・`.dojo-result`）に合わせる。
3. 定番の進行の音で迷った時は、期待データを正とする。期待データと合わない時は、自分のコードを直す（期待データを書き換えない）。
4. 記録に関わる所で迷った時は、「記録を変えない」「秒数を数えない」の側を選ぶ。報告の「仕様と違うことをした所」に書く。
5. ランダムキーで迷った時は、「練習を止めない（次のキーへ進む）」「保存しない」の側を選ぶ。
6. 止まるのは、`P10-autonomous-run.md` の3章の条件に当たった時だけ。

## 区切り A — 定番の進行のデータとベースの直し（仕様 2・3）

主に触る所：`src/domain/chordDojo/builtins.ts`・`planner.ts`（テーマ名とキーの名前だけ）。

1. **テストを先に書く。** `src/domain/chordDojo/builtins.p12-3.test.ts` を作る。
   - 期待データを読み、25 × 12 キーの `buildBuiltin(id,k)` と比べる。比べる値：
     - `chord.label`
     - `notes`
     - `beats`
     - `pointIsTheory`
     - `keyLabel`
   - すべてのコードで、次を確かめる。
     - ベースが上の音より下
     - 同じ音が無い
     - 答えのとおりに弾けば `judgeChord` が合う
   - 落ちることを確かめる（今は 8つしか無く、ベースの不具合もある）。
2. **仕様 2：** `DEFS`・`BuiltinDef`・`BUILTINS`・`keyLabel`・`BUILTIN_GROUPS` を、付録 A・B のとおりに書く。`buildBuiltin` は `DEFS` を見る形にする。
3. **仕様 3：** `placeBassBelow` を足し、`rotations` で通す。
4. 1 のテストと、今の `chordDojo.test.ts` を通す。
5. **仕様 2 のテーマ名とキーの名前：** `planner.ts` の候補作りで、次の2つを変える。
   - `title` がある進行の `source.name`
   - `mode==='minor'` の進行の `source.keyContext`
   - 単体テストで確かめる。初めての人の最初のテーマが `I–V–vi–IV` のままであることも確かめる。
6. テストを回す。
   - `npm run test:fast`・`npm run test:feature`
   - 今の Chord Dojo の E2E（`p12-chord-dojo`・`p12-1-dojo-ui`・`p12-dojo-*`・`p12-theme-score`・`p12-vertical-layout`）
7. 記録して commit：`feat(chord-dojo): P12.3 25 standard progressions and bass-below fix`。
   - `gateResults.p12.3-01-builtins`
   - 報告の 2

## 区切り B — カードで鳴らす・度数（仕様 5・6・7）

主に触る所：`src/views/chord-dojo/ChordDojoView.tsx`・`chord-dojo.css`。

1. **仕様 2：** 定番の進行の名前を出す所を `builtinDisplayName` にする（中央の見出しと度数の下の行・課題の名前・終わりの画面・`session.ts`）。
2. **仕様 5：** 進行のカードをボタンにする。`GrandStaff` に `caption`・`hiddenText` を足す（Master は渡さない）。
   - `aria-label`
   - 鳴らす
   - `data-playing`
   - 鳴っている間の鍵盤と譜面
   - 段ごとの扱い（`hints`・`answerSeen`・テンポ中は押せない）
3. **仕様 6：** 1コードの練習の `div.dojo-prompt-card` と `button.dojo-prompt-play`。`h1.dojo-prompt` は今のまま（見出しの読み上げ名を変えない）。`p12-1-dojo-ui` の中央そろえのテストを変えずに通す。
4. **仕様 7：** 「度数も出す」を消し、名前が見えているカードに度数をいつも出す。「キー未設定」は出さない。
5. `e2e/p12-3-dojo.spec.ts` に、仕様 3・5・6・7章の E2E を書いて通す。
   - 音の数え方は、`p12-master251-audition.spec.ts` の `AudioBufferSourceNode.prototype.start` を数えるやり方を使う。
6. 今の Chord Dojo の E2E を回す。
   - 直してよいのは、仕様 21章で許した所だけ（`.dojo-chord-cards>div` → `>button` など）。

7. 記録して commit：`feat(chord-dojo): P12.3 playable chord cards and always-on degrees`。
   - `gateResults.p12.3-01-cards`

## 区切り C — 一覧とランダムキー（仕様 4・8〜12）

1. **仕様 4：** 定番の進行の一覧を作る。
   - 上の行
   - まとまりへ移るボタン
   - まとまり
   - カード（度数・キーでのコード名・3つのボタン）
2. **仕様 8〜10 の中身：** `src/domain/chordDojo/endless.ts` を、単体テストを先に書いてから作る。
   - 状態：`createKeyBag`・`startEndless`・`revealChord`・`matchChord`・`skipKey`・`nextKey`・`summarize`
   - テストで確かめること：
     - 袋に 12 キーが1つずつ入る
     - 巡の変わり目に同じキーが続かない（1000 シード）
     - 同じシードなら同じ順番
     - 集計の数
3. **仕様 8〜11 の画面：** `src/views/chord-dojo/ChordDojoEndlessView.tsx`（新しい部品）を作る。
   - `ChordDojoView` は `screen==='endless'` の時、Master と同じ所で早く return してこの部品だけを出す。
   - `ChordDojoView` のキー操作は `endless` の時に何もしない。キー操作と `useDojoMidi(true, 鳴らしている間)` はこの部品が持つ。
   - 上の帯・キー・カード・結果の1行・ボタン・このセッションの記録・譜面・鍵盤
   - 判定は、今押している全部の音（`heldNotes`）で、Note On・Note Off のたびに行う。押さえ直さなくてよい。`ChordEntry` は使わない（`judgeChord`・`requiredCount` だけ使う）。
   - ヒント・クリアの札・次のキー（600ms 以上たち、かつ全部離れたら）・とばす
   - 集計とまとめ。保存しない。
   - 自分で判定・外れた時（P14 仕様 5.1）・キー操作・入力の音
4. **仕様 12：** 文言を、表のとおりにそろえる。
5. 仕様 4・8〜11章の E2E を `e2e/p12-3-dojo.spec.ts` に書いて通す。
   - キーは `data-endless-key` から読む。
   - 音はテストの中で `buildBuiltin(id, key)` から作る。
6. テストを回す。
   - `test:fast`・`test:feature`
   - 今の Chord Dojo・Master・`p14-midi-connection` の E2E
7. 記録して commit：`feat(chord-dojo): P12.3 grouped standard list and random-key endless practice`。
   - `gateResults.p12.3-01-list`
   - `gateResults.p12.3-01-endless`
