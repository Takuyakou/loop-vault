### 区切り A で作ったもの

- `src/liveMidi/connectionView.ts`：`selectMidiConnection(store の状態, controller の状態)`。仕様 3章の表の 9 行を、意図 off を一番先に判定して作る（R1）。`lost` は `lastConnected` がある時だけ。単体テスト 12 件（表 9 行・起動直後に `lost` にならない・`error` より `off` が勝つ・`connected`/`busy` の値）。
- `src/liveMidi/connectionController.ts`：入口の開け閉めをするのはここだけ。意図（on/off）・`lastConnected`・自動接続・世代番号を持つ。
  - 接続にかかわる操作（`connect`・`disconnect`・`retry`・`chooseDevice`・自動接続・自動で戻る・接続テスト・終了）のたびに世代番号を 1 増やし、整理の処理（reconcile）を頼む。**同時に動く処理は 1 つだけ**。処理中に新しい頼みが来たら、終わった後にもう一周する（`dirty`）。
  - つないでいる途中の切断は、開く処理が終わるのを待ってから閉じる。入口が閉じる回数はちょうど 1 回（E2E 7）。古い結果で `selected`・`status`・前回の機器・保存した機器を書き換えない。A につなぎ中に B を選ぶと、B を即保存し、A の結果は保存しない（E2E 8）。
  - 起動時：自動接続が ON なら意図 on で前回の機器につなぐ。OFF なら入口を開かず、機器の一覧と前回の機器だけ読む。2 回呼んでも 1 回だけ（StrictMode・複数の窓）。
  - エラーの後は自動で試さない（`retry`・機器の選び直しだけ）。機器が外れた後、同じ機器が戻ると自動でつなぐ。
  - 手動の切断は保存しない。次の起動は自動接続の設定に従う（R5）。自動接続の設定は新しいキー `loop-vault:live-midi-connection:v1`（strict の zod。壊れた値・無い時は `true`）。
- `src/liveMidi/liveMidiStore.ts`（足しただけ。既定の動きは同じ）：`activate({ autoSelect: false })` と `selectDevice(id, { persist: false })`。controller が「今の世代の結果だけ」を保存するため。`liveMidiService.ts`・`bridge.ts`・`src-tauri`・`domain/liveMidi`・プリファレンスの形は変えていない。
- `src/liveMidi/useMidiConnection.ts`：画面が状態を読む唯一の入口（hook）。
- 単体テスト `connectionController.test.ts`（15 件。本物の `LiveMidiService` を偽の bridge で動かす）：起動・自動で戻る・エラーの後は試さない・保存の値・手動の切断・世代の競合 3 種・同時に動く処理は 1 つ・接続テスト。

## 3. 仕様と違うことをした所

- **commit の順序**：指示書は区切り A に E2E 1〜9 を置くが、1〜9 は上部のパネルを操作する（仕様 2章「上部のパネルで切断」）。パネルは区切り B なので、E2E は区切り B の commit（`d4a073eb`）で入れた。区切り A の commit（`fbb3454c`）は単体テストと既存のテストで確かめた。ゲート `p14.0-01-controller`・`p14.0-01-race` は、区切り B の後に E2E 1〜9 が PASS してから `pass` にした。
- **パネルの説明文**：仕様 4章が説明を決めているのは `connected`・`lost`・`error` だけ。`off`・`connecting`・`searching`・`missing`・`no-device`・`choose` は、モックと同じ調子で短く足した（例：`off`「『接続』を押すと、選んだ機器につなぎます」）。3章の「表に無い文言は足さない」は上部のボタンの文字と見出しのことと読んだ。別案：説明を出さない。
- **`MidiRequiredNotice` の見出し**：`off`・`no-device` は今までと同じ「MIDI キーボードがつながっていません」（今の E2E の文言を変えないため）。Master だけ「MIDI キーボードをつないでください」を残した。
- **`monitorMidi` の prop を削除**：Voicing Loop は入口を開かなくなったので、意味が無くなった（呼び出す所は無かった）。
- **`liveMidiActivation`（リース管理）のファイルは残した**：使う所は無くなったが、`LiveMidiOpenGate` が同じファイルにあり、ミニモードで使っている。消すかどうかは次の整理で決めてよい。
- **練習の開始時に「busy」**：Chord Dojo は、練習を始める時に `connecting`／`searching` なら、自分で判定する形にせず、つながるのを待つ（仕様 5章「`connected` でなく `busy` でもない時に自分で判定」の裏返し）。

## 10. 判断ポイント

- **開き方（R: 迷った時）**：「開いたままにする」と「エラーの後は自動で試さない」を選んだ。画面を移っても閉じない。別案：画面ごとに開閉（今まで）。
- **切断と世代**：切断が頼まれたら、つないでいる途中の入口は「開き終わるのを待って閉じる」。開いている途中で閉じにいくと、`liveMidiService` の「古い open が新しい接続を閉じる」動きと衝突するため（`liveMidiService` は変えない決まり）。別案：すぐ閉じる。
- **保存**：選んだ機器は選んだ時に保存し、古い接続の結果は保存しない（`persist: false` を足した）。別案：成功した時に保存（今まで）だと、A の結果が B の保存を上書きできた。
- **Voicing Loop の再接続**：「再接続」を「MIDI 設定」に一本化し、中身は `retry` ではなくパネルの「もう一度試す」。別案：「再接続」を残す。
- **設定の接続テスト**：`connected`・`connecting` の間は出さない（`controller.testDevice` は入口を一度止めて、終わったら戻す）。
- **練習を始める時に busy**：待つ（上の 3 章）。

## 11. 人間が EXE で確かめること

EXE：`src-tauri/target/release/loop-vault.exe`（この worktree。`npm run tauri build -- --no-bundle`）。

1. 実際の MIDI キーボードで、起動したら自動でつながり、上部が機器名になる。
2. ホーム・Vault・Chord Dojo・2-5-1 Master・Bass Practice・Voicing Loop・設定と移っても、上部が機器名のまま。Dojo で弾くと音が出る（ほかの画面では出ない）。
3. USB を抜くと「〜が外れました」になり、挿し直すと自動で戻る。
4. 練習（Chord Dojo・Master）の途中で USB を抜くと止まり、案内が出る。挿し直して鍵盤を離すと、同じ課題から続く。「自分で判定に切り替える」は押した時だけ。
5. 上部のパネルで「切断」すると自動でつながない（同じ起動の間）。アプリを開き直すと、また自動でつながる。「起動した時に自動でつなぐ」を OFF にすると、開き直しても「MIDI に接続」のまま。
6. Live MIDI（ミニ表示）を開いて閉じても切れない。ミニ表示の状態が上部と同じ。
7. 他のアプリが機器を使っている時、「MIDI エラー」になり、勝手に試し続けない。「もう一度試す」で試す。
