## 迷った時の決め方

1. 仕様とモックが食い違う時は、仕様を正とする。
2. 入口（ポート）の開け閉めで迷った時は、次の2つを選ぶ。
   - 「開いたままにする（画面の移動で閉じない）」
   - 「エラーの後は自動で試さない」
3. 状態の文言で迷った時は、仕様 3章の表を使う。表に無い文言は足さない。
4. 練習の途中で外れた時に迷ったら、「止めて待つ」「記録しない」「自分で判定に切り替えない」の側を選ぶ（仕様 5.1）。
5. 非同期の結果をどう扱うか迷ったら、「今の世代番号と違えば捨てる」「意図 off の間は入口を開いたままにしない」を選ぶ（仕様 2.1）。
6. 止まるのは、`P10-autonomous-run.md` の3章の条件に当たった時だけ。

## 区切り A — 接続の持ち主と状態（仕様 2・2.1・3）

1. 今の入口の開け閉めを洗い出して、報告の 5 に表にする。
   - `liveMidiActivation.acquire`
   - `activate()`・`deactivate()`
   - `selectDevice`（自動で選び直す所）
2. 仕様 3章の `selectMidiConnection` を、単体テストを先に書いてから作る。
   - 表の 9 行を確かめる。
   - 判定の順（意図 off が一番先）と、`lost` は `lastConnected` がある時だけ（R1）。
   - 起動直後に `lost` にならないこと。`error` より `off` が勝つこと。
3. 仕様 2章の `connectionController` を、単体テストを先に書いてから作る。テストで確かめること：
   - 意図
   - 起動時
   - 自動で戻る
   - エラーの後は試さない
   - 自動接続の保存（新しいキー、壊れた値は `true`）
   - 手動の切断は保存しない。次の起動は自動接続の設定に従う（R5）
   - 世代番号（仕様 2.1・R2）：
     - 古い結果を捨てる（`selected`・`status`・前回の機器を書き換えない）
     - 切断の後に開いた入口は閉じる
     - A の途中で B を選ぶと B で終わる
     - 同時に動く接続の処理は1つまで
4. App の起動で `initOnAppStart()` を呼ぶ。
5. 各画面のリースと `activate`・`deactivate` の呼び出しを外す。
   - 対象：`ChordDojoView`・`ProgressionVoicingPracticeView`・`VoicingPanel`・App の Live MIDI ミニモード
   - `useDojoMidi` の「前回の機器を選び直す」処理は、controller へ移す。
6. 合成の入力（`p12DojoFixture.ts`）の `connect`・`disconnect` を、controller 経由にする。
7. テストを回す。
   - `npm run test:fast`・`npm run test:feature`
   - 仕様 2章の E2E（1〜6）を `e2e/p14-midi-connection.spec.ts` に書いて通す。
   - 仕様 2.1 の競合の E2E（7〜9）を書いて通す。それぞれ 3 回続けて回し、3 回とも PASS にする（`--repeat-each=3`）。
8. 記録して commit：`feat(live-midi): P14 app-wide MIDI connection and shared state`。
   - `gateResults.p14.0-01-controller`
   - `gateResults.p14.0-01-race`
   - 報告の 2・5
