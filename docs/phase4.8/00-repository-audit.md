# Phase 4.8-00 Repository Audit

## Product candidate generation

- Product chord templates are defined in `src/domain/midi/legacy.ts`.
- `dom7` is a whole-quality template. Altered `b9` is not generated by the template list.
- Raw diagnostics expose all window candidates before Product quick-alternative allocation through `diagnoseLegacyWindowCandidates()`.
- Product Top-3 is derived after canonical dedup and `selectQuickChordAlternatives()`.
- Product confidence is clamped for display while `rawScore` remains available to evaluation.

## Canonical identity

- `A7b9` and `A7(b9)` parse as `dom7 + tensions:["b9"]`.
- Unicode `A7♭9` is normalized to ASCII at the Phase 4.8 Shadow/Gold input boundary. Product parser is unchanged.
- Canonical display is `A7(b9)`.
- `ChordSymbol`, `NormalizedChordIdentity` and `FactorizedChordIdentity` already represent `major + minor7 + b9` without adding a new quality.
- Root-position bass is omitted canonically; a non-root bass remains a slash identity.

## Frozen scope

- Candidate Generation is the only intervention variable.
- Root, quality, tension score, confidence, tie-break, Top-3 allocation, Analyzer mode and schema are frozen.
- Shadow candidates remain under `scripts/phase48` and cannot reach Product, UI or Vault.
- Existing Phase 4.5/4.6 reports are regression evidence only.
