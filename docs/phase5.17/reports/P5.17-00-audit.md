## Key architecture decisions (see contracts)

- **Recorder is a separate state machine** parallel to the session reducer; a
  recording failure disables only recording and never abandons the session.
- **Binary take store separate from the Vault-adjacent Practice JSON:** extend
  Tauri practice storage with a dedicated `loopvault/recordings/` binary store
  (new atomic Rust commands) and back the same `RecordingTakeRepository` with
  IndexedDB in the browser; no base64 in Practice JSON, no Blob in
  `localStorage`, no new Tauri plugin.
- **Independent feature flag** `enableBassPracticeRecordCompare`
  (`loop-vault:bass-practice-record-compare-enabled:v1`), default `true` at
  release, local `false` rollback, independent of the three Echo flags.
- **Capability/codec probed at runtime, not hard-coded**; capture behind
  `RecordingCapability` / `CaptureDeviceRepository` / `PracticeRecorder` /
  `RecordingSessionController` / `RecordingTakeRepository` with fakes.

## Open risk carried into later stages

- **WebView2 microphone permission.** No native permission handler exists in
  `lib.rs`; `getUserMedia` may be denied in a production Tauri build. Must be
  verified on a real release build in P5.17-01/04; if unresolvable, stop with
  `BLOCKED — required recording capability unavailable in target runtime`. A
  Web/Playwright pass does not prove Tauri works.
