# P5.17-01 — Capture Foundation

## Determination

**Stage complete.** The recording capture stack exists behind the feature flag,
fully unit-tested on deterministic fakes, with the real browser adapters
typechecked. No 3-mode integration yet (that is P5.17-02); the only UI is an
unrouted diagnostic harness, so existing routes, E2E and visual snapshots are
untouched.

## What was built

All under `src/features/bass-practice/recording/`:

- **domain/**
  - `types.ts` — channel mode, permission, device, take metadata (non-identifying), error codes, codec choice.
  - `recorderStateMachine.ts` — the explicit recorder machine (brief §12): 18 states, validated transitions, forbidden transitions, frozen state and typed results. Survives double-start/stop, stop-immediately-after-start, cancel-during-count-in, device disconnect, permission revocation, recorder/blob error, retake/discard, save failure. Separate from the session reducer.
  - `levelMeter.ts` — pure RMS/peak/clip + meter segments (color-independent alternative).
  - `codecNegotiation.ts` — `isTypeSupported`-driven preference negotiation; no hard-coded codec; considered order reported.
  - `channelRouting.ts` — explicit channel mapping and confident-only Auto (declines on silence/ambiguity so the UI re-picks).
- **application/**
  - `ports.ts` — `RecordingCapability`, `CaptureDeviceRepository`, `PracticeRecorder`, `RecordingTakeRepository`.
  - `fakes.ts` — deterministic fakes with usage/leak accounting.
  - `browserAdapters.ts` — real WebView2/Chromium adapters. Capture graph routes the chosen channel to mono via splitter/merger into a `MediaStreamDestination`; the meter `AnalyserNode` and the graph never connect to speakers (no monitoring). `dispose()` stops tracks, disconnects nodes, closes the context, clears the recorder — idempotent.
  - `recordingSessionController.ts` — orchestrates the machine + ports; disposes recorder resources on retake/discard/error/dispose; keep() persists or, on failure, keeps the ephemeral take playable.
  - `createController.ts` — production wiring (in-memory take store is a placeholder until the P5.17-03 binary store).
- **ui/** `RecordingDiagnosticsPanel.tsx` — flag-gated, unrouted harness with an ARIA-live status and no scoring language; disposes on unmount.
- Feature flag `enableBassPracticeRecordCompare`
  (`loop-vault:bass-practice-record-compare-enabled:v1`), default `true`,
  independent local `false` rollback (`application/featureFlag.ts`).

## Contracts honoured

- No `navigator.mediaDevices` / `MediaRecorder` in the UI — only via ports (contract 04).
- Recording is a separate machine; failure never abandons the session (contract 04).
- No analysis/scoring; level values are display-only, never saved (contract 03).
- Take metadata is non-identifying; no audio in Practice JSON (contract 02).

## Open risk (unchanged, deferred)

Tauri build (P5.17-04); `lib.rs` has no permission handler yet. Not blocking for
this stage — no runtime Tauri gate is required until P5.17-04/05.
