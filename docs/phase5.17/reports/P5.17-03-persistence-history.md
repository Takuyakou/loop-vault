# P5.17-03 — Persistence / History

## Determination

**Stage complete.** Kept takes now persist in a Vault-independent, binary-safe
store with quota, non-identifying metadata, playback, delete, corruption/orphan
handling and privacy statements — verified by unit tests and a fake-media E2E
that survives a page reload.

## Key decision (contract 02 refined)

**IndexedDB is the single binary take store for both runtimes.** It is
binary-safe and persists across restarts in browsers and in Tauri WebView2
(under the app's user-data dir), so no Rust `recordings/` file store is needed.
This keeps audio out of the Vault-adjacent `practice-v1.json`, touches no Vault
schema, and adds no Tauri plugin, dependency, or capability. The earlier
Rust-store option is superseded and documented in the storage contract.

## What was built

- `recording/domain/persistence.ts` — schema version, per-take duration cap
  (`MAX_TAKE_DURATION_MS = 60s`), total quota (`TOTAL_QUOTA_BYTES = 200 MiB`),
  `canKeepTake` (never proposes auto-deletion), `isReadableMetadata` (rejects
  corrupt / future-version), `detectOrphans`.
- `recording/application/recordingStore.ts` — `RecordingStore` port,
  `InMemoryRecordingStore` fake, and `PersistentRecordingTakeRepository`
  (opaque ids, quota-checked keep, non-identifying metadata, corruption-skipping
  reads, missing-binary → unavailable, `cleanupOrphans`, `usedBytes`).
- `recording/application/indexedDbRecordingStore.ts` — thin IndexedDB adapter.
- `createController.ts` — runtime repository selector (IndexedDB, in-memory
  fallback); Keep Take now persists for real.
- `recording/ui/RetainedTakesPanel.tsx` — lists kept takes with honest facts
  (mode, date, duration, size, channel, played-back-before-review), capacity,
  play, and confirm-then-delete; shows "Recording unavailable" for a missing
  binary and stays deletable; renders nothing when empty (additive). Surfaced in
  the Record & Compare area (opt-in and review), so retained takes are viewable
  and deletable without re-requesting permission.
- `KeepContext` threaded from the section through the controller so metadata is
  non-identifying (opaque session id, exercise signature, mode, generic input
  name) — never a raw device id or path.

## Contract coverage

Ephemeral default (P5.17-02) · Keep Take only on explicit action · binary store
separate from the Vault · opaque id · versioned · deletable · bounded quota with
**no auto-delete** (over-quota keep fails, ephemeral take stays playable) ·
non-identifying metadata · corruption resilience · orphan detection/cleanup ·
"Recording unavailable" · privacy statements (local-only, no analysis/score,
feature-OFF never deletes saved takes).
