# P5.17-04 — Product Hardening

## Determination

**App-side hardening complete.** Every failure path, accessibility, viewport,
resource, build-identity and History item is implemented and verified. The one
runtime item that genuinely needs the target machine — the WebView2 microphone
permission handler — is routed to P5.17-05 hardware acceptance (the app degrades
gracefully without it).

## What was hardened

- **Unsupported codec** folded into the capability probe
  (`BrowserRecordingCapability`): when no `MediaRecorder` codec is supported the
  feature reports unavailable and disables, instead of failing at record time.
- **Failure paths** covered by tests: permission-denied, no-device (→
  device-missing, recoverable), device-disconnect (→ error mid-capture),
  storage-denial / quota-exceeded (keep fails, ephemeral take stays playable),
  route-leave (dispose), and a **resource benchmark** — 20× start/stop + retake,
  deny/retry, disconnect, then teardown — asserting zero retained recorder /
  active capture (`FakePracticeRecorder.leaked === false`).
- **Accessibility**: a fake-media Playwright test runs axe (WCAG 2 A/AA) scoped
  to the Record & Compare section with zero violations; the section uses
  ARIA-live status, labelled controls, and a confirm-then-delete for destructive
  actions.
- **Viewport**: a 320px-width Playwright test keeps the primary controls visible
  with no horizontal overflow.
- **Resource leak**: the benchmark above plus the existing dispose/retake tests.
- **Build identity**: unchanged — Settings → About already exposes app version,
  build commit and build date (P5.16).
- **Tauri compile smoke**: `cargo build` passes (Rust unchanged; 41 tests still
  green from the P5.17-00 baseline).
- **History integration**: the retained-takes panel is now folded into the
  Practice History tab (additive; renders nothing when empty, so `history.png`
  is unchanged).

## Routed to P5.17-05 (hardware acceptance)

- **WebView2 microphone-permission handler** — production Tauri runs in WebView2,
  which denies `getUserMedia` unless the host handles the permission request.
  This is native COM (`ICoreWebView2.add_PermissionRequested`) that can only be
  developed and verified against a real WebView2 runtime on the target Windows
  machine — i.e. the hardware-acceptance context. Until then the capability probe
  and permission-denied handling degrade gracefully: Record & Compare shows
  "recording unavailable / permission denied" and Bass Practice stays fully
  usable. This is the single blocking item for the feature to record in a
  production desktop build; it is the first task of P5.17-05 on hardware.
- **Full Tauri release build + direct-executable / NSIS / MSI smoke** — the
  Product Acceptance build of §24, produced in P5.17-05.
- **reduced-motion** — no animated level meter is wired yet; when live metering
  is added it must honour reduced-motion.
