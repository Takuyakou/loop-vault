## WebView2 microphone handler

`src-tauri/src/media_permission.rs` installs a WebView2 `PermissionRequested`
handler that auto-allows the microphone permission (the web layer only calls
`getUserMedia` after the user enables recording). It is written defensively:
every failure is ignored, so the worst case is no handler installed → the web
layer's permission-denied path → Bass Practice stays usable. It compiles, the
release build embeds it, and the executable launches without crashing.
**Runtime microphone capture is verified during hardware acceptance** — that is
the one behaviour this environment cannot exercise.

## Human hardware acceptance checklist (§25)

Run on the target Windows machine with a MOTU M4:

1. Select MOTU M4 as the input device.
2. Select the input channel the bass is plugged into.
3. Confirm the input meter responds.
4. Confirm it does not clip.
5. Record in Degree Echo.
6. Compare Target and My Take (never simultaneous).
7. Retake.
8. Record in Rhythm Echo.
9. Record in Bassline Echo.
10. Keep Take.
11. Restart the app.
12. Play the take back from History.
13. Delete the saved take.
14. Change tab while recording.
15. Stop while recording.
16. Confirm there is no stuck output sound.
17. Confirm the stream is released.
18. Confirm the Vault is unchanged.

If microphone capture does not work in the production build, the first suspect
is the WebView2 permission handler; iterate on `media_permission.rs` against the
real WebView2 runtime.
