## Record & Compare

- Reused the existing P5.17 `RecordCompareSection`, `RecordingSessionController`, capture permission flow, channel settings, `TargetPlayer`/`TakePlayer`, and IndexedDB take repository.
- Added optional hooks around the existing recording lifecycle. Bassline Echo first prepares its driver/sample without scheduling sound; only after preparation succeeds can count-in/capture start, and only after the recorder returns the actual recording state does the prepared accompaniment schedule at that boundary. A preparation or recorder failure, permission/device failure, cancel, stop, retake, discard, route cleanup, or unmount releases the prepared/live accompaniment and activity state. Generation cancellation protects a fast Stop while preparation, getUserMedia, or recorder start is still pending: a late resource is immediately stopped/disposed and cannot re-enter recording.
- The Review flow exposes exactly two record-accompaniment choices: Chords only and Chords + Metronome.
- The UI gives factual optional headphones guidance and states that app audio is never internally mixed into the captured take. It adds no app-side live input monitoring, second recorder, take store, binary store, or automatic analysis/scoring.
- Target and My Take preserve the P5.17 exclusive playback behavior. Their playback-start callback stops Chord Context accompaniment before target/take playback. Count-in and live capture notify Bassline Echo so source, tempo, layer, record-mode, and History-save controls are locked until the recorder returns to a safe state.
- Keeping a take exposes only the existing opaque retained-take id to the factual History record. No audio bytes, device data, path, or capture details are copied into Practice History. Kept-take metadata uses a stable Bassline/Chord Context session id, not the Degree Echo session id.

## Tempo

- Chord Context displays its immutable original BPM plus a session-only effective BPM.
- The manual effective BPM is clamped to 30-240 BPM. The +4 BPM and Use original controls use the same clamp and stop active preview/context playback before changing timing.
- Chord Context playback, legacy target preview, Record & Compare count-in, and target playback all use the effective BPM.
- The snapshot/Vault BPM is never written or mutated.

## History

- Added a strict versioned factual `chordContextHistory` collection to the existing independent Practice document. This is not a Vault schema or P5.17 RecordingTake schema change.
- Each record keeps only source kind/safe logical reference, snapshot signature, section bounds, original/effective BPM, selected Listen/Play modes, actual metronome activity, Record & Compare use, and an optional opaque retained-take reference. The metronomeUsed fact is true only when the playback engine successfully schedules metronome events; selecting a mode or failing preparation/playback remains false. Settings are frozen only after capture succeeds; changing BPM, layers, source, or record mode invalidates stale capture facts and retained-take references.
- The strict schema rejects unknown fields. The controller persists through the existing atomic Practice repository queue. A successfully recorded but unkept take disables History save until it is explicitly kept, discarded, or retaken. A review has one stable History id; after Keep, exactly one History save may attach the opaque id. BPM, Listen layer, Play layer, record mode, and snapshot changes reset the Record & Compare controller and clear stale facts/references before a new save.
- History rendering uses the stored factual snapshot rather than resolving the live Vault source, so edited or deleted source progressions remain safely visible.
