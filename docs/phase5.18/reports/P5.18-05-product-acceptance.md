The first product check found that Rhythm Echo and Bassline Echo remained in
English while the application language was Japanese. The cause was that
`App` did not pass the selected language through `BassPracticeModeView` to the
Rhythm and Bassline surfaces; both views therefore rendered their English
defaults. Commit `b4049b7` wires the selected language through and localizes
headings, descriptions, field labels, radio options, actions, status messages,
review copy, factual History copy, and accessible names. Product names

weakening their behavior assertions. The refreshed full Playwright run passed

## Source and section contract

- Vault input crosses into Practice only as a detached, immutable, versioned
  snapshot with a canonical signature and safe logical references.
- No source path, MIDI body, source asset metadata, or personal identifier
  crosses the boundary.
- Only complete one- or two-bar sections in explicit 4/4 are selectable. Chord
  boundaries are preserved; content is not clipped or silently substituted.
- A new session uses the latest source. A missing/deleted source cannot start a
  new session. Existing factual History remains renderable without re-reading
  or mutating Vault data.
- Generated Bassline remains supported separately and unchanged.

## Playback architecture, voicing, and mix

- Chord Context uses an isolated Bass Practice Tone driver and deterministic
  playback-plan boundary; it does not reuse the shared Chord Preview singleton.
- Finger Bass, chord accompaniment, and metronome route through the existing
  global master-volume path. Chord Dojo, Vault preview, and Live MIDI remain
  independent.
- Chord voicings use chord tones only in MIDI 57–76. Target bass remains in
  MIDI 28–55. Slash bass affects deterministic upper-structure placement but
  never adds a low accompaniment root.
- Default relative mix: target bass `0 dB`, chords `-12 dB`, metronome `-9 dB`.
- Listen modes: Bass only; Chords only; Bass + Chords (default); Bass + Chords
  + Metronome.
- Play modes: Chords only (default); Chords + Metronome; Metronome only; No
  accompaniment. Play never schedules the target bass, and No accompaniment
  allocates no playback player.
- Replay, mode/layer changes, natural completion, errors, Stop, Review, route
  leave, tab leave, and unmount stop/dispose owned resources. Legacy Bassline
  preview and Chord Context cannot overlap.

## Tempo, Record & Compare, and factual History

- Original BPM remains immutable. Session-effective BPM is manually clamped to
  30–240; `+4 BPM` is explicit and stops at 240. Vault BPM is never changed.
- Existing P5.17 Record & Compare infrastructure is reused. Accompaniment is
  prepared before capture and scheduled only after capture reaches its actual
  recording boundary. Failure/cancel/late-start paths release recorder and
  accompaniment resources.
- Recording choices are Chords only and Chords + Metronome. Headphones are
  recommended; application audio is never internally mixed into the captured
  take, and no live monitor or automatic scoring was added.
- History stores facts only: safe source reference/label, snapshot signature,
  section, original/effective BPM, selected modes, actual metronome activity,
  Record & Compare use, and an optional opaque retained-take reference.
- Unkept captures cannot be attached to History. BPM/source/mode changes clear
  stale capture facts. One review produces at most one factual History record.

## Feature flag and accessibility

- `enableBassPracticeChordContext` production default: `true`.
- Explicit local value `false`: tested non-destructive rollback; Bassline Echo
  remains available and existing History is not deleted.
- The flag is independent of Degree, Rhythm, Bassline, and Record & Compare
  flags and is not stored in Vault schema.
- Automated checks cover keyboard operation, labelled radio groups, status
  announcements, no horizontal overflow at 320 px, effective 200% scaling,
  and computed reduced-motion transition/animation suppression.
- The 200% automated check uses deterministic CSS zoom at a 640 px viewport to
  create an effective 320 px layout; native OS/browser scaling remains part of
  human hardware acceptance.
