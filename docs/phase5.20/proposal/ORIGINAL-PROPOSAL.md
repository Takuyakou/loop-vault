# Loop Vault 提案書 — テキスト入力によるコード進行の追加(是非の再検討)

対象: MIDIを経由せず、コードネームを打って進行を Vault へ入れる経路。
初出は Phase 5.2 提案(Chord Sketch)。**P5.16〜P5.19 の実装を踏まえて再検討する。**

---

## 1. 結論

**やるべき。ただし当初提案を2つに割り、入力路だけを先に実装する。**

| | 内容 | 判断 |
|---|---|---|
| **A. テキスト入力路** | 打つ → 解釈 → プレビュー → Vaultへ保存 | **実装する。2〜3 Stage** |
| **B. 作曲支援(Chord Sketch)** | 逐次カード生成 / 次コード候補エンジン / スタイル層 / 類似進行提示 | **保留。必要性が実使用で確認されてから** |

当初提案(Phase 5.2)は A と B を1つの機能として設計していた。**B は入力路ではなく作曲支援であり、価値も費用も別物である。**

## 2. 是非 — なぜ「やるべき」か

### 2.1 推論がゼロになる唯一の経路

7フェーズにわたる検出研究(候補生成・順位付け・role分類・melody混入・境界)は、すべて「**音からコードを推測する**」ことに由来する。テキストではコードは**推測されず宣言される**。

`| Dm7 G7 | Cmaj9 |` と打った瞬間、それが確定した正解である。候補も信頼度も要確認バッジも存在しない。

### 2.2 プリセットカタログは「開発者定義の9本」でしかない

P5.18.1 のカタログは immutable / data-driven であり、**ユーザーが増やせない**。

- 教則本で見た進行
- 誰かに教わった進行
- 頭に浮かんだ進行
- Chord Drip が生成した進行

これらを入れる口が、現在どこにもない。**テキスト入力は、プリセットカタログのユーザー拡張版である。** この framing が最も正確だと思う。

### 2.3 Chord Drip 連携が今日から成立する

PXF は未実装のままである。しかし Chord Drip の進行要約(`| Fadd9 | G | Em7 | Am7 |`)を貼れるだけで、**両アプリを触らずに繋がる**。PXF は上位互換として後で作ればよい。

### 2.4 下流が当初提案時より厚くなっている

テキストで入れた進行は、そのまま Vault → Chord Dojo → Bass Practice 4モード → Chord Context 伴奏 へ流れる。**入力路1本の追加で、既存の練習資産すべてに素材が供給される。**

## 3. 是非 — 正直な減点要素

| 論点 | 評価 |
|---|---|
| 練習用途はカタログが一部カバー済み | **減点。** ただしカタログは9本固定で拡張不能 |
| Voicing Memory が付かない | **減点。**「元の響き」は得られず、常に `自動` 表示になる。ただし T1 チップが既に正直に示すため、嘘にはならない |
| Bass Practice で使うには Contract 06 適合が必要 | **設計上の制約**(§5)。減点ではないが、仕様を決める必要がある |
| 保守面が増える | **軽微。** 新しいストレージ層も新しいデータ型も要らない(§4) |

**最大の減点は Voicing Memory の不在**だが、これは **T2「鍵盤で弾いて上書き」で埋められる**。打った進行に対して自分の手でボイシングを与えれば、記号と響きの両方が揃う。**MIDIファイルを一切経由せずに完全な進行が作れる**ことになる。

## 4. 設計の核 — 新しい型を作らず、Draft を作る

**テキスト入力は `CaptureDraft` を生成する経路として実装する。**

```
テキスト → parse → CaptureDraft → (既存の全パイプライン)
                                   ├ ProgressionGrid 表示
                                   ├ Quick Editor でのコード編集
                                   ├ 境界ドラッグ・Undo/Redo
                                   ├ プレビュー再生
                                   └ createIdeaFromDraft() で保存
```

これにより:

- **新しいデータ型・新しいストレージ層・schema変更が一切不要**
- 打ち間違いは既存の編集UIでそのまま直せる
- 保存後の扱いは MIDI 由来の進行と完全に同一
- Library の Source 分類は `sourceFileName` 不在から派生的に「手入力」になる(P3.7.1 の派生タグ方針)

再利用できる既存部品:

| 部品 | 状態 |
|---|---|
| `parseChordLabel()` / `labelFromSymbol()` | 実装済み |
| **Fast Label Entry(度数入力・key-aware autocomplete・直前quality優先)** | **Phase 5 で実装済み** |
| `CaptureDraft` / 統一Undo / 境界ドラッグ | P4.2 実装済み |
| `ProgressionGrid` / プレビュー / ボイシング生成 | 実装済み |
| `createIdeaFromDraft()` / `appendBlockToIdea()` | 実装済み |
| 度数変換・キー推定 | 実装済み |

**新規実装は「進行文字列パーサ」と「入力UI」の2つだけ。**

## 5. Contract 06 との関係(重要)

Bass Practice のソース(プリセット / Vault)はすべて **Contract 06**(完全な4/4セクション、1/2/4/8/12小節、最大48拍・48イベント)を満たす必要がある。

したがってテキスト入力は:

- **小節構造を明示できること**が必須。`| Dm7 G7 | Cmaj9 |` の記法を第一級とする(1小節に2つ書けば各2拍)
- 保存時に **Contract 06 適合かどうかを判定して表示する**
- **適合しなくても保存は許す。** 5小節の進行も Vault には有効な資産である。ただし「Bass Practice のソースには使えません」と明示する

**人工的に制限しない。できること・できないことを正直に示す**——このアプリの一貫した姿勢に従う。

## 6. 最小構成の仕様

### 6.1 入力

```
| Dm7 G7 | Cmaj9 | Am7 |          ← 小節記法(第一級)
Dm7 G7 Cmaj9 Am7                  ← 空白区切り(1コード=1小節)
iim7 V7 Imaj7 vim7                ← 度数入力(キー指定時)
```

- 区切りは `|` と空白のみ。**スペースなしのスラッシュは分数コード**(`C/E`)であり区切りに使わない
- 表記ゆれに寛容: `CM7` `Cmaj7` `CΔ7` / `Cm7` `Cmin7` `C-7` / `C°` `Cdim` / `C+` `Caug` / `Cm7(9)` / `C6/9`
- **出力は canonical に正規化する**(既存の identity 契約に従う)
- 解釈できたコードと失敗したコードを**区別して表示**し、失敗分だけ手直しできる

### 6.2 キーとBPM

- コードが2つ以上入った時点で**キーを推定**し、度数表示に反映する
- ユーザーが固定できる
- BPM は入力または既定値(練習で使うため必要)

### 6.3 置き場所

**Capture 画面に2タブ:`MIDIから` / `手で書く`。** 進行が生まれる場所を1箇所に保つ。新しいナビは作らない。

### 6.4 保存

既存の保存ダイアログを使う。タイトル初期値は `C major・Dm7→G7→Cmaj9` のような自動生成。

## 7. B(作曲支援)を保留する理由

当初提案の §4 にあった**次コード候補エンジン**(機能進行・5度下行・セカンダリードミナント・裏コード・モーダルインターチェンジ・半音経過・共通音保持・テンション変化・定型の続き の9規則族)は、単体で1フェーズ規模である。

そして**これは入力路ではなく作曲支援**である。価値は「アプリの中で作曲するか」に依存し、現状の主な作曲環境は FL Studio である。

したがって:

- **A を先に出す**
- 実際に手入力を使ってみて、「次に何を置くか迷う」場面が実使用で発生するかを確認する
- 発生するなら B を別フェーズとして設計する

**A なしに B は成立しない**(入力路がなければ候補を提示する場所がない)ので、順序としても A が先である。

## 9. Gate

- 既存テスト全通過(現在 302 files / 2301 tests 規模)
- `fileVersion = 1` / Vault schema / Practice保存形式 / snapshot境界に変更なし
- **新しいデータ型・新しいストレージ層を導入していないこと**
- Contract 06 適合判定が表示され、非適合でも保存できること
- 保存した進行が Vault検索・度数検索・Chord Dojo・Bass Practice(適合時)で MIDI 由来と同一に扱われること
- tracked MIDI 0 / `.local-evaluation` 0 / 個人絶対パス 0

## 10. やらないこと

- 次コード候補エンジン・スタイル層・類似進行提示(= B。保留)
- Webページ/歌詞混在テキストからの自動抽出
- 進行の MIDI 書き出し
- PXF 連携(別途)
- 新しいデータ型 / ストレージ層 / schema変更
- Voicing の自動付与(T2 の鍵盤上書きで足りる)

## 11. 位置づけ

Loop Vault の入口は現在「MIDIから採る」の1本しかない。本提案は**2本目の入口**を作る。

そして推論を含まないため、**7フェーズ分の検出研究の成否と無関係に、常に正確な進行が入る。** 検出精度の議論とは独立した価値がある。
