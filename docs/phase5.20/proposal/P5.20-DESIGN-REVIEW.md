# P5.20 Design Review

## Conclusion
元提案の「入力路を先に、作曲支援を別Phaseに分離」は採用。

## Adopted
- Captureの2本目の入口
- text→CaptureDraft→existing pipeline
- bar/simple notation
- existing parser/canonical identity
- key/BPM
- 非Contract06でもVault保存可能
- downstream reuse
- no new storage layer

## Corrections
1. 「推論ゼロ」はコードidentityに限定。key/degree/timing/voicing/capabilityは推定・生成・判定。
2. persistent typeは増やさないがtransient AST/diagnostic typesは許可。
3. Text→Draftは一方向。双方向live source-of-truthは禁止。
4. 解析カードは既存ProgressionGrid/コード進行詳細と同じcompact visual languageを再利用。巨大カード禁止。
5. カード詳細はVoicing Inspectorへ分離。
6. Textには元MIDI Voicing Memoryがないため`Auto`を明示。
7. Custom Voicingは既存CaptureDraft/Vaultがexact note pitchesをschema変更なしで保持できる場合のみP5.20内で許可。無理ならP5.20.1。
8. Contract06だけでなく機能別capability matrixを表示。

## Strategic outcome
音声検出精度に依存しない、決定的な2本目の入力路を作る。
