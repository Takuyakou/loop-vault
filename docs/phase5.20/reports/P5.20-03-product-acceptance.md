Text remains authoritative until one one-way, session-only Draft conversion.
The text-specific save adapter enforces canonical labels, exact 4/4 timing,
explicit BPM, and confirmed key only; it stores no source MIDI, analyzer
evidence, filename, source path, asset, or persisted text origin. Auto is
existing deterministic generated voicing. Custom accepts only a compatible
existing Live MIDI `live-played` simultaneous override.

The acceptance fix makes a card click audition the exact per-card notes planned
for saving. A generated-style selector appears before the Auto/Generated chip
and offers Default close, Shell 1–7, Open 1–7, and Rootless A/B when supported;
the saved-note list and keyboard visualization follow it. Live MIDI capture now
requires an explicit “Use these notes for saving” confirmation and then shows
both note names and exact MIDI note numbers before Draft conversion. Card
changes dispose an owned capture session. Generated style snapshots are exact,
deterministic, schema-compatible, and fail closed at both Draft and Vault save
boundaries; they do not claim source MIDI provenance.

The second acceptance fix latches a stable 2–10-note Live MIDI candidate across
staggered note-off events, so releasing the keys no longer disables “Use these
notes for saving” or replaces the intended chord with a partial release. While
capture is active, a dedicated local piano-like monitor follows note-on/note-off
through the existing global destination. Confirm, retry, cancel, card/mode/route
changes, and unmount release and dispose its audio resources; monitor startup
failure does not block capture.

Downstream coverage verifies Text Draft → normal Vault save → JSON/schema
reload → Vault chord/degree search → Chord Dojo / Bass Practice / Chord Context
/ eight-note Root Motion. Text without key or BPM remains savable/searchable but
is honestly ineligible for key/BPM-dependent practice consumers.
