# Loop Vault 提案書 Phase 5.21 — Harmonic Core: 役割証拠の強化と「和声コア」プリセット

前提: P5.1(Multi-MIDI Source Selection / Voice単位の役割指定)/ P5.12(pre-analysis inline化)実装済み。
**本書は提案であり作業指示書ではない。** 実装時は `PLAN.md` + `stages/*.md` へ分割すること。

---

## 1. 結論

**「伴奏のみ」でメロディが除去されない原因は、プリセットではなく役割推定にある。**

したがって本フェーズは2段階で行う。

| Stage群 | 内容 |
|---|---|
| **A. 役割証拠の強化** | GMプログラム優先・単音率・レガート修復・打楽器判定の多重化。**プリセットを足す前に、分類器が `melody` と言えるようにする** |
| **B.「和声コア」プリセット** | メロディ判定Voiceの重みを大きく下げ、和声の芯だけで検出する解析プリセット |

**Aなしに B を足しても、除外対象がゼロのため効果が出ない。** 順序を入れ替えてはならない。

## 2. 診断

### 2.1 実MIDIで自動推定がほぼ `mixed` を返している

SURAN(6 Voice)の実測:

| Voice | 自動推定 |
|---|---|
| voice | **mixed** |
| synth_pad | **mixed** |
| synth_lead | **mixed** |
| clean_electric_guitar | **mixed** |
| electric_bass | bass |
| drums | percussion |

`all_instruments.mid`(SMF type 0 / 11チャンネル)では全ピッチチャンネルが `mixed` になる。

**プリセットは役割に対して働く。分類器が `melody` を出さない以上、「メロディを除外するプリセット」の除外対象はゼロである。**

### 2.2 閾値を僅差で外している

synth_pad の実測: `poly = 1.7`(閾値 2.2)、`avgDur = 1.01 beat`(閾値 1.3)。**どちらも僅差で不成立。**

原因は、AI抽出・stem分離由来のMIDIで**ノートが断片化する**こと。同一ピッチが微小ギャップで分割されるため、ポリフォニーと平均音価が実態より小さく出る。

現在の指標(最大ポリフォニー・平均音価)は、この断片化に対して脆い。

### 2.3 Phase 4.1 の提案が未実装のまま残っている

Phase 4.1 §C4 で「GMプログラム > 実測 > トラック名」の優先順位と**レガート修復**を提案したが、未実装である。本フェーズはその回収を含む。

## 3. Stage群A — 役割証拠の強化

### 3.1 レガート修復(前処理)

同一 Voice・同一ピッチのノート間ギャップが閾値以下(既定: 16分音符相当)なら結合する。**役割推定と音価重みの両方が正常化する。**

- 純関数として実装し、修復前後の統計を診断出力に残す
- 修復は**解析入力に対してのみ**行い、元MIDI・Voicing Memory・表示には影響させない

### 3.2 証拠の優先順位を再編する

```
GMプログラム番号  >  実測特徴  >  トラック名
```

| 証拠 | 内容 |
|---|---|
| **GMプログラム** | 80-87 シンセリード / 72-79 笛 / 40-47 独奏弦 → melody 寄り<br>0-15 鍵盤 / 16-23 オルガン / 24-31 ギター / 88-95 パッド → harmony 寄り<br>32-39 → bass / 112-119 → percussion |
| トラック名 | `voice` `vocal` `lead` `melody` `topline` `sax` `solo` → melody 寄り。**GMが無い場合の補助**に降格 |
| 実測 | §3.3 の指標。GM・名前がいずれも無い Voice で主に使う |

**チャンネル9は無条件で percussion**(GM不問)。

### 3.3 実測指標を断片化に強いものへ置き換える

現在の「最大ポリフォニー・平均音価」に、次を追加する。

| 指標 | 定義 | melodyらしさ |
|---|---|---|
| **単音率** | そのVoiceが発音している時間のうち、同時発音数1の割合 | **高いほどmelody。**最大ポリフォニーより断片化に頑健 |
| **音域順位** | 有音Voice中でのピッチ中心の順位 | 最上位はmelodyであることが多い |
| **順次進行率** | 隣接ノートが±2半音以内で動く割合 | 高いほどmelody |
| 和声リズム比 | 音価がその区間の和声リズムに対して短い割合 | 高いほどmelody |

**単音率を主指標に据える。** 「和音を弾いているか、線を弾いているか」を直接測る指標であり、ノート分割の影響をほとんど受けない。

### 3.4 打楽器判定の多重化

現在は channel 9 に依存しているが、**AI抽出MIDIでは ch9 に乗っていないことがある**。次のいずれかで percussion とする。

- channel 9
- GMプログラム 112-119
- トラック名(`drum` `perc` `kit` `beat`)
- **署名判定**: 極端に短い音価 × 高密度 × 狭いピッチ集合

### 3.5 役割推定の信頼度を出す

推定に確信がない Voice を UI で示せるよう、`roleConfidence` を返す。**P5.1 の pre-analysis 画面で「要確認」バッジとして表示**し、ユーザーが直すべき場所を教える。

これは §6 のデータ収集にも直結する。

## 4. Stage群B —「和声コア」プリセット

### 4.1 名前

既存のプリセット名が平易な日本語であるため、それに揃える。

```
自動 / 和音+ベース / 伴奏のみ / 和声コア / 全パート / カスタム
```

**「和声コア」**を採用する。「和声の芯だけを取る」という意図が短く伝わり、他のプリセットと並べたときに強度差が直感的である。

(検討した代替: 「ハーモニーのみ(強)」冗長 /「コード検出優先」他が音楽用語なので浮く /「メロディ除去(強)」否定形が前面に出る)

### 4.2 動作

| 役割 | 「伴奏のみ」 | **「和声コア」** |
|---|---|---|
| harmony / pad | 1.3 | 1.3 |
| bass | 除外 | 除外 |
| mixed | 1.0 | **0.8** |
| **melody** | **0.5** | **0.15** |
| percussion | 除外 | 除外 |

**melody を 0 にしない。** 完全に切ると、伴奏が C-E-G でメロディに安定した D がある場合の `Cadd9` を取りこぼす。0.15 は「単独では和音を成立させないが、他の証拠を補強はする」水準。

### 4.3 トレードオフの明示

プリセット選択UIに一行を添える。

> テンションを取りこぼす代わりに、誤検出を減らします

**既定にしない。** これは選択肢であり、正解ではない。

## 5. Stage群C(任意・第2段階)— Voice内の役割混在

`all_instruments.mid` のピアノ ch0 は音域30〜88であり、**1チャンネルに低音・和音・メロディが同居**している。Voice単位の除外では和音まで失われる。

**`mixed` と判定された Voice の中でのみ**、次を全て満たすノートの重みを下げる。

- その瞬間のテクスチャ最上声である
- その瞬間に単音である
- 和声リズムに対して音価が短い
- コード変化を跨いで持続しない

**判定は「コードトーンか否か」に依存させない**(メロディ音の多くはコードトーンであり、循環参照になる)。

### 5.1 これを分ける理由

Phase 4.4系が3フェーズ非昇格に終わった原因は、**壊れている role を入力にしたフィルタを作ったこと**だった(LOSO CV 13中8退行)。

**Stage群Aで証拠側が改善したことを確認してから着手する。** 順序を守れば同じ失敗は繰り返さない。Aの効果が十分なら、Cは不要かもしれない。

## 6. 副次的な成果 — 役割訂正ログ

P5.1 で role訂正ログが実装済みである。本フェーズで `roleConfidence` が出るようになると、**「自動推定が何を、どのくらいの確信度で間違えたか」**が記録される。

これは §3.3 の指標と閾値を、合成コーパスではなく**実使用データ**で調整する材料になる。**閾値を手で当てにいかず、ログが溜まってから調整する。**

## 7. 検証

### 7.1 実MIDI比較(必須)

手元の4本(all-instruments / captured-chorus / SURAN / Endless)で次を比較する。

| 条件 | 確認すること |
|---|---|
| 現行 `伴奏のみ` | baseline |
| Stage群A後の `伴奏のみ` | **証拠改善だけで出力が変わるか**(変わるはず) |
| Stage群A後の `和声コア` | メロディ由来の誤検出が減るか |
| 各条件の Voice 役割一覧 | pad が `harmony`、voice が `melody` になるか |

**Stage群Aの効果は「和声コア」を使わなくても現れる**はずである。現れないなら証拠の設計が誤っている。

### 7.2 回帰

- 既存コーパス(Chapter 3 Seed / Chord Drip / Phase 4.5 label dev / Phase 4.7 Gold)で**退行がないこと**
- Chapter 3 Seed は 97.73% 帯であり、**許容退行は −0.25pp 以内**とする
- `defaultAnalyzerMode` を変更しない。既定プリセットも変更しない

### 7.3 A/B等価

**プリセットを変更しない場合、解析結果が現行と一致すること**は保証しない(§3の証拠改善が既定経路にも効くため)。ただし:

- 変更は**役割推定の入力側**に限定し、スコアリング・境界・候補生成には触れない
- 変更前後の差分を実MIDI 4本で目視・試聴確認する

## 9. Gate

- 既存コーパス4種で退行なし(Chapter 3 Seed は −0.25pp 以内)
- 実MIDI 4本で Voice 役割一覧が改善している(pad → harmony、voice → melody)
- `defaultAnalyzerMode` / 既定プリセット / Vault schema / `fileVersion` に変更なし
- スコアリング・境界・候補生成のコードに変更がないこと(**変更は役割推定の入力側のみ**)
- 決定性維持(同一入力 → 同一出力)
- 既存テスト全通過 / tracked MIDI 0 / `.local-evaluation` 0

## 10. やらないこと

- スコアリング・境界検出・候補生成の変更
- `defaultAnalyzerMode` の変更・既定プリセットの変更
- **melody の重みを 0 にすること**(テンションの取りこぼし)
- Stage群Aの効果確認前に note-level フィルタへ着手すること
- 合成コーパスに対する閾値の手動フィッティング(実使用ログを待つ)
- Vault schema / Voicing Memory / 表示用MIDIへのレガート修復の適用

## 11. 位置づけ

P5.1 は「ユーザーが役割を指定できる」ようにした。しかし**自動推定の初期値がほぼ `mixed` では、ユーザーは毎回すべてを手で直すことになる。**

本フェーズは、その初期値を実用水準に上げる。**プリセットが効くのは、役割が正しく付いてからである。**
