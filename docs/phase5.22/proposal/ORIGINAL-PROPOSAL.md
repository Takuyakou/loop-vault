# Loop Vault 提案書 Phase 5.22 — Source Bassline Practice

前提: v1.1.0(P5.1 Voice役割指定 / P5.16-5.19 Bass Practice 4モード / P5.18.1-5.18.2 Preset & Vault Picker / P5.20 Text Entry)実装済み。

**本書は提案であり作業指示書ではない。** 実装時は `PLAN.md` + `stages/*.md` へ分割すること。

---

## 1. 結論

**読み込んだMIDIの Bass Voice そのものを練習素材にする経路を追加する。**

現行の4モードはすべて「コード進行から作られた」素材を使う。Bassline Echo は生成、Root Motion Echo は root 列であり、仕様書 §9.5 は「**元ベースラインとは見なさない**」と明示している。

**実際に鳴っていたベースラインを練習する経路が、製品に存在しない。** P5.1 で `bass` 役割の指定が入った以上、その素材は既に手元にある。

これは Loop Vault だけが提供できる練習である。汎用の練習アプリはユーザーが採集した曲を知らない。

## 2. 最大の設計上の壁 — 保存境界

**現在、Bass Voice のノートは永続化されていない。**

| 保存されているもの | 保存されていないもの |
|---|---|
| `SavedProgressionBlock`(コード列・タイミング) | **Bass Voice の実ノート列** |
| Voicing Memory(コードごとのピッチ集合) | ベースの音価・休符・装飾 |
| 元MIDIへの参照(`sourceAssetId` / `sourceFileName`) | ベースラインの形そのもの |

したがって設計は2択になる。

### 案A: 元MIDIを再読込する(保存しない)

練習開始時に `sourceFileName` の実ファイルを読み直し、Bass Voice を抽出する。

- **保存境界を一切変えない。** privacy-safe snapshot の原則がそのまま保たれる
- ただし **ファイルが移動・削除されると練習できない**
- そして「元ファイルpath を練習へ渡さない」という §9.6 の境界と衝突する

### 案B: Bass ノート列を snapshot に含める(推奨)

保存時に、**そのブロック区間の Bass Voice ノート列だけ**を detached snapshot として保持する。

- Voicing Memory の思想と同じ:**再計算不能なユーザーの資産だから保存する**
- ファイルが消えても練習できる
- privacy 境界を保てる(ノート列は音楽データであり、path でも raw MIDI file でもない)
- **サイズは小さい**。4小節のベースで数十ノート = 数百バイト。Voicing Memory と同オーダー

**案Bを推す。** ただし §7 の制約を厳守すること。

## 3. データモデル(案B)

```
SavedProgressionBlock.sourceBassline?: {
  version: 1;
  notes: { pitch: number; startBeat: number; durationBeats: number; velocity: number }[];
  meter: "4/4";           // Contract 06 準拠
  lengthBars: number;
  capturedFrom: "voice-role-bass";   // 出所の種別のみ。path・filename は持たない
}
```

- **optional + zod `.default()`**。`fileVersion = 1` を変更しない
- 既存ブロックは `undefined` のまま。**遡及生成しない**
- P5.1 で `bass` 役割が指定された Voice からのみ生成する。役割未指定・`mixed` からは作らない
- 保存する情報は音楽データのみ。**ファイル名・パス・トラック名・device 情報を含めない**

## 4. 抽出の規約

| 論点 | 規約 |
|---|---|
| 対象 | `bass` 役割の Voice。複数ある場合はユーザーが選ぶ(既定は最も音数の多いもの) |
| 区間 | ブロックのセクション範囲のみ。範囲外は含めない |
| タイミング | 拍/小節に正規化(PPQ 非依存)。ティックを保存しない |
| 音価 | **実音価を保つ。** 量子化・補正しない |
| 和音 | ベースが2音以上同時に鳴る箇所は**最低音を採用**し、その事実を記録 |
| 上限 | Contract 06 に準拠(最大 12 小節 / 48 拍)。超過は保存しない |
| 空 | ノートが0個の区間は `sourceBassline` を作らない |

**「元の演奏をそのまま保つ」ことが本モードの価値である。** 生成モードとの差別化がここにしかない。

## 5. 練習モードの構成

**新しい5つ目のモードにせず、Bassline Echo の source として追加する。**

```
source:  [ 生成 ]  [ 内蔵 preset ]  [ Vault進行 ]  [ 元のベースライン ]  ← 追加
```

理由:
- 既存の Listen / Sing / Play / Review / Transfer がそのまま使える
- Chord Context(コード伴奏)との組み合わせが自然に成立する
- **P5.19.1 で指摘した「面が増え続ける」問題を避ける**
- ユーザーは既にこのソース選択UIを学習済み

### 5.1 段階的な難度

元のベースラインは、いきなり全部弾けるとは限らない。**同じ素材を3段で登れるようにする。**

| Level | 内容 |
|---|---|
| **1. ルートだけ** | 各コードの root を、元のタイミングに近い形で |
| **2. コードトーンだけ** | 経過音・装飾を除いた骨格 |
| **3. 元のライン** | 実際に鳴っていたそのまま |

**Level 1/2 は Level 3 からの決定的な導出**とする(別素材を作らない)。「元のライン」との差分が見えることが学習価値になる。

### 5.2 区間の切り出し

12小節を丸ごと練習するのは初学者には重い。**1〜2小節ずつ練習できるようにする。**

- ブロック内で練習区間を選べる(既存の Chord Context のセクション選択と同じ考え方)
- 選んだ区間だけをループ再生
- **Transfer は「次の区間へ」**(Bassline Echo の別キー Transfer とは別の意味になるため、明示的に区別する)

## 6. 正直さの規約(既存原則の継承)

| 規約 | 内容 |
|---|---|
| **自動採点しない** | Bass Practice 全体の原則。ここも例外にしない |
| **Level 1/2 は「簡略版」と明示する** | 元のラインだと誤解させない |
| 和音を最低音に落とした場合、その事実を表示する | 「元は2音でした」 |
| 出所は種別のみ表示 | 「元のベースライン」とは出すが、**ファイル名は出さない**(§9.6 の境界を継承) |
| 元MIDIが手元になくても練習できる | snapshot が detached であることの帰結 |

## 7. 保存境界で守ること(最重要)

**この機能は「保存しないもの」を保存する初めての変更であるため、境界を厳格に定義する。**

| # | 規約 |
|---|---|
| G1 | `fileVersion = 1` を変更しない。追加は optional + zod default のみ |
| G2 | 既存ブロックへ遡及生成しない。`undefined` のまま読める |
| G3 | ファイル名・絶対パス・トラック名・device 識別子を `sourceBassline` に含めない |
| G4 | raw MIDI バイト列を保存しない(**ノート列のみ**) |
| G5 | Contract 06 の上限(12小節 / 48拍)を超えるものは保存しない |
| G6 | Export した Vault JSON に含まれる。**そのため §7 の各項目は export 後も守られる必要がある** |
| G7 | Practice History に snapshot 本体を複製しない(既存 §9.8 の原則) |
| G8 | Voicing Memory / Vault schema の他部分 / Analyzer / MIDI Exporter に変更なし |

**G6 が見落とされやすい。** Vault export は外部へ渡り得るため、`sourceBassline` の中身がそのまま公開されることを前提に設計する。

## 9. Gate

- 旧 `data.json`(`sourceBassline` 不在)がそのまま読める
- Export した JSON に §7 の禁止項目が含まれないことの**否定テスト**
- Level 1/2 が Level 3 から決定的に導出される(同一入力 → 同一出力)
- 実音価が保たれる(量子化されていない)ことのテスト
- Contract 06 超過が保存されないこと
- 既存テスト全通過 / `fileVersion = 1` / Vault schema の他部分不変
- tracked MIDI 0 / `.local-evaluation` 0 / 個人絶対パス 0

## 10. やらないこと

- 新しい練習モードの追加(**Bassline Echo の source として実装する**)
- 自動採点・音声解析
- raw MIDI ファイルの保存
- 既存ブロックへの遡及生成
- 量子化・タイミング補正・音価の丸め
- ドラム/メロディ Voice の保存(**bass 役割のみ**)
- Contract 06 の緩和

## 11. 位置づけ

Loop Vault は「良い進行を採集して、貯めて、練習する」アプリである。しかし**練習しているのは、採集した曲そのものではなく、そこから生成した素材**だった。

本フェーズはその最後の距離を埋める。**自分が良いと思って採集した曲のベースラインを、そのまま弾けるようになる。**

そして技術的には、P5.1(Voice役割指定)への投資が、検出精度以外の形で回収される最初の例になる。
