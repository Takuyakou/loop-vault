## Scope / Findings

- `SourceBasslineSnapshotV1`、`ExactBeat`、strict schema、canonical serializerを追加した。
- PreAnalysis runtime noteへraw parser由来の`startTick` / `durationTick` / `ticksPerQuarter`をtransientに伝搬した。float beatからtickを逆算する処理は追加していない。
- proven raw-integer-tick rangeだけを受け付け、半開区間の交差をBoundary Aでclipし、両continuation flagを必須化した。
- 同時発音とoverlapを保存時に単音化せず、全対象noteをcanonical orderで保持する。
- captured harmonyは同一source/range/PPQを証明するtransient raw-tick inputから抽出関数内で構成する。prebuilt永続objectの注入を許さず、既存chord pitch-class helperと明示slash bassから構成し、重複を決定的に除去し、conflicting overlapを拒否する。
- Vault writerを同一物理pathのfileVersion 2へ更新した。v1はsnapshotなしで決定的にv2へ移行し、v2超はreadonly/non-writeとなる。
- Practice writer/storage validatorを同一物理pathのfileVersion 2へ更新した。TypeScript/Rustはv1/v2を読み、TypeScriptはv1をv2へ移行し、v2超をnon-writeにする。legacy-v1 backup restoreはCAS/atomic replaceを維持しつつ、最終canonical dataをfileVersion 2とnext revisionで永続化する。

## Contracts

- ExactBeatはsafe integerとBigInt算術で既約化し、zeroは`0/1`だけを許可する。
- rangeはconstant 4/4、bar-aligned、1〜12小節、source内、raw tick authority明示を必須とする。
- canonical note順はstart、pitch、duration、velocity、before flag、after flag。内部event indexはtie-breakにだけ使い永続化しない。
- snapshot/captured-harmony署名は固定property orderのUTF-8 canonical JSONに対する独立lowercase SHA-256とする。
- snapshotは最大8,192 notes、canonical UTF-8 1,048,576 bytesの独立ceilingを持つ。現canonical formatではbyte capが先にbindし、real canonical fixtureの1,048,575 / 1,048,576 / 1,048,577-byte境界と、8,191 / 8,192 / 8,193-note挙動を検証する。pitch、velocity、duration、end、order、signature、unknown keyをfail-closedで検証する。
- source subtreeへpath、filename、Voice identity、device、raw bytes、private metadata、Analyzer metadataを追加できないstrict schemaとした。
