## Root cause

- Card playback resolved each timeline item through the shared voicing resolver
  and passed the resulting MIDI notes as explicit playback notes.
- Capture full playback passed only `result.fullTimeline`. It omitted the
  optional event-id to MIDI-note map, so the timeline driver regenerated notes
  from each chord symbol.
- Runtime source voicing already existed in
  `ChordTimelineItem.voicingMemory.sourceVoicing`; the full-playback request was
  the missing link.

## Change

- Added a pure per-item resolver shared by card and timeline planning.
- Added a deterministic timeline playback-plan helper that assigns playback-only
  event ids and builds the explicit source-note map atomically.
- Capture full playback now sends that plan to the existing timeline audio
  driver. Entries without usable source voicing are intentionally absent from
  the map, preserving the driver's generated-voicing fallback.
- The helper clones timeline entries and does not quantize, retime, transpose,
  rewrite, or otherwise mutate source MIDI data.

## Card versus full playback

- Synthetic 12-segment fixture: exact pitch and octave equality `12 / 12`.
- Altered source voicings equivalent to G#7(b13), E13, and C#7(b9) were passed
  through unchanged even where chord-symbol generation differs.
- A local-only anonymized aggregate recheck also produced `12 / 12`
  source-backed parity and deterministic output. No private input, path, file
  identity, or raw note data is committed.

## Fallback and boundary coverage

- Missing or unusable source voicing continues to use the existing generated
  preview voicing.
- One-state and two-state bars, simultaneous notes, anticipation, sustain across
  a segment boundary, Bass-only lead material, and missing source voicing are
  covered.
- Track A OFF and ON timeline shapes both produce fresh event-id maps without
  stale/index mismatch.
