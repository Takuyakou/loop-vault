## Audit

- Card playback calls the existing per-event resolver and passes its MIDI notes
  as explicit playback notes.
- Capture full playback passes the timeline but omits the optional event-id to
  MIDI-note map.
- `ChordTimelineItem.voicingMemory.sourceVoicing` holds the runtime source MIDI
  snapshot. It is attached after analysis to the final OFF/ON timeline events.
- The shared resolver validates source memory against the current chord and
  falls back to generated preview voicing when memory is absent or incompatible.
- The timeline audio driver already accepts explicit notes per event and falls
  back independently for entries missing from that map.
- Vault, Home, Detail, Practice and other saved-progression paths already build
  explicit maps or use their existing isolated playback contracts. The requested
  defect is the Capture TimelineDetails full-timeline request; unrelated preview
  entry points stay outside this surgical change.

## Planned change

Build the Capture full-timeline explicit-note map from the same resolver used by
card playback, keyed by stable event id. Do not copy extraction, mutate notes, or
change the audio engine.
