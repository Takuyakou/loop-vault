## Chord Dojo

- Route/view: the application has one `practice` view. `PracticeWorkspace` currently switches between `chord-dojo` and `bass-practice`.
- Step: `reducePracticeSession` advances after a stable MIDI match. It is success-driven and therefore cannot be reused as the P5.27 session model.
- Flow: `PracticeClock` opens and closes scoring windows and the view records match/miss/clean outcomes. Those outcomes are Chord Dojo-only.
- Session model: levels, Step/Flow, scoring, transposition, Mix, MIDI activation, and persistence are owned by `PracticeView`.
- Scoring: correct/incorrect, stability windows, attempts, progress, and mastery semantics remain protected and must not enter P5.27.
- Shell: `shell-17` uses `getStyleTonePolicy` and deterministic candidate generation.
- Open: `open-17` exists, but P5.27 Open/Melody remains deferred because there is no Top Note contract.
- Rootless A/B: `rootless-ab` has explicit compatibility, deterministic A/B templates, and progression voice-leading optimization.
- Source/Auto: `resolveVoicingForUse` currently prefers compatible Custom, then verified/high-confidence Source, then generated notes.
- Keyboard: existing `PracticeKeyboard`/piano visualization can be reused as a read-only monitor.
- MIDI input: the current Dojo can gate start on a connected device. P5.27 must not reuse that gate; no MIDI, wrong notes, and extra notes leave its clock unchanged.

## Shared Voicing

- P5.26.1 resolver: `resolveTimelineItemVoicing` and `createTimelineVoicingPlaybackPlan` already provide common card/full-playback source fidelity and stable event-id mapping.
- Source representation: `voicingMemory.sourceVoicing` stores exact compatible MIDI pitches/octaves and simultaneous/aggregated representation.
- Custom representation: `voicingMemory.practiceVoicingOverride` stores a compatible saved override, commonly `live-played` or verified text-style data.
- Resolver hazard: MY Source cannot call the unfiltered general resolver because Custom has higher priority. P5.27 needs an explicit mode selector that exposes only the selected Source or Custom memory and returns unavailable otherwise.
- Fallback: generated fallback remains valid for existing callers, but is forbidden inside explicit MY Source/Custom selection.
- Compatibility: `voicingSourceStatus` and captured chord identity checks are the existing validation seams.
- Degree facts: chord interval descriptors expose interval labels and pitch classes. Stage02 needs a small pure mapper from exact selected MIDI notes to degree labels; it must preserve octave/pitch and must not rewrite the source.
- Preview/playback: `chordPreview` and `playbackController` use independent timeout-based timeline scheduling. They remain valid for isolated audition, but must not drive a live P5.27 session.

## Practice Clock contract

- Reuse: keep `PracticeClock`'s Tone Transport ownership, generation guards, schedule-id tracking, and cleanup patterns.
- Do not reuse unchanged: the current schedule includes count-in beats in each round length, which would insert a count-in gap on every loop.
- P5.27 single source of truth: one absolute musical position drives note playback, current chord, next chord, beat, chord/progression progress, and loop count.
- Start: optional count-in precedes the first progression pass.
- Loop boundary: last-to-first is seamless and does not repeat count-in.
- Pause/Resume: pause preserves position; resume continues without count-in and without a second transport.
- Restart: returns to the beginning and performs count-in when enabled.
- BPM: changing BPM updates the same transport and preserves musical position.
- Metronome: toggles click scheduling only; it never pauses or owns the clock.
- Mixed duration: use saved beat/duration facts for one, two, four, and mixed chord states per bar.
- Normal termination: user Stop or route exit only. Loop count never ends a session.

## Snapshot and lifecycle

- New P5.27 snapshot: an immutable detached snapshot containing safe logical source reference, canonical chord/display identity, timing, key, BPM, meter, selected family/mode, and compatible exact Source/Custom pitches.
- Excluded: raw MIDI, source path/file name, device id, performance notes, diagnostics, and private free-text metadata.
- Reuse pattern: `practiceMix` deep-clone/deep-freeze and deterministic fingerprint techniques are suitable.
- Do not reuse behavior: Practice Mix live drift-abort and scoring state are unsuitable. An active P5.27 session remains detached if its Vault source is edited or deleted.
- Chord Context snapshot: its privacy shape is useful evidence, but it strips voicing data and cannot be the P5.27 snapshot type.
- New session behavior: rebuild from current Vault state; a missing/deleted/invalid selected source returns explicit unavailable.
- Cleanup: route exit, mode change, restart, rapid start/pause, and source change must leave no stale scheduled event, audio owner, or retained player.
