## Single clock

- Added a pure non-scoring clock reducer and projection under
  `src/domain/progressionVoicingPractice/`.
- One absolute musical `transportBeat` projects Current, Next, beat-in-chord,
  beat-in-bar, chord progress, progression progress, and Loop count.
- The domain owns no `setTimeout`, `setInterval`, animation clock, audio node,
  or MIDI listener. Stage03 must feed it the position from the same Tone
  Transport that schedules playback.
- Existing Chord Dojo `PracticeClock` and its scoring callbacks are unchanged.

## Timing

- Saved event durations are normalized into a continuous progression-relative
  timeline without flattening one-, two-, four-chord, or mixed bars.
- The schedule exposes an initial `progressionStartBeat` plus one invariant
  `loopBeats`; count-in is not part of the repeated interval.
- Invalid, overlapping, or discontinuous timing fails closed.

## Loop

- Last-to-first is a modulo projection over `loopBeats`.
- Fractional loop boundaries use one shared quotient/remainder decomposition for
  Loop count and progression position. ULP-based boundary snapping is capped at
  `1e-9 beat`, preventing `%`/`floor` disagreement without consuming meaningful
  positions immediately before or after a boundary.
- Loop count is `floor(progressionElapsed / loopBeats)` and remains
  session-local.
- No completed/success state exists. A 100,000-loop deterministic simulation
  remains `running` with a constant-size state.

## Pause/resume/restart

- Pause retains the exact absolute transport beat and ignores later sync input
  while paused.
- Resume restores the prior musical position without adding a new count-in.
- Restart resets transport beat and Loop count, and reapplies the configured
  initial count-in.
- BPM changes update only the clock BPM fact; they do not seek or rebuild the
  musical projection.
- Stop is the only normal terminating action in the domain.

## Snapshot

- Added an immutable, detached v1 snapshot built from a saved progression.
- Included: safe logical idea/block ids, canonical chord facts, relative timing,
  supported key/BPM/meter, selected family, and only the exact pitches/octaves
  for the explicitly selected compatible MY voicing.
- Excluded: source filename/path/fingerprint, raw MIDI, title/summary/memo/tags,
  diagnostics, device ids, performance input, score, and persistence data.
- Source MIDI availability reuses the existing P5.26.1 `voicingSourceStatus`
  semantics. Verified or compatible high-confidence simultaneous Source is
  copied; low-confidence, aggregated, stale, invalid, and non-MIDI Source is
  omitted without substituting Custom or generated voicing.
- Custom availability reuses existing `voicingCompatibility`. Only an explicitly
  selected compatible Custom is copied.
- Detached voicing facts contain only `kind`, exact `midiNotes`, and optional
  `bassNote`. Confidence, verification, representation, extractor metadata, and
  captured identity are validation inputs and never enter the snapshot.
- Source objects can be edited after construction without mutating the active
  snapshot. A deterministic content fingerprint is derived only from safe
  snapshot facts.

## No-scoring proof

- State/projection contain no correct/incorrect, score, accuracy, streak,

- There is no MIDI action and no success-driven advance path.
