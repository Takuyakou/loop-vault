## Text save handoff

- Successful Text Progression create and append operations return the exact saved
  logical `{ ideaId, blockId }` target to Capture.
- Capture closes the draft, keeps a compact success action, and offers both
  `Voicing Loop` and `View saved progression`.
- The Voicing Loop action never creates a transient text session. It re-reads the
  exact saved Vault block and builds a new detached snapshot at click time.
- If the recorded block was deleted before launch, the target is not replaced by
  another block in the same Idea; launch fails closed with localized feedback.
- A valid Text save may intentionally omit BPM. Create and append keep that
  persisted omission unchanged, while Text-provenance handoff alone applies the
  same 120 BPM runtime default used by Text card audition.
- Explicit saved block/Idea BPM continues to win. An explicit invalid BPM is not
  masked by the default and still fails closed through snapshot validation.

## Progression Detail

- Progression Detail now exposes a dedicated `Voicing Loop` action.
- The action passes only logical Idea/block identifiers to the application
  handoff. It does not reuse the Chord Context section picker or snapshot.
- Existing unsaved-edit leave confirmation still wraps the action, so a session
  is created from saved Vault facts rather than an unsaved editor draft.

## Source / Custom

- One Vault handoff creates independent snapshots for Source MIDI, Custom,
  Basic Shell, Basic Full, and Left-hand from the same saved block.
- Source MIDI is the initial family only when every event has a validated P5.26.1
  Source voicing. Complete validated Custom is next; otherwise the explicit
  Lesson `Basic Full` family is selected.
- Partial or unavailable MY data remains present as its selected MY snapshot and
  resolves to explicit `UNAVAILABLE`; no event borrows another MY or generated
  voicing.
- Legacy non-canonical Idea key text is omitted as optional metadata rather than
  making an otherwise safe progression invalid. Canonical saved block/Idea key
  and BPM facts are detached when available; only BPM-less Text provenance gets
  the runtime-only default.

## Detached snapshot

- App owns the returned immutable handoff as session state. It is not recomputed
  from reactive Vault data while the Practice route remains active.
- The snapshot allowlist remains chord identity, timing, meter, BPM, canonical
  key, logical reference, selection, and compatible exact pitches only.
- Summary/title, memo, tags, paths, filenames, fingerprints, raw MIDI,
  diagnostics, device identifiers, and performance notes do not cross the
  boundary.
- No Vault/Practice schema, `fileVersion`, migration, or persisted setting was
  changed.

## Edited / deleted source

- Unit coverage mutates the source voicing and deletes the block collection
  after handoff; active session pitches remain unchanged.
- Leaving Practice clears the app-owned handoff. A later launch rebuilds from
  current Vault state.
- Missing Idea, missing/deleted block, unsafe timing/meter/BPM, and other invalid
  source facts return an explicit handoff failure and never revive an older
  snapshot.

## UI review (`$emil-design-eng`)

| Before | After | Why |
| --- | --- | --- |
| Text save immediately left Capture for Idea Detail | Saved draft closes into a compact success action with `Voicing Loop` and `View saved progression` | Makes the approved post-save choice explicit without adding a transient source or duplicate progression picker |
| Progression Detail only exposed the section-based Chord Context Practice action | A separate `Voicing Loop` button passes the whole saved progression reference | Keeps the two snapshot contracts honest and avoids overloading the section picker |
| A stale Text success could identify only its Idea | The success action retains the exact saved block id | Prevents an invisible substitution with another block after deletion |
| Test fixture always overrode a real saved handoff | Real Vault handoff takes precedence; the deterministic fixture remains the empty-entry fallback | Lets integration tests exercise production state while preserving isolated Stage03 UI tests |

No animation was added. Actions reuse existing `Button` and `StatusMessage`
primitives, remain keyboard operable, wrap at narrow widths, and use existing
Loop Vault tokens.
