## Sidebar / navigation structure

`src/components/AppShell.tsx` has one flat `Workspace` group containing
Home, Chord Capture, Vault, Practice, and Live MIDI. `System` contains History and Settings.
Every destination is a native button rendered by the same `SidebarItem`; there is no nested
navigation data model, disclosure state, or router URL.

`SidebarItem` already supplies:

- `min-h-10`, active indicator, `aria-current="page"`
- collapsed-mode `aria-label` and `title`
- native keyboard activation
- existing tokens and focus-visible behavior

Decision: add one flat `Voicing Loop` item immediately after `Practice` using the same component.
Do not build a nested navigation system for one shortcut.

## Practice workspace / state

`src/features/bass-practice/ui/PracticeWorkspace.tsx` already owns three flat tabs:
Chord Dojo, Voicing Loop, and Bass Practice. It implements roving `tabIndex`, ArrowLeft/Right,
Home, and End and keeps the visible panel behind one tabpanel.

`src/App.tsx` owns:

- `view`, with one `practice` application route
- `practiceMode`, including `voicing-loop`
- `voicingPracticeHandoff`, detached by P5.27
- `practiceTarget` and `chordContextSnapshot` for sibling Practice flows

The existing route-leave effect clears `voicingPracticeHandoff` when `view !== practice`.
That is insufficient when the new sidebar shortcut is clicked while already on a loaded
Voicing Loop session because `view` does not change. The direct handler must explicitly clear
all transient Practice sources before selecting `voicing-loop`. It must pass through the existing
`requestProgressionLeave` guard, with clear/mode/view updates inside the permitted callback so an
unsaved Progression Detail remains protected.

## Empty-state audit

`src/views/ProgressionVoicingPracticeView.tsx` already tolerates missing `snapshots`; it does not
throw and shows an informational message. However it currently renders a `Source MIDI` badge and
the complete MY/LESSON selector before that message, and the body only instructs the user to enter
from Vault. It has no actionable Vault/Text CTA. Its Live MIDI effect also acquires a lease whenever
`monitorMidi` is true, including the source-less empty state.

Locked delta:

- retain the existing `Voicing Loop` SectionHeading
- render existing `EmptyState` with two existing `Button` controls when no progression is loaded
- hide source badge/selector until a progression is loaded
- guard the existing View-level Live MIDI effect with `progressionLoaded`
- empty mount acquires no lease; loaded → direct empty releases the old lease and does not reacquire
- keep every loaded-session control and resolver state unchanged

The View-level effect guard is smaller and safer than passing `monitorMidi=false` only from App:
it defines the resource contract at the component that owns the lease and also covers prop-driven
loaded → empty transitions without a second caller-side condition.

## Vault / Text seams

### Vault

`App.openProgressionVoicingPractice` calls
`buildProgressionVoicingPracticeHandoffFromVault(visibleIdeas, sourceReference)`, then clears
sibling Practice targets, assigns the detached handoff, selects `voicing-loop`, and opens Practice.
`ProgressionDetailView` already exposes the `Voicing Loop` action through this function.

The Bass Practice `VaultProgressionPicker` is not a compatible reuse seam: it is typed to
`VaultChordContextSnapshot`, limits eligibility to its Chord Context catalog/sections, and confirms
a section signature rather than a P5.27 progression source reference. Generalizing it would widen
scope and risk Bass Practice. The empty-state Vault CTA therefore navigates to the existing Vault.

### Text

`CaptureView` owns `captureInputMode` locally and initializes it to `midi`. It already exposes a
Text selector and, after save, a `Voicing Loop` action wired to the same P5.27 Vault handoff builder.
The minimal seam is a mount-time `initialInputMode` prop for cross-route entry. The empty-state Text
CTA supplies `text` before Capture mounts, while normal Capture entry retains its existing `midi`
default. No same-route reset behavior is added for an already mounted Capture. No Text save or
handoff behavior changes.

## P5.27 handoff protection

`src/domain/progressionVoicingPractice/handoff.ts`:

- re-reads the saved idea/block and creates detached snapshots for every selection
- preserves each event duration through the snapshot builder
- uses block BPM/key and only the existing audited Idea/Text fallbacks
- prefers complete Source MIDI, then complete Custom, then Basic Full
- never treats partial MY voicing as complete
- fails closed for missing/deleted/invalid sources

Existing handoff tests prove exact Source/Custom MIDI note arrays, detach after source mutation,
Idea BPM/key fallback, spelling/bass preservation, missing source failure, and no retained private fields.
P5.28 must call this existing path; it must not create a second handoff or resolver.

## UI design-engineering review

The installed `$emil-design-eng` Skill was read before the audit. Existing Loop Vault visual
language and components remain the governing product contract.

| Before | After | Why |
| --- | --- | --- |
| Flat sidebar has only a generic `Practice` destination | Add one flat `Voicing Loop` item directly after `Practice` | Existing navigation has no nesting; one same-language shortcut is the smallest discoverable change |
| Directly selected empty view would show `Source MIDI` badge and MY/LESSON controls with no source | Show only heading plus actionable `EmptyState`; reveal source controls after load | Removes misleading state and directs attention to the only useful next actions |
| Empty message says to open from Vault but has no action | Add `My Vaultから選ぶ` primary CTA and `Textで進行を入力` secondary CTA | Converts instruction into immediate keyboard-operable action without inventing a new workflow |
| Loaded session can remain when the same Practice route is reselected | Direct handler clears transient sources before selecting `voicing-loop` | Invisible lifecycle correctness prevents practicing a stale progression |
| Source-less View still acquires Live MIDI | Gate the existing View activation effect on `progressionLoaded` | Empty state owns no practice resource; loaded → empty cleanup releases once and cannot reacquire |
| New shortcut could invite custom animation | Reuse native button, existing color transition, focus style, and reduced-motion rule; add no animation | A frequent navigation action should respond immediately and stay consistent with the app |
| Bass Practice picker appears superficially reusable | Keep it untouched; route Vault CTA through the established Vault detail handoff | Its snapshot/eligibility contract differs, so reuse would couple unrelated practice modes |

No CSS/token redesign, hover-only behavior, new popover, spring, keyframe, or layout animation is needed.

## Responsive / accessibility audit

- AppShell collapses automatically at `max-width: 1100px` and retains accessible route names.
- Main/sidebar containers use `min-w-0`; sidebar nav scrolls vertically.
- Common Button has 40 px minimum height; global focus-visible applies to buttons and inputs.
- Global reduced-motion reduces all animation/transition duration and disables meter motion.

- Practice tab keyboard semantics already have unit coverage and must remain unchanged.
