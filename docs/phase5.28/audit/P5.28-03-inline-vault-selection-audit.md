## Repository findings

- `App` already owns `visibleIdeas` and the transactional
  `openProgressionVoicingPractice` callback. It re-reads current Vault state through
  `buildProgressionVoicingPracticeHandoffFromVault` and returns `false` on failure.
- `ProgressionVoicingPracticeView` already stops its transport on snapshot change and
  unmount. Its source-less branch is the narrow UI replacement point.
- The harmony query parser provides existing normalized chord matching semantics. A
  small Voicing Loop projection can constrain exposed search fields to title, chord
  labels, and key without creating a general search engine.
- `VaultProgressionPicker` is coupled to Bass Practice Chord Context sections and 4/4
  eligibility. Reusing its component or candidate type would change P5.27 semantics.
- `voicingPractice/preferences.ts` persists generator span preferences. Recent source
  references are a separate concern and should use a distinct versioned local key.
- The existing App key changes from the empty sentinel to snapshot fingerprint, so a
  successful row selection unmounts the empty view before mounting P5.27 practice.

## UX determination

| Before | After | Why |
| --- | --- | --- |
| Empty state with a primary Vault navigation button | Dense inline eligible-progression rows | Removes the picker/detail round trip from the frequent path |
| Vault selection requires several screens | Whole native row button starts practice in one click | Larger target and native keyboard behavior without a new interaction model |
| No practice-specific recency | ID-only five-item LRU above the default list | Repeated practice becomes fast without creating Practice History |
| Vault and Text actions share emphasis | Saved progressions are primary; Text is a secondary action | Matches the dominant repeated workflow |
| Potential modal for all results | Same-region expansion and search | Preserves spatial context and avoids extra navigation |
| Optional motion opportunity | No list entrance or keyboard-triggered motion | This high-frequency interaction must feel immediate and respect reduced motion |

## Locked implementation seam

Add a presentation-only candidate builder, an ID-only recent preference helper,
props/callback wiring in `App`, and the source-less list in
`ProgressionVoicingPracticeView`. Do not change P5.27 handoff, snapshot, resolver,
clock, transport, Vault schema, Bass Practice, or existing picker production code.
