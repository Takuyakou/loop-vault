# P5.30 Design

## Product problem

P5.29 established correct 1/2/4-chord harmonic timing. The remaining friction is presentation and rehearsal flow: the progression should stay visually compact, transport position should be obvious, arbitrary cards should be auditionable, optional reference voicings should play with transport, and Text Entry should support substantially longer real progressions.

## Layout flow

Approved vertical order:

1. Voicing source/family controls and Learn/Recall display control
2. CURRENT + NEXT
3. compact progression timeline with cyan playhead
4. chord details + centered keyboard visualization
5. BPM / count-in / transport / reference-sound toggle

The timeline is informational and interactive, but does not become a sequencer editor in this phase.

## Timeline geometry

Every code card uses the same fixed compact width and height. Duration is **not** represented by expanding card width. Instead:

- small `1拍` / `2拍` / `4拍` metadata may be shown;
- an optional tiny beat rail may be shown;
- the playhead takes 1, 2, or 4 beats respectively to traverse the same card width.

CURRENT/active/audition/focus can change border/background/outline only. No `scale`, flex growth, min-height change, padding change, or font-size change may alter geometry.

## Playhead

A cyan vertical playhead overlays the timeline and is a pure projection of the existing P5.29 transport position. It never owns time. Pause freezes it, Resume continues, Restart returns to the first event after existing count-in semantics, BPM changes change traversal speed through the same clock.

## Audio interactions

Card click/keyboard activation is a one-shot audition. It uses the card's currently resolved voicing, does not seek transport, does not set CURRENT, and does not alter loop count.

`お手本音` is a transport reference toggle. When enabled, the selected resolved voicing sounds once at each harmonic event boundary. No in-event re-strike pattern is added.

## Long Text Entry

Text Progression Entry becomes capable of a 32-bar phrase/song section with up to four chord tokens per bar. This is a bounded extension, not a grammar redesign.
