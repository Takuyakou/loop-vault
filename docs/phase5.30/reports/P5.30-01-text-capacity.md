# P5.30-01 — Text Progression capacity

## Outcome

PASS. Text Progression Entry now accepts a bounded maximum of 32 bars, 128
chord tokens and 8192 UTF-16 code units. The 4/4 grammar remains unchanged:
each bar still accepts exactly 1, 2 or 4 chord tokens with 4, 2 or 1 beat
durations respectively.

## Implementation

- Raised the canonical parser constants from 12 / 48 / 4096 to
  32 / 128 / 8192.
- Removed duplicated Draft and Vault save limits by importing the canonical
  Text Progression constants.
- Updated English help and Japanese diagnostics from the same constants.
- Kept the generic Draft/candidate contracts, Vault schema and `fileVersion`
  unchanged.

## Boundary and downstream evidence

- 32 bars are accepted and 33 bars fail closed.
- 128 tokens are accepted and 129 tokens fail closed without truncation.
- 8193 UTF-16 code units fail before token materialization.
- A 32-bar / 128-event fixture round-trips through parse, Draft, save,
  repository reload and all five Voicing Loop snapshots.
- The last event remains bar 32 beat 4 for one beat; every practice snapshot
  remains 128 beats long at the saved key and BPM.
