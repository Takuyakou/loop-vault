# P5.30-02 — Compact layout and playhead

## Outcome

PASS. The loaded Voicing Loop now follows the approved practice hierarchy and
uses one fixed-geometry horizontal timeline with a cyan playhead projected from
the existing P5.29 clock. No timer or musical state source was added.

## UI review

| Before | After | Why |
| --- | --- | --- |
| Learn/Recall lived inside the informational NEXT card | Display controls sit beside MY/LESSON at the top | Keeps controls together and leaves NEXT informational |
| Timeline wrapped after the transport | Timeline sits between CURRENT/NEXT and chord detail | Matches the practice reading order |
| Cards grew with label/timing content | Every card is fixed at 92 × 46 CSS px | Current, duration and long labels cannot shift geometry |
| Long progressions could wrap the page | Timeline has its own keyboard-focusable horizontal viewport | Keeps 128 events bounded without page overflow |
| Only the current card color indicated position | A cyan playhead crosses each fixed card while semantic current state remains | Adds precise position without relying on color or creating another clock |

The playhead position is derived from `currentEventIndex` and `chordProgress`
from the authoritative transport projection. At one BPM, half-way through a
4-, 2- and 1-beat event the playhead is half-way through the same 92px card;
only traversal time changes. Pause freezes the same projection, Resume
continues it, and loop wrap returns to the first card with the existing loop
counter.
