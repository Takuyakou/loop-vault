## Parser and alias inventory

src/domain/textProgression.ts limits input to 8192 UTF-16 units, 32 bars, 128
tokens. Simple whitespace-separated chords each occupy one bar. Bar notation
requires outer pipes and whitespace tokenization, allocating 4 / 2 / 1 beats
for 1 / 2 / 4 cells. Three cells fail closed. Comments, compact adjacency,
root/type spaces, repeat/rest/hold tokens are not implemented.

The supplied compact fixture fails. Its manually expanded fixture has 16 bars
and 34 cells, bar 4 with four cells. Repeated outer pipes on separate lines must
also be handled by a future tokenizer; flattening bar boundaries still leaves
B7(#9,#5) unparseable. Counting cells is NOT a successful musical parse.

Alias matrix measured with parseChordLabel:
- Accepted: BbM7, CM7, Cmaj7, C△7, Cm7, Caug, Csus2, Csus4, Cadd9,
  Cdim, C7(b9), C7(b9,#11,b13), Am9/C, Dm7/G.
- Rejected: CΔ7, Cadd11, Co7, C7(#9,#5), Comit3, C#5.
- M7/△7 canonicalize to maj7. Slash root/bass identities survive.
- Δ7 -> maj7 and o7 -> dim7 are potential unambiguous lexical aliases,
  subject to Stage01 authorization and tests.
- #5 is absent from Tension, schema accepted tensions and parser tokens.
  aug exists but cannot express dominant seventh plus #9 and #5.
  b13 is not an identity-preserving replacement: the existing b13 descriptor
  retains the natural fifth. Do not silently normalize #5 to b13.
- omit3 lacks a general representation. add11 may map to maj plus 11 only
  after confirming intended identity; not implemented here.

## Timing, Draft and persistence

Current Vault writes fileVersion 2 and accepts legacy 1/2. No new version is
introduced in this audit. SavedProgressionBlock supports startBar/endBar/
lengthBars, sourceStartBeat/sourceEndBeat, arbitrary positive event durations,
sparse starts and an empty chords array.

Executable JSON repository save/load tests preserve:
- control-fixture sounding events: E7 at 0/1, E7 at 1/1, Am7 at 3/3, G at 6/2;
  implicit rest at 2..3; block length 8;
- leading/trailing silence with a chord at 2/2 and block length 8;
- an all-rest empty chord list with block length 8;
- a continuous cross-bar chord at 0/6 followed by a chord at 6/2.
No quarantine, truncation, new fields or migration was needed.

These are representation probes, NOT claims that the Text UI can save them.
Current TextProgressionEvent duration type is 1|2|4. ManualCandidateDraft has
relativeStartBeat, numeric duration, selectedRange and lengthBars; Draft timeline
conversion copies starts/durations. createTextProgressionDraft currently rejects
empty events. The save payload carries chords but not the selected score extent.
The Text store validator requires start=0, contiguous whole bars, duration 1/2/4,
no bar-crossing event, and 1/2/4 events per bar. Tests prove it rejects gaps and holds.
createSavedTextProgressionBlock derives extent from sounding events, so trailing
silence would be lost unless the transient payload carries explicit score extent.

Stage02 can use existing persistent extent fields and sparse sounding events,
but must extend transient parser/Draft/save contracts and public validation.
Preserve exact attack boundaries for repeated chords; merge '=' into preceding
event duration, never merge repeated equal chord symbols. Empty/all-rest sessions
require an explicit runtime no-chord state, not a fake chord.

## Voicing Loop and audio

snapshot.ts rejects internal gaps and empty progressions. It subtracts the first
sounding onset and derives length from the last event, losing leading/trailing
silence even when Vault metadata retained it. Numeric cross-bar duration 6 is
already accepted when contiguous; schedule eventStarts remains [0,6].
Two equal chord events remain separate at [0,4].

clock.ts always selects a current chord by latest start, with no duration-end
check or rest projection. Simply relaxing snapshot validation would show a stale
chord during silence. Current/Next, keyboard, timeline and empty-session handling
must explicitly project rest from the same musical clock.

ProgressionVoicingTransport schedules each supported event separately; repeated
identities re-attack. Extending one duration creates no intermediate scheduled
attack. It uses the duration for triggerAttackRelease. Resume/sample-ready
attackCurrentVoicing currently picks by latest start; without an end check it
could attack the previous chord while resting. Rest boundaries must release owned
reference sound and suppress targets, including release tails, while metronome
and clock continue. No second timer/engine is necessary.
Current transport regression passes; actual ReChord control audio is not yet
implemented or claimed tested.
