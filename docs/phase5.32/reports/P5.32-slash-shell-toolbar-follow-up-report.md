## Slash Shell resolution

Slash identity is retained as `X/Y`. A separate slash bass is resolved as the
single left-hand target and the approved numerator Shell or upper structure is
resolved in the right hand. No chord is canonicalized to its numerator, and no
Source MIDI, Custom, Basic, or generated fallback is used.

| Fixture | Left hand | Right hand | Identity guard |
|---|---|---|---|
| `Eadd9/F#` | F# / Bass / recommended L5 | E, G#, B / 1, 3, 5 | D# is not invented; the chord remains `Eadd9/F#` |
| `Dadd9/E` | E / Bass / recommended L5 | D, F#, A / 1, 3, 5 | C# is not invented; the chord remains `Dadd9/E` |
| `Gmaj9/A` | A / Bass / recommended L5 | G, B, F# / 1, 3, 7 in Root Shell | The approved major-family Shell is reused without removing `/A` |

For `add9`, support is deliberately narrow: Root Shell is supported only when
the separate slash bass supplies the numerator's ninth. Rootless `add9`, an
unrelated slash bass, and unaudited families remain `UNSUPPORTED_RULE`.
Existing characteristic-tone rules remain authoritative; for example, m7(b5)
keeps b5 rather than simplifying to an ordinary minor seventh.

CURRENT and NEXT use the same resolved hand split. The existing fingering engine
assigns the one-note left hand and right-hand notes, while the keyboard continues
to render left hand in Gold, right hand in Cyan, and the L/R finger labels.
Personal fingering overrides retain priority.

## Toolbar

| Before | After | Why |
|---|---|---|
| `MY` and `LESSON` group labels | Four direct choices: Source MIDI, Custom, Shell, Left-hand | Removes internal classification that did not help practice selection |
| `SHELL TYPE` plus long subtype labels | Conditional `Root 1·3·7` and `Rootless 3·7` buttons | Keeps the Shell choice compact and appears only while Shell is active |
| Repeated top-right Shell badge | No duplicate badge | The active button already communicates selection and preserves vertical space |
| Long visible names only | Short visible names; full `Root Shell 1·3·7` and `Rootless Shell 3·7` accessible names/tooltips | Preserves clarity for assistive technology without toolbar overflow |

The existing toolbar surface and controls are reused. No new design system,
animation, or explanatory section was added. Desktop page vertical/horizontal
overflow, toolbar overflow, 320px, effective 200% scaling, reduced motion, and
axe serious/critical checks remain covered by the existing focused/full E2E
suites.
