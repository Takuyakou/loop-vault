読み方

C4=MIDI60。音は低い順。指番号は1=親指、2=人差し指、3=中指、4=薬指、5=小指。L/Rは左右。

全具体例の音高・オクターブ・運指は今回の提案です。先生資料の逐音転記ではありません。理論構造の出典と分けてください。

「省略なし」は音名集合の被覆です。実際に聴こえる声部、重複、音域、機能まで同一であるという意味ではありません。

重要な訂正・判定

  • Eadd9/F# = LH F# + RH E,G#,Bで全構成音を満たす。add9には7thを自動追加しない。

  • Gmaj9/A = LH A + RH G,B,F#はD(5)省略。Dがないため厳密なA13sus4ではない。

  • Am11/BのBは9th。基本三和音／7th coreの外でも、拡張和音の外音ではない。

  • Shellの語義は教材で違う。指番号ではなく具体的な度数式を実装上の契約にする。

  • Slash Bassを低音として鳴らすことと、機能Rootと認定することは別。

実装の契約（提案）

  • Source MIDI / Customは生成Familyではなく出所。元の音高・オクターブ・時刻・重複を保ち、変換は別Variantへ明示コピーする。

  • 指定Bass、固定Melody、可聴の外部パートを含む構成音被覆をHard Constraint候補として扱う。架空のBass補完でPASSにしない。

  • Literal / Performance reduction / Creative enrichmentを分離。省略音と追加音を説明に残す。

  • Slash BassはupperRootを置換しない。Bass起点の別解釈は候補メタデータに留める。

  • Closed/Open/Drop2、左右分担、A/B、出所、コード種別を単一enumへ混在させない。

  • Drop2は指定された上声4音群の上から2番目だけを1oct下げる。Bass制約が壊れる候補は拒否する。

  • 音域・最大手幅・音色・運指候補・近接コードを別途評価。C4=MIDI60で内部処理し表示オクターブの差に依存しない。

  • 候補間最適化は途中の遷移だけでなく、Loop末尾→先頭も評価。最小距離だけを音楽の唯一の正しさにしない。

  • Bass+5th追加はSlashでは和声の変更になり得る。Eadd9/F#へC#を加えれば別の構成音が増える。

  • 手指推定は候補とConfidenceを返す。MIDIだけから実演奏者の指を確定しない。

  • Reharmonization（裏コード等）はVoicingの変更とは別に履歴保存する。

  • 既存Source/Custom fail-closed、unsupportedとgeneration-errorの分離、single-clock、無採点の保護仕様を保持する。

Melodyは独立レイヤー。指定Chord Toneの被覆には使えるが、短い非和声音を全てコード記号へ追加しない。C/E上のD旋律が常にCadd9/Eへの改名を要求するわけではない。
