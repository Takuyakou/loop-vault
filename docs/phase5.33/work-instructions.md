# P5.33 Work Instructions

## Scope

Accuracy is more important than speed. Treat the supplied 33-rule JSON and
Rulebook as research/proposal inputs, never as runtime configuration.

### P5.33-00 — Repository + research audit

Deliver the exact base and branch, current resolver/mode inventory, legacy ID
compatibility map, parser representability matrix, first-wave promotion matrix,
teacher evidence/context matrix, protected production surface list, and the
Stage01 go/no-go decision. Do not add new runtime rule behavior.

### P5.33-01 — Domain axes + Golden Corpus

After separate authorization, implement independent source, study category,
rule family, variant, coverage, context and provenance axes. Add the research
material as test/reference corpus rather than runtime-loaded configuration.

### P5.33-02 — First-wave deterministic rules

After separate authorization, promote only Stage00-approved records with
deterministic tests, explicit unsupported boundaries, provenance, coverage,
context and octave policy. Do not enable an empty study category.

### P5.33-03 — Candidate variants + cyclic ranking

After separate authorization, add bounded deterministic candidates and include
the last-to-first loop transition in ranking without adding a timer.

### P5.33-04 — Adopted upper UI and bounded lower normalization

After separate authorization, implement the approved SOURCE/STUDY/DISPLAY and
CURRENT/NEXT/status surfaces. The only permitted lower-surface changes are the
fixed 88-key A0–C8 keyboard normalization and larger Transport targets described
by contract 15. Sidebar, progression and clock/audio behavior stay protected.

### P5.33-05 — Hardening / acceptance

Run the complete semantic, regression, responsive, accessibility, production,
security/privacy, hygiene and clean-status gate set. Stop at renewed human
acceptance.

## Non-goals

- no blind runtime import of all 33 research records;
- no automatic reharmonization, AI melody or teacher-material transcription;
- no generic rootless behavior without its required Bass context;
- no scoring or correctness judgment;
- no Vault schema, fileVersion or migration change;
- no second clock, timer or playback engine;
- no sidebar or progression redesign;
- no merge, push, tag, release or P5.34.

## Definition of Done

Each stage is an independent commit with its required gates recorded against an
exact commit. P5.33-00 is done only when the research intake is verified, every
current compatibility surface and requested promotion/context matrix is
documented, production source is unchanged, focused current-behavior regression
passes, phase docs validate, the worktree is clean, and execution stops before
P5.33-01.
