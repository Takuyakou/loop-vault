## 1. Responsible transformation boundary (where 1/4 bars become dashes)

CONFIRMED. The excessive bar/dash fragmentation is created **at the meter-derived
bar/beat labeling stage**, not at segmentation.

For the same 4-chord progression (C Am F G, 16 notes) the meter 1/4 vs 4/4
comparison shows the segmentation layer is identical and only the bar labels
diverge:

| Metric | A (1/4) | B (4/4) | C (none) |
|---|---:|---:|---:|
| source notes | 16 | 16 | 16 |
| evidence notes | 16 | 16 | 16 |
| windows | 4 | 4 | 4 |
| raw timeline items | 4 | 4 | 4 |
| smoothed timeline items | 4 | 4 | 4 |
| boundaries | 3 | 3 | 3 |
| block items | 6 | 1 | 1 |
| occupied bars | 4 | 2 | 2 |
| formatted bars | 7 | 2 | 2 |
| dashes | 3 | 0 | 0 |

`windowCount`, `rawTimelineItemCount`, `smoothedTimelineItemCount`, and
`boundaryCount` are **identical** between A and B. Only `occupiedBarCount`,
`formattedBarCount`, and `dashCount` change. The responsible code is the
meter-derived bar/beat label in `buildWeightedWindows`
(`bar = floor(startBeat / barLengthBeats) + 1`): under 1/4 (`barLengthBeats = 1`),
2-beat windows land on odd bars (1,3,5,7) leaving even bars empty, which
`formatProgressionText` renders as `—`. `blockItemCount` is also meter-driven
(`extractBlockCandidates` slides 2/4/8/16-bar windows over `totalBars`: 8 → 6
blocks, 2 → 1 block).

## 2. Meter experiment interpretation

A (1/4) → 7 bars / 3 dashes; B (4/4) → 2 bars / 0 dashes.

```text
meter metadata contributes materially to fragmentation = SUPPORTED-HYPOTHESIS
```

It is **not** `CONFIRMED root cause` of LF-MIDI-001: the private fixture has not
been run yet, and this synthetic case only demonstrates the meter label effect,
not the chord-identity errors.

## 3. B vs C (meter substitution vs meter-independent segmentation)

B (4/4 view) and C (source-extent meter-independent) produce **nearly identical**
results for the progression (both 2 bars / 0 dashes / 1 block). The only
difference is at the window-grid rounding: C uses the exact source extent, B
rounds up to whole bars. For a 2-beat single chord, A/B produce 2 windows while
C produces 1 (B's grid extends to a full 4-beat bar).

```text
For fragmentation, a bounded meter-handling solution (4/4 view) is sufficient;
meter-independent segmentation does not materially outperform it on these fixtures.
```

This is a bounded conclusion from synthetic data only, not a decision to
implement a 4/4 correction.

## 4. D onset sweep

The PPQ-normalized sweep `0, 1, 2, 4, 6, 12` ticks (PPQ96) shows **minimal
effect** on the progression (all counts identical across tolerances). The default
chord profile already uses duration overlap (`overlaps` in `legacy.ts`), so onset
snapping only matters where the overlap predicate or an onset-keyed path flips.

- T02/T03 (bass +1/+4 ticks): window count changes 2→1 only at tolerance ≥4.
- T04 (distributed jitter): a boundary (bnd 0→1) appears at tolerance 6 — a
  potential false merge, not a stability win.
- No onset tolerance stabilizes a jittered chord better than C, and no tolerance
  produces semantic damage on hard negatives (T06 boundary, T07 arpeggio, T08
  slash-bass all unchanged).

```text
onset tolerance materially helps = REJECTED-HYPOTHESIS (on these fixtures)
```

No production threshold is promoted. The first tolerance at which a boundary
changes is 4–6 ticks; the "safe region" (no false merge) is 0–4 ticks and is
narrow, so D does not justify an onset-clustering phase on its own.

## 5. Re-strike (T05)

Full chord → bass re-strike → same chord: boundary count 0 across A/B/C/D; the
re-strike produces one timeline item (same harmony). Consistent with
"re-strike is not a direct boundary primitive"; its only observed effect is the
attack/onset evidence (sourceNoteCount 4→5), not a boundary.

## 8. Closed-vocabulary classification

- S02 (`G7(#9,b13,no5)`): `#9`/`b13` are representable as dom7 alterations, but
  "no5" is **not** representable in the closed 21-quality vocabulary; the legacy
  matcher collapses to `G7` (dom7 core) — representability-limited, not purely a
  ranking failure.
- S04 (`B11(no5)`): not representable as-is; the matcher emits `B9`
  (inventing F#, omitting E) — a ranking + representability failure.
- S01 (`Abmaj9`): fully representable (`maj9`); the legacy matcher ranks `Am7b5`
  higher — a pure ranking/identity failure (quality evidence candidate).
- S05 (`C/E`): representable (maj + bass E); the matcher emits `Edim` — a
  bass/identity failure.

## 10. Required conclusions

1. **Does meter cause/materially contribute to bar/dash fragmentation?** Yes
   (SUPPORTED-HYPOTHESIS), via the meter-derived bar labels.
2. **Is 4/4 substitution sufficient vs meter-independent segmentation?** On
   synthetic data, 4/4 view is sufficient; C does not materially improve on B.
3. **Does onset tolerance materially help?** No (REJECTED on synthetic fixtures).
4. **False-merge cost as tolerance grows?** A boundary appears at tolerance 6 on
   the jitter fixture (false-merge risk); safe region 0–4 ticks, narrow.
5. **Does bass re-strike contribute?** No boundary effect (attack evidence only).
6. **Do P5.24/P5.26 run on this topology?** Only under 4/4; not under 1/4
   (unsupported-meter), and flag-off by default.
7. **Which chord-identity failures remain after segmentation is controlled?**
   S01, S02 (partial), S04, S05.
8. **Remaining failure class?** Ranking/identity (S01, S05) and
   representability (S02, S04), not segmentation.
9. **Rejected hypotheses?** onset jitter, re-strike-as-boundary,
   identity-is-meter-driven.
10. **Unresolved?** LF-MIDI-001 private fixture (not run yet); whether quality
    evidence (phase4-v1) corrects S01/S04/S05.
