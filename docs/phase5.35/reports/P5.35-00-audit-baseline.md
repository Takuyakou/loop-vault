## Insertion seam (smallest safe)

The carryover mechanism is in production `src/domain/midi/legacy.ts`:

- **`buildWeightedWindows` (l.353)** accumulates per-note weight
  `overlapBeats × beatPositionFactor × rangeFactor × velocityFactor × roleFactor ×
  simultaneityBonus` into `histogram[pc]` for **every note overlapping the window**.
  A note sustained/carried from a neighboring harmony contributes by its overlap
  with **no attack-vs-carryover distinction** — the exact contamination P5.34 found.
- **`rankWindowCandidates` (l.497) → `scoreTemplates(histogram, bassPc, previous, scoring)`**
  ranks candidates on that (possibly contaminated) histogram; `matchWindow` (l.420)
  returns top-1. `bassPc = maxIndex(bassHistogram)` is the structural bass.

**Seam:** a new **shadow module `scripts/p535/`** (mirroring `scripts/p534/`) that,
given the same parsed `data.notes` + `roles` + window bounds, (a) classifies each
note's temporal role from `note.startTick` vs the window start, (b) emits a shadow
histogram + reason codes, and (c) re-ranks the **exact current candidate set**
(`scoreTemplates`) to compare shadow top-1 vs production top-1. No edit to
`buildWeightedWindows` / `matchWindow` / `scoreTemplates` until P5.35-04.

### Audit answers

1. Per-note weights: `buildWeightedWindows` (formula above).
2. Failing lane: `rankWindowCandidates`/`scoreTemplates` top-1 on the contaminated
   histogram (correct narrow chord generated but out-ranked); `analyzeMidiWithRankingScores`
   is the production ranking lane.
3. Temporal-role metadata computable shadow-only: yes — `attack` iff
   `note.startTick >= windowStartTick`, else carryover/sustained; derivable purely
   from already-parsed notes + window bounds, no mutation.
4. Reuse candidate set: yes — call `scoreTemplates` on the shadow histogram or
   re-rank the same `scored[]`.
5. Deciding components: template score → confidence, `bassPc`, quality coverage;
   contamination inflates density so broad templates over-cover.
6. Attributable: histogram is a sum but re-walkable from the overlapping notes →
   per-note (pc, weight, role, attack/carryover) reason codes are reconstructable.
7. Sustained across windows: a note spans windows via `overlaps()`/`overlapBeats`;
   cross-window identity detectable via `note.startTick`.
8. Prev/next evidence: `rankWindowCandidates` already threads `previous?: ChordSymbol`;
   next-window lookahead is available from the `windows[]` array — no new boundary engine.
9. Reusable: `roleFactor`, `melodyWeight`, `beatPositionFactor`, `velocityFactor`,
   `rangeFactor`, `simultaneityBonus`.
10. Threshold suites: `scripts/p534` + `src/domain/midi` analyzer domain (below).
