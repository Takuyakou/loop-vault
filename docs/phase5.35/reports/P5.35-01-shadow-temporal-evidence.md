## Insertion seam (unchanged from P5.35-00)

Production carryover lives in `src/domain/midi/legacy.ts`: `buildWeightedWindows`
(l.353) accumulates a per-note weight into `histogram[pc]` for **every** note
overlapping a 2-beat window, with **no attack-vs-carryover distinction**;
`rankWindowCandidates`/`scoreTemplates` (l.497) then rank on that possibly
contaminated histogram, and `matchWindow` returns top-1.

The classifier is a **separate shadow module** (`scripts/p535/`, mirroring
`scripts/p534/`). It reads the same parsed `data.notes` + optional track `roles`
and labels each per-window note contribution. It calls **no** production ranking,
mutates nothing, and does not touch `buildWeightedWindows`, `matchWindow`, or
`scoreTemplates`. Wiring the shadow into any comparison against production is
P5.35-02; production integration (if ever) is P5.35-04.

## Classifier inputs

Reuses production's own evidence filter `selectChordEvidenceNotes(data.notes)`
(drops percussion/non-chord voices) and `normalizePc`, so the analyzed note set
matches production parity. Window grid is **meter-independent**: a fixed
`durationBeats` (default 2) grid over the source-note beat extent — it never reads
`timeSignature`/bars and never touches the meter-fragmentation family (P5.34
family 1). Options: `attackToleranceTicks` (default 2, near-boundary robustness —
NOT production onset clustering), `transientMaxBeats` (default 0.35).

## Role definitions (and why onset is only ONE feature)

| Role | Condition (in priority order) | Reason code |
|------|-------------------------------|-------------|
| `STRUCTURAL_BASS` | lowest bass-ish contribution (pitch < 60 or `bass` role) | `structural-bass` |
| `SHORT_TRANSIENT` | duration `< transientMaxBeats` beats | `short-duration-transient` |
| `CURRENT_ATTACK` | attacks within `[start − tol, end)` | `attack-in-current` |
| `CURRENT_SUSTAIN` | sustained **and window introduces no new pitch class** (held/pad/re-strike) | `held-window-no-new-harmony` |
| `COMMON_TONE` | sustained **and** its pc is freshly attacked in this window | `shared-with-adjacent-state` |
| `CARRIED_IN_SUSTAIN` | sustained, pc **foreign** to a *competing new harmony* (≥2 new pcs), supported only by prior state | `prior-state-only-support` |
| `UNCERTAIN` | none of the above | `ambiguous-context` |

The **forbidden shortcut** (`startTick < windowStart → carryover → weaken`) is not
used. Onset only participates via `attackInWindow`. A sustained note becomes
`CARRIED_IN_SUSTAIN` **only** when a competing new harmony (`newAttackPcs =
attackPcs \ sustainedPcs`, size ≥ 2) attacks in the window **and** the note's pc is
absent from that new state. A held chord (`newAttackPcs = ∅` → `heldWindow`)
stays `CURRENT_SUSTAIN`; a sustained pc that is re-attacked in the new state is a
`COMMON_TONE`. Structural bass is reported as its own role regardless of onset (a
correct bass with a wrong root is a ranking concern, decided later, not here).
Confidence values are role confidences in [0,1], **not** chord scores.

## Results (from `scripts/p535/temporalEvidence.test.ts`, 15 tests, all pass)

- **Held current harmony (hard negative):** `heldHarmony` window 1 is `heldWindow =
  true` with **0** `CARRIED_IN_SUSTAIN` and ≥1 `CURRENT_SUSTAIN`. A held chord is
  not mislabeled wholesale as carryover.
- **Pad / long sustain:** `padSustain` windows 1 and 2 held, 0 carryover.
- **Common tone (safety):** `commonTone` window 1 yields ≥1 `COMMON_TONE` (the
  sustained G re-attacked by Am9) and **0** carryover — a shared pitch across a
  change is not auto-classified as contamination.
- **Contamination (positive):** `contamination` window 1 yields exactly **3**
  `CARRIED_IN_SUSTAIN` (C/E/G foreign to Bm7), **1** `STRUCTURAL_BASS` (B), and ≥3
  `CURRENT_ATTACK` (D/F#/A). Distinct carryover evidence is produced.
- **Boundary robustness:** for onset offsets −1, 0, +1 ticks the classifier
  produces **0** carryover and **0** uncertain in every case — one-tick numeric
  noise never manufactures a semantic role flip.
- **Structural bass:** the bass of `structuralBassSlash` is labeled
  `STRUCTURAL_BASS` with pc = E (4); the classifier does not force the bass to the
  root — bass estimation is left unchanged (P5.34: bass may be correct while root
  is wrong).
- **Re-strike / arpeggio / genuine transition:** re-strike stays a held window (no
  false boundary); arpeggio steps are real attacks (0 carryover, 0 uncertain);
  genuine C→Am carries nothing across.
- **Source immutability:** `JSON.stringify(data)` is identical before and after
  classification.
- **Determinism:** two runs on the same input produce byte-identical output (no
  clock/random).
- **Role-distribution summary:** clean (`heldHarmony`) vs contaminated
  (`contamination`) `roleCounts` are distinct — clean has 0 carryover, contaminated
  has > 0. This is the shadow diagnostic signal P5.35-02 will consume.
- **Stress / boundedness:** 200 back-to-back chords (600 notes / 100 windows) — the
  sum of `roleCounts` equals `contributionsProcessed` (each contribution counted
  exactly once), confirming bounded per-window cost with no unbounded search.

## Remaining uncertainties (for P5.35-02+)

- `UNCERTAIN` is currently only reached for a sustained, non-bass, non-transient pc
  that is neither shared nor prior-supported in a competing window; real corpora may
  populate it more — P5.35-02 should surface its rate.
- The single-note structural-bass pick is lowest-pitch/`bass`-role; multi-voice bass
  ambiguity is out of scope (P5.34 said do not change bass detection without
  evidence it is wrong).
- `competingNewHarmony ≥ 2` is a deliberate threshold (`ponytail:` heuristic; a
  single foreign attack is not yet treated as a competing state). Whether 1 suffices
  is a P5.35-02 tuning question, measured against the promotion gates — not weakened
  here.
- Whether reduced carryover contamination actually flips contaminated-window **top-1**
  is explicitly deferred to shadow ranking (P5.35-02) and the Contract-04 promotion
  gates (P5.35-03).
