## Native-vs-fixed-candidate methodology

Production `scoreTemplates` ranks the **same full candidate set** (12 roots × the
fixed template vocabulary) on every window — a candidate is never "absent", only
re-ranked. So "native sub-window analysis" and "fixed-candidate counterfactual"
coincide: both rank the constant candidate set on B0 / B1 evidence. Ranks come from
a **parity-guarded replica** of `scoreTemplates` (default scoring),
`scripts/p536/shadowScore.ts`.

**Parity guard (§6):** the replica's top-1 label equals production `matchWindow`'s
on **every** window tested — 21/21 synthetic-fixture windows and **98/98**
LF-MIDI-001 windows (W2 + 1-beat), 0 mismatches. The ranks below are therefore
production-faithful.

This is **Case B**, not a bass-extraction failure:


Consistent with P5.34/P5.35 (the bass estimate is not the failure).

## P5.37 implications (no fix decided here, §30)

A naïve production "window = 1 beat" is **rejected** by the hard negatives (rolled,
syncopation, layered extended harmony, genuine slash all degrade under a fixed
1-beat split). P5.36-04 must choose a **minimal, bounded** target from options such
as: adaptive harmonic-state / attack-state segmentation, local evidence selection
within the 2-beat window, or a union-chimera guard that only re-examines windows
exhibiting the confirmed signature (root wins neither beat + support spans both +
bass from one beat) while leaving coherent windows (held / re-struck / layered /
slash) untouched. The synthetic hard negatives are the promotion gates for any such
target.
