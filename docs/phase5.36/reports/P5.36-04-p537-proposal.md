## 3. Existing-code reuse audit (read-only, §6)

The repository already contains a P5.24/P5.26 **local-harmonic-state segmentation +
consolidation** subsystem:

- `src/domain/midi/segmentation.ts` — `generateBoundaries` emits boundary
  candidates with reasons **`bass-change`**, **`strong-onset-burst`**,
  `pitch-profile-change`, `silence-gap` (exactly Family B's confirmed signals);
  `buildSegmentLattice` builds bounded variable-length segments (`maxEndsPerStart`
  default 8, `maxSegmentBeats` default = beatsPerBar).
- `src/domain/midi/harmonicState/` — `fragmentConsolidatorCore.ts` makes
  `P524BoundaryDecision` of `"merge-same-state" | "split-strong-change"`;
  `harmonicIdentity.ts` identifies a state from a PC signature **using the existing
  `chordTemplates` vocabulary** (`labelP524IdentityWithStableBass`);
  `shadowEvidence.ts` estimates bass lane + harmonic rhythm;
  `localHarmonicStateShadow.ts` (P5.26) builds `P526LocalEvidenceCell`s with
  boundary evidence `persistent-bass-change` / `persistent-upper-change` /
  `same-pitch-material` / `stable-upper-structure`.
- `src/domain/midi/localHarmonicStateIntegration.ts` — the integration seam
  `prepareLocalHarmonicStateAnalyzerOptions(bytes, options)`, wired in
  `analyzeMidi` (`analysis.ts:62`) behind the feature flag
  **`enableLocalHarmonicStateConsolidation`** (OFF by default; default mode
  `phase4-v1`). Every unsupported/ambiguous case returns a legacy fallback
  (`unsupported-analyzer-mode`, `unsupported-meter`, `legacy-fallback`) — an
  **OFF = exact legacy** design already in place.

**Why it does not already fix LF-MIDI-001:** the P5.26 path is **hard-gated to
4/4**. `prepareLocalHarmonicStateAnalyzerOptions` returns
`{applied:false, reason:"unsupported-meter"}` when `data.timeSignature !== "4/4"`
(localHarmonicStateIntegration.ts:82), and the input builder hardcodes
`meter:[4,4]` and `totalBeats = data.totalBars * 4` (line 189);
`P526LocalHarmonicStateShadowInput.meter` is typed `readonly [4,4]`. LF-MIDI-001 is
1/4, so the engine **refuses to engage** and falls back to legacy — which is exactly
the failing path.

**Reuse verdict: PARTIAL REUSE (strong).** The boundary detection, split/merge
decisions, harmonic-identity vocabulary, integration seam, feature flag, and
legacy-fallback/rollback are all reusable. The **only** structural change needed is
to make the local-harmonic-state path **meter-independent** — justified because
P5.36-02 proved the 2-beat evidence grid is already meter-independent (a "beat" =
`ticksPerBeat` ticks regardless of the meter tag). This is far smaller and safer
than a new segmentation engine.

**Caveat for P5.37-00 (must verify, not assumed here):** (a) that the consolidation
path actually **splits** a mixed 2-beat region (not only merges fragments) and
re-ranks toward a coherent candidate; (b) the exact relationship between this path
and the **default `phase4-v1`** analyzer (the P5.36 wrong-root labels were measured
on the legacy `scoreTemplates` lane via `diagnoseLegacyWindowCandidates`; P5.37-00
must confirm the same failure on the default path and that the seam covers it). If
(a) or (b) fails, fall back to Option S2/S1 below.

## 6. Exact insertion seam (§25)

- **Fallback / OFF behavior:** unchanged — flag OFF or any `unsupported-*` /
  `legacy-fallback` reason returns **exact legacy** output. No default-mode change

## 12. Complexity bound (§18)

Bounded by construction: `generateBoundaries` is O(notes); `buildSegmentLattice`
caps segments per start (`maxEndsPerStart` = 8) and length (`maxSegmentBeats`), so
per-window work is bounded and there is no combinatorial explosion over input
length; identity lookup is a precomputed PC-signature map. P5.37 must state and test
an explicit bound (operations vs input length) and accept a small analysis-time
increase in exchange for correct harmonic-state reconstruction (§18), never
unbounded search.

## 13. Automation strategy (§19)

Maximize automated gates: synthetic fixtures, the LF-MIDI-001 local fixture, the
semantic corpus, the hard negatives, full analyzer regression, privacy tests,
determinism, and a performance/boundedness test — all automated. Human acceptance
is limited to a final confirmation.

source-truth architecture, no vocabulary expansion, no change to Source Voicing /
Bassline. The confirmed problem is harmonic evidence mixing; scope stays there.
