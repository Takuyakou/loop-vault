## S0 / S1 / S2 findings

- **S0 — current 4/4 behavior.** The shadow seam applies on a dense 4/4 two-region
  fixture (C major → A minor): `applied = true`, **2 coherent states**, a
  `split-structural-change` exactly at the C→Am change (boundary trace `mmmSmmm`).
  The engine and seam are correct for 4/4.
- **S1 — mechanical `beatsPerBar = 1` generalization (source-faithful for 1/4).**
  On a *dense* 1/4 two-region fixture (every beat a full held chord),
  `applied = false`, reason **`ambiguous-local-evidence`**. The engine reaches its
  bar-level harmonic-rhythm machinery (`deriveBarEvidence`, the 1/2/4/8
  quarter-beat period model) which is **degenerate for 1-beat bars** → some bar's
  `quarterBeats` is `"unknown"` → `estimateInternal` returns
  `ambiguous-local-evidence` → legacy fallback.
- **S2 — meter-neutral (bar-position prior neutralized).** Same dense 1/4 fixture,
  `neutralizeBarPositionPrior = true`: **identical fallback**
  (`ambiguous-local-evidence`). The neutralized prior lives in `decideBoundary`,
  which runs *after* the bar-period gate — so the fallback happens **before** the
  prior can matter. Neutralization does not change the outcome.

## The definitive finding — reuse insufficient via minimal parameterization

Beyond the Type-A/B/C 4/4 assumptions classified in the BLOCKED report, the engine
has **Type-D, truly-4/4-dependent layers** that a minimal `beatsPerBar`
parameterization does **not** generalize:

1. **Bar-level harmonic-rhythm period model** — `deriveBarEvidence` scores periods
   `1/2/4/8` quarter-beats *within a bar* (`patternSimilarity` to `[1,2,3]`/`[2]`,
   `exactLocalPeriod`). This model presumes a multi-beat bar; with `beatsPerBar = 1`
   the bars are single beats and the model yields `"unknown"`, forcing
   `ambiguous-local-evidence`.
2. **Strict per-cell evidence gate** — `insufficient-local-evidence` fires when *any*
   per-beat cell has weak/absent upper coverage. The 1/4 topology's sparse /
   "excessive empty" cells (noted in the LF-MIDI-001 known-failure) trip this gate.

**Conclusion:** the authorized minimal parameterization successfully lets the
engine be *invoked* on non-4/4 (no longer `unsupported-meter`), but it then **falls
back to legacy** at these deeper 4/4-tuned gates. The P5.36-04 "PARTIAL-REUSE
(strong)" assessment is **empirically downgraded**: reusing the existing engine via
a *minimal* generalization does **not** fix Family B. Making it work would require
generalizing the bar-period model and relaxing the cell-evidence gate — a
substantial redesign that approaches inventing a new segmentation (which §8
forbids), not a minimal parameterization.

## Recommendation / decision requested

The minimal-parameterization reuse path is insufficient. Choose the P5.37 direction:

1. **Deeper generalization of the existing engine** — make the bar-level
   harmonic-rhythm model and the cell-evidence gate meter-independent (a larger,
   non-minimal change; must be evaluated against the §8 "don't invent a new
   segmentation" caution). Keeps the vocabulary/scorer unchanged.
2. **An alternative Family-B fix** that does not depend on the bar-period model —
   e.g., a bounded local-evidence partition applied at the candidate-ranking layer
   only for windows exhibiting the P5.36-confirmed union-chimera signature (root
   wins neither beat + support spans both + bass from one beat), leaving coherent
   windows untouched.
3. **Keep the (b') parameterization** as a foundation and pursue (1) under a further
   authorization; or revert it if (2) is chosen.

The (b') parameterization + shadow seam are retained (behavior-preserving,
parity-safe) as the evidence basis; if direction (2) is chosen, they should be
reverted.
