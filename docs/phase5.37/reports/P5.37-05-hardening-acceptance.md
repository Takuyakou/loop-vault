## DEFAULT-ON decision

```text
DEFAULT-ON = NOT APPROVED
```

All §4 hard gates pass for the ON *behavior*, and default-ON is safe against the
existing suite. It is **not** approved as the **default** for two engineering
reasons, neither of which faults the fix itself:

1. **Cost/benefit as a universal default.** The trigger fires on **0%** of normal
   4/4 material, so default-ON would impose the ~2.5× per-analysis overhead on every
   user for a correction that never fires for them; the benefit is confined to
   1/4-mixed files. That is the wrong trade for a silent default.
2. **Unconfirmed additional triggers.** 4 of the 8 LF triggers are SUPPORTED but not
   oracle-CONFIRMED. Making the correction the silent default applies an unverified
   change to those windows (and any similar user-file windows) without ground truth.

Therefore the fix ships as an **opt-in** (`enableUnionChimeraPartition`, default
OFF): fully working, test-locked (ON == promoted shadow), and reversible. Files that
need it (1/4-mixed / confirmed wrong-root material) enable the flag; normal analyses
pay nothing and are byte-identical to legacy.

## Rollback state

Flag retained; default OFF. `true` = promoted v1; `false`/omitted = exact legacy.
Flag removal is out of scope (a future decision).

## Next research (to revisit default-ON)

1. Reduce the overhead: reuse the main-loop per-window ranking and only evaluate B0/B1
   for windows that could be chimeras, instead of re-ranking W2/B0/B1 unconditionally
   (an implementation optimization, not a policy change).
2. Obtain ground truth for the 4 additional same-family windows to move them from
   SUPPORTED to CONFIRMED (or reveal a needed guard — which would be a new policy
   version, evaluated from Stage-01).
