## Production path audit

Current default analysis is `phase4-v1`. Its Family-A path is:

```text
raw time signature
  -> timing.beatsPerBar
  -> parser.parseMidi totalBars
  -> legacy.buildWeightedWindows bar/beat assignment
  -> legacy.smoothTimelineWithRankingScores
  -> fullTimeline (source bar/beat coordinates)
  -> legacy.extractBlockCandidates
  -> candidateBlock.buildCandidateEvents
  -> candidateBlock.summaryFromEvents
  -> candidate.summaryText / UI

fullTimeline or saved candidate chords
  -> progressionText.formatProgressionText
  -> "-" empty-start cells
```

The exact point at which source-bar count becomes presentation topology is not a
single formatter. It starts when `data.totalBars` and `barLengthBeats` bound and
label the window timeline, then continues when `extractBlockCandidates` enumerates
2/4/8/16 **source-bar** windows. Both block summaries and later text formatting
consume those bar labels.

## Required audit questions

1. **Which functions compute `beatsPerBar` / `barLengthBeats`?**
   `timing.beatsPerBar` parses the meter. `parser.parseMidi` uses it as
   `barLengthBeats` to compute `totalBars`. `legacy.analyzeMidiWithRankingScores`,
   `legacy.buildWeightedWindows`, block builders, save conversion, playback, and
   UI consumers independently call or receive the same value.
2. **Which functions assign timeline items to bars?**
   `legacy.buildWeightedWindows` assigns
   `bar=floor(startBeat/barLengthBeats)+1` and the corresponding beat. Family B
   may partition a fixed two-beat window before
   `smoothTimelineWithRankingScores`, but it retains source-meter coordinates.
   `hybrid.timelineFromHybridPipeline` and `candidateEventsAsTimeline` use the
   same absolute-beat-to-source-bar formula on their paths.
3. **Which functions build blocks?**
   The production default calls `legacy.extractBlockCandidates`, which calls
   `candidateBlock.buildCandidateEvents` and `summaryFromEvents`. Other analyzer
   modes use `blocks.extractHybridBlocks`; coverage modes use
   `coverageCandidates` and `occurrence`. All currently accept source
   `totalBars` plus source `beatsPerBar`.
4. **Which functions emit placeholders?**
   `progressionText.formatBar` emits ASCII `-` when no timeline item starts in a
   bar. `candidateBlock.summaryFromEvents` separately emits `—` for a true
   carry-in sustain and `N.C.` when no event overlaps. These meanings must not be
   conflated.
5. **Does UI consume source bars or only formatted grouping?**
   It consumes both. Capture displays `result.totalBars`, `SongMiniMap` receives
   source `totalBars`, `beatsPerBar`, timeline, and candidates, and
   `ProgressionGrid` constructs visible cells from `ChordTimelineItem.bar/beat`.
   Candidate cards also display source `startBar/endBar` and `summaryText`.
6. **Are persistence schemas keyed by bar number?**
   Yes. `ChordTimelineItem` persists `bar/beat`; `SavedProgressionBlock` persists
   optional `startBar/endBar/lengthBars`, source timing, `timeSignature`, chords,
   and summary text. Directly replacing source bars with presentation bars would
   make saved timing inconsistent and is not acceptable.
7. **Can a separate presentation grouping be introduced without migration?**
   Yes in principle, only if it is runtime/non-persistent and the saved chord
   events remain in source coordinates. Existing saved data need not change.
   A projected bar array cannot silently replace `SavedProgressionBlock.chords`;
   Stage01 must demonstrate a source-coordinate round trip before promotion.
8. **Can downstream grouping operate from absolute beats/ticks?**
   Yes. `buildCandidateEventsInBeatRange` already clips by absolute beats;
   candidate events carry `relativeStartBeat/durationBeats`; saved blocks already
   compute `sourceStartBeat/sourceEndBeat`. This is the safest existing primitive.
9. **What does normal 4/4 expect?**
   Exact parity. On the frozen 8-beat control: source/formatted bars `2/2`, four
   timeline items, zero dashes, one block candidate. Text, topology, identities,
   timing, and source metadata must remain identical.
10. **What do genuine 3/4 and 2/4 fixtures do?**
    On the same 8-beat control, 3/4 produces source/formatted bars `3/3`, four
    timeline items, zero dashes, two block candidates; 2/4 produces `4/4`, four
    timeline items, zero dashes, four block candidates. P5.38 must not normalize
    these meters to 4/4. A genuine one-beat-bar case must also fail closed rather
    than be assumed pathological.
11. **Is there already an equivalent presentation-group abstraction?**
    No end-to-end abstraction exists. The closest reusable pieces are absolute
    beat ranges and block-relative candidate events. `summaryFromEvents` has a
    grouping loop, but its unit is still named/typed as source bars.
12. **What is the smallest reversible seam?**
    Immediately downstream of the resolved `fullTimeline`, before automatic
    block enumeration and summary formatting: introduce a pure, bounded shadow
    projection from source-coordinate events to explicit presentation groups.
    Keep `fullTimeline`, source meter, and persisted events unchanged. An explicit
    legacy/off path can continue using current source-bar grouping. Do not touch
    Family B, scoring, or vocabulary.
