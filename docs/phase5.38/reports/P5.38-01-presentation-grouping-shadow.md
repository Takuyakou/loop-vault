## Shadow architecture

The selected comparison candidate is a minimal hybrid (`S3`) built from the
safe parts of `S2`:

```text
post-P5.37 resolved fullTimeline (source coordinates, immutable)
  -> oracle-free fragmentation evidence
  -> runtime-only PresentationGroup[]
  -> presentation formatted cells
  -> legacy selected blocks projected through absolute beat ranges
```

The production seam remains unchanged. The shadow consumes the production
analysis result but never writes it back.

### Source / presentation type distinction

`PresentationGroup` is intentionally separate from source bars and contains:

- `groupIndex`;
- `absoluteStartBeat` / `absoluteEndBeat`;
- `containedTimelineItemIds`;
- `sourceGroupSpan` (source-coordinate provenance only).

`PresentationBlockProjection` separately records presentation-group indices,
absolute beat bounds, source-coordinate provenance, block-relative events,
structured signature, cells, and summary. It does not replace
`ChordTimelineItem.bar/beat` or `SavedProgressionBlock.startBar/endBar`.

## Frozen policy v1

Policy identifier: `p538-presentation-grouping-shadow-v1`.

The policy was fixed and passed synthetic/hard-negative tests before the private
fixture was evaluated. Application requires all of:

- source meter exactly `1/4` and source beats/group exactly `1`;
- at least 8 source groups;
- at least 4 resolved timeline items;
- occupied-start/source-group ratio `<= 0.625`;
- legacy `-` ratio `>= 0.4`;
- ratio of harmonic events longer than one source group `>= 0.5`.

No fixture id, filename, path, chord label, or expected private result is part
of the trigger.

### Projection construction

- Boundaries are the sorted distinct absolute starts of resolved harmonic
  events, with a leading zero boundary only when required.
- The final group ends at the larger of the truthful source extent and resolved
  event extent.
- Group spans are therefore data-derived and may be syncopated or uneven; there
  is no `four source bars = one presentation group` rule.
- Each event retains its original object and source `bar/beat/duration` data.
- The projected formatted cell is an event-start cell when an event begins in
  the group, otherwise `-`.
- Existing selected block ranges are mapped to overlapping presentation groups,
  then rebuilt with `buildCandidateEventsInBeatRange`. Equivalent projected
  ranges/signatures are deterministically deduplicated.
- Block cells are classified independently as event start, true carry-in
  sustain (`—`), or no overlap (`N.C.`).
- At most 16 already-selected legacy blocks are projected. There is no search or
  global optimizer.

### Fallback and reason codes

Weak or inapplicable evidence returns exact legacy presentation topology.

- `legacy-meter-topology`
- `insufficient-fragmentation-evidence`
- `genuine-one-beat-meter-preserved`
- successful application emits both `fragmentation-detected` and
  `presentation-projection-applied`

## Synthetic meters and hard negatives

| case | legacy formatted / `-` / blocks | shadow formatted / `-` / blocks | result |
|---|---:|---:|---|
| 4/4 control | 2 / 0 / 1 | 2 / 0 / 1 | exact legacy parity |
| 3/4 control | 3 / 0 / 2 | 3 / 0 / 2 | exact legacy parity |
| 2/4 control | 4 / 0 / 4 | 4 / 0 / 4 | exact legacy parity |
| pathological 1/4 | 7 / 3 / 6 | 4 / 0 / 4 | projection applied |
| genuine 1/4, one harmony per bar | 8 / 0 / 0 | 8 / 0 / 0 | fail closed |

The pathological synthetic reduction is 42.9% for formatted groups and 100%
for `-` cells. Its four two-beat harmonic spans arise from the input events, not
from a fixed grouping width.

Additional hard negatives cover empty, sparse, long-held, rapid one-beat, and
syncopated/uneven timelines. Empty/sparse/long-held inputs fail closed; uneven
positive spans follow their exact event starts and contain no fixed four-beat
boundary assumption.

## Placeholder semantics

The shadow keeps three meanings and three explicit cell kinds:

- `-`: no event starts in a formatted presentation/source cell;
- `—`: an event started before the block cell and truly sustains into it;
- `N.C.`: no event overlaps the block cell.

Tests exercise all three. There is no marker substitution to reduce the dash
count.

## Source-coordinate round trip and identity

Every runtime presentation item id maps back to the original timeline object.
The automated round trip recovers the source timeline in original order and
deep-compares its bar, beat, duration, chord, confidence, alternatives,
warnings, and voicing memory.

Harmonic identity snapshots lock, in order:

- canonical chord identity;
- absolute start beat;
- duration;
- source group / beat;
- timeline item count and order.

All synthetic and private comparisons report zero identity differences. Source
bytes and parsed source metadata are unchanged. No schema/fileVersion/migration
surface was touched.

## Block topology

For every projected block, the audit verifies:

- monotonic group and absolute-beat boundaries;
- ordered, positive, range-bounded relative event timing;
- `structuredSignature(events)` equality;
- cell/summary equality;
- source timeline object provenance.

Synthetic applied and all fallback projections are coherent and deterministic.
The 4/4, 3/4, and 2/4 fallback block boundaries, signatures, and summaries are
exactly the production candidates.

The approved private fixture was evaluated only after policy freeze. The runner
selected one fixture using previously frozen aggregate metadata and emitted no
filename, path, raw notes, bytes, checksum, audio, chord labels, full
progression, or per-cell transcription.

| aggregate | legacy | frozen shadow v1 |
|---|---:|---:|
| source meter | 1/4 | 1/4 |
| source groups | 65 | 65 (immutable) |
| timeline items | 25 | 25 (immutable) |
| formatted groups | 65 | 65 |
| `-` cells | 40 | 40 |
| selected/projected blocks | 10 | 10 |

Trigger evidence:

- occupied-start ratio: `0.384615` (passes `<= 0.625`);
- dash ratio: `0.615385` (passes `>= 0.4`);
- multi-source-group harmonic-span ratio: `0.44` (**fails `>= 0.5`**).

Result: `insufficient-fragmentation-evidence`; exact legacy fallback. Formatted
group reduction is 0% and dash reduction is 0%, so frozen Gate A is not met.
The fallback still reports zero identity differences, truthful source-coordinate
round trip, coherent blocks, and byte-identical repeated projection output.
Observed shadow projection time was about 1.4 ms for 25 timeline items, 65
fallback presentation groups, and 10 blocks; timing is informational, not a
deterministic field.

## Boundedness and determinism

- Evidence and group construction: `O(timeline items + presentation groups)`.
- Formatted projection: linear in groups plus contained starts.
- Block projection: input is capped at 16 already-selected legacy blocks, so
  the existing beat-range scan is fixed-window bounded.
- No dynamic programming, backtracking, global optimizer, or unbounded search.
- Repeated stable projection JSON is byte-identical for all tested inputs.

## Required questions

1. **Can presentation grouping be built without mutating source bars?** Yes.
   Separate runtime types and source-object provenance prove this.
2. **Can 4/4 / 3/4 / 2/4 exact parity be maintained?** Yes, including timeline,
   source counts, formatted text, dashes, blocks, boundaries, summaries, and
   metadata.
3. **Can genuine 1/4 be distinguished from pathological 1/4 oracle-free?** Yes
   for the synthetic positive/hard-negative set. Genuine one-event-per-bar 1/4
   fails closed. The private case also demonstrates conservative fail-closed
   behavior when one signal is weak.
4. **Does LF-MIDI-001 reduce formatted groups by at least 50%?** **No** (65 to
   65).
5. **Does LF-MIDI-001 reduce `-` by at least 50%?** **No** (40 to 40).
6. **Is block topology coherent?** Yes for applied synthetic projection and
   exact-legacy fallback, but this does not compensate for Gate A failure.
7. **Are saved/source coordinates truthful and round-trippable?** Yes. No
   persisted coordinate or schema changes.
8. **Is there any Family B output diff?** No; focused regressions are exact.
9. **Can the shadow policy be frozen for P5.38-02?** Yes. V1 is frozen exactly
   as documented and was not retuned. Current evidence argues against promotion;
   P5.38-02 must make the formal `PROMOTION = PASS|FAIL` decision without tuning.
