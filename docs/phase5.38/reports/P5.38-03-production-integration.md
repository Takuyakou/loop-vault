## Exact production seam

The only runtime call site is after final spelling of the already-resolved
post-P5.37 analysis result:

```text
post-P5.37 fullTimeline
-> optional Family-A presentation projection
-> runtime-only presentationGrouping result
```

The projection is not called from MIDI parsing, candidate generation, ranking,
smoothing, or Family-B partitioning.

## Shared pure implementation

The frozen research implementation was moved into production domain modules:

- `src/domain/midi/presentationGroupingCore.ts` — common projection,
  provenance, cells, text, blocks, source round-trip helpers;
- `src/domain/midi/presentationGrouping.ts` — frozen v2 trigger/policy and
  production adapter.

The former research modules now only re-export those production modules.
Research, production and tests therefore execute one implementation; there is
no scripts/src logic copy.

## Production representation

`MidiProgressionAnalysis.presentationGrouping` is optional and runtime-only.
It provides:

- variable-duration `PresentationGroup[]` with
  `absoluteStartBeat`, `absoluteEndBeat`, contained timeline ids and source
  group provenance;
- formatted presentation cells/text;
- projected block topology, summaries, structured signatures and original
  `sourceCandidateIndex`.

The contract remains:

```text
PresentationGroup != source bar
PresentationGroup != rewritten meter bar
```

## Source and persistence invariants

Production ON preserves:

- source time signature and `totalBars`;
- timeline `bar`, `beat`, duration, identity, order and count;
- PPQ, tempo, tempo events, notes and source bytes;
- original selected `blockCandidates` used by save paths;
- saved source coordinates and timing;
- Vault schema and `fileVersion`.

No `PresentationGroup` is persisted. The optional result exists only on the
runtime analysis object.

## Placeholder and block semantics

The shared implementation retains the promoted meanings:

- `-`: no event starts in a presentation/source cell;
- `—`: true carry-in sustain;
- `N.C.`: no overlap.

Projected blocks still derive from an already-selected source candidate's beat
range, overlap PresentationGroups, use `buildCandidateEventsInBeatRange`, keep
source provenance, deduplicate deterministically, and are capped at 16. The
block-selection algorithm itself is unchanged.

## Meter and trigger safety

The production implementation uses the previously frozen positive and
hard-negative matrix through the shared modules.

- positive Family-A-like topologies apply;
- 4/4, 3/4 and 2/4 retain exact legacy text, summaries and block topology;
- genuine one-event-per-bar, long-held, sparse, bursty, short and
  alternating-density 1/4 cases fail closed;
- hard-negative false positives: 0;
- both counterfactual reductions remain mandatory before application.
