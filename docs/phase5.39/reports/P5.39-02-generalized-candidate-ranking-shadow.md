## Scorer adapter and parity

The Shadow adapter reproduces the current legacy scorer's evidence model:

- template hit share;
- outside share with the same `0.12` multiplier;
- root evidence with the same `0.12` multiplier;
- the same root/in-chord/foreign bass values;
- the production `evaluateQualityEvidence` and `attenuateRootBonus` functions with active `phase4QualityEvidence` (`full`, penalty `0.08`, threshold `0.02`);
- the same semantic template-size complexity penalty;
- the same score-descending, canonical-label tie-break.

Existing qualities are scored from the production legacy template intervals,
not from a folded semantic extension descriptor. A generated all-root/all-quality
corpus compares all 252 existing candidate scores and their relative ordering
against `diagnoseLegacyWindowCandidates`; every score agrees to 12 decimal
places and ordering is exact.

## Omission and alteration treatment

Target candidates add only two named Shadow extensions to the reused scorer:

1. every explicitly written extension/alteration must be present above the
   production presence threshold;
2. every explicitly omitted structural tone must remain absent above that same
   threshold.

These two penalties are Shadow-only components, explicitly separated from the
active production quality-evidence penalty (`0.08`). They each use the bounded
evaluation constant `0.35`; they are reported separately in every explanation
and are never applied to the existing 252 candidates. Production scorer parity
therefore compares like-for-like against active Phase 4, while omission and
explicit-modifier policy remain visible rather than being presented as
production components.

Omitted tones still count toward semantic template complexity. Therefore `no5`
does not gain a smaller-template bonus. Exact Family-C evidence has neither
extension penalty nor omission conflict beyond the scorer's ordinary semantic
complexity cost. With-fifth, partial-modifier, and single-alteration evidence
cannot win as the full Family-C target.

Each ranked row exposes honest components:

```text
matched structural PCs
matched explicit modifiers
missing expected tones
conflicting present tones
omission conflicts
bass compatibility
hit/outside/root evidence
legacy quality-evidence penalty
Shadow explicit-modifier and omission-conflict penalties
total score
```

## Ambiguity and bass

The Shadow candidate set adds only the two authorized target archetypes. It does
not add a competing `#5` spelling for the Target-A pitch-class set and therefore
does not invent a global `b13` preference. Stage01's `b13`/`#5` ambiguity remains
in the representability oracle and neighbor evaluation.

Structural bass is a separate scoring input. It never changes the upper-family
key and is attached to the ranked display identity only when the legacy
in-chord slash rule allows it. All 24 target slash controls retain their exact
upper identity and independent bass.

## Frozen Stage03 input policy

The policy frozen for any separately authorized Promotion Evaluation is:

- candidate families: existing 21 qualities plus only Target A and Target B;
- enumeration: legacy root-major 252, Target A roots 0-11, Target B roots 0-11;
- visits: exactly 276 per non-empty evaluated window, hard maximum 300;
- scorer: legacy formula and production quality-evidence functions;
- omission: no missing-tone penalty for the omitted fact, but explicit penalty
  when that omitted structural PC is materially present;
- alterations/extensions: every explicit modifier must be materially present;
- sparse bias: omitted tones remain in semantic complexity accounting;
- tie-break: score descending, canonical label, then fixed enumeration index;
- output: Stage01 explicit canonical notation, never `alt`;
- fallback: production behavior remains untouched because this is Shadow only;
- ambiguity: retain Stage01 contract ambiguity; do not add spelling preference;
- private evaluation: not run in Stage02.

No retuning or extra candidate family is authorized during Promotion Evaluation.
