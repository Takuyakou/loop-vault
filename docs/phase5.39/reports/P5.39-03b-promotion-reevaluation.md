Two sequence models were compared without changing policy:

- **Model A:** expanded W2/B0/B1 ranking, then Family B partition, then
  smoothing. FC-REAL-01 remains correct and FC-REAL-02 stays separated, but

Model B is rejected by the reviewed target. Model A is the only plausible seam
of these two, **conditional** on resolving the whole-file H/J failures. This
stage does not select or implement a production seam.

## Representation constraints, not an integration proposal

- **R1 — expand structured production identity/schema:** can encode omissions
  honestly, but requires parser/persistence compatibility work not authorized
  here.
- **R2 — runtime enriched identity:** avoids immediate stored-schema changes,
  but display/export/save must never silently discard an omission or replace
  a complex displayed identity with a simpler stored one.
- **R3 — bounded dual representation:** could preserve both current structured
  identity and a separate explicit enriched analysis identity, but requires
  an exact consumer contract and downgrade/fail-closed behavior.

Because Promotion fails, none is chosen and no P5.39-04 plan is activated.
