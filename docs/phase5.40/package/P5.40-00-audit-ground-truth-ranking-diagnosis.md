# P5.40-00 — Audit / Ground Truth / Ranking Diagnosis

## Objective

Without changing ranking behavior, determine the correct local harmonic identities for FC-SAFETY-03 and explain numerically why the frozen current policy selects the rejected local identity sequence.

## Required work

### 1. Repository and Git audit

Confirm:

- P5.39 Closeout exists and P5.39 is closed;
- no existing P5.40 package/branch conflicts with this package;
- current branch/base/HEAD;
- no in-progress merge/rebase/cherry-pick;
- protected production surfaces and current analyzer defaults;
- exact current scoring/candidate/tie-break implementation used by the frozen P5.39 Shadow path.

### 2. Baseline lock

Record, without changing:

- existing candidate count/order;
- Target A/B count/order;
- visits/window;
- score formula and every component;
- penalty values;
- tie-break;
- Family B projection seam;
- smoothing seam;
- source-fidelity contract.

### 3. Independent local ground truth

Create ignored-local anonymous source-only packets for each FC-SAFETY-03 local state.

Freeze a human classification before exposing candidate origin or score/rank.

Do not force an exact identity if evidence is insufficient.

### 4. Candidate-score instrumentation

Add evaluation-only diagnostic tooling that recomposes the exact current score and emits a structured row for **every current candidate**.

The diagnostic path must not alter score, order, candidate generation or production imports.

Required fields are defined in `04-score-breakdown-spec.md`.

### 5. Root-cause analysis

For each local state:

- identify the current winner;
- identify the independently correct candidate if representable;
- report its rank;
- compute winner-vs-correct contribution deltas;
- identify the first decisive term(s) responsible for the wrong ordering;
- report whether the issue is representability, candidate generation, scoring evidence, missing-tone handling, conflicting-tone handling, bass/root evidence, complexity bias, or tie-break.

### 6. Generalization check

Attempt to reproduce the same failure mechanism using privacy-safe synthetic/control examples.

This is diagnosis only. Do not alter any weight/threshold/candidate.

### 7. Automated verification

At minimum run:

- focused P5.40 diagnostic tests;
- relevant P5.39/P5.38/P5.37/chord identity/factorization/scoring tests;
- TypeScript;
- changed-scope ESLint;
- class lint;
- source-contract lint;
- phase-doc validation;
- AI-handoff validation;
- `git diff --check`;
- privacy/path/media guard;
- source immutability/determinism checks.

A full Vitest run is recommended if practical, but do not misreport historical evidence as a fresh run.
