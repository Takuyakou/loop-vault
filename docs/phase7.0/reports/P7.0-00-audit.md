## Current architecture map

| Checkpoint | Production path and observed responsibility |
| --- | --- |
| MIDI input | `src/domain/midi/rawSmf.ts`, `parser.ts`, `timing.ts`: bytes to parsed notes, tempo, meter, and bars. |
| Role | `legacy.ts:inferTrackRoles` assigns track roles; `voices.ts` builds voice features for capture selection. A separate Role v2 exists but is not the default analyzer's role implementation. |
| Boundary and evidence | `legacy.ts:buildWeightedWindows` uses fixed 2-beat weighted windows by default. The promoted P5.37 union-chimera partition may split a window before smoothing. |
| Candidate and ranking | `legacy.ts:matchWindowWithRankingScore` and template scoring form identities; `phase4Analyzer.ts` turns on quality-tone evidence. |
| Temporal decision | `legacy.ts:smoothTimelineWithRankingScores` applies an A-B-A singleton adjustment and merges adjacent equal labels; `extractBlockCandidates` builds candidate cards. |
| Presentation | `analysis.ts` applies P5.38 presentation grouping after the resolved timeline by default. It is a display projection, not source meter or harmonic truth. |
| Source voicing | `vaultStore.ts` attaches voicings from parsed notes to timelines and cards through `sourceVoicing.ts` and `extractVoicing.ts`. Extraction is conditioned on the analyzed chord and segment; automatic playback use depends on compatibility, representation, and confidence. |
| Persistence | `src/domain/schema.ts`, `repository.ts`, `src/store/vaultStore.ts` retain Vault `fileVersion: 2`; source voicing is per chord, not a full-polyphonic performance snapshot. |
| Playback | `src/domain/voicing/resolveVoicing.ts` creates capture timeline playback plans; `src/domain/progressionVoicingPractice/snapshot.ts` copies selected saved source note numbers into Voicing Loop snapshots. Generated fallback is possible and must be measured against independent Gold. |

This is a path audit, not a Tier 1 fidelity PASS. The source voicing extractor may choose a candidate note set, cap note count, or decline automatic source use; P7.0-03 must measure each checkpoint against independent Gold.

- Family C: extended/altered/omission-sensitive representability and local ranking can improve, but P5.39 and P5.40 failed whole-file safety. P5.40's key residual is activation scope and temporal arbitration: locally correct candidates can affect unreviewed regions and boundary decisions.
