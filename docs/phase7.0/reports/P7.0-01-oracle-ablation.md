# P7.0-01 — Boundary × Role Oracle Ablation

## Contract and data audit

This evaluation holds the Gold chord symbol fixed across all four conditions. It isolates source-voicing extraction under Product or Gold segment boundaries and Product or Gold role evidence; it does not measure candidate generation or final harmonic identity. Product Boundary comes from the current default `analyzeMidi` full timeline. Each Gold event is paired with the product segment having maximum positive overlap. Gold Boundary uses the event's independent start/end. Boundary start matching uses one parsed MIDI tick of tolerance, fixed before comparing metrics.

Product Role follows the capture source-voicing path: `buildVoices`, `normalizeNotes`, `annotateVoiceRolesV2`, then `extractVoicing` on unfiltered parsed notes. Gold Role uses independent per-note role truth to omit melody/percussion and applies Gold track-role overrides to the same extractor. That arm is an oracle upper bound, not a shippable classifier. Note matching uses track, channel, pitch, and onset with one-to-one consumption; duration is not a matching key because exact duration-key matching did not cover every parsed note. The role labels are complete for the evaluated files. Selected dev/validation MIDI bytes matched their manifest byte lengths and checksums; the holdout files were not opened.

The melody-containing corpus supplies event boundaries, per-note and track roles, and target voicing notes. Its dev split has 20 files / 160 events and validation has 6 files / 48 events. The chord-only control is a new deterministic in-memory synthetic fixture: four transposed files / 16 events, with all notes designated harmony. No MIDI bytes or individual Gold rows are committed. Existing historical holdout was not read.

## Interpretation and limits

The Gold Role oracle removes all measured melody leaks in both splits. On validation, product role labels already identify melody correctly, yet the current source-voicing extractor still includes 32 melody pitches because role labels weight candidates rather than remove notes. A better classifier alone cannot be assumed to fix this mechanism. Conversely, hard filtering product melody labels would risk the 120 dev harmony-as-melody notes.

Gold Boundary improves note F1 in mixed dev but does not change exact rate there. In mixed validation, Gold Boundary with Gold Role is slightly worse than Product Boundary with Gold Role: one extra note appears. The arms therefore interact; oracle improvements are not guaranteed to be monotonic when the extractor chooses a representative subspan. The clean control is intentionally simple and cannot stand in for long-tail, short passing-chord, or same-track melody cases.

The measured leak improvement from Gold Role is an oracle opportunity, not a causal first-loss count for production. Gold Role changes both note inclusion and voice weights. P7.0-02/03 must add explicit temporal classes and end-to-end checkpoints before final attribution. No validation retune was performed.

## Reproduction and scope

Run `npx vite-node scripts/p7/oracleAblation.ts --corpus <ignored-local Gold directory> --split dev` and again with `validation`. The script refuses `holdout`. It prints only aggregate counts and rates. The Phase 7 tracked files contain no source MIDI, raw note rows, private corpus path, or individual failure position. Production paths remain unchanged.
