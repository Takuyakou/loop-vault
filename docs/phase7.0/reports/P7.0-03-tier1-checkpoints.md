# P7.0-03 — Tier 1 checkpoint fidelity and Copy-Oracle

## Measurement contract

`scripts/p7/runTier1Harness.ts` evaluates independent versioned Gold note-number targets at six checkpoints: extractor snapshot, card/source representation, Vault repository save and reload, card note resolution, capture playback plan (including generated fallback), and whole-progression Voicing Loop source selection. Every checkpoint is compared directly with Gold; parity with an upstream checkpoint alone cannot pass. Copy-Oracle installs the Gold note set on Gold boundaries without chord inference, then uses the same repository and playback paths. It is an upper-bound control, not a product result.

The product-extractor arm fixes Gold boundary and Gold chord identity before the current capture voicing extractor. This isolates note extraction and downstream loss. It does not measure the current product's boundary or identity errors; those are measured separately in P7.0-01 and later stages. Source voices follow the capture path. Each ignored-local corpus file is checked against its versioned manifest byte length and SHA; only dev/validation splits are opened. The private local regression witness has no human Gold and is excluded.

## Loss attribution

On Harmony Support dev, extraction has 164 missing and 54 extra Gold note numbers. The representation and repository reload retain those counts exactly, so there is no measured persistence loss in this arm. Card and capture playback drop from 31 to 25 exact events; F1 falls to 0.748698 and extra notes rise to 209. On validation, extraction is 16/48 exact and card/capture playback is 0/48; note F1 falls from 0.802139 to 0.628571. The playback resolver can select generated fallback when a source snapshot is low confidence or aggregated, so a stored snapshot being exact does not guarantee audible exactness.

Voicing Loop explicit source selection keeps the product-extractor snapshot's exact counts in both splits, including low-confidence compatible simultaneous snapshots. This endpoint is a distinct selection contract; it does not prove default card/capture playback fidelity. Copy-Oracle reaches every downstream endpoint exactly on these Gold sets, showing that the current Vault representation and measured playback paths can preserve the tested note numbers when given valid explicit source snapshots.

The harness compares note-number sets and does not yet measure expression, velocity, sustain sound, or arbitrary-meter Voicing Loop. Synthetic temporal Gold and the tested corpus are 4/4, which that practice path supports. The production extractor was conditioned on Gold boundaries and identities, so these are optimistic relative to full product analysis. There is no correctness claim for the unannotated local real-MIDI witness.

## Verification

Run `npx vite-node scripts/p7/runTier1Harness.ts --corpus <ignored-local Harmony Support Gold directory> --split dev` and repeat with `validation`. The CLI rejects `holdout` and emits only aggregate metrics. TypeScript, ESLint, manifest integrity, deterministic repeat, phase-doc validation, protected-path diff, and privacy guard are Stage gates. No source MIDI, individual Gold note rows, source checksum, or private path is tracked.
