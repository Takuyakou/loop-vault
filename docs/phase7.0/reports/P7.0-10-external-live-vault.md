# P7.0-10 — Official external baseline and product seams

## Official BACHI baseline

The [authors’ official BACHI implementation](https://github.com/AndyWeasley2004/BACHI_Chord_Recognition) was cloned only into ignored-local storage at public commit `f0bead1a9ffad4720190a5e4ddc57c35926327aa`. Its [published pop checkpoint](https://huggingface.co/datasets/Itsuki-music/BACHI_Chord_Recognition/tree/main/pop909_film_kdec) (125 MB) and isolated Python 3.14/PyTorch 2.14 CPU environment were used with the unmodified `inference.py`. The official source accepts MIDI and returns quarter-note beat positions and root/quality/bass tokens; the [paper/project page](https://andyweasley2004.github.io/BACHI/) describes the boundary-conditioned iterative model. The local smoke and full run succeeded: 13/13 synthetic and 26/26 anonymous Harmony Gold MIDI files. Neither source MIDI nor individual predictions are tracked.

`scripts/p7/evaluateBachiOfficial.ts` maps the official tokens to the existing product root/quality/bass vocabulary and scores them at independent Gold event midpoints; it also matches exact beat boundary positions. `N`/no-chord is counted as an unsupported quality mismatch, not discarded. Official output has no MIDI note-set representation, so Tier 1 is unavailable for BACHI; it must not be assigned zero or compared to Copy-Oracle Tier 1. This model was trained on piano-range material and its 32-beat configuration and label vocabulary differ from this project’s Gold; these are domain and metric limitations, not an equivalent head-to-head product benchmark.

## Live MIDI sharing decision

Current Live MIDI reduces held/sustained note state, detects a provisional chord under a short gather window, stabilizes history, then `historyToSavedProgressionBlock` stores each history entry as one four-beat card with `origin: live-midi`. This is a distinct latency contract from offline file analysis and does not preserve the full live source note stream in the saved progression. Current `ChordSymbol` and `VoicingSnapshot` can be shared as *output adapters* when a label and explicit MIDI note set are valid. Offline Core v2 may share candidate identity semantics, vocabulary normalization, and renderer compatibility with Live MIDI, but the offline lookahead boundary lattice and dynamic decoder must remain outside the live capture path until a latency-bounded streaming version is separately tested. The existing Live MIDI tests passed 12/12 on this research HEAD. Live history’s synthetic four-beat durations must not be treated as source temporal Gold.

## Vault vocabulary and representation decision

Current `ChordQuality` is a finite enum and `ChordSymbol` has root, quality, tensions, optional bass, and display label. `ChordTimelineItem` has one chord plus alternatives and optional source voicing; repository schema is strict. Versioned Tier 2 Gold includes accepted alternate interpretations and explicit omission factors independently of spelling. The parser accepts five of six authored primary examples and rejects explicit `no5`. Rootless interpretation, omissions, extensions, alterations, and slash bass are **observed/Gold-defined**; some are structurally representable with current quality/tension/bass fields, while explicit omission semantics and multiple accepted identities are **unsupported** by persisted chord identity. Canonical label aliases can be **renderer-only** differences when semantic identity and audible output agree. Vault cannot simply serialize factorized candidates into current strict schema or overwrite source voicing with generated chord tones. Phase 8 needs a versioned optional semantic-factor/accepted-identity adapter and migration tests while keeping source-note snapshots independent.

## Architecture shortlist, frozen before final holdout

1. **A — Source-fidelity first:** preserve the shipped source-voicing extractor and Vault snapshot contract, add separately validated harmonic/voicing boundary selection, then improve candidate identity. This is the most conservative Phase 8 exploration path because Stage 03 retains 31/160 dev and 16/48 validation exact extracted note sets, while Stage 09’s modular copy prototype gets zero on Harmony.
2. **B — Bounded factorized identity + calibrated C2:** keep source fidelity from A; use a 160-or-smaller shortcut/factorized vocabulary and a calibrated temporal decoder that protects genuine 1-beat and half-beat passing chords. Structural candidate reachability improves, but Stage 09 validation decoded Top1 and candidate explosion prevent promotion today.
3. **C — Current Core fallback:** retain existing offline and live behavior until A/B meet independent Tier 1, full Tier 2, correction-cost, latency, and regression gates. This is the rollback baseline, not a proposed Core v2 replacement.

The shortlist is a Phase 8 research decision, not production approval. No candidate currently satisfies a Core v2 release gate. The sealed synthetic holdout has not been opened and will be evaluated once without subsequent retuning.
