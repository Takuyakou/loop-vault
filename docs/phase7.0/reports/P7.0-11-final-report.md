# P7.0-11 — Final research report and architecture decision

## Decision

Choose **Architecture A, source-fidelity first**, as the Phase 8 implementation direction. Keep **C, the current Core**, as the production fallback throughout Phase 8. Explore **B, bounded factorized identity with a calibrated C2 decoder**, only behind an evaluation/feature seam after A restores independent Tier 1 fidelity. No research prototype is approved for production today. This is an architecture decision with explicit release gates, not a Core v2 implementation or merge.

The decision is driven by checkpoint evidence, not one ranking score. Copy-Oracle preserved 160/160 dev, 48/48 validation, and 44/44 sealed synthetic note sets through the evaluated copy path. The shipped Gold-conditioned source extractor reached 31/160 dev and 16/48 validation exact at extraction, then card/capture playback fell to 25/160 and 0/48. The modular note-copy prototypes reached 0 exact on both Harmony splits despite promising synthetic results. A must solve that cross-domain note/role failure before changing the production identity path. Candidate coverage improves under factorization, but decoder Top1 does not reliably improve on validation. Temporal proposals protect short passing chords, but lattice over-splits Harmony heavily.

## Final sealed evaluation

A first CLI attempt failed the hash guard before marker creation or Gold parsing; no semantic answer or failure location was exposed. This holdout is transposed variants of authored public-safe categories, so it measures pitch/generalization consistency within those categories, not independent human performance on real MIDI.

## Performance and regression

On public-safe 120 BPM repeated-chord workloads of 3, 5, and 10 minutes, the current product returned 90, 150, and 300 timeline segments in approximately 206, 303, and 607 ms respectively on this host. A separate factorized candidate generation loop remained bounded at 240 candidates and took approximately 15, 20, and 36 ms respectively. These are local wall-time samples, not isolated CPU/peak-memory guarantees or end-to-end Core v2 benchmarks. Heap snapshots ranged around 196–235 MB without controlled garbage collection. Full Stage 09 per-arm telemetry is available in its aggregate JSONL. No unmeasured latency claim is made for Live MIDI. Final focused regression passed 11 test files / 50 tests across research, current Analyzer, source-voicing/playback, and Live MIDI. The production `src/` diff against the research base is empty.

## Limitations and risk register

- **LOCAL HUMAN GOLD = NOT AVAILABLE.** The local real-MIDI witness has an ignored-local source-only HTML/JSON review pack and verified immutable bytes/notes/timing/meter, but independent human semantic labels remain `PENDING_HUMAN_REVIEW / NON_BLOCKING`. It was excluded from every Gold-dependent ranking. Its 1/4 meter was preserved as source truth. No Analyzer prediction, candidate, score, rank, or prior evaluation was used to invent Gold.
- The sealed cohort is generated from 13 known structural fixture families, then transposed. It is novel at the note instance level but related to development patterns. The paired interval is not a real-world generalization guarantee.
- Stage 09 modular `old Decoder` is a greedy adapter over displayed candidates; it is not identical to the complete shipped decoder. Its Tier 2 table is root/quality/bass structural accuracy, not the full accepted-alternative and renderer-equivalence contract. Phase 8 must implement and run that full contract against suitable independent Gold.
- The modular note-copy implementation loses exact fidelity on Harmony Gold. Role/voicing selection, source sustain, playback fallback, candidate-count growth, lattice over-splitting, current strict Vault vocabulary, and Live MIDI latency are release risks. Official BACHI is an external label baseline with a different training domain and output contract.

## Stop boundary

Phase 7 ends at this research handoff. No Core v2 production code, production connection, merge, push, tag, or release was performed. Phase 8 starts from the separate handoff, with fresh implementation gates and human authorization for any future merge or release.
