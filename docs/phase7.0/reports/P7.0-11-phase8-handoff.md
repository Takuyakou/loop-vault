# Phase 8 handoff — Core v2 implementation order

**Chosen direction:** source-fidelity first (Architecture A). Keep the current Core as a selectable rollback baseline. Factorized identity/C2 remains a research option until it passes the same independent end-to-end gates. No production implementation is authorized by this handoff.

1. **Freeze full evaluation adapters.** Carry the versioned temporal and Tier 2 Gold contracts forward. Add accepted-alternative, canonical-name, audible pitch-class+bass, and renderer-only scoring to the tournament. Keep note-number exactness, note F1, harmonic/voicing boundary metrics, ornament event handling, and correction vectors separate. Continue excluding the local real-MIDI witness from quantitative ranking until independent human labels exist.
2. **Repair source note fidelity first.** Prototype role-aware source note selection that retains sustained support notes, avoids melody contamination, and preserves explicit source snapshots across representation, Vault reload, card/capture playback, and whole-progression playback. Use Copy-Oracle as an endpoint control and compare against Copy-Simple, Copy-ProductBoundary, and the shipped extractor. A candidate that worsens Harmony dev/validation Tier 1 cannot be promoted on synthetic gains alone.
3. **Separate temporal heads.** Generate harmonic boundaries, voicing-only boundaries, and note-event ornaments independently. Score fixed/onset/change/lattice proposals with a bounded selector. A one-beat or half-beat passing chord remains eligible for a harmonic boundary; duration alone must never erase it. Explicitly test 1/4 source meter and source timing invariance.
4. **Then test identity and decoder jointly.** Keep a bounded shortcut/factorized vocabulary, inspect candidate recall before Top1, and compare old/new Identity with old/C1/C2 Decoder in a non-greedy matrix. Calibrate with unsaturated scores. Limit candidate counts and record false-candidate and runtime costs. Use full Tier 2 accepted-equivalence truth rather than label exactness as the promotion metric.
5. **Version the product seam deliberately.** Add optional semantic factors and accepted-identity metadata only with schema migration/roundtrip tests; preserve raw source voicing independently of any rendered chord. Keep current `ChordSymbol`/strict Vault reader compatibility behind an adapter and reversible feature flag. Use source role/identity semantics in Live MIDI only through a latency-bounded streaming adapter; do not copy offline lookahead or fabricated four-beat history timing into source truth.
6. **Promotion and rollback gates.** On fresh HEADs, require independent Tier 1 and full Tier 2 dev/validation/regression, short passing-chord preservation, correction-cost and card-count checks, 3/5/10-minute resource budget, Live MIDI latency, Vault migration, and no private artifact tracking. Keep the old analyzer/decoder path available for immediate rollback. Use a new sealed cohort for any later final selection; do not retune against the consumed Phase 7 holdout.

The final Phase 7 aggregate and limitations are in `P7.0-11-final-report.md`. The local source-only review can continue independently and does not block architecture planning. Any future merge, push, tag, or release requires its own authorization.
