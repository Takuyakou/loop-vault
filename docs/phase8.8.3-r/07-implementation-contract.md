# R08 — conditional Phase 8.8.3 implementation contract

**Research specification only. Do not implement or promote while the R09 gate is blocked.** This contract is versioned to current-site manifest SHA-256 `2e4cc38d421ea0b9ff5ff199730ca684b0c66f0922fc53f7a091df3dadc469ba` and Product base commit `c618479b88ccc44f1d749ec30416058fa27d1e23`.

## Compatibility boundary

1. A site-accepted label inside the frozen grammar must either produce the independent semantic meaning from `p8.8.3-r-literal-degree-v1` or receive an explicit, user-visible unsupported/ambiguous diagnostic. It must never be silently reinterpreted as a different chord. A label accepted by the site but rejected by the independent policy is diagnosed; site acceptance alone does not authorize Product to invent a meaning.
2. Product may preserve its existing narrower grammar for the 29,224 site-accepted rows that Text Intake currently rejects, if rejection remains explicit and lossless. The 6,384 unusual composite rows that the independent theory policy rejects must remain explicit diagnostics unless a separately approved, versioned policy defines their meaning.
3. Review the 138 A rows by family. For each supported label, fix the semantic identity or reject the label explicitly. Priority cases include extended diminished and suspended eleventh compositions, plus altered dominants in which quality folding silently adds or erases a written ninth. Do not patch individual matrix rows with label-specific exceptions.
4. Fix B on literal Text Capture and saved text-card audition before making a text-confirmation fidelity claim. The current matrix records 274 Preview/Vault defining-tone-loss rows. Remove any fixed upper-note truncation that drops a required written factor, preserve slash bass as the lowest note, and keep exact Preview/Vault note parity after save/reload. A Product Parser diagnosis must occur before audition if the chosen chord meaning cannot be represented.
5. Voicing Loop `basic-full` is a practice arrangement, not a literal site-playback oracle. Its 379 defining-tone-loss rows require an explicit product choice: either a separate literal-confirmation mode that includes all required factors, or a clear style explanation that the current generated practice style omits them. Never label the latter as literal source-fidelity playback. The 180 `UNSUPPORTED_RULE` cases remain disabled with a reason.
6. C's 52 optional-only omissions are allowed under this policy. D's 311 concrete voicing differences may remain in a practice style, but a future literal-confirmation policy must define its own stable register and doubling. E is not a mandate to support every odd site spelling; explicit rejection is sufficient when the site and independent policy disagree.

## Proposed `TEXT_CHORD_TONES_V1` (separate from Voicing Loop)

- Input is an adjudicated `ChordSymbol` plus the raw written factors and optional slash bass. Reject if the written-degree provenance was lost, if the policy labels the composition unsupported, or if required factors cannot be represented.
- Build required pitch classes from the [R03 contract](02-semantic-contract.md). Keep both distinct written alterations of a degree. Remove the unaltered degree only when the policy says replacement; preserve separately written sixth and thirteenth. Deduplicate identical pitch classes for playback while retaining written-degree provenance for diagnostics.
- Deterministic register: choose the explicit slash bass, otherwise the root, in MIDI 36–47; choose each required upper pitch class in MIDI 60–71 in degree order, then sort by absolute pitch for playback. Do not impose a fixed five-upper-tone cap. If the lowest upper note duplicates the bass pitch class, keep both unless a separately versioned doubling rule says otherwise. Optional implied ninth, eleventh, and fifth are omitted in v1; a required written factor is never omitted for density or duration.
- The literal mode uses the same resolved MIDI array for Text Capture preview and Vault card audition, saves only identities that the existing Vault schema can preserve losslessly and round-trips them without changing factors. If the schema cannot preserve a written factor, saving is disabled with an explicit reason until a separately approved migration exists. It does not alter source MIDI snapshots, Generated practice voicings, or current production defaults merely by being specified here.
- Slash/on spellings normalize only after raw text is preserved. A slash bass must remain the lowest sounded pitch, including non-chord-tone bass. Enharmonic spellings may share a MIDI number, but the original spelling remains available to show the user what they entered.

## Permanent gates after any future implementation

- Rebuild the synthetic matrix from the pinned site grammar without looking at Product results; assert planned/emitted row parity, no duplicate row IDs, no unclassified accepted row, all A and B outcomes either fixed or explicitly diagnosed, and Preview/Vault byte-for-byte note parity on every supported row.
- Add a direct regression for each of the six required risk families and for `b9/#9`, `#5/b5`, omission/addition, power, double accidental, Unicode accidental, root/chord-tone/non-chord-tone slash bass, and invalid site-only composites. Check written factors, required/optional/prohibited pitch classes, absolute notes, bass, save/reload, and Voicing Loop availability separately.
- Test at least two predecessors and two followers for each risky Product Generated family; concrete voice-leading may differ while semantic policy/diagnostic status remains stable. The current site path is chord-local at the pinned deployment.
- Before claiming full compatibility, complete the local witness gate under an authorized privacy-safe method and re-prove lexical/factor independence. A changed site asset hash, grammar production, alias, or semantic operator invalidates this compatibility version and requires a fresh manifest/matrix; historical source parity alone cannot renew it.
