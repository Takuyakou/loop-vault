# P8.8.5-00 — Repository and UI audit

Local master is clean at 340e454. The root checkout contains unrelated uncommitted work and is not used for this phase. This dedicated D-drive worktree starts from local master. Local origin/master is behind local master; no rebase, reset or push is planned.

- Capture input tabs are instantiated in four separate return branches of CaptureView, with different wrapper padding. Their DOM geometry can change across MIDI/Text modes.
- Standard and Extended keep the same parent raw-text state, but switch between distinct workspace trees. Selection/caret is not retained.
- Capture has a persisted global Piano/EP context, yet Text passes a hardcoded EP sound into its panel, draft event audition and Extended default.
- Standard and Extended have separate top controls. Extended owns a local metronome boolean; Voicing Loop and Rhythm Practice also own local metronome toggles. Bass Practice chord-context accompaniment choices are separate playback modes, not a plain ON/OFF toggle. Chord Dojo has no separate click switch.
- Standard and Extended use the real parser-backed score view-models, including duration, reattack, hold, rest, diagnostics and source spans. These paths must be retained.
- Text Transport uses generic primary/secondary button classes; Voicing Loop has separate controls. A common variant layer is needed.
- Standard allows unset BPM with a practice-only 120 fallback. Key suggestions are a short inferred list, with manual text confirmation. Extended uses a selectable 1/4–12/4 meter.

The HTML mock is a visual/interaction reference only. Its demo parser is excluded from product code.
