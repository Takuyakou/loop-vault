# P8.8-01 — Shared chord semantic core

## Implementation

The shared chord implementation exposes the stable MIDI/Product entry
`parseChordLabel` and the text-only entry `parseTextChordLabel`. Both standard
and extended text modes use the latter. The text policy represents `mMaj7`, power chords,
`add13`, dominant `11`, and explicit `omit3`/`omit5` (`no5` is a spelling
alias). The shared `ChordSymbol`, Vault v2 schema, normalized identity,
factorization, Generated tone tables, transposition, and Voicing Loop detached
chord copy preserve these factors. Unmodified symbols retain their old shape.
`6/9` remains a quality slash; a final note suffix remains a bass slash.

The Phase 8.8 semantic policy treats a written `11` as a dominant seventh plus
9 and 11; a written `13` retains the current product dominant 13 identity,
whose generated voicing may omit the optional interior 11. Explicit `b9`,
`#9`, `#11`, `b13`, `add13`, and omissions remain distinct. The external
translator's exact pitch-class set is comparison evidence, not a mandate to
clone its voicing. No external reference-voicing policy is shipped.

## Compatibility and scope

Previously valid standard labels retain their canonical meaning in focused
tests. The previously invalid `C#5` is intentionally accepted as a power
chord; its old negative test was updated to test `C#5junk` as malformed.
Product MIDI Analyzer/Extractor and Phase 9 candidate code were not edited.
The legacy parser entry retains its previous vocabulary; the P5.39 vocabulary
baseline passes. The Analyzer still uses its existing candidate generation and ranking.
