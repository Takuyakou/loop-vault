# P8.8-04 — Vault v2 text-source persistence

## Design

`SavedProgressionBlock.textSource` is an optional, bounded, strict Vault v2
member. Existing records need no rewrite and `fileVersion` stays 2. The
field retains exact raw UTF-16 source, the extended dialect, accepted metadata,
source sections, grid slots (including rests and holds), written labels,
harmonic spans, attack positions, source ranges, parser/semantic versions and
the Generated voicing policy ID. No external concrete notes or reference
voicings are persisted.

The store re-parses supplied raw text and requires its complete reconstructed
structure to match the submitted metadata and normalized chord timeline.
Tampered raw text or mismatched Key/BPM is rejected before Vault mutation.
Unknown future fields continue to use the existing quarantine/readonly safety
path; they are not silently stripped by an unrelated write.

## Round trip and compatibility

A public 3/4 score with a comment, percent reattack, hold and rest preserved
the exact source and structure through save, strict v2 serialize/parse,
unrelated idea creation and edit, save and reload. No migration or new
fileVersion was required. Existing standard text and unrelated Vault records
retain their prior shape.
