## 2. 実装した製品経路

利用者はCaptureのテキスト入力でStandardまたはExtendedを選ぶ。初期値はStandardであり、拡張記法らしい入力を検出しても自動切替はしない。Extendedでは元テキストを保持したまま、小節・スロット・コメント・再生マーカー・拍位置・診断を表示する。KeyとBPMのコメントは候補として示すだけで、利用者が「使う」を押したときのみ適用する。

有効な入力は一回のSave to Vaultで進行として保存する。VaultからVoicing Loopを開くと、保存した拍子・区間・発音位置を使って練習できる。無効または曖昧な入力は診断を表示し、部分的な解析結果を保存しない。保存失敗時も入力は編集可能なまま残る。

## 3. 意味と時系列の契約

テキスト専用のコード解釈として、mMaj7、power chord、明示的なomit3/omit5、add13、11th、alteration、6/9、slash bassなどの要素を保持する。従来のMIDI Analyzer入口と現在のProduct extractorの選択・ランキングは変更していない。Phase 8.5 PREの98件の合成fixtureは改変せず、EV1-070〜077の意味上の差は独立した正誤表で扱った。

Extendedの時系列は和声区間と発音イベントを分ける。%は同じ和声の再発音、=は再発音しない保持、_とN.C.は明示的な無音区間として扱う。同じコード名をもう一度書いた場合も発音イベントを残す。等分できるn/4拍子の整数拍スロットから拍位置を決め、コード名が同じという理由だけで発音を消さない。

元テキストはUTF-16位置を含めて保持する。上限は8192 UTF-16 code units、32小節、128 score tokens、128コメント・再生マーカー行。未知・曖昧な記法、上限超過、非対応拍子には位置付き診断を出し、保存を止める。

## 4. Vaultと再生の保護

Vault fileVersionは2のまま。保存済み進行へ任意の厳格なtextSource情報を加え、元テキスト、metadata、section、slot、harmonic span、attack位置、parser/semantic policy version、Generated Voicing policyを保存する。既存recordの書換えやVault v3 migrationは要求しない。

保存時に元テキストを再解析し、提出されたmetadata、コード列、区間、長さと一致しなければVaultを変更しない。合成3/4例では保存→serialize/parse→別record編集→再保存→再読込後も元テキストと時系列が保持された。既存の未知metadataは従来のquarantine/readonly方針を維持する。

Voicing Loopでは、一つの和声区間を一枚のカードとして扱い、区間内の複数attackを再生予定に展開する。次のattackまたは区間終端を越えて発音を延長しない。holdは新たに鳴らさず、restは無音になる。現行のGenerated Voicingを使い、テキスト入力を元MIDIの実音やSOURCE MIDIとして表示しない。
