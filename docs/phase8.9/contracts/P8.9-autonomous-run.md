# P8.9 — 全自動で進める時の決まり

root `AGENTS.md` が安全の規則の正本。この文書は Phase 8.9 での上乗せだけを書く。食い違う時は `AGENTS.md` を優先する。

## 1. 進め方

- 1段階＝1つの zip＝1セッション。zip の `START-HERE.md` に従い、段階を最後まで進める。
- **途中で人間の承認を求めない。** 計画モードは使わず、計画は報告の冒頭に書いてそのまま実装に入る。
- 人間は段階の成果物（報告・スクリーンショット・EXE・差分レビューの結果）で判断する。次の段階の zip が渡されることが、前の段階の承認になる。
- 段階が終わったら merge 候補で止める。次の段階・次のフェーズへ自動で進まない。

## 2. 迷った時の扱い（止まって聞かない）

| 状況 | やること |
| --- | --- |
| 承認されていない機能を消したくなった・動きを変えたくなった | 消さず変えずに進め、報告の「判断ポイント」に案として書く |
| 新しい依存パッケージが欲しくなった | 追加せずに今あるもので作り、報告に書く |
| モックどおりだと使いにくい・幅に収まらない | モックに近い形で調整して進め、違いと理由を報告に書く |
| テストの期待値が古い配置を固定している | その段階で作り直した画面の分だけ更新してよい。更新理由を報告に書く |
| 指示書の記述が Git の実態と合わない | Git を正として進め、差異を報告に書く |

## 3. 段階をそこで終える条件

次のどれかに当たったら、その段階をそこで終える。変更は捨てずに commit し、報告と `execution-state.json`（`blocked: true`、`blockerReason`）に理由を書いて終了する。

- 保存形式（fileVersion 2）の変更や、既存の記録の書き換えをしないと進めない。
- core（`src/domain/midi/`、Generated ボイシング）、transport scheduler、SOURCE の音とタイミング、8.8.3 の「コードを決める音」の決まりに手を入れないと進めない。
- データ保持の往復テストが、製品コードを変えないと通らない（今のコードでデータが失われている疑い）。
- `AGENTS.md` の停止条件（説明のつかない変更・依存・移行など）に当たった。

## 4. 触らない範囲と読まない場所

- 上の core と transport。`AGENTS.md`。
- `.local-evaluation/` は `test-logs/` と `gate-cache/` だけ読んでよい。それ以外は、読み取りの道具でもシェルのコマンド（cat・grep・find など）でも開かない。
- `test/private-midi/`、`docs/loop-vault-evaluation-corpus/`、私的な MIDI や音声を読むスクリプト（`npm run eval:*`・`tune:*`・`benchmark:*`・`diagnose:*`・`ablate:*`）は使わない。
- リポジトリ直下の `Claude outputs/` は人間の資料置き場。読んでもよいが、コミットしない。
- サイト名は UI・コード・テスト・公開文書に出さない（「拡張記法」と呼ぶ）。

## 5. 許可の設定

- `.claude/settings.json`（コミットする）：普段の作業は確認なしで通し、禁止操作は設定で止める。すべて許可のモード（`bypassPermissions`）は使わない。
- `.claude/settings.local.json`（コミットしない）：`.local-evaluation/` の中の私的なフォルダへの読み取り禁止など、この PC だけの設定。フォルダ名そのものを Git に残さないため、こちらに置く。
- 設定で確認が出た操作は、報告の「判断ポイント」に書き、次の段階の zip で許可か禁止に振り分ける。

## 6. git

- 段階ごとにブランチを切る（`feat/p8.9-0N-<短い名前>`）。基点は local `master`。
- `git add` はパスを明示する。`-A`・`.`・`--all` は使わない。commit の前に `git status --short`・staged の差分・name-status を確認する。
- 小さい単位で commit する。ロジック分離は、UI の差し替えとは別の commit にする。
- merge 候補で止める。push・tag・release はしない。

## 7. 報告とレビュー

- 報告は日本語で `reports/` に書く（書く項目は [reports/README.md](../reports/README.md)）。
- 差分レビューは必須：Claude の実装 → Codex か別の Claude セッションによる差分レビュー → 人間の成果物確認。Claude Code は、レビューする側がすぐ読めるように、報告の最後に「レビューで見てほしい所」を3〜5点書く。
