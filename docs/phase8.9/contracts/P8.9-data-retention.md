# P8.9 — データ保持の契約

8.9 は**表示の上でまとめるだけ**で、保存データの項目を自動で移し替えたり、消したり、書き換えたりしない。Vault の保存形式は `fileVersion: 2` のまま。

## 1. 対象の項目

`src/domain/types.ts` の `SongIdea` と `VaultFile.settings`：

| 項目 | 8.9 での扱い |
| --- | --- |
| `genre`・`moods`・`chordMemo` | 進行ページで「以前の項目」として**読むだけ**で表示する。新しく書くのは進行（`SavedProgressionBlock`）の `tags` と `memo` だけ。まとめた見た目のまま1つの欄で編集させない（書き戻し先が決まらず、結局データを移すことになるため） |
| `status`・`prevStatus`・`statusHistory`・`completedAt` | 画面から外す。新しい Idea を作る時の初期値と記録の仕方は今のまま |
| `nextAction`・`references` | 画面から外す。値はそのまま残す |
| `assets` | 「関連ファイル」の画面だけ外す。進行の `sourceAssetId` などが参照しているので、中身は変えない |
| `chordDrip` | 触らない |
| `settings.monthlyGoal`・`settings.language` | 画面から外す。表示は日本語固定にしても、保存された値は書き換えない（`"en"` のままでも残す） |

`genre`・`moods`・`chordMemo` は Idea 単位、`tags`・`memo` は進行単位。1つの Idea に進行が複数ある時は、どの進行ページでも同じ「以前の項目」を表示する。

## 2. 往復テスト（P8.9-00 で追加し、以降の全段階で通す）

- 上の項目を**すべて既定値ではない値で埋めた**合成の Vault（`VaultFile`）を用意する。合成データだけを使う。実在の曲名・個人のパスは入れない（`assets[].path` も合成の相対風の文字列にする）。
- 実際の読み込みの経路（`src/domain/schema.ts`・`src/domain/repository.ts`・`src/storage/` の、アプリが本当に使う parse / normalize / serialize）を通して読み込み、保存し直す。
- 結果が入力と **deep-equal** で一致することを確かめる。
- 今のコードがすでに正規化している所（既定値の補完など）があれば、その差をテストの中で明示的に書き、監査（`audit/P8.9-00-baseline.md`）に記録する。「一致しない所を黙って除外する」ことはしない。
- 今のコードで項目が失われる場合は、テストを skip せず、その段階をそこで終えて報告する（[P8.9-autonomous-run.md](P8.9-autonomous-run.md) の3章）。

## 3. 編集の往復テスト（P8.9-05 で追加）

- 進行ページでタグ・メモを編集して保存しても、1章の項目がすべて変わらないこと。
- 画面から外した操作（ステータスの切り替えなど）を経由しなくても、既存の値が保たれること。

## 4. 将来の移行

項目を本当に移し替える時は、別のフェーズで、移行の設計と承認を取ってから行う。8.9 では行わない。
