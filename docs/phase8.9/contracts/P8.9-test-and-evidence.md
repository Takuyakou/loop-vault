# P8.9 — テストの回し方と証跡

テストは Test DX（`docs/test-dx/README.md`）の決まりに従う。毎回全部は回さない。

## 1. いつ何を回すか

| いつ | 回すもの |
| --- | --- |
| 意味のある編集の後 | `npm run test:fast -- <変えたファイル>` |
| まとまりができた時 | `npm run test:feature -- <変えたファイル>` |
| 画面の動きや見た目を変えた時だけ | `npm run test:ui -- --changed` |
| merge 候補の時に1回だけ | `npm run test:full`（常に fresh。キャッシュで省略しない） |

- `edit → FULL → edit → FULL` を繰り返さない。
- FULL が落ちたら：失敗を特定 → その失敗だけ再実行 → 直す → その失敗だけ再実行 → 落ち着いてから FULL をもう一度。
- 成功した時は要約行だけ読む。失敗した時だけ `.local-evaluation/test-logs/` の該当ログを読む。
- ゲートを実行せずに PASS と書かない。前の HEAD の結果を今の HEAD の結果として使わない。

## 2. テストの選び方の対応表

- 新しいソースのフォルダを作ったら、同じ段階で `scripts/test-dx/selection.mjs` の担当の対応表に登録し、その Node テストも更新する。登録しないと「不明＝安全側」で広く選ばれ、FAST が遅くなる。
- 共通の外枠・部品（`src/styles/`・`src/components/ui/`・新しい共通部品のフォルダ）は `shared-ui`（広く選ぶ）のままでよい。

## 3. 画面の基準画像

- `e2e/visual.spec.ts-snapshots` の基準画像は、**その段階で作り直した画面の分だけ**更新してよい。
- 更新した画像の名前と理由を報告に書く。関係のない失敗を緑にするためには使わない。
- 画面の位置や幅を固定しているテストも、同じ条件で新しい配置に合わせてよい。

## 4. テストの削除

- 承認済みの機能削除に伴って不要になったテストは、「機能削除に伴う削除」として1件ずつ報告に書く（テスト名・守っていた内容・消した理由）。
- それ以外のテストは消さない。同じ内容がより強く守られている時だけ、理由を書いて消してよい。
- skip・fixme・retry で緑にしない。

## 5. スクリーンショット（証跡）

- 置き場所は git 管理外の `p89-generated/<段階の名前>/`（例：`p89-generated/P8.9-00-baseline/`）。コミットしない。`.local-evaluation/` には置かない。
- 大きさは4つ：1920×1080（最大化）、1440×900（起動時）、960×1032（1920 の画面の半分にスナップ）、768×640（最小）。
- 中身は合成データだけ。E2E の合成データの仕組みを使い、個人の Vault は読まない。
- ブラウザで撮るので、Tauri のタイトルバーは写らない。タイトルバーは EXE で確かめる。
- P8.9-00 で作る `npm run p89:screens -- <名前>` を使う。

## 6. EXE

製品コードを変えた段階では、merge 候補で EXE を作る。ビルドの出力は D ドライブに置き、インストーラは作らない（`AGENTS.md`）。
