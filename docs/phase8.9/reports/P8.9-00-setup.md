## 7. 判断ポイント

- **往復テストの通し方**：ストアの `flush()` は変更がないと保存しないので、保存の本体の `JsonVaultRepository.load()` → `save()` を製品の `BrowserMemoryVaultStorage` で通した。ストアは `ideas` と `settings` を素通しするだけ（`setVault`・`currentVault`）なのを確かめ、監査に書いた。別案：ストアに無害な変更を入れて `flush()` させる → データを変えることになるので採らなかった。
- **合成データの誤りと製品の決まり**：最初、`mix` の記録に `reason` を付けたところ、Idea が隔離された。製品の決まりは「理由は保留・没の時だけ」なので、合成データを直した（製品の欠落ではない）。この決まりは監査の0章に書いた。
- **既定値の補完**：値が無い任意の項目にだけ既定値が入る（`language`・`showRomanNumerals`・`progressionBlocks`・`pinned`・`suppressedAutoTags`）。黙って除外せず、3件目のテストで期待値として明示した。
- **撮影の道具の置き場と名前**：`vite.config.ts` の Vitest は `scripts/` を除外していないため、`*.spec.ts` にすると Vitest に拾われて落ちた。ファイル名を `capture-screens.pw.ts` にして Vitest の対象から外した（共通の設定は変えていない）。専用の Playwright 設定にしたので、`test:ui`・`test:full` にも入らない（FULL の Playwright は 129件のまま）。
- **狭い幅での画面の移動**：1100px 以下ではサイドバーが閉じ、練習の下の項目が隠れる。道具は一時的に開いてクリックし、閉じ直してから撮る（写るのは閉じた状態）。
- **トースト**：保存の直後のトーストは 3.2 秒残り、次の画面のヘッダーに重なるので、保存のあとに閉じてから撮った。MIDI 解析の直後の画面は、使う人が実際に見る状態としてトーストを残した。
- **Voicing Loop の画面の中身**：撮影は視覚テストと同じ fixture 付きのビルド（`VITE_P527_E2E_FIXTURE=1`）を使うので、Voicing Loop には E2E の fixture の進行が出る（保存した合成の進行ではない）。
- **許可の確認**：このセッションは自動承認のモードで動いていたので、`.claude/settings.json` の効き目（確認が出ない・禁止が止まる）はこの段階では確かめられていない。途中で確認は出なかった。段階1の最初に確かめるのがよい。
- **FULL の順番**：FULL を製品側の最後の commit で1回だけ回し、そのあとに文書だけの commit を足した。文書の commit のあとにもう一度 FULL を回すと「edit → FULL → edit → FULL」になるので避けた。
