## 7. 判断ポイント

- **IconButton のツールチップ**：新しいツールチップを既定にすると、ブラウザの `title` と二重に出る。`title` を外すと、作り直さない Vault のテスト（`VaultView.test.tsx` の4か所）が壊れる。そこで既定は今のまま（`title`）にし、新しいツールチップは `tooltip="styled"` の時だけにした。各画面を作り直す段階で `styled` に切り替える。別案：全体で `title` を外し、Vault のテストを今書き換える → 作り直す画面の分だけ書き換えるという契約から外れるので採らなかった。
- **通知の重なり順**：まとめた通知はダイアログより上（トーストの層）に置いた。以前の元に戻すはダイアログより下、以前の右上のトーストは上だった。設定のダイアログを開いたまま出るお知らせ（`SettingsDialog` から24か所）が見えなくならないように、上にそろえた。別案：元に戻すの行だけダイアログの下に置く → 1つの重なりにまとめるという指示と合わない。
- **元に戻すのトーストは止めない**：`useUndoQueue` の元に戻せる時間は固定の 5 秒で、マウスを乗せても延びない。そのため元に戻すの行は止めず、残り時間の線も 5 秒で進む。
- **通知の件数**：最大3件は普通の通知に当てた。元に戻すの行は数えず、消さない（元に戻せる操作が画面から消えると動きが変わるため）。元に戻すが多い時は、今までどおり重なりの中でスクロールする。
- **下の帯を避ける方法**：Voicing Loop の画面から通知の重なりには変数が届かないので、`:root:has(…)` で `--lv-toast-offset-bottom` を上げた。採集は既存の変数で足り、ファイルの変更はない。Voicing Loop の変更は class を1つだけ。
- **モックとの違い**：
  - トーストの右と下の余白は、モックの 24px ではなく指示の変数（既定 16px）にした。
  - 種類の見分けは、モックの「アイコンの色＋下の線」に加えて、指示どおり左の細い線も足した。
  - セグメントは、モックの `aria-pressed` のボタンの並びではなく radiogroup にした（←→で動かす指示のため）。
  - 色はモックの Dojo（別の緑）ではなく、tokens の `--lv-accent-soft` にそろえた。
- **部品の見本の開き方**：`p89:screens` は本番と同じ作りのビルドで撮るので、`import.meta.env.DEV` だけでは見本を撮れない。撮影のビルドだけ `VITE_P89_GALLERY=1` を付ける形にした。本番のビルドの出力に見本が含まれないことは確かめた。
- **見本の中の重なり**：見本の画面では、アイコンボタンのツールチップ（固定表示）が1つ上の行に少し重なる。見本の画面の中だけのことなので、そのままにした。
- **EXE**：インストーラを作らないため `npm run tauri build -- --no-bundle` で作った。
