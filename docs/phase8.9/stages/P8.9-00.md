# P8.9-00 — 準備

**製品の画面と動きは変えない段階。** 後の段階を全自動で安全に回すための足場を作る。

- ブランチ：`feat/p8.9-00-setup`（local `master` から）
- 報告：`docs/phase8.9/reports/P8.9-00-setup.md`（日本語）
- 監査：`docs/phase8.9/audit/P8.9-00-baseline.md`
- 最後は merge 候補で止める。EXE は作らない（製品コードを変えないため）。

## 手順

### 0. Git の実態を確かめる

1. branch・worktree・HEAD・`git status --short` を確かめ、報告に書く。
2. local `master` に P8.8.6 と Test DX が入っていること（`package.json` に `test:fast` / `test:feature` / `test:ui` / `test:full` があり、`docs/test-dx/README.md` がある）を確かめる。ない時は段階を終える。
3. 未コミットの変更が他にあれば触らない。`Claude outputs/` は人間の資料置き場なのでコミットしない。
4. local `master` から `feat/p8.9-00-setup` を作る。報告の冒頭に、この段階の計画を書く。

### 1. phase package を置く

1. zip の `docs/phase8.9/` をリポジトリの `docs/phase8.9/` に置く。
2. `execution-state.json` の `baseCommit`・`currentBranch`・`status: "in-progress"` を実態に合わせる。
3. `npm run validate:phase-docs` を PASS させる。→ ゲート `p89-00-phase-docs`

### 2. Claude Code の許可設定を置く

1. zip の `templates/claude/settings.json` を `.claude/settings.json` に置く。既にある時は、中身を合わせて1つにする。
2. `.local-evaluation/` の**直下の名前だけ**を一覧する。中のファイルやサブフォルダは開かない。`test-logs` と `gate-cache` 以外のそれぞれについて、`Read(./.local-evaluation/<名前>/**)`（ファイルなら `Read(./.local-evaluation/<名前>)`）の deny を `.claude/settings.local.json` に書く。この名前は Git にも報告にも書かない。報告には件数だけ書く。
3. `.gitignore` に `p89-generated/` と `.claude/settings.local.json` を足す。
4. `CLAUDE.md` の末尾に、zip の `templates/CLAUDE.md-addendum.md` の節を足す。`CLAUDE.md` は案内役のままにし、`AGENTS.md` の内容は書き写さない。
5. 設定は次のセッションから確実に効く。この段階の途中で確認が出た操作は、報告の「判断ポイント」に書く。

### 3. データ保持の往復テストを入れる

[データ保持の契約](../contracts/P8.9-data-retention.md) の2章のとおり。

1. アプリが実際に使う読み込み・保存の経路を特定し、監査に書く（関数名とファイル）。
2. 廃止する項目をすべて既定値ではない値で埋めた合成の `VaultFile` を作る。
3. 読み込み → 保存し直しの結果が、入力と deep-equal で一致することを確かめるテストを追加する（例：`src/domain/p89DataRetention.test.ts`）。
4. 今のコードがすでに正規化している差があれば、テストの中で明示し、監査に記録する。製品コードは変えない。
5. テストを `scripts/test-dx/selection.mjs` の `persistence` と `vault` の恒久的な契約テストに登録し、その Node テストも更新する。
6. `npm run test:feature -- <追加したテスト>` を PASS させる。→ ゲート `p89-00-data-retention`

製品コードを変えないと通らない場合は、skip せずに段階をそこで終える。

### 4. スクリーンショットの道具を作る

1. 4つの大きさ（1920×1080・1440×900・960×1032・768×640）で主な画面を撮る道具を作る。E2E の合成データの仕組み（`e2e/helpers/`）を使い、個人の Vault は読まない。
2. 置き場所は `p89-generated/<名前>/<画面>@<幅>x<高さ>.png`。
3. `npm run p89:screens -- <名前>` で動くようにする。通常の Playwright の実行（`test:ui`・`test:full`）には含めない。
4. 道具のフォルダを `scripts/test-dx/selection.mjs` の対応表に「製品の契約ではない証跡の道具」として登録する。
5. 撮る画面：ホーム、コード採集（空・MIDI を読んだ後・テキストの通常・拡張）、Vault、進行ページ、Idea 詳細、Chord Dojo、Voicing Loop、Bass Practice（4つ。届く所まで）、設定、履歴。届かない画面は報告に書く。

### 5. 「変更前」を記録する

1. `npm run p89:screens -- P8.9-00-baseline` を実行する。→ ゲート `p89-00-screens-baseline`
2. 撮れた画面と大きさの一覧を報告に書く（画像はコミットしない）。

### 6. 後の段階のための監査

`docs/phase8.9/audit/P8.9-00-baseline.md` に書く。→ ゲート `p89-00-audit`

1. **ロジック分離の調査**（段階4〜7と段階2の App.tsx）：対象は `HomeView.tsx`・`VaultView.tsx`・`ProgressionDetailView.tsx`・`DetailView.tsx`・`PracticeView.tsx`・`features/bass-practice/ui/`・`App.tsx`。それぞれについて、状態・effect・イベント処理のまとまり、分けた先の hook / controller の名前の案、それを守っている既存テストを書く。
2. **テスト選択の対応**：上のファイルと `components/progression-editing/`・`AppShell.tsx` が、今の `selection.mjs` でどの担当に当たるか（「不明＝広く選ぶ」に落ちるものを明示する）。
3. **画面の基準画像**：`e2e/visual.spec.ts-snapshots` の各画像が、どの段階で更新されそうか。
4. **廃止する項目の使用箇所**：`genre`・`moods`・`chordMemo`・`status` 系・`nextAction`・`references`・`assets`・`monthlyGoal`・`language` を画面で読み書きしている所（段階3・5の入力）。
5. **トーストと保存状態**：今のトースト2種類と「保存済み」表示を出している所。
6. **英語表示**：言語を切り替えている所と、`i18n.ts` の英語の文言の量。
7. **ウィンドウ**：`src-tauri/tauri.conf.json` のウィンドウ設定と capabilities の今の状態（段階2の入力）。
8. **Test DX の実測**：この HEAD での FAST / FEATURE の目安時間（要約行のまま）。

### 7. 仕上げ

1. `npm run test:full` を fresh に1回。→ ゲート `p89-00-full-fresh`
2. 報告 `reports/P8.9-00-setup.md` を書く（[reports/README.md](../reports/README.md) の項目。レビューで見てほしい所を3〜5点）。→ ゲート `p89-00-report`
3. README の Status と `execution-state.json`（`completedStages`・`gateResults`・`lastVerifiedCommit`・`nextAction`）を揃える。
4. パスを明示して commit する。merge 候補で止める。取り込み・push・tag・release はしない。

- 監査の8項目が埋まっている。
- fresh FULL が PASS。
- 製品の画面と動きが変わっていない（製品コードの差分がない）。
