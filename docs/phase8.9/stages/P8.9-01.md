### 1. 許可の設定を絞り、効き目を確かめる

段階0のレビュー1点目への対応。`.claude/settings.json` の `deny` に足す：

- `Bash(npm run test:e2e:update:*)`（基準画像の一括更新。画面ごとの `--grep` 付きの更新は許可のまま）
- `Bash(git switch -f:*)`・`Bash(git switch --force:*)`・`Bash(git switch --discard-changes:*)`
- `Bash(git checkout -f:*)`・`Bash(git checkout .:*)`
- `Bash(rm -rf:*)`

確かめ方：禁止した操作（push の dry-run と、`git add -A` の dry-run）を1回ずつ試し、**設定で止められること**を確かめて報告に書く（実行されてしまったら、その時点で段階を終える）。このセッションが自動承認のモードで動いていて確かめられない時は、その旨を報告に書く。

`contracts/P8.9-test-and-evidence.md` の3章に「一括更新（`test:e2e:update*`）は使わない。画面ごとに `--grep` を付けて更新する」を1行足す。

### 3. tokens を磨く

`src/styles/tokens.css` の変数名は変えず、足りないものを足す。値の出どころは [P8.9-ui-direction.md](../contracts/P8.9-ui-direction.md) とモック。

- 練習の記録の色：`--lv-record`（ロゴの黄色 `#e6ae4a`）と `--lv-record-soft`。
- 文字の大きさ：`--lv-text-11`・`-12`・`-13`・`-14`・`-16`・`-20`・`-28`。
- 角の丸み：`--lv-radius-pill`（999px）を足す。sm 8・md 12・lg 16 はそのまま。
- 外枠の寸法（段階2で使う）：`--lv-titlebar-height: 36px`、`--lv-header-height: 56px`、`--lv-sidebar-wide: 232px`、`--lv-sidebar-narrow: 64px`。今の `--lv-sidebar-expanded` などは段階2まで残す。
- トースト：`--lv-toast-offset-bottom`（画面の下の帯の高さぶん上げるための変数。既定 16px）。

**`body` の文字の大きさなど、画面全体に効く既定値はこの段階では変えない。** 新しい大きさは、作り直す画面から順に使う（採集と Voicing Loop の見た目を守るため）。

### 4. 自作アイコン

`src/components/icons/` に、線の太さと角の丸みを揃えたアイコンを作る。

- 24×24 の viewBox、`stroke="currentColor"`、太さ 1.8、`stroke-linecap` と `stroke-linejoin` は round、塗りなし。`size` と `aria-hidden`（既定 true）を受け取る。
- 形はモック（`RHome.dc.html` のサイドバー・ヘッダー・タイトルバー・トースト）にある path を優先して使い、無いものは同じ作りで描く。
- 最初のセット：ホーム・取り込む・Vault・練習・Chord Dojo・Voicing Loop・Bass Practice・Live MIDI・設定・検索・MIDI・試聴音色・メトロノーム・音量・最小化・最大化・元に戻す（ウィンドウ）・閉じる・成功・お知らせ・注意・エラー・再生・停止・ループ・入れ替え・お気に入り・元に戻す（操作）。
- lucide-react は外さない。この段階で画面のアイコンを一斉に置き換えることはしない。使うのはトーストと部品の見本から。

### 5. 共通部品

`src/components/ui/primitives.tsx` を作り直すか、`src/components/ui/` に部品を足す。今の呼び出し側が壊れないように、既存の props は残す。

| 部品 | 決まり |
| --- | --- |
| Button | `primary`（青緑の塗り。1画面に1つ）・`neutral`（枠線）・`ghost`（塗りなし）・`state`（紫。`aria-pressed` のオンの時だけ紫）。今の `secondary` は `neutral` の別名として残す。`danger` は確認ダイアログの「削除する」だけで使う（普段の画面では使わない）。押せない時は `disabledReason` をツールチップで出す |
| IconButton | 名前（`aria-label`）必須。ホバーでツールチップ |
| SegmentedControl | モックの Dojo の「進み方」。キーボードの ←→ で動く |
| Select | ネイティブの `<select>` に見た目を付ける（モックの Dojo の「判定」） |
| Chip | タグ・絞り込み用。選択中は青緑 |
| Tooltip | ホバーとキーボードのフォーカスで出る。0.12 秒 |
| Popover | 音量などを1つのボタンから開く |
| ProgressBar | 進み具合の帯（青緑）と、練習の記録の帯（`--lv-record`） |
| EmptyState・LoadingState | 今の部品を新しい見た目に |
| Modal・ConfirmDialog | 見た目を揃える。Esc で閉じる、フォーカスを中に閉じ込める（今の動きを守る） |

共通の動き：ホバー 0.12 秒、キーボードのフォーカスの時だけ青緑の枠（`:focus-visible`）、押した時は少し沈む、OS の「動きを減らす」設定で動きを止める。

**部品の見本**：全部品の全状態（通常・ホバー・フォーカス・押せない・オン）を並べた画面を作る。開発のビルドだけで開けるようにし（例：`import.meta.env.DEV` の時だけ `?gallery` で開く）、本番のビルドには入れない。`p89:screens` で撮れるようにする。

### 6. トーストを1つにまとめる

今の `Toast`（右上・1件）と `UndoToast`（左下／下の中央）を、右下の1つの仕組みにまとめる。

- 受け口：`src/components/notifications/` に Provider と `useNotify()`（例：`notify({ tone, message, action?, durationMs? })`）。App の `toast` の state と 3.2 秒の effect は、ここへ移す（監査1章の `useAppNotifications`）。
- **呼び出し側は変えない**：今の `setToast(...)` の呼び出し（約150か所）は、同じ形のまま新しい受け口に流す。呼び出し側の書き換えは、各画面を作り直す段階で行う。
- 見た目と動き（モックの `RHome.dc.html` の `.toast`）：
  - 右下。最大3件まで重ね、4件目が来たら古いものから消す。
  - 下から少しスライドしてフェードイン（0.18 秒）。約4秒で消え、下に残り時間の細い線を出す。
  - マウスを乗せている間とフォーカスがある間は止まる。
  - 種類は成功・お知らせ・注意・エラー。アイコンと左の細い色の線で見分ける。エラーは自動で消えず、閉じるボタンで閉じる。
  - 1行の文と、必要な時だけ操作を1つ（「開く」「元に戻す」）。
  - `aria-live`：エラーは assertive、それ以外は polite。
  - 「動きを減らす」設定ではスライドと残り時間の線を止める。
- **元に戻す**：`useUndoQueue` の決まり（元に戻せる時間、複数の操作、元に戻した後のフォーカスの戻り先）はそのまま守る。トーストが消える時間は、元に戻せる時間に合わせる。マウスを乗せて止めても元に戻せる時間が延びないなら、元に戻すトーストは止めない（どちらにしたかを報告に書く）。
- **下の帯と重ならない**：画面の下に帯や再生ボタンがある画面（Voicing Loop・採集の下の帯など）では、`--lv-toast-offset-bottom` をその高さに合わせる。採集と Voicing Loop への変更はこの変数を設定する1行程度にとどめる。
- ヘッダーの「✓ 保存済み」表示は段階2で扱うので、この段階では触らない。
- 古い `Toast.tsx`・`UndoToast.tsx` は、使われなくなったら消す。テストは新しい仕組みのテストに置き換え、消したテストを1件ずつ報告に書く。
