# P8.9-02 — 共通レイアウト

アプリの**外枠**（タイトルバー・サイドバー・ヘッダー・スクロールの持ち方）を作り直す段階。各画面の中身はまだ作り直さない。

- ブランチ：`feat/p8.9-02-shell`（段階1を取り込んだ local `master` から）
- 報告：`docs/phase8.9/reports/P8.9-02-shell.md`（日本語）
- モック：zip の `mocks/` を `p89-generated/mocks/` に置いて見本にする（`RHome.dc.html` の外枠が正。狭い時は `RHomeCompact.dc.html`）
- 最後は merge 候補で止める。EXE を作る。

## 手順

### 0. 始める前

1. zip の `START-HERE.md` の手順で段階1の候補を取り込み、Git の実態を報告に書く。
2. `feat/p8.9-02-shell` を作り、このファイルを置き、README の Status と `execution-state.json` を段階2に進める。報告の冒頭に計画を書く。
3. 報告に書くファイルの場所は、`/` 区切りでコードの書式（バッククォート）に入れる。`\` は使わない（段階1の報告で EXE の場所の文字が化けたため）。

### 1. App.tsx の外枠と画面切り替えを分ける（見た目は変えない）

監査1章の案に沿って、独立した commit にする。

- `useAppNavigation`：画面の行き先と「離れてよいか」の確認（`view`・`selectedId`・`selectedProgression`・`progressionDetailDirty`・`pendingProgressionLeave`、`navigateTo`・`openDetail`・`openProgression`・`requestProgressionLeave` など）。
- 音量とキー操作（`masterVolume`・`changeMasterVolume`・`handleKeyDown`）は、新しいヘッダー側から使える形にする。
- 残りの hook（練習への受け渡し・取り込み・Live MIDI・削除）は、この段階で必要な分だけ分ける。無理に全部は分けない。
- `App.test.ts` と既存のテストがそのまま通ることを確かめてから、次へ進む。

### 2. 一体型タイトルバー（高さ 36px）

1. `src-tauri/tauri.conf.json` の main ウィンドウに `decorations: false`。起動時の大きさを 1440×900 に（`minWidth: 768`・`minHeight: 640` はそのまま）。Live MIDI の小窓（`live-midi`）は変えない。
2. `capabilities/default.json`（main）に足りない権限を足す：`core:window:allow-minimize`・`allow-close`・`allow-start-dragging`・`allow-toggle-maximize`、画面に収める処理に要る分（`allow-center` など）。`tauriSecurityConfig.test.ts` を明示して回す。
3. タイトルバーの中身（`RHome.dc.html` のタイトルバー）：
   - 左：ロゴ（`public/loop-vault-icon.svg`）とアプリ名。
   - 中央：検索のボタン（Ctrl+K）。**この段階では、Vault に移って検索欄にフォーカスするだけ**にする（検索パレットは作らない）。
   - 右：最小化・最大化（最大化中は「元に戻す」のアイコン）・閉じる（46×36px。閉じるだけホバーで赤）。段階1の自作アイコンを使う。
4. 動き：空いている所のドラッグで移動（`data-tauri-drag-region` か `startDragging`）、ダブルクリックで最大化／元に戻す。ボタンや入力の上ではドラッグにしない。
5. **閉じるボタンは、今の閉じる時の保存の仕組み（`src/store/closeGuard.ts`）を必ず通す。** 標準の × と同じ経路（ウィンドウの close 要求）にし、未保存の変更が失われないことをテストで確かめる。
6. ブラウザ（E2E・`p89:screens`）でもタイトルバーは描く。Tauri が無い時、ウィンドウのボタンは押せない状態にする（見た目は同じ）。
7. 起動時：画面（モニターの作業領域）が 1440×900 より小さい時は、収まる大きさに縮めて中央に置く。
8. **逃げ道**：設定のダイアログに「標準のタイトルバーを使う」を1つ足す。オンにすると、次の起動から `setDecorations(true)` で標準に戻し、自作のタイトルバーは出さない。保存先は Vault ではなく、今の音色やメトロノームの設定と同じ端末ローカルの保存にする（Vault の保存形式は変えない）。
9. `src/voicingPractice/mainWindowWorkArea.ts` など、ウィンドウの大きさを使っている所が、タイトルバーが中に入っても正しく動くことを確かめる。

### 3. サイドバー（幅 232px、狭い時は 64px）

1. 項目（`RHome.dc.html` の `navTop`・`navPractice` の順）：ホーム・取り込む・Vault、見出し「練習」の下に Voicing Loop・Chord Dojo・Bass Practice、その下に Live MIDI、下の方に設定。履歴は段階3で画面ごと外すので、この段階では設定の上に置いたままでよい。
2. 各項目に `data-nav="home"` などの変わらない印を付ける。E2E のヘルパー（`e2e/helpers/app.ts`）と `p89:screens` は、名前ではなくこの印で辿るように直す。
3. 画面名は日本語（固有名はそのまま）。英語の見出し（WORKSPACE・SYSTEM）はなくす。
4. 幅 1200px 未満では、最初からアイコンだけ（64px）にする。手で切り替えた状態は端末ローカルに記憶する。アイコンだけの時は、ホバーとフォーカスで名前をツールチップで出す。
5. 選択中は青緑の印（`aria-current="page"`）。自作アイコンを使う。
6. `--lv-sidebar-expanded` などの古い変数は、使う所がなくなったら消す。

### 4. ヘッダー（高さ 56px）

1. 左：画面名。古い説明文（`pageContext`）は出さない。その画面の操作を置く場所（今の採集の `capture-mode-tabs-host` を含む）は残す。
2. 右（アプリ共通）：MIDI の状態・試聴音色・メトロノーム（ON/OFF）・音量。
   - **音量**：音量メーターとつまみは、1つのボタン（音量のアイコン＋小さなメーター）にまとめ、押すと段階1の Popover でつまみを出す。再生中の停止は今までどおりすぐ押せるようにする。
   - **MIDI の状態**：今ある Live MIDI の状態（`src/liveMidi/`）を読むだけにする。起動時に MIDI の許可を新しく求めない。押すと Live MIDI を開く。
3. 「＋ Idea」は段階3で外す。この段階では無彩色のボタンにして残す（主役の青緑は画面の中の1つだけにするため）。
4. **保存の状態**：
   - 自動保存が成功した時は何も出さない（毎回トーストを出すとうるさいため）。
   - 保存中・未保存の間だけ、ヘッダーの右端に小さく出す。
   - 保存に失敗した時は、エラーのトースト（自動で消えない）と、ヘッダーの印の両方を出す。
   - 進行ページの「保存済み／変更を保存」は画面の中の表示なので、そのまま残す。

### 5. スクロールの持ち方

1. `html`・`body`・`#root` は固定。タイトルバー・サイドバー・ヘッダーは動かさず、**中身の欄だけ**がスクロールする。
2. 二重のスクロール（外枠と画面の両方がスクロールする所）をなくす。採集は段階8.8.6で高さを外枠に任せる形にしてあるので、その決まりを壊さない。
3. スクロールバーの見た目を1つの決まりにする（細い・暗い地に馴染む色）。

### 6. 段階1の申し送り

1. **下の帯を避ける仕組み**：段階1の `:root:has(…)` と実測の高さ（64・112・288px）をやめ、下の帯の側が自分の高さを申告する形にする（例：`useReserveBottomSpace(ref)` が ResizeObserver で高さを測り、通知の重なりの下の余白に反映する）。採集・Voicing Loop・Live MIDI の小窓（ブラウザ版）で使う。採集と Voicing Loop への変更は、その呼び出しを足す程度にとどめる。
2. **部品の見本が本番に入らない検査**：FULL の本番ビルドのあとに、出力（`dist/`）に見本の印が含まれないことを確かめる手順を足す。印の文字列は見本の側に1つ決めて置く。
3. **撮影の道具**：`data-nav` で辿る。保存の状態が落ち着いてから撮る（段階1の Vault の「未保存／保存済み」の揺れをなくす）。768×640 で「ダイアログを開いた状態でトーストが出ている」画面を1枚足し、ダイアログのボタンに重ならないことを確かめる。重なる場合は、ダイアログが開いている間の通知の位置を直す。

### 7. 基準画像とスクリーンショット

1. 外枠が変わるので、E2E の基準画像（9枚）は全部動くはず。画面ごとに `--grep` を付けて更新し、画像ごとに「外枠の作り直し」と書く。外枠以外の差があれば、その理由も書く。
2. 名前で画面を探している E2E は、`data-nav` や日本語の名前に合わせて直す。直した spec を報告に並べる。
3. `npm run p89:screens -- P8.9-02` で撮る。段階1と比べ、**採集と Voicing Loop の中身（外枠の内側）に差がないこと**を確かめて報告に書く。

### 8. 仕上げ

1. `npm run test:full` を fresh に1回。→ `p89-02-full-fresh`
2. `p89:screens` の結果。→ `p89-02-screens`
3. EXE を作る（`npm run tauri build -- --no-bundle`）。→ `p89-02-exe`
4. 報告を書き、README の Status と `execution-state.json` を揃える。→ `p89-02-report`
5. パスを明示して commit し、merge 候補で止める。

**EXE で人間が確かめる項目**を報告の最後に並べる（Claude Code は実機のウィンドウ操作を確かめられないため）：ドラッグで移動・ダブルクリックで最大化・最小化・閉じる（未保存があっても失われない）・縁でのサイズ変更・Win+←/→ のスナップ・画面の端へのドラッグでのスナップ・起動時の大きさ・「標準のタイトルバーを使う」の切り替え。

## 完了条件

- App.tsx の外枠と画面切り替えが分かれ、分ける commit の時点で既存のテストが通っている。
- 一体型タイトルバーが描かれ、閉じるは closeGuard を通る（テストあり）。標準に戻す設定がある。
- サイドバーが日本語・自作アイコン・`data-nav` 付きで、1200px 未満でアイコンだけになる。
- ヘッダーが新しい形で、音量はまとめられ、自動保存の成功でトーストが出ない。保存の失敗はエラーのトーストで出る。
- 中身の欄だけがスクロールし、二重のスクロールがない。
- 下の帯を避ける仕組みが申告の形になり、`:has()` と固定の高さがない。
- FULL の中で、本番のビルドに部品の見本が入っていないことを確かめている。
- 採集と Voicing Loop の中身に、外枠以外の差がない。
- データ保持の往復テストが PASS。fresh FULL が PASS。EXE が作れた。人間が確かめる項目が報告にある。
