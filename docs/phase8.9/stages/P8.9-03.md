### 3. 機能を画面から外す

**外すのは画面と、それによってどこからも使われなくなったコードだけ。** 型（`src/domain/types.ts`）・検証（`schema.ts`）・読み込みと保存の処理は変えない。新しい Idea を作る時の初期値（`status: "idea"`・`nextAction`・`chordMemo` など）もそのまま。1項目ごとに commit を分け、項目ごとに FAST → FEATURE を回す。

| # | 外すもの | 今ある場所（監査4章） | 注意 |
| --- | --- | --- | --- |
| a | 制作ステータス（パイプライン・切り替え・保留／没の理由） | `DetailView`・`StatusPipeline`・`StatusActionMenu`・`HomeView`（件数・停滞中・「保留にする」）・Vault の絞り込み・`App.tsx`（`transitionIdea` など） | 保存済みの `status`・`statusHistory`（`reason` を含む）はそのまま残る |
| b | 月間ゴールと「今月の完成」 | `SettingsDialog`・`HomeView`・`App.tsx` | `settings.monthlyGoal` の値は残す |
| c | 次の一手・停滞中の一覧 | `HomeView`・`DetailView` | 保存時の下書き（`CaptureView` など）の初期値は残す |
| d | 「＋ Idea」と空の Idea を作るダイアログ | ヘッダー・`HomeView`・`VaultView`・`App.tsx`（`isCreateOpen` など） | Idea の作り方は「取り込む」からだけになる |
| e | 参考曲・参照、関連ファイル | `DetailView` | `assets` は進行の `sourceAssetId` が参照するので値は残す |

**AI で展開案（h）の注意**：

- 外すのは画面（ボタン・引き出し・設定の欄）と App の配線だけ。`src/llm/`・`src/domain/progressionAdvisor/`・`src-tauri/src/llm/`（API キーの保存を含む）は、評価のスクリプト（`eval:advisor`・`diagnose:llm-schema`）が使っているので残す。消す候補として報告に一覧を書く。
- 設定の欄を消すと、保存済みの API キーを消す手段が画面から無くなる。そこで、**設定の奥の「開発者向け」に「保存した API キーを削除」だけを残す**（今ある削除の処理を呼ぶだけ。キーが無い時は押せない）。難しい場合は残さず、報告に書く。

### 4. 表示を日本語だけにする

1. 表示の言語を日本語に固定する。設定の言語の切り替えを外す。`store/vaultStore.ts` のエラー文も日本語だけにする。**保存された `settings.language` は書き換えない**（`"en"` のままでも日本語で表示する。往復テストで確かめる）。
2. `src/i18n.ts` の英語のブロック（`en`）を消し、型（`AppCopy` など）を日本語だけに合わせる。
3. `language === "ja" ? … : …` の形の分岐（監査6章：49ファイル・488か所）は、**作り直す画面も含めて全部**、日本語の側だけを残す形に機械的に直す。1ファイルずつ直し、表示が変わらないこと（日本語のまま）を FAST で確かめる。
4. 英語しかない表示の文言（例：大文字の見出し・ボタンの名前）は、**作り直さない画面**（取り込む・Voicing Loop・Chord Dojo・Bass Practice・Live MIDI・外枠・共通部品）だけ日本語にする。作り直す画面（ホーム・Vault・進行ページ・Idea 詳細・設定）の英語だけの文言は、その画面の段階で扱う。
   - 日本語にしない：固有名（Loop Vault・Vault・Voicing Loop・Chord Dojo・Bass Practice・Live MIDI・Degree Echo などの練習名）、MIDI・BPM、コード名と度数、内部の値（表示に出ない列挙の値など）。
   - 取り込むと Voicing Loop は、文言の変更だけにとどめ、並びや大きさを変えない。文言の長さで折り返しが変わる所は報告に書く。
5. `#main-content` の読み上げ名（`aria-label`）を日本語の画面名にそろえる。E2E の `/コード採集|Capture/` のような「日本語か英語」の探し方は、日本語だけにする。
6. 英語の表示や言語の切り替えを確かめていたテストは、日本語の確かめに直すか、「機能削除に伴う削除」として1件ずつ報告に書く。

### 5. 基準画像とスクリーンショット

1. 変わった画面の基準画像だけ、テストごとに `--grep` を付けて更新し、画像ごとに理由を書く。`history` は消す（理由：履歴画面を外したため）。
2. `p89:screens` から履歴画面を外し、`npm run p89:screens -- P8.9-03` で撮る。
3. 取り込む・Voicing Loop・Chord Dojo・Bass Practice について、段階2との差が文言の変更の範囲に収まっていることを報告に書く。

### 6. 仕上げ

1. `npm run test:full` を fresh に1回。→ `p89-03-full-fresh`
2. `p89:screens` の結果。→ `p89-03-screens`
3. EXE を作る（`npm run tauri build -- --no-bundle`）。→ `p89-03-exe`
4. 報告を書き、README の Status と `execution-state.json` を揃える。→ `p89-03-report`
5. パスを明示して commit し、merge 候補で止める。

報告の3章（外した機能）は、上の表の a〜h ごとに「何を・どこから外したか・消したコード・残したコード・消したテスト」を書く。

**EXE で人間が確かめる項目**を報告の最後に並べる：いつもの Vault を開いて進行と Idea がそろっていること、ジャンル・ムード・メモがあった Idea で「以前の項目」に出ること、以前に英語表示にしていても日本語で出ること、履歴・＋ Idea・AI 展開案・月間ゴール・言語の切り替えが無いこと、「保存した API キーを削除」（残した場合）。
