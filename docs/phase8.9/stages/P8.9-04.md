# P8.9-04 — ホームと Vault

ホームと Vault を新しい見た目で作り直す段階。先にロジックを分け、既存のテストが通ってから UI を差し替える。

- ブランチ：`feat/p8.9-04-home-vault`（段階3を取り込んだ local `master` から）
- 報告：`docs/phase8.9/reports/P8.9-04-home-vault.md`（日本語）
- モック：zip の `mocks/` を `p89-generated/mocks/` に置く。
  - ホーム：`RHome.dc.html`（1920）と `RHomeCompact.dc.html`（狭い時）。**人間が承認済み。これが正。**
  - Vault：`Vault.dc.html` は前の案で、外枠が古い。**中身の並び（左の絞り込み・検索・並び順・一覧）の参考だけ**にし、見た目はデザインシステムと下の仕様で作る。Vault の新しいモックは無いので、人間はスクリーンショットで判断する。
- 最後は merge 候補で止める。EXE を作る。

## 手順

### 0. 始める前

1. zip の `START-HERE.md` の手順で段階3の候補を取り込み、Git の実態を報告に書く。
2. `feat/p8.9-04-home-vault` を作り、このファイルを置き、README の Status と `execution-state.json` を段階4に進める。報告の冒頭に計画を書く。
3. 人間が決めたこと（下の「今日のループの決まり」と「取り込むの次の一手の入力を外す」）を `contracts/P8.9-ui-direction.md` に1節足して記録する。

### 1. ロジックを分ける（見た目は変えない・独立した commit）

- ホーム：`useHomeSummary(ideas, now)`（純粋な集計）。段階3で外した集計の残りを整理する。
- Vault：`useVaultLibraryFilters`（絞り込み・検索・並び・表示モードの記憶）と `useVaultKeyboardSelection`（キー操作と仮想スクロール）。
- `HomeView.test.tsx`・`VaultView.test.tsx`・`e2e/vault-flow.spec.ts` がそのまま通ってから次へ進む。新しいフォルダを作ったら `selection.mjs` に登録する。

### 2. ホームを作り直す

モックの `RHome.dc.html` の順と形で作る。主役の青緑のボタンは「続きをやる」の1つだけ。

| カード | 中身 | データ |
| --- | --- | --- |
| ヘッダー | 画面名「ホーム」と今日の日付（例：9月28日（月）） | — |
| 続きから | 最後に練習・編集した進行。譜面の帯（8.8 の帯を流用）と「続きをやる」 | 下の「練習の記録の集め方」の最新。無ければ最後に更新した進行。どちらも無ければカードを出さない |
| 取り込む | MIDI とテキストへの入口 | 取り込むの画面を、それぞれのモードで開く |
| 今日のループ | 1つの進行。再生すると今のコードが光る。入れ替え（元に戻すのトースト付き）とお気に入り | 下の「今日のループの決まり」。お気に入りは進行の `pinned`（今ある項目と今ある書き込みの処理） |
| 今日の練習 | 練習の輪と、直近5日の連続日数の点（練習の記録の黄色 `--lv-record`） | 下の「練習の記録の集め方」 |
| 最近の進行 | 最近取り込んだ・触った進行の行。押すと進行ページ | 進行の `capturedAt` と Idea の `updatedAt` |

- 大きさ：1920 はモックどおり。1440×900 は同じ順で列を減らす。1200px 未満（サイドバーがアイコンだけ）は `RHomeCompact.dc.html` の形。768×640 でも横にはみ出さない。
- 進行が1つも無い時は、「最初の進行を取り込む」の案内だけを出す（空の状態の部品）。
- 再生は今ある試聴・再生の仕組みを使う（transport scheduler は変えない）。
- 画面の文言はすべて日本語。自作アイコン、`IconButton` は `tooltip="styled"`。トーストは `useNotify()` で種類（成功・お知らせ・注意・エラー）を付ける。

**今日のループの決まり**（人間が決めた）：

1. 候補は保存されたすべての進行（隔離中の Idea のものは除く）。
2. 端末の日付（YYYY-MM-DD）で1つに決める。同じ日なら開き直しても同じ進行。
3. 直近7日に「今日のループ」に出た進行は除く。全部が除かれる時は、この条件を外す。
4. お気に入り（`pinned`）の進行は3倍出やすくする。
5. 入れ替えを押すと、今の進行と直近7日のものを除いて次の1つを選び、「元に戻す」付きのトーストを出す。入れ替えた結果はその日のうちは保たれる。
6. 「出た記録」と「その日の入れ替え」は端末ローカル（例：`loop-vault:today-loop:v1`）に置く。**Vault には書かない。**
7. 日付を固定した単体テストで、同じ日は同じ・7日の除外・お気に入りの重み・全部除外の時・入れ替えと元に戻す、を確かめる。

**練習の記録の集め方**（読むだけ）：

- 今ある記録だけを使う。新しい保存先や保存の項目は作らない。
  - Chord Dojo：進行の `practice`
  - Bass Practice：`features/bass-practice/application/practiceData.ts` の記録（`derivePracticeHistory` など）
  - Voicing Loop：今ある記録の置き場を調べて使う
- 日付の無い記録は数えず、報告に書く。
- 連続日数：1日に1つでも記録があればその日を数える。
- 練習の輪：今日の練習の数。目標の数は決め打ちせず、今日やった数だけを見せる。数字で急かさない。

### 3. Vault を作り直す

1. **一覧は「進行」だけ**にする。Idea 一覧（Idea のカードの格子と、表示の切り替え）を外す。
   - **進行を1つも持たない Idea を見失わないようにする**：一覧の最後に「進行のない Idea（n件）」のまとまりを出し、押すと今の Idea 詳細を開く。件数を報告に書く。
2. **左の絞り込み**（件数付き。欄の中は「または」、欄どうしは「かつ」）：キー・長さ（小節）・タグ・取り込み元（MIDI・テキスト・Live MIDI）・お気に入り。「すべて解除」。今の絞り込みの状態は、今までどおり記憶する。中身の欄が 900px 未満の時は、今の引き出しの形で出す。
3. **検索**（`#vault-search` のまま。タイトルバーの検索がここに来る）：
   - コード名の前方一致（例：`Dm7`）
   - 度数の流れ（例：`2-5-1`）。進行のキーから `src/domain/harmony/degrees.ts` の `degreeOf` で度数を出して連続で一致を探す。キーの無い進行は度数の検索に出さない。
   - 入力欄の説明に「コード名か度数（2-5-1）で探す」と出す。
4. **並び順**：新しい順・名前順・長さ順・最近練習した順。
5. **行**：名前・キー・BPM・小節数・タグ・小さな譜面の帯・試聴のボタン・お気に入りの星。押すと進行ページ。
6. 今の仮想スクロールとキー操作はそのまま動かす。
7. 状態の「要確認あり」の絞り込みと、度数表示の切り替えは Vault には置かない（設定の度数表示はそのまま）。

### 4. 取り込むの「次の一手」の入力を外す（人間が決めた）

`SaveProgressionPopover`・`ManualCandidateEditor`・`CaptureView` から入力欄だけを外す。保存する時の初期値（空の `nextAction`）は今のまま入れる（データ保持の契約）。取り込むは微修正だけの画面なので、並びと大きさは変えない。初期値が変わらないことをテストで確かめる。

### 5. 基準画像とスクリーンショット

1. `home`・`vault` の基準画像を、テストごとに `--grep` を付けて更新し、理由を書く。
2. `npm run p89:screens -- P8.9-04` で撮る。ホームは「進行がある」「進行が無い」の両方、Vault は「絞り込みあり」「検索あり（度数）」も撮る。
3. 取り込むは、次の一手の入力を外した所以外に差が無いことを報告に書く。

### 6. 仕上げ

1. `npm run test:full` を fresh に1回。→ `p89-04-full-fresh`
2. `p89:screens` の結果。→ `p89-04-screens`
3. EXE を作る（`npm run tauri build -- --no-bundle`）。→ `p89-04-exe`
4. 報告を書き、README の Status と `execution-state.json` を揃える。→ `p89-04-report`
5. パスを明示して commit し、merge 候補で止める。

**EXE で人間が確かめる項目**を報告の最後に並べる：いつもの Vault でのホームの見え方・今日のループ（開き直しても同じ、入れ替えと元に戻す、お気に入り）・今日の練習の数と連続日数が実感と合うか・Vault の件数が前と同じか・絞り込み・コード名と度数の検索・並び順・進行のない Idea に辿り着けるか・取り込むで保存できるか。

## 完了条件

- ロジックを分けた commit の時点で既存のテストが通っている。
- ホームがモックの順と形になり、主役のボタンは1つ。3つの大きさ（1920・1440・1200 未満）で崩れない。
- 今日のループが決まりどおりに動き、単体テストがある。Vault には書かない（お気に入りの `pinned` を除く）。
- 練習の記録は読むだけで、新しい保存先が無い。
- Vault の一覧が進行だけになり、進行のない Idea にも辿り着ける。件数が段階3と同じ。
- 絞り込み・コード名と度数の検索・並び順・キー操作が動く。
- 取り込むの次の一手の入力が無く、保存の初期値は変わらない。
- データ保持の往復テストが PASS。fresh FULL が PASS。EXE が作れた。
