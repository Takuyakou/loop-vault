- モック：zip の `mocks/` を `p89-generated/mocks/` に置く。設定の新しいモックは無い。ヘッダーの部品は `RHome.dc.html`、ボタンと色は `Common.dc.html`。
- 最後は merge 候補で止める。EXE を作る。

## 手順

1. zip の `START-HERE.md` の手順で段階4の候補を取り込み、Git の実態を報告に書く。
2. `feat/p8.9-08-settings` を作り、このファイルを置く。報告の冒頭に計画を書く。

### 1. フェーズ計画の更新（人間が決めたこと）

1. **進行ページの作り直し（P8.9-05、Idea 詳細の吸収を含む）も 8.9 から外し、後日、別のフェーズで行う。** 後回しにした画面（Chord Dojo・Bass Practice・進行ページ）は、それぞれ別のフェーズで後ほど作り直す。P8.9-05 を欠番にする（README の見出しは残して中身を書き換え、`requiredGates` から消す、`work-instructions.md` の Scope・Non-goals、`contracts/P8.9-ui-direction.md` の8章の進行ページ・Idea 詳細の行を直す）。
2. **段階8を2つに分ける。** README の段階一覧と `execution-state.json` に `P8.9-09 — 微修正・整理・フェーズの締め` を足す（ゲート：`p89-09-full-fresh`・`p89-09-screens`・`p89-09-exe`・`p89-09-report`）。P8.9-08 の説明をこのファイルの題に合わせて直す。

4. README の Status と `execution-state.json` を段階8に進め、`validate:phase-docs` を通す。

### 2. Vault の並び順の既定（人間が決めた）

アプリを起動した時の Vault の並び順を、必ず「新しい順（取り込んだ日が新しいものが上）」にする。起動の間は、選んだ並び順を今までどおり覚えてよい。お気に入りを先頭に固定しない今の形はそのまま。単体テストで、起動し直すと「新しい順」に戻ることを確かめる。

### 3. 設定をダイアログから画面にする

1. サイドバーの「設定」（`data-nav="settings"`）で、ダイアログではなく**画面**（`view: "settings"`）を開く。ヘッダーの画面名は「設定」。
2. 形：左に欄の一覧（押すとその欄へ移る）、右に中身。中身の欄が 900px 未満の時は1列に積む。
3. 欄（今ある設定を移すだけ。項目を増やさない）：
   - **一般**：度数表示、標準のタイトルバーを使う
   - **音と MIDI**：今ある試聴・MIDI・ベースの録音の設定（`BassPracticeRecordingSettingsSection` など、今設定にあるもの）
   - **Live MIDI**：`LiveMidiSettingsSection`
   - **データ**：書き出し・読み込み・バックアップと復元・形式の情報
   - **開発者向け**（最初は閉じている）：解析の設定・評価データ・ビルドの情報・「保存した API キーを削除」
4. 英語だけの文言（「Build commit」「Accuracy First」「Backup / Restore」など）を日本語にする。固有名と内部の値はそのまま。
5. 設定の動き（変えるとすぐに効く・確認のダイアログ・書き出しと読み込み・復元）は今のまま。今のテストの確かめる内容を弱くしない。
6. ダイアログが開いている間に通知を上の中央に移す仕組み（`useAnyModalOpen`）は、確認のダイアログなどで今も使うので残す。
7. 設定を画面にしたので、`p89:screens` の `settings-toast`（768×640）は「確認のダイアログを開いた状態でトーストが出ている」画面に置き換え、ダイアログのボタンに重ならないことを確かめる。

### 4. 起動・復旧・空の状態

`App.tsx` の起動中（`StartupState`）・空の Vault（`EmptyState`）・壊れたデータの隔離の案内（`QuarantineNotice`）・大きさの復旧の案内（`SizeRecoveryNotice`）を、段階1の共通部品（空の状態・読み込み中）で作り直す。

- 起動中：ロゴと小さな読み込み中の表示。
- 空の Vault：「最初の進行を取り込む」の案内と、取り込む（MIDI・テキスト）への入口。ホームの空の状態と文言をそろえる。
- 隔離の案内：何が起きたか・データは消えていないこと・次にすること、を短く。今の復旧の操作は変えない。
- 動きと文言の確かめる内容を今のテストのまま保つ。

### 5. Live MIDI の小窓

別ウィンドウの Live MIDI（`LiveMidiMiniMode.tsx`・`LiveMidiWindowRoot.tsx`）の色・文字・ボタン・アイコンを、デザインシステムにそろえる。ウィンドウの設定（常に手前・標準のタイトルバー）と動きは変えない。ブラウザ版の小窓も同じ見た目にする。

### 6. ヘッダーの部品をモックに合わせる（段階2の申し送り）

- 試聴音色：`RHome.dc.html` のヘッダーの形（ピアノ／エレピのセグメント）。段階1の SegmentedControl を使う。
- メトロノーム：アイコンだけのボタン。オンの時はボタンの `state`（紫、`aria-pressed`）。名前はツールチップで出す。
- 1300px 未満で文字を隠している今の決まりは、アイコンだけになるので不要なら外す。
- 動き（音色の保存・メトロノームの共通の状態）は変えない。

### 7. 基準画像とスクリーンショット

1. `settings` の基準画像は設定の画面の形で作り直す（テストの `--grep` を付け、変化があるはずなので `--update-snapshots=all` で作り直して差分を目で見る）。ヘッダーの部品が変わるので、ほかの基準画像も動いたものだけ作り直し、画像ごとに理由を書く。
2. `npm run p89:screens -- P8.9-08` で撮る。設定の画面（各欄）、起動中、空の Vault、隔離の案内（合成データで出せる範囲）、Live MIDI の小窓（ブラウザ版）も撮る。
3. 取り込む・Voicing Loop・Chord Dojo・Bass Practice の中身に、ヘッダー以外の差が無いことを報告に書く。

### 8. 仕上げ

1. `npm run test:full` を fresh に1回。→ `p89-08-full-fresh`
2. `p89:screens` の結果。→ `p89-08-screens`
3. EXE を作る（`npm run tauri build -- --no-bundle`）。→ `p89-08-exe`
4. 報告を書き、README の Status と `execution-state.json` を揃える。→ `p89-08-report`
5. パスを明示して commit し、merge 候補で止める。

**EXE で人間が確かめる項目**を報告の最後に並べる：設定が画面で開き、各欄の設定が今までどおり効くこと（度数表示・標準のタイトルバー・Live MIDI・書き出しと読み込み・バックアップと復元）、開発者向けの欄が最初は閉じていること、Vault を開き直すと「新しい順」になっていること、起動中と空の状態の見え方、Live MIDI の小窓、ヘッダーの音色とメトロノーム。
