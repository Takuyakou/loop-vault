# P8.9-09 — 微修正・整理・フェーズの締め

Phase 8.9 の最後の段階。作り直さなかった画面の微修正、使われなくなったコードの整理、全画面の最終確認、フェーズの最終報告を行う。

- ブランチ：`feat/p8.9-09-finish`（段階8を取り込んだ local `master` から）
- 報告：`docs/phase8.9/reports/P8.9-09-finish.md` と最終報告 `docs/phase8.9/reports/P8.9-FINAL.md`（どちらも日本語）
- モックは使わない。
- 最後は merge 候補で止める。EXE を作る。

## この段階の決まり

- **履歴は書き換えない。** `--amend`・rebase は使わず、直しは新しい commit で行う。
- **報告の判断ポイントは短く書く。** 1項目ごとに「選んだこと／理由／別案」を1〜2行ずつ。途中の考えは書かない。`reports/README.md` の7番をこの書き方に直す。
- 保存データの形・core・transport・AI 展開案の裏側のコードは変えない（人間の判断で残す）。

## 手順

### 0. 始める前

1. zip の `START-HERE.md` の手順で段階8の候補を取り込み、Git の実態を報告に書く。
2. `feat/p8.9-09-finish` を作り、このファイルを置き、README の Status と `execution-state.json` を段階9に進める。報告の冒頭に計画を書く。
3. `reports/README.md` の7番を上の書き方に直す。

### 1. 微修正（作り直さなかった画面）

1. **進行ページと Idea 詳細の日本語化**：英語だけの表示の文言を日本語にする（段階3の決まりどおり、固有名・コード名・度数・内部の値はそのまま）。解析の警告の内部の名前（例：`ambiguous-bass`）がそのまま画面に出ている所は、日本語の短い説明に置き換える（対応表を1か所に作る。内部の値は変えない）。
2. **トーストの種類**：まだ `setToast(文字列)` のまま「お知らせ」で出ている呼び出しのうち、**失敗を伝えるものは「エラー」、保存や書き出しの成功を伝えるものは「成功」**にする（`useNotify()` に置き換える）。対象は取り込む・Voicing Loop・Chord Dojo・Bass Practice・進行ページ・Idea 詳細・App。どれにも当たらないものは「お知らせ」のまま。置き換えた数を画面ごとに報告に書く。エラーは自動で消えなくなるので、同じエラーが続けて何件も重ならないことを確かめる。
3. **練習画面からの設定**：Chord Dojo・Voicing Loop の MIDI の横の「設定」は、画面を移らずに、Live MIDI の設定（`LiveMidiSettingsSection`）だけを確認のダイアログと同じ部品（`Modal`）で開く。練習の途中の状態が消えないことをテストで確かめる。設定の画面の Live MIDI の欄はそのまま残す。
4. **Voicing Loop の下のバー**：段階3で約 30px 右にずれた件を、4つの大きさで確かめる。はみ出し・重なり・折り返しがあれば直す。無ければそのままにして、確かめた結果を報告に書く。

### 2. 使われなくなったコードの整理

段階3・4・8の報告の「削除候補」を、どこからも使われていないことを確かめてから消す。1まとまりごとに commit を分ける。

- 消すもの（例）：ストアの使われない操作（`transitionIdea`・`setMonthlyGoal`・`updateNextAction`・`createIdea`・`removeReference`・`unlinkAsset`・`setLanguage`）、`src/domain/transition.ts`・`monthlyStats.ts`、`focus.ts` の使われない関数（`pickFocus`・`needsNextAction`・`stale`）、`undoDeletion.ts` の参考曲・関連ファイルの種類、`displayLabels.statusLabel`、`BassPracticeHomeCard`・`derivePracticeHomeSummary`・`derivePracticeHistory`、`ProgressionLibraryRail`・`progressionFilters.ts`、`RecordingDiagnosticsPanel`、`styles.css` の古いメトロノームの class、`i18n.ts` の使われない文言。
- **消さないもの**：保存の型と検証（`types.ts`・`schema.ts` の `AppLanguage`・`appLanguageSchema` など）、読み込みと保存の処理、`assetSecurity.ts`（安全の決まり）、`Modal`、自作アイコンの集まり（`HistoryIcon` を含む）、AI 展開案の裏側（`src/llm/`・`src/domain/progressionAdvisor/`・`src-tauri/src/llm/`・評価のスクリプト）。
- 消したテストは「使われなくなったコードの削除」として1件ずつ報告に書く。
- 消したあとで、データ保持の往復テストが通ることを確かめる。

### 3. 全画面の最終確認

`npm run p89:screens -- P8.9-09` で全画面を4つの大きさで撮り、次を確かめて報告に表で書く（画面 × 項目、問題があれば直すか、後日のフェーズへの申し送りにする）。

- 主役の青緑の塗りのボタンが1画面に1つ以下
- 赤と黄が操作ボタンに使われていない（確認ダイアログの「削除する」を除く）
- 英語だけの表示の文言が残っていない（固有名・コード名などを除く）
- キーボードで選んだ時だけ青緑の枠が出る
- 768×640 で横にはみ出さない、二重のスクロールが無い
- トーストが下の帯やダイアログのボタンに重ならない

`e2e/accessibility.spec.ts`・`reduced-motion.spec.ts` を明示して回し、結果を書く。

### 4. フェーズの締め

1. 最終報告 `reports/P8.9-FINAL.md`：
   - 8.9 でやったこと（段階ごとに1〜3行）と、欠番にした段階（05・06・07）
   - 画面から外した機能の一覧と、保存データを守った根拠（往復テスト、保存の型・検証・読み込みと保存に差が無いこと）
   - 後日のフェーズに回したもの：Chord Dojo の作り直し（ミックス練習の削除を含む）、Bass Practice の作り直し、進行ページの作り直し（Idea 詳細の吸収、タグ・メモの編集の往復テストを含む）、練習の記録の保存先（Voicing Loop・Chord Dojo の日付）
   - 残したコード（AI 展開案の裏側）と、その理由
   - テストの数と FULL の時間の推移（段階0と最後）
2. `docs/ai-handoff/` の決まりに従って、8.9 の結果を引き継ぎの文書に反映し、`validate:ai-handoff` を通す。
3. README の Status と `execution-state.json`：P8.9-09 までの完了した段階とゲートを記録する。フェーズの `status` は、人間の確認のあとで取り込む時に `completed` にするので、この段階では `in-progress` のまま、`nextAction` を「人間の確認のあと、段階9の候補を取り込んでフェーズを completed にする」にする。

### 5. 仕上げ

1. `npm run test:full` を fresh に1回。→ `p89-09-full-fresh`
2. `p89:screens` の結果。→ `p89-09-screens`
3. EXE を作る（`npm run tauri build -- --no-bundle`）。→ `p89-09-exe`
4. 報告2つを書き、README の Status と `execution-state.json` を揃える。→ `p89-09-report`
5. パスを明示して commit し、merge 候補で止める。

**EXE で人間が確かめる項目**を報告の最後に並べる：進行ページと Idea 詳細が日本語で、警告の名前が説明になっていること、失敗がエラーのトーストで出て閉じるまで残ること、Chord Dojo・Voicing Loop の「設定」で練習が途切れないこと、Voicing Loop の下のバー、全体をひととおり触って気になる所。
