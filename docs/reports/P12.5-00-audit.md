## 2. Original Practice の前提（Stage 02 の前提）

### 2.1 データ

1. **カードごとの実際の音**：`BuiltinDef`（`builtins.ts`）に**無い**（`roots` / `qualities` / `beats` / `degrees` / `tensions` / `basses` のみ）。音は実行時に `buildBuiltin` が、型の表（`recipeData.json`）または `voiceChordForPreview` から選びます。
   - **提案：** `BuiltinDef` に、省略可能な `pitches?: number[][]`（参照キー E♭ での MIDI ノート番号。カードごと）と `referenceKey` を足し、`buildBuiltin(id,key)` は、あれば `pitches` を `key − referenceKey` 半音ずらして使う。既存の定義は変えない。
2. **「登録した音を覚える」**：登録した音は `file.voicings[key].occurrences`（和音・音の高さ）に持ち、練習時は `today.lesson.targets[].chord.notes`（実音）と `judge:'exact'`。判定は `judgeChord` の `exact`（**音の集合が完全に一致。余分な音は間違い。オクターブも含む**）。この判定は Original Practice では**そのままでは使えません**（余分な音を無視し、押さえたままの音を数える必要があるため）。
3. **`ChordSymbol` で表せるか**：すべて可。`Fm11` = `min11`、`B♭7sus4` = `dom7sus4`、`B♭9` = `dom9`、`E♭maj9` = `maj9`、`Edim7` = `dim7`、`Cadd9/E` = `add9` + bass E。`Cadd2` を表す品質は無いので `Cadd9/E`（同じ音）。
4. **同じコード名が続く 2 枚（`E♭maj9` → `E♭maj9`）**：`BuiltinDef.roots` の配列は 1 要素が 1 枚で、定義・表示（`.dojo-chord-cards` は 1 コード = 1 ボタン）・`targetFor` のいずれも、同じコードを**まとめません**（P12.4 のジャズブルースで `I7`・`I7` が別カードになっているのを確認）。
   - ただし、**判定の側**（2.2）が、前のカードで合格した鍵盤を全部離すまで次を判定しないため、「弾き直し」の挙動は今の判定で再現できる一方、「押さえたままで進む」はできません。

### 2.2 判定

1. **押さえている鍵盤か、新しく押された鍵盤か**：Dojo の練習（`ChordEntry`）は、**note-on のたびに、その時点で押さえている鍵盤全部**（`held` マップ）を候補にします。つまり「押さえている鍵盤」基準です。Master（`HeldChordSettler`）も、押さえている鍵盤全体（前のコードから押さえたままの音を含む）で判定します。どちらにも「新しく押された鍵盤を別に持つ」仕組みは無い。
2. **前のカードから押さえたままの音**：Dojo の練習では**数えない**（`releaseGate`: 判定後、`soundingNotes` が空になるまで次の入力を受けない）。Master は数える。
3. **サステインペダル（CC64）**：`soundingNotes` は押さえている鍵盤 + ペダルで伸びている音（`sustained`）を返し、`releaseGate` の判断に使われるため、**ペダルを踏んでいる間は次のカードの入力が始まりません**（`P12 automatic failure retry, repeated notes and pedal release prevent double judgment` がこの挙動を確かめている）。`ChordEntry` 自体は note-on / note-off しか受けない。Master は `heldNotes`（物理的に押さえている鍵盤のみ）を使う。
4. **猶予時間**：Dojo は `file.settings.settleMs`（既定 **60ms**、0〜1000）で `new ChordEntry(requiredCount(target), settleMs)`。必要な数の音が揃った後、その時間が経つと確定する。Master は `policy.settleMs` と `partialTimeoutMs`（1200ms）。

### 2.3 その他

1. **カードを押したときに鳴らす処理**：`playCard` が `playbackController.play({type:'chord', chord, sound, explicitMidiNotes: c.notes})` を呼びます。**実際の音を渡せます**（カードの `notes` が使われる）。
2. **進行全体を元のリズムで再生する機能**：Dojo の練習画面には無い（`進行を聞く` は 2-5-1 Master にある）。「テンポで弾く」は `tempoPlan(chords, bpm)` + `ProgressionVoicingTransport` で、**拍の位置はコードの `beats` から作る**（`referenceSoundEnabled:false` ＝ 基準の音は鳴らさない）。`struck[].offsetBeats` を使う再生は無い。
3. **ランダムキーから外す条件**：`longProgression.ts` の `isLong` ＝ 拍の合計 ÷ 4 が **8 以上**。P12.4 で入れたのはこれだけです。「コード数 9 以上」への変更は反映されていません（0 章 6）。
4. **今日の練習の候補から外す仕組み**：`BuiltinDef.todayPool?:boolean`（`false` で外す。`planner.ts` が `BUILTINS.filter(b=>b.todayPool)`）。P12.4 の進行 18 件が使用中。**Original Practice は `todayPool:false` にすれば足りる**。

### 2.4 記録の集計（指示書 §2.2.1）

- 「完奏」を既存の `ItemRecord` に入れると、`applyAttempt` が `provisional` / `passed` に進める。今日の結果・「覚えた」判定・`progressions[key]` の状態表示（`LABEL`）と**同じ表示に混ざる**。
- **今日の練習の候補には入らない**ので、「今日の結果」の集計（`today.taskResults` ほか）には混ざらない。ただし**一覧のバッジ**（`stateLabel`）と**キーの記録表**（`DojoKeyGrid`）は `itemFor(file, task)` を読むため、同じ項目に入れると「クリア済みのキー」と区別できない。
- **提案：** 完奏は `ItemRecord` に省略可能なフィールド（例 `completed?: {[key]: {lastAt,laps}}`）を足して持つ（`keys` / `state` / `recent` は触らない）か、`progressions` と別の置き場にする。Stage 02 の前に決める。

1. **目的の確認**：「長い進行で、間違えたとき最初に戻される」と感じる原因は、実際には**ヒントが出ること**（5 秒考えると名前が出て、1 周の終わりに最初から覚え直し）だと考えています。どれを直したいですか。
