## 3. 前回と同じ設定

- **保存するもの**: パートの数、各パートの MIDI チャンネル・音色番号・ドラムか、各パートの役割と使う／使わない、「アプリに任せる」の選択、各パートに線を使ったか（有無のみ）。
- **保存しないもの**: ファイル名、トラック名、音符、線の高さ。
- 保存先は `localStorage` の `loopvault.preAnalysisMemory`（バージョン 1、最大 20 件）。「解析する」を押して解析が成功したときに書く。
- 出すのは、パートの並び（シグネチャ）が一致したときだけ。押すまで何も変えない。
- 適用すると帯に「前回の役割を使いました。今回の曲にも合っているか、色で確かめてください」と「元に戻す」が出る。適用されたパートには今までの「変更」の印が付く。
- 線があったパートには、**この曲に対して**提案される線を入れる（提案が無ければ線なし）。
- 「詳しい設定」にも「前回の設定を使う」を置いた（一致が無いときは押せない）。
- ドラムと重複パートは、前回の設定でも変えない。

## 4. 単純な MIDI のたたみ表示

- 条件は、以前のコンパクト表示の条件（`needsPreAnalysisReview` が偽）に、「使うパートが1つで、コードとして使っている」「線を使っていない」を加えたもの。**条件は変えていない**。
- 表示: 「{パート名} 1パートをコードとして解析します　[パートを確認する ▾]」。ロールと「解析する」はそのまま。「パートを確認する」で一覧が開く。
- **注意（報告事項）**: 以前の条件では、音色番号 0〜23（ピアノ・オルガンなど鍵盤系）のパートは確認が必要とされる。そのため**単独のピアノはたたまれない**（コードとメロディが混ざっている可能性があるため）。「Piano 1パートをコードとして…」の例のとおりにしたい場合は、この条件を緩める判断が要る。判断をお願いしたい。
