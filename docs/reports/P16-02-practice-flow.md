## 2. 決定の反映

| 決定 | 反映 |
|---|---|
| §3 答えの決め方 | 押している**鍵**だけを見る(ペダルは見ない)。**音名**で数える(別オクターブの同じ音名は1つ)。**途中**(押している音名が全部答えの中にあり、まだそろっていない)は何も判定せず、時間がたっても間違いにしない。**答え**は、音名がそろった、または答えに無い音名が入ったときに、**最後に押してから 300ms(設定で 150〜600ms)押す音が変わらなかったら**。**全部の鍵を離したとき**、2音名以上押していたら、そのときの音が答え(足りなければ間違い1回)。1音名だけは答えにしない。次に進むのは**鍵を全部離してから**。秒数は「答えがそろった最後に押した時刻」まで(待ち時間は含めない) |

## 3.1 承認後の3点の直し

1. **狭い窓の楽譜が小さすぎた** → 音部記号・調号・和音の部分だけを切り出し(`cropX` を x 58・幅 366 に)、枠の幅いっぱいに描くようにした。1023px 以下では五線の下の音名の行を省き(見出しと、「鳴った音」などの1行の説明は残す)、枠の高さは変えずに五線を大きくした。**五線の線の間隔: 768px で 6.4px、1440px で 11.7px**(目標は 6px 以上・8px 以上)。音が無いときも、調号つきの空の五線を出す(`GrandStaff` の `alwaysStaff`。何も渡さない今の Dojo の表示は同じ)。
2. **鍵盤の下端** → 鳴らす音のベースは C2 以上なので、**C2(MIDI 36)から始める**。1オクターブ分の無駄な幅が無くなり、白鍵が広がった。`earRange.test` で、364個×12キーすべてが C2 始まりで、全部の音が範囲に入ることを確かめている。
3. **楽譜の見出し** → 1023px 以下では「楽譜」だけにし、「拡大」ボタンは折れずに1行に収まる(e2e で高さを確認)。

## 5. 実機で確かめてほしいこと(受け入れ基準の手動の項目)

- **MIDI 鍵盤をつないで、1問通して弾けるか**。ここまでの確認は、テスト用の偽の MIDI 鍵盤だけ。
- **時計**: 「詳しい設定」の「時計のずれを表示する(機器の確認用)」をオンにすると、練習中の左の列に「音の時計とページの時計の読みのばらつき ○ ms ・ 出力の遅れ ○ ms」が出る(コードを1つ鳴らしたあと)。**ばらつきが 100ms を超えると、橙色で警告が出る**。決定書 §8 のとおり、**実機でこの値(ばらつきと出力の遅れ)を見て、教えてください**。100ms を超える機器では、方法を見直すために止まる。
- 重い曲(16小節のレベル5)で、カードや楽譜の動きが重くないか。

## 6. 気づいたこと

- **鍵盤の幅**: 今の Dojo の鍵盤は最小の幅(760px)が決まっていて、狭い窓では横にはみ出す。この練習では、その最小の幅を 0 にして(`--target-keyboard-width`)、窓の幅に収めた。5オクターブで白鍵 18px 以上。
- **範囲**: 鍵盤は、鳴らす全部の音が入る C から C まで(3〜5オクターブ)。6オクターブになることは無い(ベースは C2 より下、上の音は E6 まで)。
- **印の置き場所**: 見本どおり、カードの右上。印が3つ付いてもコード名に重ならないよう、番号と同じ行に並べた。
- **一発の意味**は画面に書いてある(結果の画面の下)。
- 答えを確定するまで 300ms 待つので、**合ったことが画面に出るのは、最後の鍵を押してから約 0.3 秒後**。秒数には含めない。
- **聴き直しのあと**に弾くと、秒数は聴き直した時間も含む(止めない)。
- テスト用の偽の MIDI 鍵盤(アドレスに `?p12=` を付けたときだけ有効)があるときだけ、テストが「今の問題の答え」を読める入口(`window.__earAnswer`)ができる。ふだんの画面には無い。
