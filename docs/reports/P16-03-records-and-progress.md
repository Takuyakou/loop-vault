## 2. 記録(§1)と保存

- 保存先は **Dojo の記録とも Bass の記録とも別**。Tauri では `AppData/loopvault/ear-practice-v1.json`(封筒 `app: "loopvault-ear-practice"`、`version` 1、`fileVersion` 1)。ブラウザでは `loop-vault:ear-practice-v1:*`。Rust 側は封筒の `version`・`fileVersion` が 1 以外だと保存を断り、バックアップから戻すときも `fileVersion` を上げない(Bass のライブラリと同じ扱い)。
- 記録されるのは**最後まで弾いた問題だけ**(全カードが「合った」になったとき)。途中で戻った問題は何も残らない。曲名・ファイル名・進行の名前は入れない(`questionId` だけ)。
- `judge` は決定どおり `core` / `pitchset` / `sounded`。**主な成績は `core` と `pitchset`**、`sounded` は別の小さな欄(「鳴った音で判定したコード n ・ 一発 x%」)。
- **仕様書に足した項目(3つ)**: `play`(1回の通しを表す id。1問の全コードが同じ値)、`run`(腕試し1回の id。腕試しのときだけ)、`length`(小節数)。結果画面の「同じレベル・同じ長さの直近10問」と、腕試しの「前回」を数えるのに要るため。曲名などは入らない。
- 古い記録は消さない。1年より前を週ごとのまとめに縮める処理は**作っていない**(1コード約250バイトで 16MB まで約6万コード。足りなくなったら別に相談したい)。

## 3. 成績の数え方(§2)

仕様どおり。測るコード = `given` でも `manual` でも `sounded` でもないもの。一発 = 間違い0・ヒント0。秒数は測るコードのうちヒント0のものの中央値。聴き直しなしで一発は、一発のうち `replays` が 0 のもの。週は月曜はじまり(日本時間、端末の時間帯に左右されない計算)。10コード未満は薄く「まだ少ない」(折れ線では白抜きの点)。

## 5. 腕試し(§5)

- 各レベルの固定の4問を、**`benchmark` に書いた固定のキー**で、テンポ90・1つ目のコード名あり・自動で鳴らす・答えの確定 300ms に固定して続けて出す。設定画面の値は使わない。聴き直し・ヒントは使える(数が結果に並ぶ)。
- 4問それぞれの結果画面は出さず、4問目のあとで結果を出す。前回の腕試し(同じレベル)と「今回 / 前回 / 差」で並べる。一発・聴き直しなしで一発・秒数の中央値・ヒントの数・聴き直しの合計・測ったコード。
- 前回から7日たっていないと、選ぶ画面に「7日以上空けると比べやすくなります」(止めない)。
- 途中でやめた腕試しは、結果にも折れ線にも出さない(4問そろったものだけ)。記録そのものは、ふだんの記録として残る。
- ふだんの練習では、腕試しの問題を腕試しのキーで出さない(Stage 01 の仕組みのまま)。

## 6. 私が決めたこと(基準が書かれていなかった点)

| 点 | 決めたこと |
|---|---|
| 「順調です」を出す条件 | 基準(直近40コードで一発80%以上・秒数4秒以下)を満たし、測ったコードが10以上のとき。1コードだけで言わないため |
| 数が足りて基準に届かないとき | 何も言わず、数字だけ出す |
| コードの動きの最小数 | 苦手と同じ 8 コード以上 |
| コードの動きの対象 | 出題用の進行だけ。名前は「同じルート・半音上・全音上・短3度上・長3度上・4度上・トライトーン・5度上・長3度下・短3度下・全音下・半音下」 |
| 苦手の練習 | そのまとまりのコードが最も多い進行の半分以上を持つ進行から出す。レベルは、そのまとまりを最も多く測ったレベル |
| コードの種類 | 記号から決める。テンション付きの三和音・maj7 などは「テンション」。7(#5) は「7」。転回形は、ベースがコードの音のとき |

目安の数字(40・5・80%・4秒)はそのまま使った。調整の提案は、実機で弾いてから出したい。

## 11. 確認項目への答え

1. **judge は3つ**(`core`・`pitchset`・`sounded`)。決定書 §1 を優先した。主な成績(一発・聴き直しなしで一発・ヒントなし・秒数・聴き直し・レベルの目安・苦手・コードの動き)は `core` と `pitchset` で数え、`sounded` だけ別の欄。テスト: 7alt を含む出題用の進行を最後まで弾くと、記録に `pitchset` で残り、測ったコードに入ること / `sounded` を足しても主な成績が変わらないこと(`earRecords.test.ts` の「7alt(pitchset)は…」)。
2. **kind**: 7alt・mMaj7・括弧のテンション(♭9・♯9・♯11・♭13、2つ重ねたもの)は「オルタード」。**6/9 は「maj7・6」**(テンションではない)。add9 は「テンション」。同じテスト群。
3. **週の区切り**: 日曜 23:59:59(日本時間)は前の週、月曜 0:00:00 は新しい週。計算は UTC の数値だけで行い、端末の時間帯を使わない。テストで `TZ` を UTC・東京・ロサンゼルス・オークランドに変えても同じ結果になることを確認。
4. **レベルの目安**: 40コード・5進行・80%・4秒ちょうどで出る。コードが39・進行が4・75%・4.1秒のどれか1つ足りないと出ない。「順調です(あと n コード・進行 m つ…)」は、数が足りず基準は満たしているときだけ(測ったコード10以上)。
5. **腕試し**: 4問が `benchmark` の `tonic` で出る(各レベルで確認。同じ問題は何度作っても同じコード・同じ音)。ふだんの練習では、キーを腕試しのキーに固定しても、レベル・長さ・乱数の値を200通り変えても、その問題は出ない。キーを乱数にしたときも腕試しのキーは避ける(Stage 01 の `pickBankQuestion` の仕組みをそのまま使っている)。e2e では、2回続けて測って、問題とキーが同じ順で出ることを確認。
6. **曲名・ファイル名**: 記録の項目に名前は無い。`collection` は内部の id(`collection:<ブロックの id>:<小節>`)だけ。名前を持った問題で記録を作り、記録の JSON にその名前も `.mid` も入らないことをテスト。**データに無い id**(後で消した進行)の記録は、成績にも目安にも普通に数えられ、画面は落ちない(e2e でそういう記録を入れて開いている)。なお、記録の画面は進行の名前を一切出さない(答えが分かるため)ので、「追加の進行」と出す場面は今は無い。
7. **Rust**: 許可リストに足しただけ**ではない**。変更は3か所(`git diff` で47行): ① 名前空間 `ear-practice` の保存先(データ `ear-practice-v1.json`・置き場 `ear-practice-storage`)、② `validate_document` の「バージョンが 1 であること」を、封筒 `loopvault-ear-practice` にも適用、③ バックアップを戻すときに `fileVersion` を 2 に上げない対象に `loopvault-ear-practice` を追加(②③が無いと、耳の記録の封筒が「app が違う」と断られる)。ほかの既存の処理は変えていない。Dojo の記録は別のファイル `chord_dojo_storage.rs` で、**変更なし**。確認: Rust のテスト(Bass と耳の記録は別のファイルで、元の記録ファイルは変わらない)/ Vitest(ブラウザの保存先で、Dojo・Bass・Vault のキーが変わらない)/ e2e(耳を1問弾いたあと、耳の記録以外の localStorage が1文字も変わらない)。
8. **画面写真**: §4 のとおり。記録が無いとき・数週間ぶんの、1440×900 と 768×640。
