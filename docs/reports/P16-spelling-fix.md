# P16 コード名の綴りの直し(報告)

`P16-spelling-fix.md`(決定書 §7 の「綴り」を置き換える)を実装した。ブランチ `feat/p16-ear-practice`。**`master` には、この直しが入る前の P16 が、すでにローカルでマージ済み**(`533618eb`。そのとき作った exe にも入っていない)。この直しはブランチだけにあり、master への反映・exe の作り直しは、まだしていない。push はしていない。

## 1. 直したところ

`src/domain/earPractice/spelling.ts` だけ。`chordFromDegreeToken` のコード名の根音とベースの綴りを、新しい決まりにした。

1. キーの主音の文字は、キー名のとおり(`earKeyName`)。
2. 度数の数字の分だけ文字を進める(I は同じ文字、II は次 … VII は6つ先)。`b`・`#` は文字を変えない。
3. 実際の高さとの差から ♯/♭ を付ける。
4. **E♯・B♯・C♭・F♭、または ♯♯・♭♭ になるときだけ**、普通の名前に置き換える(E♯→F・B♯→C・C♭→B・F♭→E・F𝄪→G)。二重の記号の結果が黒鍵になるときは、元の向きに合わせた名前(♯♯ なら ♯、♭♭ なら ♭)にする。

新しい関数 `degreeName(tonic, mode, degreeRef)` に決まりを置いた。コード名のうち、種類やテンションの書き方は、今までどおり `formatChordSymbol` に任せ、根音とベースの文字だけを差し替えている。今の Dojo の `accidentalPreferenceForKey`・`formatChordSymbol`・`spellMidi` は変えていない。根音の高さ・コードの種類・判定・鳴らす音は変わらない。

楽譜の綴り(`spellMidi`・`degreeSpelledPitch`)は、コード名の根音の文字から決まるので、コード名が直れば一緒に直る(練習中の楽譜・結果の譜面とも)。
