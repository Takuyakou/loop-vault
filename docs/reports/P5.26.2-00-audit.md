## 2. 提案（推測を含む。Stage 01 の設計に関わる所）

- **A. 「曲の編集画面で帯が機能していない」の直し方は小さい**：進行モードで帯を差し替えず、取り込み側と同じ帯を出す。進行の版の切り替えは、すでにヘッダーの `この曲の進行（n）` セレクト（`ProgressionWorkspacePage.tsx:77`）にあるので、帯のボタン列は**重複**です。
- **B. 共有部品の切り出し**：帯（961–986）と `scrollToBeat`・追従・`scrollLeft` の state を、`CorrectionWorkspace` の中から「帯のコンポーネント + フック」へ出す、が妥当だと考えます。パッケージの `TimelineOverview` / `useTimelineScrollSync` の形です。**今の実装でも再描画なしのヘッド移動（rAF + transform）は守られている**ので、その性質は保つ必要があります。
- **C. Canvas について**：今の帯は DOM で、要素数は「カード数 + 区切り数 + 要確認数」です。128 小節・数百枚でも DOM の `span` で足りるかもしれません。**Canvas にすると既存の E2E（`correction-overview*`）と、アクセシビリティ（カードの tooltip など）の置き換えが要る**ので、ここは判断が要ります。
- **D. Voicing Loop は別系統**：スクロール・追従・ページめくりが別実装（`timelineFollow.ts`）で、2 つを 1 つにするのは大きな作業になります。パッケージの Stage 01 は「Voicing Loop は後続」としているので、Stage 01 では**触らない**のが安全です。
- **E. 「取り込み画面を共有部品に移行（挙動を変えない）」** は、同じ部品なので、実質は「進行モードの差し替えをやめる」ことと「帯の切り出し」の 2 点です。

## 3. 症状との対応（事実と推測）

- **事実**：保存済み進行の編集画面（Vault → 進行を開く）の「曲全体」は、`ProgressionWorkspacePage.tsx:97` の版ボタンの列で、表示範囲の枠も、再生ヘッドも、要確認の位置も、移動の操作もありません。
- **事実**：取り込み後の画面（CaptureView）の「曲全体」には、それらがあります（961–986）。
- **推測**：「ただ全体を出しているだけ」という報告は、この差し替えの見た目（名前のボタンがずらっと並ぶだけ）を指していると考えられます。
