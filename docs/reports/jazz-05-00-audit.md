### 1.1 見当の確認(コードと測定)

### 1.2 直し方の案
- **案C(おすすめ)**:各カードの**全部の音**(`expected`)を、カードの開始拍に、長さ = カードの拍数 × 0.9(=3.6拍。次のカードまで約 0.33 秒の余韻)、強さ 0.72 で鳴らす。経路は今と同じ `{type:'notes'}`。**カード1枚と同じ音量**になり(上の表)、音の時計で予約されるので、シークバー(§2)と合わせられる。停止の時の急な切れ目の対策(Stage 01 で入れたフェード)も効く
- 案D:`previewChordTimeline`(`{type:'timeline'}`):使える(Master 2-5-1 の「通して聴く」が同じ経路)。ただし強さが **0.7 固定**(カード1枚の 0.72 より 3〜5% 小さい)で、カードの時刻は**画面の JavaScript の時計(`setTimeout`)**で鳴らすので、音の時計とそろえるシークバーに向かない
- ほかの定番の進行の「通して鳴らす」:定番の進行(見て弾く・ランダムキー)には**進行を通して鳴らす機能はなく**、カード1枚ずつ(`{type:'chord'}`)。通しの再生を持つのは Master 2-5-1(`timeline`)・保存した進行(`timeline`)・耳で弾く(`notes`)
- 整理:案Cなら `jazzPlaybackNotes`(`struck` から作る)は使い道がなくなる。`{pitch, startBeat, durationBeats, velocity}` を `expected` から作る関数に置き換え、テスト(全カードで「鳴らす音 = カードの音」・間に拍の 1/2 を超える無音が無い)に差し替える

### 1.3 楽器

## 2. シークバー(位置が見えるだけ)

1. **音の時計から取れる。**
   - 耳で弾くの `createEarPlayback` は、`playbackController.play(..., {onStarted})` の `onStarted` の中で `Tone.now()`(= **拍 0 の音の時間**。`previewMidiNotes` が予約に使う `startedAt` と同じ瞬間)を取り、`getOutputTimestamp()` で画面の時計に直している。**画面の側で時間を数えない**方法
   - シークバーは、これを使って `位置(拍)= (今スピーカーから出ている音の時間 − 拍 0 の時間) × テンポ / 60` を、描画のたびに(`requestAnimationFrame`)読む。`rawContext.getOutputTimestamp().contextTime` が使える(使えないときは `currentTime − outputLatency`)。再生・プレビューのコード(`playbackController.ts`・`chordPreview.ts`)は**変えずに**作れる
   - 案C(`notes` 経路)であることが前提。`timeline` 経路(案D)は音の予約が JavaScript の時計なので、音の時計と位置が結べない
2. **使える部品**:`ProgressBar`(`components/ui/controls.tsx`。`role="progressbar"`・`aria-valuenow`)がある。保存した進行の位置の線(`useTextScorePlayhead`)は、フレームごとに React を再描画せず DOM を直接書く作り方で、これに合わせる。Voicing Loop・耳で弾く・定番の進行に、同じ種類の進み具合の表示は無い
3. **`playingIndex`**:今は `jazz:card:` で始まる再生の id だけを見ているので、通して聴く(`jazz:all:…`)では**動かない**(コードで確認)。位置から「今のカード」を出し、鳴っているカードの枠・譜面・鍵盤に使う(カードが変わったときだけ状態を更新する)。今の「練習中のカード」の印(緑の枠)と見分けがつくよう、鳴っているカードは別の色の輪(見本の写真は金色)にする

## 3. 鍵盤の○の色

1. **同じ色になっている理由**:`PianoKey.tsx` の Dojo 表示は `answerColor = colorGuideHands ? 手の色 : "#42d8c6"`(1色)。`colorGuideHands` は既定で偽で、**Master 2-5-1 だけが渡している**(その e2e が左=橙・右=水色を確かめている)。Original / Jazz / 見て弾く・ランダムキーは渡しておらず、`leftHandGuideNotes`・`rightHandGuideNotes` は渡しているのに色が1色になる
2. **道筋**:`HeldCardParts.tsx` の `PracticeKeyboard` に `colorGuideHands` を渡す。**変わるのは `HeldCardParts` を使う Original と Jazz だけ**。見て弾く(`ChordDojoView`)・ランダムキー(`ChordDojoEndlessView`)・Master 2-5-1 は変わらない。見本では橙・水色になり、指の印の色も手に合う(今も手で色分け済み)
   - **色だけに頼らない**:Jazz は鍵盤の印に「左5」「右1」の字がある。Original は指が無いので、印に「左」「右」の字だけを出す(指の印と同じ仕組み `fingerLabels` に手の字を渡す。`PianoKey` は変えない)。Original の e2e に「指の印が無い」確かめがあれば直す(Stage 01 で確認)
   - 凡例(「押している音」「このカードの音」)に、橙=左手・水色=右手を足す

## 4. ランダムキー

### 4.1 ほかの定番の進行の「ランダムキーで練習」
- **入口**:一覧の各カードの「ランダムキーで練習」→ `ChordDojoEndlessView`(`endless.ts`)
- **キーの順**:**12キーをシャッフルした袋**(`createKeyBag(seed, previous)`、Fisher–Yates)を1巡(12キー)ずつ使う。巡の最初のキーは前のキーと同じにならない。巡ごとに新しい袋
- **進み方**:1キーを弾き終える(クリア)と、**鍵盤を離すと自動で次のキー**(「鍵盤を離すと、次のキーが出ます」)。途中で「飛ばす」もできる
- **表示**:「n巡目 k/12」・クリアの数・ヒントなしの数・弾いたキーの印(chip)。終えると今回のまとめ
- **記録**:**何も保存しない**(「画面の状態だけ」)。Jazz の完奏は、今までどおり専用の記録に数える

### 4.2 Original の部品(Jazz で使えるか)
Original の「ランダムキー」は**ボタンを押したときに1回だけ別のキーに変える**(`pickOriginalShift`:この画面で弾いた回数が少ないキーから・同じキーを続けない)。**1周ごとの自動切り替えはありません。**
- 使えるもの:キーの選択・12キーの完奏の欄(`ORIGINAL_KEYS` と同じ形)・「最初から」。ただし `ORIGINAL_TONIC`(E♭)・`shift`(−6〜+5)に結びついているので、Jazz では**項目の主音(0〜11)**で持つ形に作り直す
- 順の決め方:標準と「同じ動き」にするなら、**`createKeyBag` をそのまま使う**のをすすめる(純粋な関数で、標準の「ランダムキー」と同じ順・同じ巡の考え方になる)。`pickOriginalShift`(回数の少ないキーから)でも結果はほぼ同じ分布だが、「巡」の表示が作れない
- **自動で次のキーへ**:完奏の知らせに「次は A」を出す。切り替えの時刻は、(a)完奏と同時、(b)標準と同じく鍵盤をすべて離してから、の2案。**(a)をすすめる**:Jazz は次のカードの音を押し直さないと通らない(`HeldCardJudge` の「新しく押した」判定)ので、押さえたまま切り替わっても誤判定にならず、MIDI が外れたときも止まらない

### 4.3 記録
`laps[進行の id][主音]` は **12キーにそのまま伸びる**(主音の鍵が 0〜11、スキーマは変更なし。今の記録も有効なまま)。
- 数え方の案:**版ごとに、その版の主音で数える**(例:009 の後半の版は、主が G♯m のとき Em = 4、Cm のとき G♯m = 8 で数える)。一覧の完奏の数は全キー・全版の合計(今と同じ)
- ランダムキーの「この画面で弾いた回数」(巡の袋)は**項目のキー**(主の進行のキー)で数える。版ごとの主音から項目のキーへは、正解表の `itemTonic` と `tonic` の差で直せる

### 4.4 正解表(`jazz-transpose.expected.json`)で困る所
検査:正解表をアプリの読み取り・判定・綴りの関数にかけた。
- **252(21進行 × 12キー)・672枚**:コード名の読み取り 672/672・`judgeChord` の `core`・`shape` の両方 **不合格 0**・音名と MIDI の高さの食い違い 0・左右の手が重ならない・`HeldCardJudge` での押さえたまま・押し直しの通し **失敗 0**・押さえたままの音を前のカードと同じ指で押さえている(例外 0)
- 音の範囲 **A1〜E♭5(MIDI 33〜75)**。C2(36)より低いカードが 40枚(34の「進行 × キー」)。鍵盤は自動で C1〜C6 に広がる(61鍵)
- 綴り:ダブルシャープ 18音・ダブルフラット 5音(すべて今の表示・譜面で書ける:カードの音名は `♭♭`・`𝄪`、譜面は `GrandStaff` が対応)
- **版を切り替えたときのキーの表示**:項目のキー(画面で選ぶ)は保ち、画面には**今の版のキー**を出す。主の版と同じキーのときは1つ(「キー G♯m」)、違うときは両方(例「キー Em(項目のキー G♯m)」)。009 の後半は、主が G♯m のとき Em、Cm のとき G♯m を確かめた
- 移調は項目ごと:同じ項目の版どうしで同じ和音が同じ音になること(504組で0)は、提供のテストの雛形が確かめる。困る点なし

### 4.5 指(12キー)
正解表の指はデータと同じ。確かめた:
- **窮屈な形**:「右手の親指が黒鍵で、すぐ上(2半音以内)の人差し指が白鍵」は**4枚**(こちらの数えと一致):004 の `B♭sus(11)13`(E♭・R1=E♭4・R2=F4)・`Fsus(11)13`(B♭)、007 の `Gm11`(F)・`Cm11`(B♭)。左手の鏡の形は0枚
- **何を「弾きにくい」とするか**:上の形(親指が黒鍵で人差し指が白鍵のすぐ上)。ただし**親指が黒鍵になること自体は普通**で、今の元のキーでも右手の親指は 56枚中 20枚が黒鍵(全キーで 260/672 = 39%)。小指・左手の親指も同程度。**幅(音程)はキーによらず元と同じ**なので、広すぎる形は増えない
- **今の運指の仕組み**(`dojoFingerings` = `rankPracticeHandFingerings`):**決まった音と手を渡して指を出せる**(使える)。試した結果:全 3384 音のうち **81.2%(2748)がデータと一致**(元のキー 229/282)。窮屈な4枚は、004 の2枚で「R1・R3・R5」(人差し指をとばす)、007 の2枚で「R1・R2・R3・R5」と**別の指**を出すが、**親指が黒鍵であることは変えない**。**ただし「押さえたままは同じ指」を守らない**:押さえたままの 480音のうち 36音(7.5%)が前のカードと違う指になる。変えるなら、その影響で前後のカードの指も直す必要がある
- **おすすめ:データの指のまま**。窮屈な4枚は 672枚の 0.6% で、親指が黒鍵になるのは元のキーにもある普通の形。指を直すと押さえたままの指がそろわなくなる心配があるので、**実機で弾いて引っかかったらその枚だけ直す**(直す形は、その進行の前後のカードの指も一緒に決める)

### 5.2 譜面の重なりの本当の原因と、左右の手で譜表を決める案
- **原因は「手」ではなく「譜表の間隔」**:`GrandStaff` の compact は、高音部の一番下の線と低音部の一番上の線の間を **16px**(本来の五線の間隔は 24px = 線の間 12px × 2)に詰めている。そのため、高音部の加線の C4(下に 12px)と、低音部の一番上の線の A♭3(下に 16px)が **4px まで近づいて重なる**。001 の右手 A♭3 は MIDI 59 以下なので低音部に書かれ(C4 は MIDI 60 で高音部)、**同じ右手の列で重なる**(写真 `now-001@1660x1035`)
- **間隔を 24px にすると**、この2音は **12px 離れて重ならない**(写真 `proto-A/B-001@1660x1035`。`staffGap` は耳で弾くの譜面がすでに使っている引数で、新しい仕組みは要らない)。**ほかの画面の描き方(音の高さで譜表を決める)のまま**でよい
- **左右の手で譜表を決められるか**:できる(`GrandStaff` に任意の指定を足す。ほかの画面は既定のまま)。ただし**本来の間隔(24px)なら、音の位置(y)は計算上、譜表の選び方によらず同じ**(どちらの譜表の式でも同じ高さになる)で、変わるのは加線を描くかどうかだけ。しかも 12キーでは**右手の音が C4 より低い**カードが多く(590音・404枚 = 60%)、右手を高音部に決めると **高音部の下に加線が 4〜5本** 積み上がる(右手の一番低い音は C3 で、加線 4本を超える)。今の描き方(C4 から下は低音部)のほうが読みやすい。**おすすめ:音の高さで決めるまま、間隔だけ 24px(余裕を見て 28px)**。左手の音が C4 以上になるのは 26音だけ
- 指番号の線:右手の指の印を、音符の列から斜めに長く伸ばさず、列の右に縦に並べる(Stage 03 で調整。今は指が重ならないよう間を空けているので、間隔を 24px にしたあとで見直す)
- 鍵盤:高さが**128px固定**(CSS が 128px に抑えている)。耳で弾くの**白鍵の幅 × 4.2** の仕組み(`keyboardKeyHeight` と `dojoHeight`)が使える。1660×1035 の白鍵の幅は 48px → 高さ 202px(見本)。Dojo の CSS の固定を Jazz の画面だけ外す

### 5.3 配置の案(2つ。写真は 1660×1035・1920×1080。1280×720 は今のまま)
どちらも共通:譜表の間隔 24px・鍵盤は手で色分け(§3)・譜面と鍵盤の行を画面に合わせて育てる(見本では譜面 250px・鍵盤 232px)・ランダムキーのキー選択とシークバー(見本では細い進み具合の棒と区切りの目盛り、鳴っているカードの金の輪)を置く・**1280×720 は今の収まり**(縦スクロールなし・カードの2行目まで)を保つ。

- **案A「ひとまとまりを大きく、縦に積む」**(`proto-A-001/002@…`):上から、キー選択・ランダムキー・ボタンの行 → 大きなカード(幅 300px・コード名 22px・音名 15px)→ シークバー → ヒント → 「この進行で学ぶこと」(16px・カードと同じ幅で、長い進行は3行)。全体を中央に置く。
