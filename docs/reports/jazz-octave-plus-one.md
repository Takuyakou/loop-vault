# Jazz Progressions: 1オクターブ上で練習する(+1)

ブランチ `feat/jazz-octave`(master `b39a3892` から)。`playbackController.ts`・`chordPreview.ts`・Rust・記録の形・Original Practice・移調の決まりと正解表は変えていません。

## 1. 動き
- 練習画面の操作の行、BPM の欄の右に「オクターブ 標準 / +1」(`jazz-octave`)
- **+1**:移調の結果(`transposeJazzProgression`)の全カードの音を 12 半音上げる(`raiseJazzProgression`、`jazzProgressions.ts`)。手・指・押さえたまま/押し直す音・時間はそのまま。音名はオクターブの数字だけ +1(綴りはそのまま)、譜面の綴りもオクターブだけ +1
- 判定(`HeldCardJudge`)・カードの音名・譜面・鍵盤の○と指の印・「通して聴く」・カード1枚の再生は、上げた音で動く(同じ `prog` を読むため)。標準の音は +1 では通らない
- ランダムキー・キーの選択・版の切り替えをしても、オクターブは保つ。切り替えたときは1枚目からやり直す(キー・版・ランダムキーはそのまま)
- 値は BPM と同じく、アプリを開いている間は項目を移っても保つ(閉じたら標準に戻る)。完奏の記録はオクターブで分けない(`laps[id][主音]` のまま)
- 譜面の上下の範囲の固定(項目ごと)は、標準と +1 で別々に求める(`staffExtent` が `octave` で変わる。練習中は動かない)
- 鍵盤の範囲は、上げた音が入るように自動で広がる(001 を B で +1 にすると C7 まで)

## 2. 画面の収まり(1280×720 を崩さない)
オクターブ欄を足すと、009 のように行の長い項目で操作の行が2段になり、小さい画面(compact)の中央が 29px はみ出した。次のように収めた(`chord-dojo.css`):
- compact(コンテナ幅 901px 以上のとき):中央の上下の余白・行の間隔・カードの行間と上下の余白・ヒント行の行間・2段目のボタンの高さを少しずつ詰めた(768×640 の縦に積む表示は変えていない)
- wide:左の列の幅を `minmax(340px,32%)` → `minmax(380px,36%)` に広げ、操作の行が4段に増えないようにした
- 小さい画面ではカードの余白が少し詰まった見た目になる(実機で見てほしい)
