## 1. 時間の対応の持ち方(案の比較)

### いまの前提(コードで確認)

- `buildCorrectionModel` は、元の音を**元の拍**で `context.sourceNotes` に入れる(`startTick / ticksPerBeat`、`correctionModel.ts:161-188`)。カードは `fullTimeline` の `bar`/`beat` から画面の拍を作る(`:202-216`)。音符は `cutFragments` で「元の音」と「カードの範囲」を突き合わせて切る(`:218-221`, `:244-264`)。
- つまり **画面の時間 = 元の MIDI の時間** が暗黙の前提。
- `recut` は「分ける」「つなぐ」「境目」「カードを消す」で、`context.sourceNotes`(元の時間)とカードの範囲(画面の時間)で切り直す(`cardEdits.ts:57-102`)。
- `cardTimelineItem` は `timeline[card.timelineIndex]`(元の解析)とカードの `start`/`duration`(画面)を `sameSpan` で比べる(`saveCandidate.ts:83-124`)。詰めた後は `sameSpan` が false になり、保存用の音を作り直す枝に落ちる。
- `workspaceToProgression` は `sourceStartBeat`/`sourceEndBeat` を `base + (cards[0].start - original.cards[0].start)` と `base + totalBeats - original.totalBeats` で作る(`progressionWorkspace.ts:47-73`)。詰めると `totalBeats` が減るので、この式は「元の位置」を表さなくなる。

### 案A: 消した小節の一覧を持ち、元の時間 ⇔ 画面の時間を変換する

モデルに `removedBars`(元の拍の範囲の配列)を持ち、`screenToSource(beat)` / `sourceToScreen(beat)` を通す。`sourceNotes` と解析は**元の時間のまま**。

- 良い点: `sourceData` も解析も触らない。`Ctrl+Z` は前のモデルに戻すだけで完全に戻る。保存時の「元の位置」も `screenToSource` で戻せる。詰め方を増やしても規則が1つ。
- 困る点: `cutFragments`/`recut`/`cardTimelineItem.sameSpan` に変換を渡す必要がある(`context` に写像を持たせる)。写像を忘れた箇所が静かに別の音を拾うので、テストで縛る必要がある。

### 案B: 詰めるときに `sourceNotes`・解析の位置そのものを書き換える

- 良い点: 下流は「画面 = 元」のまま。`cutFragments` を変えなくてよい。
- 困る点: 元の位置が失われる(`Ctrl+Z` 用に前のモデルは持てるが、保存時の「元の位置」は別に残す必要がある)。解析(`fullTimeline`)は `CaptureView` から props で渡っており、モデル内に「詰めた解析」のコピーを持つことになる。区切り・おすすめ・評価の元位置も別管理になる。

### 案C: 案A + 解析だけは「元の timelineIndex のまま、比較のときだけ変換」

- 案A の写像を `cardTimelineItem` の `sameSpan` にだけ使い、`timeline` は元のまま。
- 良い点: 解析のコピーを作らない。保存の「同じ範囲か」判定だけ正しくなる。
- 困る点: `timelineIndex` は元の並びのままなので、詰めた後に「カードの並び」と「解析の並び」がずれる。並び順で何かを引いている箇所は別途確認が要る。

### おすすめ: 案A(案C の比較変換を含む)

理由: 元データと解析を不変に保てる。`Ctrl+Z` が1回で完全に戻る。保存の「元の位置」を写像で戻せる。変更は `cutFragments`/`recut`/`sameSpan` と保存の数か所に集中し、既存の「分ける・つなぐ・境目・カードを消す」の規則を保ったまま拡張できる。

## 3. 元の音(`A`)の再生

- 取り込みの `A` は、**元の MIDI ファイルの音をそのまま鳴らすのではなく**、選んだカードの `SOURCE` の音を高さでまとめて**コードとして鳴らし直す**(`CorrectionWorkspace.tsx:419-429`。`mine.filter(provenance==="SOURCE").map(note.originalPitch ?? note.pitch)` を `controller.play` の `explicitMidiNotes` に渡す)。
- したがって、詰めて消した小節の音は**モデルから消える**ので、`A` でも鳴らない。飛ばして鳴らす特別な処理は不要。
- 曲の再生も、各カードの `cardAuditionNotes`(使用音)を並べるだけ(`songPlayback.ts:17-38`)。消した小節の音は入らない。

## 4. 曲の再生・シークバー・追従・小節の行・「曲全体」の帯

- すべて `present.totalBeats` と `meter` を基準にしている(§2 の追加分)。詰めて `totalBeats` を1小節分減らし、カードを前へ動かせば、再生・シーク・追従・ループ・帯は同じ規則で縮む。
- 注意: `segments` と `saveRange` は**小節番号**で持っているので、詰めた小節より後を -1、含む範囲を縮める、全部消える範囲を外す、の3つが要る。`rangeFrom` はカード id なので、消えたカードなら外す。
- 追従(`follow`)は再生位置とスクロールだけなので、`totalBeats` が縮めば自然に収まる。

## 5. 境目にかかるカード

- 一部だけかかるカード: かかる分だけ `duration` を縮める。
- 全部入っているカード: 無くす。
- 両側にはみ出すカード: 消す小節の分だけ縮める(前後はそのまま)。
- **¼拍より短くなる場合**(`MIN_CARD_BEATS = 0.25`, `cardEdits.ts:23`):
  - 案1(推奨): 消す小節に**完全に入る**カードは無くす。境目に残る**¼拍未満の切れ端**は、隣のカードへ吸収する(前なら前を伸ばす、後ろなら後ろを伸ばす)。
  - 案2: ¼拍未満になるなら、その小節は詰めずに知らせる。
  - 案3: ¼拍に丸める(音と小節線がずれるので非推奨)。
- 連打の数(`attacks`): 残るカードはそのまま。吸収された切れ端の分は足さない(「カードを消す」と同じ)。
- 名前: 変えない(詰めるのは時間だけ)。読みが変わる場合は P5.26.1 と同じく `suggest` で知らせるだけ。
- 要確認: `refreshModel` で出し直す。詰めた後に同じコードが隣り合っても**自動ではつながない**(「同じコードが分かれています」の要確認が出てよい)。

## 6. 消す小節をまたぐ1つの元の音

- 前の小節から伸びて、消す小節を越えて続く音は、**消す小節の分を抜いて2つの断片**にする(前の断片は前のカード、後ろの断片は後ろのカード)。`recut` と同じく、断片は自分の `pitch`・`originalPitch` を持つ。
- 再生は、今の「カードをまたぐ音」と同じく**カードごとに1回ずつ**鳴る(2つの断片 = 2回のアタック)。1つの音に聞かせたい場合は、詰めた後に「つなぐ」でカードを1つにすれば1回になる。Stage 01 では**今の挙動を変えない**(2回でよい)ことを推奨。
- 消す小節の**中だけ**にある音は、モデルから消える(断片も残さない)。

## 7. 区切り・おすすめの範囲・保存する範囲

- 区切り(`segments`): 小節番号で持つ。詰めた小節が区切りの内側 → 終わりを -1。先頭 → 開始を -1(次とつながる)。区切り全体が消える → 区切りを外す。`repeatCount` は作り直す。
- おすすめの範囲: `segments`/解析から作るので、詰めた後に**作り直す**(古い範囲を引きずらない)。
- 保存する範囲(`saveRange`): 後ろ → 両端 -1。含む → 終わりを -1。その小節だけ → 外す。`rangeFrom` はカード id なので、消えたカードなら外す。
- 保存する範囲は**小節単位**のまま(指示どおり)。カードの長さで詰めるのは進行ページの4モードだけ(変えない)。

## 8. 保存

- **詰めた所をまたぐ範囲**: 保存はできるが、元の MIDI では**連続していない**。推奨は指示の案どおり「**元の位置を持たない**(テキストで作った進行と同じ扱い)。保存の欄にその旨を1行出す」。

  - いずれも「フォールバックする」だけで落ちない。ただし、Chord Dojo の表示や評価の元位置は変わるので、保存の欄の1行と報告に明記する。

## 13. 取り込みの保存経路の追加調査(§8 の訂正。コード変更なし)

### 13.0 承認されたこと(この節の前提)

1. 時間の対応は **案A**。ただし、詰めた所の両側にかかるカードは元の時間では2つの範囲になるので、`screenToSource` は**範囲の一覧**を返す。`cutFragments`/`recut` はそれぞれの範囲から切って画面の時間に戻す。**何回詰めても重ねて正しく変換できる**こと。
2. ¼拍未満の切れ端は**隣へ吸収**(案1)。
3. 詰めた所をまたぐ保存は**元の位置を持たない + 保存の欄に1行**。またぐ範囲では、元の MIDI から位置で取り出す処理(ボイシング・ベースライン)も**しない**。またがない範囲は、元の時間に戻した位置で取り出す。
4. Correction Log は**元の位置のまま**。
5. 区切りは作り直さず**番号で詰める**(長さが変わった区切りだけ `repeatCount` を外す)。おすすめの範囲は `sourceToScreen` で移し、詰めた所にかかるものは出さない。消す小節をまたぐ音が2回鳴るのは今のまま。

### 13.1 保存の経路(実際の順)

**新規保存**も**追加保存**も、同じ候補・同じ `toSavedProgressionBlock` を通る。

1. `CorrectionWorkspace` の保存欄 → `WorkspaceSaveForm` → `buildSaveCandidate(model, range, timeline)`(`saveCandidate.ts:143`)。
   - `ready.candidate`: 画面の小節・拍(`range.startBar`/`endBar` と、カードの `bar`/`beat`/`duration`)。
   - `ready.original`: `originals`(`saveCandidate.ts:154-155`)。**元の解析の `bar`/`beat`/`durationBeats` をカードの画面値で上書き**している。
   - `ready.editable`: `createEditableProgression(original, meter)`(`:174`)。以降の直しの記録の元。
2. `CaptureView.tsx:790-798` が `workspaceBassline.forSave(ready.candidate)` を呼び、`saveNew` / `appendExisting` に候補・`original`・`editable`・ベースラインを渡す。
3. `useCaptureSave.ts:91-102`(新規)/`:200-207`(追加)が `createIdeaFromDraft` / `appendBlockToIdea` に `progressionBlock: candidate`、`progressionAnalysis: analysis.result`、`progressionMetadata`(`sourceBassline` を含む)を渡す。
4. `vaultStore.ts` の `toSavedProgressionBlock`(`:1294`)。
   - `candidateEventsAsTimeline(block.events, block.startBar, barLengthBeats)`(`:1320-1322`)で、ブロック内のイベントを画面の小節に直す。
   - `sourceStartBeat`/`sourceEndBeat` を **`savedChords` の `bar`/`beat`(画面)** から作る(`:1323-1326`)。
   - 各コードに `attachExtractedVoicing`(`:1337-1345`, `:1413-1425`)。
   - `persistChordEvents` で `eventId` を永続化(`:1427-1439`)。
5. `attachExtractedVoicing` は、`voicingMemory.sourceVoicing` が無いときだけ `attachSourceVoicing`(`sourceVoicing.ts:57-103`)を呼ぶ。ここが `(bar-1)*meter + beat-1`(`:71-72`)で `sourceData.notes` を**位置で**切り、ボイシングを作る(`:73-86`)。キャッシュのキーも `bar`/`beat`(`:41-55`)。
   - なお、取り込みの解析結果には**元の位置で**付けた `sourceVoicing` が入っている(`vaultStore.ts:758-784` の `attachSourceVoicings`)。`cardTimelineItem` が `sourceVoicing` を付けた場合は、ここの位置抽出は走らない(§13.2 の 4)。
6. 保存の後、`useCaptureSave.ts:104-115` が修正イベントと記録を書く。
   - `buildCorrectionEvents`(`feedback.ts:29-60`): `detected.bar/beat` から `startBeat`(`:50-56`)。
   - `buildProgressionSaveFeedbackEvent`(`analysisFeedback.ts:67-109`): **`saved.chords`(画面)** から `startBeat`(`:83-93`)。

### 13.3 `screenToSource` を「範囲の一覧」にする(承認点1の具体化)

```ts
type BeatRange = { start: number; end: number };

// 元の拍で持つ。消した小節ごとに昇順・重ならない。
removedBars: BeatRange[];

// 元の拍 → 画面の拍。消した範囲の中なら undefined。
sourceToScreen(beat: number): number | undefined;

// 画面の範囲 → 元の範囲の一覧(昇順・重ならない・長さの合計 = 画面の範囲の長さ)。
screenToSource(start: number, end: number): BeatRange[];
```

- **合成**: 詰めるたびに `removedBars` を**元の拍**で足す(新しい小節の画面範囲を、今の写像で元の拍に戻してから `removedBars` に加える)。写像は常に「元の拍の集合」1つで表されるので、**何回詰めても関数の合成にならず、重ねて正しく変換できる**。
- **不変条件**(テストで縛る):
  - `screenToSource(s, e)` の各範囲の長さの合計 = `e - s`。
  - 消した範囲と交わらない画面の範囲は、必ず1範囲だけ返る。
  - `screenToSource(s, e)` の各範囲の両端を `sourceToScreen` に通すと、元の画面の範囲に戻る(消した範囲を飛ばして詰まる)。
  - `removedBars` は昇順・重ならない・長さ > 0。
- **`cutFragments`/`recut`**: カードの画面範囲 `[card.start, card.start + card.duration]` → `screenToSource` → 各範囲について `context.sourceNotes` を切り、断片の画面の開始を `sourceToScreen(断片の元の開始)`、長さをそのまま(消した範囲は範囲に入らないので必ず `undefined` にならない)で戻す。断片は `pitch`・`originalPitch`・`sourceNoteId` を保つ。カードが詰めた所をまたぐ場合は、1枚のカードに2範囲ぶんの断片が付く(それで正しい)。
  - 同じカードの中で画面の時間が隣り合う断片は、`sourceNoteId`・`pitch`・`originalPitch` が同じなら1本にまとめる(Stage 01 の細部。カードをまたぐ場合はまとめないので、2回鳴る今の挙動は変わらない)。
- **¼拍未満の切れ端**: 元の範囲から切った結果が ¼拍未満なら、`removedBars` の隣(前なら前のカード、後ろなら後ろのカード)へ吸収する。吸収は「カードの境界を動かす」ではなく、切れ端を捨てて隣のカードの範囲を伸ばす(§5 の案1)。
- **2回鳴る**: 詰めた所をまたぐ1つの元の音は、範囲が2つに分かれるので断片も2つ。別々のカードに付く場合は今までどおり2回鳴る(承認どおり)。同じカードに2断片が付く場合は、そのカードのコードとして1回鳴る(今の `cardAuditionNotes`/`songPlaybackNotes` は音の集合なので同じ)。

### 13.4 詰めた所をまたぐ保存で「しない」こと(承認点3の具体化)

保存する範囲(画面)を `screenToSource` に通し、結果が **2範囲以上**なら「またぐ保存」:

- `sourceStartBeat`/`sourceEndBeat` を**付けない**(`toSavedProgressionBlock`)。
- ボイシングの**位置抽出をしない**(`attachExtractedVoicing` を呼ばない。`cardTimelineItem` が使用音から作った `voicingMemory` は残す)。
- ベースラインを**付けない**(`forSave` は `undefined`。保存欄に1行)。
- 保存欄の1行(例): 「詰めた所をまたぐため、元の MIDI の位置は残りません。ボイシングとベースラインは元の音から取りません。」
- 結果が **1範囲**なら、今までどおり `screenToSource` で戻した位置で `sourceStartBeat`/`sourceEndBeat`・ボイシング・ベースラインを作る。位置が戻るので、Chord Dojo・評価・練習の既存の読み方もそのまま使える。

補足: ベースラインの選択は `sourceBasslineCandidateRangeKey`/`sourceBasslineAuthorizationKey` が `startBar`/`endBar` を含む(`captureSnapshot.ts:41-53`)ので、詰めて小節が動くと選択は自動的に外れる(別の範囲に付くことはない)。詰めた後に選び直す。

### 13.5 Correction Log・修正イベントの位置(承認点4の具体化)

- `buildSaveCandidate` の `originals`(`:154-155`)を「元の解析の位置のまま」にする。これで `labelCorrectionLog`(`:84-90`)と `buildCorrectionEvents`(`feedback.ts:50-56`)の `startBeat`/`endBeat` は**元の位置**になる。
- `editable` は `original` から作るので、スロットの位置も元の位置になる。`saveCandidate.ts:176` の「カードを位置で探す」は、**並び(index)で対応**させる(位置一致は詰めた後に成立しない)。
- `buildProgressionSaveFeedbackEvent`(`analysisFeedback.ts:83-93`)は `saved.chords` の画面位置を使う。1範囲に戻るときは `screenToSource`、2範囲以上なら `detected`(元の位置)を使う。
- 記録は「元の解析に対する直し」の来歴なので、詰めたこと自体は**別の履歴1つ**(「◯小節を消して詰めた」)で残す。

### 13.6 Stage 01 のテストに足すもの(この節ぶん)

**単体**
1. 詰めた**後ろ**を保存: `sourceStartBeat`/`sourceEndBeat` が詰める前と同じ元の位置。`sourceData` は不変。ボイシングが詰める前と同じ音(別の所の音を拾わない)。ベースラインの `snapshot` が元の小節の音。
2. 詰めた所を**またぐ**保存: `sourceStartBeat`/`sourceEndBeat` が無い。位置抽出をしない(`sourceVoicing` が付かない/使用音のまま)。ベースラインが付かない。保存欄の1行。
3. 詰めた所の**両側にかかるカード**: `screenToSource` が2範囲を返す。`cutFragments`/`recut` が両方から切って画面に戻す。**2回詰めても**元の音と一致(合成の確認)。
4. Correction Log・修正イベント・保存フィードバックの `startBeat`/`endBeat` が**詰める前と同じ**(元の位置)。
5. 詰めた後に「分ける・つなぐ・カードを消す・境目」をしても、別の所の音を拾わない(§11 の 5 に追加)。
6. `sameSpan`: 詰めた所より後ろの、中身の変わっていないカードが「区間を変えた」と判定されない(2音未満の保存失敗が出ない)。

**e2e**
1. 詰める → 後ろを保存 → Vault に書かれた `sourceStartBeat`・ボイシング・ベースラインが元の位置のまま。
2. 詰めた所をまたぐ範囲を保存 → 保存欄に1行、`sourceStartBeat` が無い、ベースラインの選択が外れている。
