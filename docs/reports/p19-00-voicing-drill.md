## 2. 中身(§1)

- 組は **20**(① 5・② 5・③ 3・④ 7)。カードは **163 枚**(① 20・② 40・③ 10+18+28・④ 47)。③ は組が重なる(前・後・全部)ため、同じ形が別の組にも出ます。
- ① ② の右手は固定の 3 音。三和音だけは右手にもルートを入れ、4 和音・7sus4・6 はルートを省きます(§1.2)。置き方は「1 オクターブ以内の転回形」「最初は 60〜71 で一番上を 76 に近く」「次からは 57〜74 で動きの合計が最小、同じなら一番上の動き、次に低いほう」です。
- ③ は §1.3 の表をデータとして持ち、形A → 形B の 4 音。**表の音と生成したカードの音が一致することをテストで確かめています**(14 形 × A/B)。同じ右手の形(例:CΔ7(9) A と Am7(9,11) A)は同じ並びになります。
- ④ は 7 進行。右手の音は §1.4 の表の決まりから作り、置き方は「最初は 57〜69 で一番上を 74 に近く」「次からは 57〜74 で動きの合計(音の数が違うときは下から対応し、余りは一番近い音との差)」です。分数コードは左手が分母です。
- 12 キー:① ② ④ はそのキーで置き方を当てはめ直し、③ は表の音を **−5〜+6** の半音数だけ動かします(F♯ は +6、G は −5)。左手は §1.2・§1.4 で 40〜51、③ は表の左手を動かします(そのため +6 のキーでは 40〜51 を超えます。§1.3 の「全部の音を同じ半音数だけ動かす」に従った結果です)。
- 綴り:ルートはキーと度数から綴り、構成音はルートからの音程どおりに綴ります。**ダブルフラット・ダブルシャープが要るときだけ**、ルートを異名同音の隣の文字に替えます(例:D♭ の ♭VI = B𝄫 → **AΔ7**、F の ♯IV → **Bø7(11)**)。F♯ の I は F♯ のまま(G♭ にしない)、F の A7 には C♯ が出ます。
- 参考にした教材・練習曲・譜例は写していません。名前も書いていません。

## 3. 判定(§3)

`drillShapeMatches(カード, 押さえている鍵)` は、① 一番低い鍵が左手の音、② 残りが右手の形と同じ間隔・同じ数(オクターブは問わない)、③ 右手が左手より上、④ ほかの鍵が無い、を満たすときだけ通します。**ペダルは数えません**(渡すのは押さえている鍵だけ)。`HeldCardJudge` は変えていません。

- 「迷った」の印は `drillDistracted(カード, 押した鍵)`(音名で見る。オクターブ違いは含めない)。
- 周の時計は `createDrillLapClock` / `noteFirstPress` / `passCard`。周の始まりは最初の鍵、カードの秒数は前のカードが通った瞬間からです。
- 記録に数える条件(ヒントを見た周・MIDI でない周を数えない、切断で無効、押さえたまま始めたら離すまで待つ)は **Stage 1 で画面とつなぐ**ときに実装します。Stage 0 では時計と判定の純粋な部分だけです。

## 4. 記録ファイル(§4)

- `voicing-drill-v1.json`(`app: loopvault-voicing-drill`、`fileVersion: 1`、`version: 1`)。`sets[組][中身の版]` に **その版の C のカード**(コード名・度数・形・左右の音)と `keys[キー]` の `see` / `recall` を持ちます。
- `Entry = { laps, best?, last? }`、`best`/`last` は `{ totalMs, cardMs[], at }`、`last` には `marks[]`。自己ベストは今の版の最小 `totalMs`。前の版の記録は残り、新しい版には引き継ぎません。
- 読み込み時に、`cardMs` の枚数がカードと合わない・`marks` が範囲外・合計が `totalMs` と合わない Entry は**その Entry だけ**捨てて、報告(返り値の `rejected`)に残します。ファイル全体は壊しません。
- 新しい版のファイルは開かず、そのまま保持します。壊れたファイルは検証済みのバックアップから戻し、壊れたバイトは隔離に残します。CAS(版と内容トークン)で競合を弾きます。
- Rust 側は `voicing-drill` の置き場所だけを足し、`every_storage_namespace_accepts_only_its_own_app` に 1 つ加えました。Dojo の記録・Jazz・Original のファイルには書きません。

## 7. 判断したこと(レビューのときに見てください)

- **判定の「ルート」は左手の音**としました。④ の分数コード(G/F など)は左手が分母なので、「一番低い鍵がルート」をそのまま当てると G/F が通りません。左手は仕様どおり固定(分母)で、判定は左手の音を見ます。
- **③ の左手は表の音を移す**ので、+6 のキー(F♯)では 40〜51 を超えます(C3 → F♯3 など)。§1.3 の「全部の音を同じ半音数だけ動かす」を優先しました。① ② ④ は 40〜51 に収まります。
- **綴りの替えはダブルのときだけ**です。F♯ の I は F♯(G♭ にしない)、D♭ の ♭VI は A、F の ♯IV は B になります。
- ③ の「同じ右手の形」の印は、いまは `right` の間隔から作れます(テストで CΔ7(9) A と Am7(9,11) A が同じことを確認)。画面の印は Stage 1 で付けます。

## 9. レビュー後の修正(2026-11-08)

1. **cycle-a・cycle-b の最初のコードを三和音 I(C)に**しました。C では右手 **G4 C5 E5**(ルートを含む 3 音)、F♯ では **E♯4 A♯4 C♯5**(C♯ の三和音)、B♭ では **D4 F4 B♭4**(B♭ の三和音)です。
2. **④ の左手の綴りを、そのカードのコード名のルートと同じに**しました。原因は、左手だけ三和音の形で綴り直していたことです(ダブルの回避で E♭ などが選ばれていました)。分数コード以外は右手のコードのルートの綴りを使い、分数コードは分母の綴りを使います。F♯ キーの VIm は **D♯3**、IIIm は **A♯2**、♯IVø7 は **B2** になりました。全 20 組 × 12 キーで「左手の音名 = コード名のルート(分数は分母)の綴り」をテストしています。
3. **micro-6b の最初を F♯ø7(テンションなし)に**しました。右手は ø7 のルート以外の 3 音(A C E)です。C では **E4 A4 C5**、F♯ では **E♯4 A♯4 C♯5**、B♭ では **E4 A4 B♭4** です。

この 3 点を直したあとの表を §5 に差し替えました(163 枚)。
