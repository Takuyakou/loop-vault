# Loop Vault 検出器研究 報告書

**Stage F0 〜 F5a / root・quality・tension の8段階 shadow 研究**

- 作成日: 2026-07-26
- 対象コーパス: 199ファイル / 7490 chord window / Gold 5962 window
- 実装への反映: **なし**（8段階すべて非昇格、製品既定は `phase4-v1` のまま）

---

## 0. 要旨

MIDI からコード進行を検出する製品検出器について、**root / quality / tension の3層すべてを独立に置き換えられるか**を8段階に分けて調べた。

結論は明快である。

> **どの層も、置き換えると悪化した。8段階を通じて製品を上回った subset は1つも無い。**

| 層 | 製品 | 代替実装 | 差 |
|---|---|---|---|
| root 精度 | **92.1%** | 80.2% | −11.9pp |
| quality（canonicalExact） | **78.7%** | 72.8% | −5.9pp |
| tension（F1 score） | **65.7%** | 52.7% | −13.0pp |

ただし研究は失敗ではない。**製品の実力と限界が初めて数値になった**こと、**失敗の構造が特定できた**こと、そして**「精度を上げる」以外の方向が見えた**ことが成果である。

---

## 1. 何を問うたのか

出発点は具体的な不具合報告だった。

- `A7#5` が `A7` として検出される（tension 脱落）
- pedal ベースの上のコードが誤って命名される
- rootless voicing がベース音から命名される

これらは個別のバグに見えたが、**検出器の構造そのものに起因するのではないか**という仮説があった。

現行検出器は `ChordQuality` という**21個の完成品の閉じたリスト**を持ち、pitch class 集合をそれらのテンプレートと照合して最良のものを選ぶ。この設計だと:

- root は「最も辻褄の合う quality」の root として決まる → **root は quality 層の誤りを継承する**
- リストに無い和音（`A7#5`）は、リストにある中で一番近いものへ丸められる
- 「3度が聞こえない」と「3度が別の音だった」が区別されない

そこで問いを3つに分けた。

| 問い | Stage |
|---|---|
| **root を quality から切り離して決められるか** | F0 → F2 → F2R → F2W → F2A |
| **root を固定したまま quality を決め直せるか** | F3a |
| **core を固定したまま tension だけ独立に検出できるか** | F5a |

## 2. 方法論

製品を壊さずに研究するため、全段階で **shadow 方式**を採った。新しい判定は計算するが**製品出力へは一切接続しない**。

これに加えて、自分の測定を信用しないための規律を5つ課した。

### 2.1 不変条件を「入力だから当然」で済ませない

F3a では root/bass を入力として受け取るので、定義上動かない。それでも**製品の列と shadow の列を直接比較**して 199/199 を確認した。F5a の core 4列も同様。

### 2.2 摂動テストの非空虚性を必ず確認する

「quality パラメータを振っても root が変わらない」は、**何も読んでいないパラメータを振れば自明に通る**。どんな実装でも「独立」を証明できてしまう。

そこで全段階で「摂動が実際に何かを動かしたか」を別の Gate として測った。F2 は 199/199、F3a は 199/199、F5a は **30/199**（閾値の境界に乗るファイルが199中30しかない、という正直な数字）。

### 2.3 評価 subset を、測定対象の分類器で定義しない

F2W では walking bass の subset を **3通り独立に定義**した。F1 の `relation` だけで定義すると、その分類器が取りこぼした window は黙って subset から消え、**測定がその分類器を実際より良く見せる**。

結果、3定義の一致は**わずか4 window**（corpus 宣言 531 / 音から判定 265 / F1 relation 501）。これ自体が結果だった。

### 2.4 閾値は測定前に凍結する

F2R では6条件の閾値を、**測定を1回も実行する前に** JSON へ凍結した（`frozenBeforeMeasurement: true`）。導出はすべて公開済みの証拠分布からで、override の当たり外れからではない。

### 2.5 結果を見てから解釈を変えない

F2 の H4 で Hard Gate が1件 FAIL したとき、Gate の文言を緩く読み替えれば PASS にできた。**そうしなかった。** 結果を見てから解釈を変えれば凍結の意味が消える。

## 3. 段階ごとの経過

### F0 — 内部分解（振る舞い不変）

21個の quality 名を `root / triad / seventh / tensions[] / bass` へ分解した。**製品の出力は1バイトも変えない。**

| 検証 | 結果 |
|---|---|
| 199ファイル・7490コードの canonical identity 保持 | **7490/7490** |
| ラベル種類 → 分解形の種類 | **492 → 492（1対1）** |
| Timeline / 候補順位 / warning | 199/199 不変 |

**492→492 が重要である。** 2つのラベルが1つの分解形へ潰れた箇所が無いので、**新しい同値関係を持ち込んでいない**ことが示せた。`Em/G` と `G6` は別のまま、`Cmaj9` と `Cmaj7(9)` は同一（元から canonical identity がそう扱っている）。

設計上の判断を3つした。

- **6度は triad ではなく tension** — 独自 triad にすると `C6` と `C` が、耳では共有している triad を共有しなくなる
- **21個のリストに無い組み合わせには名前を付けない**（`undefined` を返す）— 黙って近い綴りへ丸めるのは「名前を付けられないコード」が「間違った名前のコード」になる経路
- **quality 分解表はデータで持つ** — 逆引きを Map にして、条件分岐の手動同期を避けた

### F1 — shadow 診断（製品非接続）

bass / root / defining tone / ambiguity の根拠を計算した。

この段階で**研究全体を支える規則**が決まった。

> **音が無いことは、否定されたことではない。**

短3度がどこにも鳴っていないなら、そのコードは「minor ではない」のではなく **minor と他の何かの間で未確定**である。minor を否定するのは長3度が明確に鳴っているときだけ。

実測でこれは効いていた。

| quality | supported | contradicted | **underdetermined** |
|---|---|---|---|
| major | 49.6% | 39.0% | **11.4%** |
| minor | 32.5% | 50.4% | **17.1%** |
| minor7 | 59.9% | 28.6% | **11.5%** |

**minor が未確定の window が 17.1%（1280件）。** これを「否定」に丸めていたら、その全部で根拠の無い断定をしていたことになる。

bass-upper relation の分布も出た。

| relation | 割合 |
|---|---|
| aligned | 76.7% |
| **pedal** | **16.6%** |
| walking | 6.7% |
| none | 0.1% |

**6件に1件が pedal** — bass と upper が別のことを言っている。

### F2 — quality 非依存 root（仮説の本体）

`rootPresence` / `tertianSkeleton` / `susSkeleton` / `shellSkeleton` / `guideToneImplication` / 弱い keyPrior / 制限付き continuity だけから root を決める。**quality テンプレートは一切見ない。**

**独立性は完全に達成された。** quality 層のパラメータを 0.7 / 1.0 / 1.3（および 0.1 / 1.0 / 10）に振っても root 列は 199/199 で完全一致し、その摂動が quality スコアを実際に動かしたことも 199/199 で確認した。

**しかし精度は悪かった。**

| subset | product | shadow top1 | shadow top3 |
|---|---|---|---|
| plain-triad | **100.0%** | 100.0% | 100.0% |
| pedal/slash | **87.5%** | 58.6% | **100.0%** |
| inversion | **86.7%** | 57.5% | **100.0%** |
| rootless | **99.4%** | 52.3% | 85.2% |
| walking-bass | **93.8%** | 52.4% | 86.6% |
| **全体** | **92.1%** | **80.2%** | 94.4% |

correction cost **471 → 1179（+708）**、改善 subset **ゼロ**。

ここで**目を引く数字**が出た。**inversion と pedal/slash では shadow top3 が 100%。** 正解は候補の中にあり、順位で負けているだけである。

### F2R — 選択的訂正（top3 が良いなら、狭く使えないか）

top3 が良いなら、**製品の root を既定に置いたまま、証拠が一方的な場所だけ訂正**すればよいのではないか。6条件（接戦 / relation 信頼度 / 代替の骨格証拠 / 現Top1への明確な反証 / 既知候補内 / 未達なら abstain）を**事前登録**して測った。

| 指標 | 値 |
|---|---|
| override | **1件 / 7490** |
| overridePrecision | **0.0%** |
| net correction gain | **0** |
| abstention | **99.99%** |
| correction cost | **±0** |

**害は無いが、規則が何もしていないことと区別できない。**

原因は自分の事前登録にあった。`contestBand = 0.05` を**公開済み rootMargin の分布**から導いたが、rootMargin は「shadow 自身の1位と2位の差」で、条件1が測るのは「**製品の root と shadow の代替候補の差**」— **別の量だった**。実測 contestGap の p10 は 0.0591 で、事前登録値は**10パーセンタイルより下**。条件1に到達した window の9割以上を排除していた。

**この観測を見てから閾値は動かさなかった。** 契約が禁じる Gold への当てはめそのものだからである。

### F2W — walking の候補生成（top3 が悪い唯一の場所）

walking だけ top3 が 60.9% と低かった。**正解が候補に入っていないのではないか** — つまりランキングでは直せない生成の失敗ではないか。

低音のどの音を数えるかについて6つの答え（現行 / 強拍重視 / 長音価重視 / 通過音減衰 / 上声より速い bass の減衰 / 境界優先）を用意し、ランキングを固定して比較した。

**仮説は否定された。**

| 指標 | 全 variant / 全 subset |
|---|---|
| **walkingCandidateRecall** | **100%** |

**正解 root は常に12候補の中に正のスコアで存在していた。** 入っていないのではなく、順位で負けている。

6 variant のどれも **@1 と @3 を1件も動かさなかった**。`strong-beat` は通過音を170件落として正解 root を**0件**しか落とさない（除去規則としては筋が良い）が、**それが順位を変えないという事実が、通過音は元々問題ではなかったことを示していた**。

### F2A — 敗因の項目別特定

正解が候補にあって順位で負けるなら、**どの項目が勝者にリードを与えているのか**。

corpus が事前注釈した walking subset（357 window）で、7項目それぞれの寄与差を window ごとに計算した。

| dominant failure component | 割合 |
|---|---|
| **rootPresence** | **55.6%** |
| **continuity** | **34.5%** |
| shellSkeleton / guideToneImplication | 8.8% |
| **tertianSkeleton / susSkeleton / keyPrior** | **0%** |

誤 Top 1 を Gold root からの音程で記録すると:

| 半音 | 割合 |
|---|---|
| **+7（完全5度）** | **42.1%** |
| **+4（長3度）** | **24.6%** |

**上位2つは和音の構成音。** 走るベースが5度と3度を通過し、持続時間で重み付けした `rootPresence` がその通過音に票を入れている。教科書どおりの署名で、診断としては明快だった。

`tertianSkeleton` は一貫して **Gold root の味方**をしていた（平均 −0.0152）。

**だが validation で再現しなかった。**

| split | rootPresence 寄与率 |
|---|---|
| dev | 66.7% |
| **validation** | **0.0%** |
| holdout-v2 | 98.9% |
| regression-v3 | 100.0% |

3対1で割れた。validation の losing window は15件と少ないので「例外」と片付けることもできたが、**それは都合の良いほうを選ぶこと**であり、事前条件は validation での再現だった。

決定打はもう2つあった。**product は同じ window で 93.8%（335/357）正しい** — 直す対象は shadow のほうである。そして**失敗が stress variant に集中**していた（clean top1 93.3% / stress 10.7%）。walking の問題として測ってきたものは、**実際の walking bass の性質というより stress 生成器が加えた劣化の性質**である可能性が高い。

ここで **root 研究を終了**した。

### F3a — quality 三値判定（root を固定して）

root/bass を製品から受け取って固定し、**同一 root 内でのみ** quality を比較する。F1 の三値判定をそのまま使い、**反証があるときだけ候補を除外する**。

三値判定自体は設計どおり働いた。

| | |
|---|---|
| 反証により除外 / window | **7.12**（候補11個中） |
| **音の欠落のまま生存 / window** | **1.50** |
| triad がどれも supported でない | **11.6%** |
| seventh がどれも supported でない | **7.9%** |

`Cmaj` と `Cmin` は3度が鳴っていなければ**両方生き残る**。`seventh:none` も既定値ではなく判定として扱った。

**精度は悪かった。** canonicalExact **78.7% → 72.8%**、cost **+349**。

**ただし形が重要だった。**

| subset | canonicalExact | cost差 |
|---|---|---|
| **plain-triad** | 100→**100** | **0** |
| **pedal** | 56.3→**56.3** | **0** |
| **inversion** | 53.3→**53.3** | **0** |
| **rootless** | 85.5→**85.5** | **0** |
| clean | 77.9→75.4 | +86 |
| **stress** | 79.8→69.3 | **+263** |

**Stage F を始める動機になった4つの subset はすべて同点**で、悪化は普通の window に集中した。三値判定は**難しいケースを助けもしないが壊しもせず、簡単なケースを壊す**。

原因の推測: 三値化の過程で**持続時間と信頼度の重みを捨てている**。「3度が鳴っている」は二値だが、0.2拍と4拍は同じではない。

### F5a — 独立 tension 検出（core を固定して）

root / bass / triad / seventh をすべて製品から受け取って固定し、**残った pitch class の解釈だけ**を問う。

設計上の難所が2つあった。

**同じ音程が下の和音次第で別の意味になる。** 6半音は5度が鳴っていれば `#11`、なければ `b5`。9半音は7度があれば `13`、なければ `6`。3半音は長三和音の上なら `#9` だが短三和音では**核**。core を固定しているからこそ、テーブル参照ではなく**固定 core に対する解釈**として扱えた。

**鳴っている音が tension とは限らない。** presence / duration / metric-position / voice-role / sustained を別々に記録し、**2つ以上が一致したときだけ assert** する。通過音は presence しか持たないので2に届かない。

**過検出の防御は効いた。** plain-triad への tension 誤追加は **0 → 0**。

**しかし識別力が足りなかった。**

| 指標 | product | shadow | 差 |
|---|---|---|---|
| precision | **74.6%** | 46.3% | **−28.3pp** |
| **recall** | 58.7% | **61.3%** | **+2.6pp** |
| F1 | **65.7%** | 52.7% | −13.0pp |
| **FP / window** | **0.082** | 0.290 | **3.5倍** |

**recall だけ上がって false positive が増える**形で、事前に定めた非推奨条件そのものだった。humanized subset では precision が **65.7% → 22.6%**、FP/window は 0.121 → 0.815 まで悪化した。

**この段階で最も重要な発見があった。**

| | precision | recall |
|---|---|---|
| **product の alteration 検出** | 測定不能（1つも予測していない） | **0.0%** |

`b9` / `#9` / `#11` / `b13` / `b5` / `#5` の recall が **0.0%**。**製品は alteration を1つも検出していない。**

つまり最初の報告 `A7#5` → `A7` は**個別の不具合ではなく、alteration 検出という機能が存在しないことの一例**だった。研究の出発点になった症状の正体が、最後の段階で判明した。

## 4. 分かったこと（製品について）

### 4.1 製品検出器は思っていたより強い

8段階すべてで代替実装が負けた。特に:

- **plain triad では製品も shadow も 100%** — 簡単なケースは既に解けている
- **rootless の root 精度 99.4%** — 「rootless が苦手」という直感は root については誤り
- **Gold walking window で 93.8%** — walking も root は取れている

製品の quality template 方式は、pitch class 集合全体を持続時間と信頼度で重み付けして照合する。**この重み情報が効いている。** 証拠を二値化した実装は例外なくこれに負けた。

### 4.2 既知の弱点が数値になった

| 制約 | 実測 |
|---|---|
| pedal / slash | canonicalExact **56.3%** |
| inversion | canonicalExact **53.3%** |
| rootless | canonicalExact **85.5%**（root は 99.4%） |
| **alteration 検出** | **recall 0.0%**（機能が存在しない） |
| tension 全体 | recall **58.7%** / precision 74.6% |
| arpeggiated | canonicalExact **62.7%** |
| Chord Drip corpus | canonicalExact **29.7%** |

**pedal と inversion は root ではなく和音全体の同定で落ちている**（root 87.5% / 86.7% に対し canonicalExact 56.3% / 53.3%）。ここが最大の改善余地だが、F3a が示したとおり素朴な作り直しでは同点にしかならない。

### 4.3 製品は根拠なく断定している場所がある

canonicalExact 78.7% の残り **21.3%** のうち、どれが根拠のある断定でどれが根拠の無い断定かを**区別する手段がいま無い**。

F3a の三値判定はその材料を出した — triad がどれも supported でない window **11.6%**、seventh **7.9%**。F1 の ambiguity 分布も同様（rootless-inferred 24.7% / pedal-or-root 17.3% / inversion-or-added 12.4%）。

## 5. 分かったこと（方法論について）

研究そのものから学んだことのほうが、次に効くかもしれない。

### 5.1 「差分が予想どおりの場所に出る」は正しさの証拠ではない

F1 の時点で、shadow root と製品 root の食い違いが walking / rootless / pedal / inversion に集中し plain-triad で0件だったので、**「分布が仮説と一致している」と書いた。**

F2 で Gold と突き合わせた結果、**その解釈は誤りだった**。食い違う場所は正しく特定できていたが、**そこで正しいのは製品の側**だった（rootless: product 99.4% / shadow 52.3%）。

F1 は「どちらが正しいか」を測っていなかったので、あの時点でああ書くべきではなかった。**訂正して記録に残した。**

### 5.2 shadow stage は「接続する前に分かる」ためにある

F2b / F2R / F2Wb / F3b / F5b — 5つの接続候補すべてを、**製品に一切触れずに**却下できた。もしどれか1つでも先に接続していたら、劣化した製品を出荷してから気づくことになっていた。

### 5.3 自分の測定ハーネスのバグを3件見つけた

いずれも**結果が「バグ」ではなく「データが無い / 効果が無い」ように見える**形で壊れていた。

| Stage | バグ | 見え方 |
|---|---|---|
| F0 | `--files` をカンマ区切りにしていた | ファイル名にカンマを含む private MIDI が黙って切られる |
| F2 | Gold の `startBeatInBar` に +1 していた | 全キーが1拍ずれて join が空振り → **「gold 0件」と表示** |
| F2W | 音響 heuristic の判定条件が厳しすぎた | 531 の注釈 walking window のうち **7 しか拾えない** |

3件目は F2A で corpus 注釈と突き合わせて初めて判明した。**F2W の「音から判定」subset が8 gold window しか持たなかったのはこれが原因**で、F2W の該当部分の結論は実質的に無効である（他の2定義での結論は有効）。

### 5.4 事前登録は、正しい分布から導かないと意味が薄れる

F2R の `contestBand` は事前登録という手続きは守ったが、**導出元の分布が問いに対応していなかった**。手続きの形式だけでは足りず、「その閾値は何の分布のどこに置いているのか」を明示する必要がある。

## 9. 将来 root / quality / tension を再訪する人へ

再訪するなら、ここから始めるのが早い。

### 9.1 やっても無駄だと分かっていること

- **証拠を二値化して重み情報を捨てる方式** — F2 / F3a / F5a すべてこれで負けた
- **bass relation を root 決定へ直結する** — relation が最もはっきりする walking で shadow root が最も外れる（top1 11.8%）
- **通過音の除去** — F2W が 170件落として順位が1つも動かないことを示した
- **F2R の帯を広げる** — 唯一の発火が wrong-to-wrong で、広げれば劣ったランキングをより多く採用することになる

### 9.2 有望かもしれないこと

- **`tertianSkeleton` は一貫して正しい方向に働いている**（F2A で平均 −0.0152）。この項目単独は信頼できる
- **shadow top3 は inversion / pedal で 100%** — 候補集合は良い。順位付けだけが課題
- **pedal / inversion の canonicalExact 56.3% / 53.3%** が最大の改善余地。root は取れているので、**quality と bass の関係**が焦点
- **持続時間と信頼度の重み**を保ったまま三値判定を足す方向（F3a は重みを捨てたので負けた）

### 9.3 測定するときの注意

- **subset を、測定対象の分類器で定義しない**（F2W の教訓）
- **摂動テストは非空虚性を必ず確認する**（何も読まないパラメータは自明に「独立」）
- **clean と stress を分けて見る** — 混ぜると stress の劣化が全体を支配する
