## 0. 目的

テキスト取り込みで、ジャズの曲のコード表を Vault に入れられるようにする。

現状、`Cm(maj7)` と `G7alt` が読めない(P12.4 の調査で判明)。この2つはジャズの曲で頻出するため、
**読めないと「実曲をテキストで取り込み、Chord Dojo の『登録した音を覚える』で練習する」という使い方が成立しない。**

### 範囲

| 含む | 含まない |
|---|---|
| コード記号の読み取り(表記の種類を増やす) | 検出ロジック(MIDI 解析)の変更 |
| 読み取った記号の内部表現と表示名 | 小節記法・区切り記法の文法変更 |
| 試聴の音(=保存時に「登録時の音」になる音) | 新しいボイシング生成の仕組み |
| 各機能(消費側)での扱いの確認 | **12小節上限の変更**(§9) |
| | Chord Dojo の出題対象の変更 |

## 1. 考え方:記号の意味と、鳴らす音を分ける

本仕様の全判断はこの区別に従う。

| 層 | 何か | 例(G7alt) | Loop Vault での置き場所 |
|---|---|---|---|
| ① コード記号の意味 | 作曲者が紙に書いたこと | 「G のオルタード・ドミナント」 | `ChordSymbol` |
| ② 使える音の範囲 | その記号で許される構成音・テンション | 3・♭7 + ♭9 / ♯9 / ♯11 / ♭13 から選ぶ | 記号から導く(保存しない) |
| ③ 実際に鳴らす音 | 具体的なボイシング | G2 B3 F4 B♭4 E♭5 | Voicing Memory(音の高さの記録) |

**①と③は既に別々に保存されている**(`ChordSymbol` と、Phase 3.8.5 以来の Voicing Memory)。
本作業で足りないのは、①で「alt という分類」を言い表す手段だけである。

守ること:

- **①に③の都合を持ち込まない。** 「試聴でこの3音を鳴らすから、alt = この3音」としない
- **①の情報を表示で失わない。** `G7(b9,#9,b13)` と `G7alt` は別の記号である
- テキストのコード記号からは、原曲で実際に弾かれたボイシングは分からない。
  **試聴の音は、アプリが選んだ推奨ボイシングである**(§6)

## 2. 前提

### 2.1 分かっていること(P12.4 の調査より)

- テキスト入力の解析は `Cm(maj7)` と `G7alt` を読めない
- `alt` は `ChordQuality` に存在しない
- Chord Dojo の品質の集合に `aug` / `six` / `minMaj7` は元々無く、P12.4 で `EXTRA_QUALITIES` として追加された(`QUALITIES` は 14 のまま)
- P12.4 では定番進行の `7alt` を `7(♭9)` で代用した。**本作業とは別の話であり、その代用は変えない**
- Voicing Loop の生成ボイシングは、三和音・dim7・aug を全スタイルでは鳴らせない
- テキスト取り込みには「通常」と「拡張記法」の2つの読み方がある
- テキストで保存すると、試聴で鳴っていた音が「登録時の音」として保存される

### 2.2 確かでないこと(Stage 00 で確認する)

本仕様書の書き手はコードを直接見ていない。過去に何度も、指示書の前提がコードの実態とずれた。
**以下は推測であり、Stage 00 で事実を確認すること。**

1. `minMaj7` が `ChordQuality` に既にあるか
2. `tensions` の型が `♭9` `♯9` `♯11` `♭13` `9` `13` を表せるか
3. `label` が保存されるのか、構造から毎回作り直されるのか。移調時はどうか
4. `ChordSymbol` に省略可能なフィールドを足した場合、**既存の保存データがそのまま読めるか**(Zod の定義、`fileVersion`、書き出し/読み込み)
5. 「通常」と「拡張記法」が同じコード記号の読み取り部品を使っているか
6. `,` がトークンの区切りに使われているか(`C7(b9,#9)` が壊れないか)
7. `/` の扱い(`C6/9` が分数コードと誤認されないか)
8. `♭` `♯` `Δ` `ø` `°` や全角括弧などの正規化が既にあるか
9. テキストで保存した「登録時の音」に、**出どころ(MIDI から採った音か、アプリが選んだ音か)**の記録があるか(Phase 11 の決まり)

## 3. 進め方

1. **Stage 00:調べて報告して止まる。** 製品コードを変更しない
2. 人間の承認後、**Stage 01:実装**

**alt の内部表現(§5.2)は、Stage 00 の結果を見るまで確定しない。** 調査の前に実装方式を決めて書き始めないこと。

### Stage 00 で報告すること

1. §2.2 の各項目の事実(ファイルパスと該当コード)
2. **§10 のテスト表の全トークンを今の解析に通した結果**。成功・失敗だけでなく、
   **root / quality / tensions / bass の内部構造まで**出して、期待と比べること。
   分類は「正しく読める / 読めない / 誤って読める(例: `C6/9` が bass=9 扱い)」の3つ。
   一時的なテストで調べてよいが、報告後に消すこと
3. コード記号を表示名に変える処理の場所と、その規則
4. 試聴の音を作る処理の場所。`minMaj7` と、テンション付きの dom7 を今その処理に渡すと何が鳴るか
5. §8 の各消費側が `minMaj7` を受け取ったときの挙動(鳴る / 非対応表示 / 例外)
6. **§8 の表の「必要な情報」の列を、実コードで確かめた結果**(推測で埋めない)
7. **§5.2 の候補 A・B・C のどれが実現できるか**と、それぞれの互換性の影響
8. 試聴の音を作る処理が、作れないコードを渡されたときに何をするか(例外 / 空 / 別の音を返す)
9. テキスト取り込みで一部のトークンがエラーになったとき、残りを保存できるか(今の挙動)
10. 本仕様書と実態が食い違う箇所。**推測で埋めずに、食い違いとして列挙すること**

## 4. 受け付ける表記

### 4.1 A群:本作業の目的(必須)

| 種類 | 受け付ける表記(C の例) | 意味 |
|---|---|---|
| マイナー・メジャー7 | `Cm(maj7)` `CmMaj7` `Cm(Maj7)` `CmM7` `Cm(M7)` `CmΔ7` `Cm(Δ7)` `Cm△7` `C-maj7` `C-(maj7)` `C-Δ7` `Cmin(maj7)` `CminMaj7` | C minMaj7 |
| マイナー・メジャー9 | `Cm(maj9)` `CmM9` `CmΔ9` `C-(maj9)` | C minMaj7 + 9 |
| オルタード | `G7alt` `G7(alt)` `Galt` | G のオルタード・ドミナント(**分類**。§5.2) |

分数コードとの組み合わせ(`Cm(maj7)/G`、`G7alt/B`)も受け付ける。

### 4.2 B群:ジャズのコード表で普通に使う表記(読めなければ直す)

**Stage 00 で「読めない」または「誤って読める」と分かったものを直す。正しく読めているものは触らない。**
「読めた」かどうかではなく、内部構造が正しいかで判断する(`C6/9` が成功していても bass=9 扱いなら直す)。

| 種類 | 表記の例 | 意味 |
|---|---|---|
| ハーフディミニッシュ | `Cm7b5` `Cm7(b5)` `Cø` `Cø7` `C-7b5` | C m7b5 |
| ディミニッシュ7 | `Cdim7` `C°7` `Co7` | C dim7 |
| テンション付きドミナント | `C7b9` `C7(b9)` `C7#9` `C7(#9)` `C7#11` `C7(#11)` `C7b13` `C7(b13)` `C7(b9,#9)` `C7(b9,b13)` `C7(#9,b13)` `C7(b9,#11)` | C dom7 + **書かれたテンションそのまま** |
| 9 / 13 | `C9` `C13` `C7(9)` `C7(13)` | C dom7 + 9 / 13 |
| サス | `C7sus4` `C7sus` `C9sus4` `C9sus` | 既存の sus の表し方に従う |
| 6/9 | `C6/9` `C69` `C6(9)` | C six + 9。**分数コードと誤認しないこと** |
| メジャー7 | `Cmaj7` `CM7` `CΔ7` `C△7` `CΔ` `Cmaj7#11` `Cmaj7(#11)` | C maj7(+ ♯11) |
| マイナー6 | `Cm6` `Cmi6` `Cmin6` | C m6 |
| ダッシュのマイナー | `C-` `C-7` `C-9` `C-6` | C minor / m7 / m9 / m6 |
| 略記のマイナー | `Cmi7` `Cmin7` `Cmi` `Cmin` | C m7 / C minor |
| オーギュメント7 | `C+7` `C7#5` `C7(#5)` `Caug7` | 既存の表し方に従う。無ければ dom7 + ♯5 |

**大文字小文字に注意:** `CM7` はメジャー7、`Cm7` はマイナー7、`CmM7` はマイナー・メジャー7。

### 4.3 C群:本作業では受け付けない

| 表記 | 理由 | 扱い |
|---|---|---|
| `Cm/maj7` | `/` が分数コードの記号と衝突する | 位置付きのエラー |
| `G7 alt`(空白入り) | 空白はトークンの区切り | `alt` が未知のトークンとしてエラー |
| `Cdim`(7 無し) | 三和音か dim7 か曲によって違う | **既存の挙動を変えない** |
| 上部構造の多段表記(`D/C7` 等) | 本作業の範囲外 | 位置付きのエラー |

**読めない表記を黙って捨てない。** 既存のエラー表示(位置とトークンを示すもの)に出す。

## 5. 内部表現

### 5.1 マイナー・メジャー7

`ChordQuality` の `minMaj7` を使う。無ければ足す(足す前に報告する)。9 は `tensions` に入れる。

### 5.2 オルタード

**alt は「分類」であり、特定のテンションの組ではない。**

- オルタード・ドミナントで使える音:3・♭7 + ♭9 / ♯9 / ♯11(♭5)/ ♭13(♯5)
- 実際にはこの中から選んで弾く。全部を同時に鳴らす必要はない
- **`G7alt` を「dom7 + 決まった3テンション」として保存しない**(v1 の定義は撤回)

Stage 00 で、次の候補のどれが実現できるかを調べて報告する。**どれにするかは人間が決める。**

| 候補 | 内容 | 長所 | 気をつけること |
|---|---|---|---|
| **A(推奨)** | `ChordSymbol` に省略可能な印(例: `altered?: true`)を足す。quality は dom7、`tensions` は空 | 意味が正確。移調も印が付いていくだけ | 既存データとの互換(§5.4)。印を知らない機能の扱い(§8) |
| B | 既存の `label` が保存され、構造から作り直されないなら、`label` で区別する | スキーマを変えない | 移調や編集で `label` が作り直されると alt が消える。消える経路が1つでもあれば不可 |
| C | `tensions` に「alt」を表す特別な値を足す | フィールドを足さない | テンションの値を数える処理が誤動作しないか |

**v1 の「スキーマを変えない」はここで緩める。** 優先順位は次のとおり:

1. **既存の Vault データがそのまま読めること**(絶対条件)
2. **記号の意味を失わないこと**
3. 保存スキーマを変えないこと

### 5.3 表示名の規則

| 入力 | 表示 | 意味 |
|---|---|---|
| `Cm(maj7)` `CmM7` `C-Δ7` など | `Cm(maj7)` | 綴りの揺れは正準形に揃える |
| `Cm(maj9)` | `Cm(maj9)` | |
| `G7alt` `G7(alt)` `Galt` | `G7alt` | オルタード(分類) |
| `G7(b9,#9,b13)` | `G7(♭9,♯9,♭13)` | **明示されたテンション。`G7alt` に変えない** |
| `G7(#9,b13)` | `G7(♯9,♭13)` | 同上 |
| `G7(b9,#11)` | `G7(♭9,♯11)` | 同上 |

- 綴りの揺れ(`CmM7` / `Cm(maj7)`)は揃えてよい。**意味の違い(分類 / 明示テンション)は揃えない**
- テンションの書き方(♭ か b か、括弧の付け方)は既存の表示規則に従う
- **移調しても崩れないこと。** `G7alt` を全音上げたら `A7alt`。`G7(♭9,♭13)` なら `A7(♭9,♭13)`

### 5.4 互換性と往復の保証

- **入力 → 保存 → 読み込み → 表示** で、構造と表示名が変わらないこと。書き出し → 読み込みでも同じ
- フィールドを足す場合、**足す前の保存データ(フィールドが無いもの)は、従来どおりの意味で読めること**
- 足したフィールドを、記録・ログ・書き出しに載せてよいか、既存のプライバシーの決まりに照らして確認する

## 6. 入力の正規化

| 入力 | 正規化後 |
|---|---|
| `♭` | `b` |
| `♯` | `#` |
| `−`(U+2212)/ `–`(U+2013) | `-` |
| `△` / `Δ` | 同じものとして扱う |
| `°` / `º` | dim の印 |
| `ø` / `Ø` | m7b5 の印 |
| 全角括弧 `（` `）` | `(` `)` |
| 全角英数字・全角記号 | 半角 |

- 日本語入力のまま打った `Cm（maj7）` を読めることを必須とする
- **正規化は冪等であること**(2回かけても結果が同じ)
- **正規化でトークンの意味を変えないこと。** `M` と `m` を同一視しない。`6/9` の `/` を分数の記号にしない
- 既に正規化の処理がある場合はそこに足す。**正規化を2か所に作らない**
- 「通常」と「拡張記法」で、同じトークンは同じ意味になること

## 7. 試聴の音(=登録時の音)

テキストで保存すると、試聴の音がそのまま「登録時の音」になる。
**試聴の音が不自然だと、それが利用者のボイシングとして記録に残る。**

### 7.1 全般

- 試聴の音は**アプリが選んだ推奨ボイシング**である。原曲の音ではない
- 保存するとき、**出どころが「アプリが選んだ音」であると記録する**(Phase 11 の出どころの決まりに従う。MIDI から採った音と区別できること)
- 分数コードのベースを必ず最低音にする
- C4 より下で、半音でぶつかる並びを作らない(P12.4 で B♭maj7/G に見つかった濁りと同じ問題を作らないため)
- **新しいボイシング生成の仕組みは作らない。** 既存の試聴の処理に、下の条件を満たす音を作らせる

### 7.2 マイナー・メジャー7

- ♭3 と長7度の**両方**を含む(C の例: C E♭ G B。5度は省いてもよい)

### 7.3 オルタード(`G7alt`)

- 3度と♭7 を必ず含む
- ♭9 / ♯9 / ♯11 / ♭13 から **1〜2個**を選んで含む
- **含めてはいけない音:** 完全5度、9(♭♯なし)、13(♭♯なし)
- どれを選ぶかは試聴処理の判断でよい。参考: G2 | B3 F4 B♭4 E♭5(3・♭7・♯9・♭13)

### 7.4 明示テンション(`G7(♭9,♭13)` など)

- **書かれたテンションを鳴らす。** 書かれていないオルタードのテンションを足さない

### 7.5 作れないとき・作った音が記号と合わないとき(重要)

**絶対に避けること:** 試聴の処理が `G7(♭9,♯9,♭13)` を扱えず、代わりに `G7` の音を作り、
それが「登録時の音」として保存され、利用者が間違った音を練習すること。

#### 生成後の検査

試聴の処理が例外を出さずに**別の音を返す**こともあるため、「失敗したら」だけでは防げない。
**作った音を、記号と照らし合わせて検査する。**

- 記号から「必ず含む音」と「含めてはいけない音」を導く関数を1つ作る(§7.2〜7.4 の条件をそのまま式にしたもの)
- 試聴の処理が返した音を、この関数で検査する
- 検査に通らなければ、**作れなかったものとして扱う**

この関数は §10.5 のテストでも使う(テストと製品で同じ基準を使う)。

#### 作れなかったときの扱い

| 場面 | 扱い |
|---|---|
| コード記号 | **正しく保持する**(読み取りは成功している) |
| 試聴 | そのコードは**鳴らさない**。カードに「試聴の音を作れません」を示す。別の音で代用しない |
| 保存 | コード記号は保存する。**そのコードの登録時の音は保存しない**(Voicing Memory はコードごとに音が無くてもよい) |
| Chord Dojo「登録した音を覚える」 | 登録時の音が無いコードは、既存の非対応表示で示す。別の音を作って出題しない |

- 代用として「3度と♭7 だけ」のような部分的な音を鳴らすことも、本作業ではしない
- 作れなかったコードの数と記号を、取り込み画面で分かるようにする(既存の警告表示があればそれを使う)

#### 前後のつながり

既存の試聴の処理が前後のコードとのつながり(ボイスリーディング)を考慮しているなら、それを使う。
本作業で新しく考慮させる必要はない。

## 8. 消費側(各機能)での扱い

テキスト取り込みで変換された進行は、他の機能が使う(Phase 5.20 の決まりで、
Vault 保存 / Chord Dojo / Bass Practice / Chord Context / Root Motion / Voicing Memory が、
それぞれ自分で対応可否を判定する)。

- 各消費側について、`minMaj7` と alt を渡したときの挙動を Stage 00 で確認する
- **例外で落ちるものは直す**
- 対応できないものは**既存の非対応表示**に任せる。新しい表示を作らない

### alt を知らない機能の扱い(重要)

§5.2 で印やフィールドを足すと、それを知らない機能は alt のコードを**ただの `G7` として読んでしまう。**
これは「黙って別のコードとして扱う」ことであり、禁止する。

ただし、**全機能を一律に非対応にはしない。** 機能ごとに、実際に必要な情報が違うためである。
一律に非対応にすると、本作業の目的(Dojo の「登録した音を覚える」で練習する)が達成できない。

#### 必要な情報の表で判定する

各機能が「何の情報を使っているか」を、**1か所の表**に宣言する。判定はその表から行う。機能ごとに判定を書かない。

| 機能 | 必要な情報(想定。Stage 00 で確かめる) | alt の扱い |
|---|---|---|
| Vault 保存 | 記号のすべて | **対応**(alt の情報を欠かさず保存できること) |
| Chord Dojo「登録した音を覚える」 | 保存された音の高さ | **対応(本作業の合格条件)**。登録時の音が無いコードは §7.5 のとおり非対応 |
| Root Motion | 根音のみ | 根音だけで成り立つことを確かめたら対応 |
| Bass Practice | 根音・ベース音 | 同上 |
| Chord Context | 確認が要る | Stage 00 の結果で決める |
| Voicing Memory | 保存された音の高さ | Dojo と同様 |
| Voicing Loop の生成ボイシング | 記号のすべて(音を作る) | **非対応のまま**(本作業では直さない。誤った音を作る危険があるため) |

- 表に**載っていない機能は、alt を非対応とする**(既定は非対応)
- 「根音のみ」と宣言した機能に、根音以外の情報を読む経路が1つでもあれば、その宣言は誤り。Stage 00 で確かめる
- Voicing Loop の生成ボイシングで非対応になるスタイルは報告する

## 9. 範囲外:12小節の上限

テキスト取り込みの上限(4096 文字単位 / 12 小節 / 48 トークン)は**変えない**。

ジャズの曲は 32 小節(AABA)などが多く、**曲全体は取り込めない。** 当面は、
**A 部分(8 小節)・B 部分(8 小節)などのセクションを別々に取り込む**使い方になる。

上限を上げる話は、アプリ全体の決まり(Contract 06:1 / 2 / 4 / 8 / 12 小節、48 イベント)に関わるため、別のフェーズで扱う。
本作業では、取り込み画面で 12 小節を超えたときのエラー文言が
「セクションごとに分けて取り込めること」が分かる内容になっているかだけ確認し、なっていなければ文言を直す。
